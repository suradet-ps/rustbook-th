# โปรเจกต์ I/O: สร้างโปรแกรมบรรทัดคำสั่ง

บทนี้เป็นการทบทวนทักษะหลายอย่างที่คุณได้เรียนรู้มาจนถึงตอนนี้ และเป็นการสำรวจฟีเจอร์ของไลบรารีมาตรฐานอีกสองสามอย่าง เราจะสร้างเครื่องมือบรรทัดคำสั่ง (command line) ที่โต้ตอบกับไฟล์และอินพุต/เอาต์พุตของบรรทัดคำสั่ง เพื่อฝึกฝนแนวคิด Rust บางส่วนที่คุณมีอยู่ในตอนนี้

ความเร็ว ความปลอดภัย เอาต์พุตไบนารีไฟล์เดียว และการรองรับข้ามแพลตฟอร์มของ Rust ทำให้มันเป็นภาษาที่เหมาะสำหรับสร้างเครื่องมือบรรทัดคำสั่ง ดังนั้นสำหรับโปรเจกต์ของเรา เราจะสร้างเวอร์ชันของเราเองของเครื่องมือค้นหาบรรทัดคำสั่งคลาสสิกอย่าง `grep` (**g**lobally search a **r**egular **e**xpression and **p**rint) ในกรณีการใช้งานที่ง่ายที่สุด `grep` ค้นหาสตริงที่ระบุในไฟล์ที่ระบุ เพื่อทำเช่นนั้น `grep` รับพาธไฟล์และสตริงเป็นอาร์กิวเมนต์ (argument) ของมัน จากนั้นมันจะอ่านไฟล์ ค้นหาบรรทัดในไฟล์นั้นที่บรรจุอาร์กิวเมนต์สตริง และพิมพ์บรรทัดเหล่านั้น

ระหว่างทาง เราจะแสดงวิธีทำให้เครื่องมือบรรทัดคำสั่งของเราใช้ฟีเจอร์ของเทอร์มินัลที่เครื่องมือบรรทัดคำสั่งอื่นๆ จำนวนมากใช้ เราจะอ่านค่าของตัวแปรสภาพแวดล้อม (environment variable) เพื่อให้ผู้ใช้กำหนดค่าพฤติกรรมของเครื่องมือของเรา เราจะพิมพ์ข้อความแสดงข้อผิดพลาดไปยังสตรีมคอนโซลข้อผิดพลาดมาตรฐาน (`stderr`) แทนเอาต์พุตมาตรฐาน (`stdout`) ด้วย เพื่อให้ตัวอย่างเช่น ผู้ใช้สามารถเปลี่ยนเส้นทางเอาต์พุตที่สำเร็จไปยังไฟล์ได้ในขณะที่ยังเห็นข้อความแสดงข้อผิดพลาดบนหน้าจอ

สมาชิกชุมชน Rust คนหนึ่งชื่อ Andrew Gallant ได้สร้างเวอร์ชันที่เต็มไปด้วยฟีเจอร์และรวดเร็วมากของ `grep` ชื่อ `ripgrep` ขึ้นแล้ว เมื่อเทียบกันแล้ว เวอร์ชันของเราจะค่อนข้างง่าย แต่บทนี้จะให้ความรู้พื้นฐานบางส่วนที่คุณต้องใช้ในการทำความเข้าใจโปรเจกต์ในโลกจริงอย่าง `ripgrep`

โปรเจกต์ `grep` ของเราจะผสมผสานแนวคิดหลายอย่างที่คุณได้เรียนรู้มาจนถึงตอนนี้:

- การจัดระเบียบโค้ด ([บทที่ 7][ch7]<!-- ignore -->)
- การใช้เวกเตอร์ (vector) และสตริง (string) ([บทที่ 8][ch8]<!-- ignore -->)
- การจัดการข้อผิดพลาด (error handling) ([บทที่ 9][ch9]<!-- ignore -->)
- การใช้เทรต (trait) และไลฟ์ไทม์ (lifetime) อย่างเหมาะสม ([บทที่ 10][ch10]<!-- ignore -->)
- การเขียนเทสต์ (test) ([บทที่ 11][ch11]<!-- ignore -->)

เราจะแนะนำโคลเชอร์ (closure) อิเทอเรเตอร์ (iterator) และเทรตออบเจกต์ (trait object) แบบสั้นๆ ด้วย ซึ่ง[บทที่ 13][ch13]<!-- ignore --> และ[บทที่ 18][ch18]<!-- ignore --> จะครอบคลุมอย่างละเอียด
