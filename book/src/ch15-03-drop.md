## รันโค้ดเมื่อทำความสะอาดด้วยเทรต `Drop`

เทรตที่สองที่มีความสำคัญต่อรูปแบบสมาร์ตพอยน์เตอร์ก็คือ `Drop` ซึ่งช่วยให้คุณสามารถกำหนดพฤติกรรมที่จะเกิดขึ้นเมื่อค่าของตัวแปรหนึ่งกำลังจะหลุดออกจากขอบเขต (scope) ได้ คุณสามารถอิมพลีเมนต์เทรต `Drop` ให้กับชนิดข้อมูลใดก็ได้ และโค้ดดังกล่าวมักถูกนำมาใช้เพื่อปลดปล่อยและคืนทรัพยากรต่าง ๆ เช่น ไฟล์ หรือการเชื่อมต่อเครือข่าย

เราแนะนำเทรต `Drop` ในบริบทของสมาร์ตพอยน์เตอร์ เพราะการทำงานของเทรตนี้ถูกนำมาใช้อยู่เสมอในการสร้างสมาร์ตพอยน์เตอร์ ตัวอย่างเช่น เมื่อ `Box<T>` ถูกทิ้ง (drop) ตัวมันเองก็จะคืนพื้นที่หน่วยความจำบนฮีปที่บ็อกซ์นั้นชี้อยู่ให้โดยอัตโนมัติ

ในบางภาษาและกับชนิดข้อมูลบางประเภท โปรแกรมเมอร์จะต้องเรียกใช้คำสั่งเพื่อคืนหน่วยความจำหรือทรัพยากรด้วยตนเองทุกครั้งที่ใช้งานอินสแตนซ์เหล่านั้นเสร็จสิ้น เช่น ตัวจัดการไฟล์ (file handles), ซ็อกเก็ต (sockets) หรือล็อก (locks) หากโปรแกรมเมอร์ลืม ระบบก็อาจทำงานหนักเกินไปจนเกิดการล่ม (crash) ได้ แต่ใน Rust คุณสามารถกำหนดโค้ดเฉพาะเจาะจงให้ทำงานโดยอัตโนมัติเมื่อใดก็ตามที่ค่านั้นหลุดออกจากขอบเขต โดยที่คอมไพเลอร์จะเป็นผู้แทรกโค้ดนี้ให้เอง ส่งผลให้คุณไม่ต้องคอยกังวลกับการวางโค้ดเก็บกวาดทรัพยากรไว้ทุกหนทุกแห่งในโปรแกรมหลังจากเลิกใช้งานอินสแตนซ์ของชนิดข้อมูลนั้น ๆ โดยไม่มีการรั่วไหลของทรัพยากรเกิดขึ้นเลย!

คุณสามารถกำหนดโค้ดที่จะให้ทำงานเมื่อค่าหลุดออกจากขอบเขตได้ด้วยการอิมพลีเมนต์เทรต `Drop` โดยเทรต `Drop` กำหนดให้คุณต้องอิมพลีเมนต์เมธอดหนึ่งตัวชื่อ `drop` ซึ่งรับพารามิเตอร์เป็นเรเฟอเรนซ์แบบเปลี่ยนแปลงได้ที่ชี้ไปยัง `self` เพื่อให้เห็นภาพชัดเจนว่า Rust เรียกใช้งาน `drop` เมื่อใด เราจะมาลองเขียนเมธอด `drop` โดยใส่คำสั่ง `println!` ไว้ในเบื้องต้นกันก่อน

ทว่าการปิดใช้งานการทำงานอัตโนมัติของ `drop` นั้นไม่ใช่เรื่องที่จะทำได้โดยตรง ซึ่งโดยปกติแล้วการปิดการทำงานของ `drop` ก็ไม่มีความจำเป็นอยู่แล้ว เพราะจุดประสงค์หลักของเทรต `Drop` คือการดูแลเรื่องนี้ให้โดยอัตโนมัติ อย่างไรก็ตาม ในบางครั้งคุณอาจจำเป็นต้องเก็บกวาดค่าใดค่าหนึ่งก่อนเวลาอันควร ตัวอย่างเช่น การใช้สมาร์ตพอยน์เตอร์ที่คอยจัดการล็อก (locks) คุณอาจต้องการบังคับให้เมธอด `drop` ปลดล็อกทันที เพื่อให้โค้ดส่วนอื่นในขอบเขตเดียวกันสามารถเข้าถือครองล็อกต่อไปได้ Rust จะไม่อนุญาตให้คุณเรียกเมธอด `drop` ของเทรต `Drop` ด้วยตนเอง แต่คุณจะต้องเรียกใช้ฟังก์ชัน `std::mem::drop` ที่ไลบรารีมาตรฐานจัดเตรียมไว้ให้แทน หากคุณต้องการบังคับให้ค่านั้นถูกทิ้งก่อนที่จะสิ้นสุดขอบเขตของมัน

ข้อความแสดงข้อผิดพลาดนี้ระบุชัดเจนว่าเราไม่ได้รับอนุญาตให้เรียกใช้ `drop` อย่างโจ่งแจ้งด้วยตนเอง โดยข้อความนี้ใช้คำว่า _destructor_ ซึ่งเป็นคำศัพท์ทั่วไปในการเขียนโปรแกรมสำหรับฟังก์ชันที่ทำหน้าที่เก็บกวาดทำลายอินสแตนซ์ คำว่า _destructor_ เปรียบได้กับคู่ตรงข้ามของ _constructor_ ที่ทำหน้าที่สร้างอินสแตนซ์ขึ้นมา โดยฟังก์ชัน `drop` ใน Rust ก็จัดเป็น destructor รูปแบบหนึ่งนั่นเอง

สาเหตุที่ Rust ไม่อนุญาตให้เราเรียกใช้ `drop` ด้วยตนเอง ก็เพราะ Rust จะยังคงเรียกใช้ `drop` กับค่านั้นโดยอัตโนมัติเมื่อสิ้นสุดฟังก์ชัน `main` อยู่ดี ซึ่งจะนำไปสู่ข้อผิดพลาด double free (การพยายามปลดปล่อยหน่วยความจำซ้ำซ้อน) เนื่องจาก Rust พยายามจะเก็บกวาดค่าเดิมถึงสองครั้ง

ในเมื่อเราไม่สามารถปิดการแทรกคำสั่ง `drop` อัตโนมัติเมื่อค่าหลุดออกจากขอบเขตได้ และไม่สามารถเรียกเมธอด `drop` ด้วยตนเองได้ ดังนั้นหากเราจำเป็นต้องบังคับให้เก็บกวาดค่าหนึ่งก่อนเวลาจริง ๆ เราจึงต้องใช้งานฟังก์ชัน `std::mem::drop`

ฟังก์ชัน `std::mem::drop` แตกต่างจากเมธอด `drop` ในเทรต `Drop` เราเรียกมันโดยส่งค่าที่ต้องการบังคับให้ทิ้งเป็นอาร์กิวเมนต์ ฟังก์ชันนี้อยู่ในพรีลูด เราจึงแก้ไข `main` ในลิสติ้ง 15-15 ให้เรียกฟังก์ชัน `drop` ได้ ดังที่แสดงในลิสติ้ง 15-16

คุณสามารถนำโค้ดที่กำหนดไว้ในการอิมพลีเมนต์เทรต `Drop` ไปประยุกต์ใช้งานได้หลากหลายรูปแบบ เพื่อให้การเก็บกวาดทรัพยากรทำได้อย่างสะดวกและปลอดภัย ตัวอย่างเช่น คุณอาจใช้มันเพื่อสร้างตัวจัดสรรหน่วยความจำ (memory allocator) ขึ้นมาใช้เอง! ด้วยเทรต `Drop` ร่วมกับระบบความเป็นเจ้าของ (ownership) ของ Rust คุณจึงไม่ต้องคอยจำว่าต้องเก็บกวาดทรัพยากรเมื่อใด เพราะ Rust จะจัดการทุกอย่างให้โดยอัตโนมัติ

นอกจากนี้ คุณยังไม่ต้องกังวลกับปัญหาที่เกิดจากการเผลอไปเก็บกวาดค่าที่ยังถูกใช้งานอยู่ เพราะระบบความเป็นเจ้าของที่คอยดูแลให้เรเฟอเรนซ์มีความถูกต้องสมบูรณ์อยู่เสมอนั้น ยังรับประกันด้วยว่า `drop` จะถูกเรียกเพียงครั้งเดียวเมื่อค่านั้นไม่มีการใช้งานอีกต่อไปแล้วเท่านั้น

หลังจากที่เราได้ศึกษา `Box<T>` และคุณลักษณะสำคัญของสมาร์ตพอยน์เตอร์ไปแล้ว ต่อไปเรามาดูสมาร์ตพอยน์เตอร์ตัวอื่น ๆ ที่น่าสนใจในไลบรารีมาตรฐานกันต่อ
