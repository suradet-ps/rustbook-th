## รันโค้ดเมื่อทำความสะอาดด้วยเทรต `Drop`

เทรต (trait) ที่สองที่สำคัญต่อแพตเทิร์น (pattern) สมาร์ตพอยน์เตอร์ (smart pointer) คือ `Drop` ซึ่งช่วยให้คุณปรับแต่งว่าอะไรจะเกิดขึ้นเมื่อค่าหนึ่งกำลังจะออกจากสโคป คุณสามารถจัดหาการอิมพลีเมนต์สำหรับเทรต `Drop` บนชนิดใดก็ได้ และโค้ดนั้นสามารถถูกใช้เพื่อปลดปล่อยทรัพยากรอย่างไฟล์หรือการเชื่อมต่อเครือข่ายได้

เราขอแนะนำ `Drop` ในบริบทของสมาร์ตพอยน์เตอร์ เพราะฟังก์ชันการทำงานของเทรต `Drop` ถูกใช้แทบทุกครั้งเมื่ออิมพลีเมนต์สมาร์ตพอยน์เตอร์ ตัวอย่างเช่น เมื่อ `Box<T>` ถูกทิ้ง (drop) มันจะคืนพื้นที่บนฮีป (heap) ที่บ็อกซ์ชี้ไป

ในบางภาษา สำหรับบางชนิดข้อมูล โปรแกรมเมอร์ต้องเรียกโค้ดเพื่อคืนหน่วยความจำหรือทรัพยากรทุกครั้งที่ใช้อินสแตนซ์ของชนิดเหล่านั้นเสร็จ ตัวอย่างได้แก่ file handle, socket และ lock หากโปรแกรมเมอร์ลืม ระบบอาจโอเวอร์โหลดและล่มได้ ใน Rust คุณสามารถระบุว่าโค้ดบางส่วนจะถูกรันทุกครั้งที่ค่าหนึ่งออกจากสโคป และคอมไพเลอร์จะแทรกโค้ดนี้ให้โดยอัตโนมัติ ด้วยเหตุนี้ คุณจึงไม่จำเป็นต้องระมัดระวังในการวางโค้ดทำความสะอาดไว้ทุกที่ในโปรแกรมที่ใช้อินสแตนซ์ของชนิดข้อมูลหนึ่งเสร็จ—คุณจะยังไม่รั่วไหลทรัพยากร!

คุณระบุโค้ดที่จะรันเมื่อค่าออกจากสโคปโดยการอิมพลีเมนต์เทรต `Drop` เทรต `Drop` กำหนดให้คุณอิมพลีเมนต์เมธอดหนึ่งตัวชื่อ `drop` ที่รับเรเฟอเรนซ์แบบเปลี่ยนแปลงได้ไปยัง `self` เพื่อดูว่า Rust เรียก `drop` เมื่อใด มาอิมพลีเมนต์ `drop` ด้วยสเตตเมนต์ `println!` ไปก่อนในตอนนี้

น่าเสียดายที่การปิดใช้งานฟังก์ชัน `drop` อัตโนมัตินั้นไม่ง่ายเลย การปิดใช้งาน `drop` มักไม่จำเป็น จุดประสงค์ทั้งหมดของเทรต `Drop` คือมันถูกจัดการให้โดยอัตโนมัติ อย่างไรก็ตาม ในบางครั้งคุณอาจต้องการทำความสะอาดค่าหนึ่งก่อนกำหนด ตัวอย่างหนึ่งคือเมื่อใช้สมาร์ตพอยน์เตอร์ที่จัดการ lock: คุณอาจต้องการบังคับให้เมธอด `drop` ที่ปลดปล่อย lock ทำงาน เพื่อให้โค้ดอื่นในสโคปเดียวกันสามารถขอ lock ได้ Rust ไม่ให้คุณเรียกเมธอด `drop` ของเทรต `Drop` ด้วยตัวเอง แต่คุณต้องเรียกฟังก์ชัน `std::mem::drop` ที่ไลบรารีมาตรฐานมอบให้ หากคุณต้องการบังคับให้ค่าหนึ่งถูกทิ้งก่อนสิ้นสุดสโคปของมัน

ข้อความแสดงข้อผิดพลาดนี้ระบุว่าเราไม่ได้รับอนุญาตให้เรียก `drop` อย่างชัดแจ้ง ข้อความแสดงข้อผิดพลาดใช้คำว่า _destructor_ ซึ่งเป็นคำทั่วไปทางการเขียนโปรแกรมสำหรับฟังก์ชันที่ทำความสะอาดอินสแตนซ์ _destructor_ เทียบได้กับ _constructor_ ซึ่งสร้างอินสแตนซ์ ฟังก์ชัน `drop` ใน Rust เป็น destructor ชนิดหนึ่งโดยเฉพาะ

Rust ไม่ให้เราเรียก `drop` อย่างชัดแจ้ง เพราะ Rust จะยังคงเรียก `drop` บนค่าที่ส่วนท้ายของ `main` โดยอัตโนมัติ สิ่งนี้จะทำให้เกิดข้อผิดพลาด double free เพราะ Rust จะพยายามทำความสะอาดค่าเดียวกันสองครั้ง

เราไม่สามารถปิดใช้งานการแทรก `drop` โดยอัตโนมัติเมื่อค่าออกจากสโคปได้ และเราไม่สามารถเรียกเมธอด `drop` อย่างชัดแจ้งได้ ดังนั้น หากเราจำเป็นต้องบังคับให้ค่าหนึ่งถูกทำความสะอาดก่อนกำหนด เราจึงใช้ฟังก์ชัน `std::mem::drop`

ฟังก์ชัน `std::mem::drop` แตกต่างจากเมธอด `drop` ในเทรต `Drop` เราเรียกมันโดยส่งค่าที่ต้องการบังคับให้ทิ้งเป็นอาร์กิวเมนต์ ฟังก์ชันนี้อยู่ในพรีลูด เราจึงแก้ไข `main` ในลิสติ้ง 15-15 ให้เรียกฟังก์ชัน `drop` ได้ ดังที่แสดงในลิสติ้ง 15-16

คุณสามารถใช้โค้ดที่ระบุในอิมพลีเมนต์ของเทรต `Drop` ได้หลายวิธีเพื่อทำให้การทำความสะอาดสะดวกและปลอดภัย ตัวอย่างเช่น คุณอาจใช้มันสร้างตัวจัดสรรหน่วยความจำของคุณเอง! ด้วยเทรต `Drop` และระบบความเป็นเจ้าของ (ownership) ของ Rust คุณไม่จำเป็นต้องจำว่าจะต้องทำความสะอาด เพราะ Rust ทำมันให้โดยอัตโนมัติ

คุณยังไม่ต้องกังวลเกี่ยวกับปัญหาที่เกิดจากการทำความสะอาดค่าที่ยังถูกใช้งานอยู่อย่างไม่ตั้งใจ: ระบบความเป็นเจ้าของที่รับประกันว่าเรเฟอเรนซ์ใช้ได้เสมอ ยังรับประกันว่า `drop` ถูกเรียกเพียงครั้งเดียวเมื่อค่าไม่ได้ถูกใช้งานอีกต่อไป
