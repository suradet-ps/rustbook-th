# การจัดการข้อผิดพลาด

ความผิดพลาดเป็นเรื่องที่หลีกเลี่ยงไม่ได้ในการพัฒนาซอฟต์แวร์ Rust จึงมีฟีเจอร์มากมายสำหรับรับมือกับสถานการณ์ที่ไม่เป็นไปตามที่คาดหวัง ในหลายๆ กรณี Rust กำหนดให้คุณต้องตระหนักถึงโอกาสที่จะเกิดข้อผิดพลาดและเขียนโค้ดจัดการเตรียมไว้ก่อน โค้ดจึงจะสามารถคอมไพล์ผ่านได้ ข้อกำหนดนี้ช่วยให้โปรแกรมของคุณมีความเสถียรและทนทาน (robust) ยิ่งขึ้น เพราะมั่นใจได้ว่าคุณจะตรวจพบและจัดการกับข้อผิดพลาดได้อย่างเหมาะสมตั้งแต่ก่อนที่จะนำโค้ดขึ้นสู่ระบบจริง (production)!

Rust แบ่งข้อผิดพลาดออกเป็นสองกลุ่มหลัก ได้แก่ ข้อผิดพลาดที่กู้คืนได้และข้อผิดพลาดที่กู้คืนไม่ได้ สำหรับ *ข้อผิดพลาดที่กู้คืนได้ (recoverable error)* เช่น การเกิดข้อผิดพลาดประเภท *ไม่พบไฟล์ (file not found)* เรามักต้องการเพียงแค่แจ้งเตือนปัญหาให้ผู้ใช้ทราบแล้วลองทำงานใหม่อีกครั้ง ส่วน *ข้อผิดพลาดที่กู้คืนไม่ได้ (unrecoverable error)* มักเป็นสัญญาณของบั๊กเสมอ เช่น การพยายามเข้าถึงตำแหน่งที่เกินขอบเขตของอาร์เรย์ ซึ่งในกรณีนี้เราต้องการให้โปรแกรมหยุดทำงานในทันที

ภาษาโปรแกรมส่วนใหญ่ไม่ได้แยกความแตกต่างระหว่างข้อผิดพลาดทั้งสองประเภทนี้ และมักจัดการทั้งสองแบบด้วยวิธีเดียวกันผ่านกลไกอย่างข้อยกเว้น (exception) แต่ Rust ไม่มี exception ทว่าจะมีประเภทข้อมูล `Result<T, E>` สำหรับจัดการข้อผิดพลาดที่กู้คืนได้ และมีแมโคร `panic!` ที่จะสั่งหยุดการทำงานทันทีเมื่อโปรแกรมพบกับข้อผิดพลาดที่กู้คืนไม่ได้ ในบทนี้เราจะเริ่มต้นด้วยการเรียกใช้ `panic!` ก่อน จากนั้นจึงตามด้วยการส่งคืนค่า `Result<T, E>` นอกจากนี้ เรายังจะมาดูข้อพิจารณาว่าเมื่อใดที่เราควรพยายามกู้คืนจากข้อผิดพลาด และเมื่อใดที่เราควรปล่อยให้โปรแกรมหยุดทำงาน
