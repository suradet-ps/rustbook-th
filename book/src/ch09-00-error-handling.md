# การจัดการข้อผิดพลาด

ข้อผิดพลาดเป็นเรื่องธรรมดาของชีวิตในซอฟต์แวร์ ดังนั้น Rust จึงมีฟีเจอร์หลายประการสำหรับการจัดการข้อผิดพลาด (error handling) ในสถานการณ์ที่บางสิ่งบางอย่างผิดพลาด ในหลายกรณี Rust กำหนดให้คุณยอมรับความเป็นไปได้ที่จะเกิดข้อผิดพลาดและดำเนินการบางอย่างก่อนที่โค้ดของคุณจะคอมไพล์ผ่าน ข้อกำหนดนี้ทำให้โปรแกรมของคุณทนทานมากขึ้นโดยรับประกันว่าคุณจะค้นพบข้อผิดพลาดและจัดการกับมันอย่างเหมาะสมก่อนที่คุณจะนำโค้ดของคุณขึ้นโปรดักชัน!

Rust จัดกลุ่มข้อผิดพลาดออกเป็นสองประเภทใหญ่ๆ คือ ข้อผิดพลาดที่กู้คืนได้และข้อผิดพลาดที่กู้คืนไม่ได้ สำหรับ_ข้อผิดพลาดที่กู้คืนได้_ (recoverable error) เช่นข้อผิดพลาดแบบ_ไม่พบไฟล์_ เรามักต้องการเพียงรายงานปัญหาให้ผู้ใช้ทราบและลองดำเนินการซ้ำ _ข้อผิดพลาดที่กู้คืนไม่ได้_ (unrecoverable error) เป็นอาการของบั๊กเสมอ เช่นการพยายามเข้าถึงตำแหน่งที่เลยจุดสิ้นสุดของอาร์เรย์ ดังนั้นเราจึงต้องการหยุดโปรแกรมทันที

ภาษาโปรแกรมส่วนใหญ่ไม่แยกความแตกต่างระหว่างข้อผิดพลาดสองชนิดนี้และจัดการทั้งคู่ด้วยวิธีเดียวกันโดยใช้กลไกอย่างข้อยกเว้น (exception) Rust ไม่มีข้อยกเว้น แต่มีชนิดข้อมูล `Result<T, E>` สำหรับข้อผิดพลาดที่กู้คืนได้ และมาโคร `panic!` ที่หยุดการทำงานเมื่อโปรแกรมพบข้อผิดพลาดที่กู้คืนไม่ได้ บทนี้ครอบคลุมการเรียก `panic!` ก่อน จากนั้นจะพูดถึงการคืนค่า `Result<T, E>` นอกจากนี้ เราจะสำรวจข้อควรพิจารณาในการตัดสินใจว่าจะพยายามกู้คืนจากข้อผิดพลาดหรือหยุดการทำงาน
