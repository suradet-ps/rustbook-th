## แยกมอดูลออกเป็นไฟล์ต่างๆ

จนถึงตอนนี้ ตัวอย่างทั้งหมดในบทนี้กำหนดมอดูล (module) หลายตัวไว้ในไฟล์เดียว เมื่อมอดูลมีขนาดใหญ่ขึ้น คุณอาจต้องการย้ายนิยามของมันไปไว้ในไฟล์แยกต่างหากเพื่อให้โค้ดนำทางได้ง่ายขึ้น

ตัวอย่างเช่น มาเริ่มจากโค้ดในลิสติ้ง 7-17 ที่มีหลายมอดูลของร้านอาหารกัน เราจะแยกมอดูลออกเป็นไฟล์ต่างๆ แทนที่จะนิยามมอดูลทั้งหมดไว้ในไฟล์รากของเครต (crate root) ในกรณีนี้ ไฟล์รากของเครตคือ _src/lib.rs_ แต่ขั้นตอนนี้ใช้ได้กับเครตไบนารี (binary crate) ที่มีไฟล์รากของเครตเป็น _src/main.rs_ ด้วย

ก่อนอื่น เราจะแยกมอดูล `front_of_house` ออกไปเป็นไฟล์ของตัวเอง ลบโค้ดภายในวงเล็บปีกกาของมอดูล `front_of_house` ออก เหลือไว้เพียงประกาศ `mod front_of_house;` เพื่อให้ _src/lib.rs_ มีโค้ดดังที่แสดงในลิสติ้ง 7-21 โปรดสังเกตว่ามันจะยังคอมไพล์ไม่ผ่านจนกว่าเราจะสร้างไฟล์ _src/front_of_house.rs_ ในลิสติ้ง 7-22

โปรดสังเกตว่าคุณต้องโหลดไฟล์ด้วยประกาศ `mod` เพียง_ครั้งเดียว_ในแผนผังมอดูลของคุณ เมื่อคอมไพเลอร์รู้ว่าไฟล์นั้นเป็นส่วนหนึ่งของโปรเจกต์ (และรู้ว่าโค้ดอยู่ที่ใดในแผนผังมอดูลเพราะตำแหน่งที่คุณวางสเตตเมนต์ `mod`) ไฟล์อื่นๆ ในโปรเจกต์ของคุณควรอ้างถึงโค้ดของไฟล์ที่โหลดแล้วโดยใช้พาธ (path) ไปยังตำแหน่งที่มันถูกประกาศ ดังที่กล่าวไว้ในหัวข้อ[“พาธสำหรับอ้างถึงรายการในแผนผังมอดูล”][paths]<!-- ignore --> กล่าวอีกนัยหนึ่ง `mod` _ไม่ใช่_ การดำเนินการ “include” ที่คุณอาจเคยเห็นในภาษาโปรแกรมอื่น

ต่อไป เราจะแยกมอดูล `hosting` ออกไปเป็นไฟล์ของตัวเอง กระบวนการจะต่างออกไปเล็กน้อยเพราะ `hosting` เป็นมอดูลลูกของ `front_of_house` ไม่ใช่ของมอดูลราก เราจะวางไฟล์สำหรับ `hosting` ไว้ในไดเรกทอรีใหม่ที่จะตั้งชื่อตามมอดูลบรรพบุรุษของมันในแผนผังมอดูล ในกรณีนี้คือ _src/front_of_house_

ในการเริ่มย้าย `hosting` เราจะแก้ _src/front_of_house.rs_ ให้มีเพียงประกาศของมอดูล `hosting`:

> ### พาธไฟล์ทางเลือก
>
> จนถึงตอนนี้ เราได้ครอบคลุมพาธไฟล์ที่เป็นสำนวนนิยมที่สุดที่คอมไพเลอร์ Rust ใช้ แต่ Rust ยังรองรับรูปแบบพาธไฟล์แบบเก่าด้วย สำหรับมอดูลชื่อ `front_of_house` ที่ประกาศในรากของเครต คอมไพเลอร์จะมองหาโค้ดของมอดูลใน:
>
> - _src/front_of_house.rs_ (สิ่งที่เราครอบคลุมไป)
> - _src/front_of_house/mod.rs_ (รูปแบบเก่า ยังเป็นพาธที่รองรับ)
>
> สำหรับมอดูลชื่อ `hosting` ซึ่งเป็นมอดูลย่อยของ `front_of_house` คอมไพเลอร์จะมองหาโค้ดของมอดูลใน:
>
> - _src/front_of_house/hosting.rs_ (สิ่งที่เราครอบคลุมไป)
> - _src/front_of_house/hosting/mod.rs_ (รูปแบบเก่า ยังเป็นพาธที่รองรับ)
>
> หากคุณใช้ทั้งสองรูปแบบกับมอดูลเดียวกัน คุณจะได้รับข้อผิดพลาดจากคอมไพเลอร์ การใช้รูปแบบผสมกันกับมอดูลต่างกันในโปรเจกต์เดียวกันอนุญาตให้ทำได้ แต่อาจสร้างความสับสนให้ผู้ที่นำทางในโปรเจกต์ของคุณ
>
> ข้อเสียหลักของรูปแบบที่ใช้ไฟล์ชื่อ _mod.rs_ คือโปรเจกต์ของคุณอาจมีไฟล์ชื่อ _mod.rs_ หลายไฟล์ ซึ่งอาจสร้างความสับสนเมื่อคุณเปิดไฟล์เหล่านั้นในโปรแกรมแก้ไขพร้อมกัน

เราได้ย้ายโค้ดของแต่ละมอดูลไปยังไฟล์แยกกัน และแผนผังมอดูลยังคงเดิม การเรียกฟังก์ชันใน `eat_at_restaurant` จะทำงานได้โดยไม่ต้องแก้ไขใดๆ แม้ว่านิยามจะอยู่ในไฟล์ที่ต่างกัน เทคนิคนี้ช่วยให้คุณย้ายมอดูลไปยังไฟล์ใหม่ได้เมื่อมอดูลมีขนาดใหญ่ขึ้น

โปรดสังเกตว่าสเตตเมนต์ `pub use crate::front_of_house::hosting` ใน _src/lib.rs_ ก็ไม่เปลี่ยนแปลงเช่นกัน และ `use` ไม่มีผลต่อว่าไฟล์ใดจะถูกคอมไพล์เป็นส่วนหนึ่งของเครต คำสงวน `mod` เป็นตัวประกาศมอดูล และ Rust จะมองหาโค้ดที่จะเข้าไปในมอดูลนั้นในไฟล์ที่มีชื่อเดียวกับมอดูล

## สรุป

Rust ช่วยให้คุณแยกแพ็กเกจ (package) ออกเป็นหลายเครต (crate) และแยกเครตออกเป็นมอดูลต่างๆ เพื่อให้คุณอ้างถึงรายการที่นิยามในมอดูลหนึ่งจากอีกมอดูลหนึ่งได้ คุณทำเช่นนี้ได้โดยระบุพาธแบบสัมบูรณ์หรือแบบสัมพัทธ์ พาธเหล่านี้สามารถนำเข้าสู่สโคป (scope) ด้วยสเตตเมนต์ `use` เพื่อให้คุณใช้พาธที่สั้นกว่าได้สำหรับการใช้รายการนั้นหลายครั้งในสโคปนั้น โค้ดในมอดูลเป็นแบบส่วนตัว (private) โดยค่าเริ่มต้น แต่คุณสามารถทำให้คำนิยามเป็นแบบสาธารณะ (public) ได้โดยเพิ่มคำสงวน `pub`

ในบทถัดไป เราจะดูโครงสร้างข้อมูลแบบคอลเลกชัน (collection) บางส่วนในไลบรารีมาตรฐานที่คุณสามารถใช้ในโค้ดที่จัดระเบียบเรียบร้อยแล้วของคุณ
