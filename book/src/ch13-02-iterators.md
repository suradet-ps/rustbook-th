## ประมวลผลลำดับรายการด้วยอิเทอเรเตอร์

### เทรต `Iterator` และเมธอด `next`

อิเทอเรเตอร์ทั้งหมดอิมพลีเมนต์เทรต (trait) ชื่อ `Iterator` ที่นิยามในไลบรารีมาตรฐาน นิยามของเทรตมีหน้าตาดังนี้:

```rust
pub trait Iterator {
    type Item;

    fn next(&mut self) -> Option<Self::Item>;

    // methods with default implementations elided
}
```

โปรดสังเกตว่านิยามนี้ใช้วากยสัมพันธ์ใหม่: `type Item` และ `Self::Item` ซึ่งเป็นการนิยามชนิดข้อมูลที่เชื่อมโยง (associated type) กับเทรตนี้ เราจะพูดคุยถึงชนิดข้อมูลที่เชื่อมโยงอย่างละเอียดในบทที่ 20 สำหรับตอนนี้ สิ่งที่คุณต้องรู้คือ โค้ดนี้บอกว่าการอิมพลีเมนต์เทรต `Iterator` กำหนดให้คุณนิยามชนิด `Item` ด้วย และชนิด `Item` นี้ถูกใช้ในชนิดที่คืนกลับของเมธอด `next` กล่าวอีกนัยหนึ่ง ชนิด `Item` จะเป็นชนิดที่ถูกคืนกลับมาจากอิเทอเรเตอร์

เทรต `Iterator` กำหนดให้ผู้ที่อิมพลีเมนต์นิยามเพียงเมธอดเดียว: เมธอด `next` ซึ่งคืนสมาชิกของอิเทอเรเตอร์ทีละตัว ห่อไว้ใน `Some` และเมื่อการวนซ้ำสิ้นสุดลง จะคืน `None`

เราสามารถเรียกเมธอด `next` บนอิเทอเรเตอร์ได้โดยตรง ลิสติ้ง 13-12 สาธิตว่าค่าใดถูกคืนกลับจากการเรียก `next` ซ้ำๆ บนอิเทอเรเตอร์ที่สร้างจากเวกเตอร์

### เมธอดที่บริโภคอิเทอเรเตอร์

เทรต `Iterator` มีเมธอดต่างๆ มากมายที่มีการอิมพลีเมนต์ค่าเริ่มต้นจากไลบรารีมาตรฐาน คุณสามารถเรียนรู้เกี่ยวกับเมธอดเหล่านี้ได้โดยดูในเอกสาร API ของไลบรารีมาตรฐานสำหรับเทรต `Iterator` เมธอดเหล่านี้บางตัวเรียกเมธอด `next` ในนิยามของมัน ซึ่งเป็นเหตุผลว่าทำไมคุณจึงต้องอิมพลีเมนต์เมธอด `next` เมื่ออิมพลีเมนต์เทรต `Iterator`

เมธอดที่เรียก `next` เรียกว่า_ตัวปรับแบบบริโภคค่า_ (consuming adaptor) เพราะการเรียกมันใช้จนหมดอิเทอเรเตอร์ ตัวอย่างหนึ่งคือเมธอด `sum` ซึ่งรับความเป็นเจ้าของอิเทอเรเตอร์และวนซ้ำผ่านสมาชิกโดยเรียก `next` ซ้ำๆ จึงบริโภคอิเทอเรเตอร์ ขณะที่มันวนซ้ำผ่าน มันจะบวกสมาชิกแต่ละตัวเข้ากับผลรวมที่สะสมและคืนผลรวมเมื่อการวนซ้ำเสร็จสมบูรณ์ ลิสติ้ง 13-13 มีเทสต์ (test) ที่แสดงการใช้งานเมธอด `sum`

### โคลเชอร์ที่จับสภาพแวดล้อมของมัน

เทสต์แสดงว่าเมื่อเราเรียก `shoes_in_size` เราจะได้เฉพาะรองเท้าที่มีขนาดเดียวกับค่าที่เราระบุกลับคืนมา
