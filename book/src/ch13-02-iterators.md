## ประมวลผลลำดับรายการด้วยอิเทอเรเตอร์

รูปแบบอิเทอเรเตอร์ (iterator pattern) ช่วยให้คุณทำงานกับชุดลำดับของข้อมูลทีละสมาชิกได้อย่างเป็นระเบียบ ตัวอิเทอเรเตอร์ (iterator) จะรับหน้าที่จัดการตรรกะในการวนลูปผ่านสมาชิกแต่ละตัว และคอยตรวจสอบว่าลำดับข้อมูลนั้นสิ้นสุดลงเมื่อใด ทำให้เมื่อคุณใช้งานอิเทอเรเตอร์ คุณจึงไม่จำเป็นต้องเขียนตรรกะการวนลูปเหล่านั้นขึ้นมาใหม่ด้วยตัวเอง

ในภาษา Rust อิเทอเรเตอร์จะทำงานแบบ_ประเมินผลตามความต้องการ_ หรือ เลซี่ (lazy evaluation) ซึ่งหมายความว่ามันจะยังไม่เริ่มประมวลผลข้อมูลใดๆ จนกว่าคุณจะเรียกใช้เมธอดที่ดึงข้อมูลจากอิเทอเรเตอร์ไปใช้งานจริง ตัวอย่างเช่น โค้ดในลิสติ้ง 13-10 เป็นการสร้างอิเทอเรเตอร์เพื่อวนอ่านสมาชิกในเวกเตอร์ `v1` โดยเรียกเมธอด `iter` ที่นิยามไว้บน `Vec<T>` ซึ่งลำพังโค้ดชุดนี้เพียงอย่างเดียวยังไม่ได้ก่อให้เกิดผลลัพธ์ที่เป็นประโยชน์ใดๆ

### เทรต `Iterator` และเมธอด `next`

อิเทอเรเตอร์ทุกตัวใน Rust จะต้องอิมพลีเมนต์เทรต (trait) ที่ชื่อว่า `Iterator` ซึ่งถูกนิยามไว้ในไลบรารีมาตรฐาน โดยนิยามของเทรตนี้มีหน้าตาดังนี้:

```rust
pub trait Iterator {
    type Item;

    fn next(&mut self) -> Option<Self::Item>;

    // methods with default implementations elided
}
```

โปรดสังเกตว่านิยามนี้ใช้ไวยากรณ์ใหม่: `type Item` และ `Self::Item` ซึ่งเป็นการนิยามชนิดข้อมูลประจำเทรต (associated type) ร่วมกับเทรตนี้ เราจะพูดถึง associated type อย่างละเอียดในบทที่ 20 สำหรับตอนนี้ สิ่งที่คุณต้องทราบคือ โค้ดนี้ระบุว่าการจะอิมพลีเมนต์เทรต `Iterator` ได้นั้น คุณจะต้องกำหนดชนิดข้อมูล `Item` ด้วยเสมอ และชนิดข้อมูล `Item` นี้จะถูกนำไปใช้เป็นชนิดของค่าที่ส่งกลับจากเมธอด `next` หรือกล่าวอีกนัยหนึ่งคือ ชนิดข้อมูล `Item` จะเป็นชนิดข้อมูลของสมาชิกที่อิเทอเรเตอร์ตัวนั้นส่งออกมา

เทรต `Iterator` กำหนดให้ผู้อิมพลีเมนต์ต้องเขียนนิยามเพียงเมธอดเดียวเท่านั้น นั่นคือเมธอด `next` ซึ่งจะส่งสมาชิกของอิเทอเรเตอร์ออกมาทีละตัวโดยห่อหุ้มไว้ใน `Some` และเมื่อวนจนครบข้อมูลลำดับสุดท้ายแล้ว มันก็จะส่งกลับเป็น `None`

เราสามารถเรียกใช้เมธอด `next` บนอิเทอเรเตอร์ได้โดยตรง ลิสติ้ง 13-12 สาธิตให้เห็นว่าค่าใดบ้างที่จะถูกส่งกลับมาจากการเรียกใช้ `next` ซ้ำๆ บนอิเทอเรเตอร์ที่สร้างขึ้นจากเวกเตอร์

โปรดสังเกตว่าเราจำเป็นต้องประกาศให้ `v1_iter` เปลี่ยนแปลงค่าได้ (`mut`): การเรียกเมธอด `next` บนอิเทอเรเตอร์จะไปเปลี่ยนสถานะภายในที่อิเทอเรเตอร์ใช้คอยติดตามลำดับตำแหน่งของข้อมูล กล่าวคือ โค้ดชุดนี้จะ_ดึงใช้ข้อมูล (consume)_ จากอิเทอเรเตอร์ โดยการเรียก `next` แต่ละครั้งจะดึงข้อมูลสมาชิกหนึ่งตัวออกจากอิเทอเรเตอร์ไป ทั้งนี้เราไม่จำเป็นต้องทำให้ `v1_iter` เปลี่ยนแปลงค่าได้เมื่อเราใช้ลูป `for` เนื่องจากลูป `for` จะรับสิทธิ์ความเป็นเจ้าของ `v1_iter` และจัดการให้มันเปลี่ยนแปลงค่าได้อยู่เบื้องหลังโดยอัตโนมัติ

โปรดสังเกตเพิ่มเติมว่า ค่าที่เราได้จากการเรียก `next` จะเป็นเรเฟอเรนซ์แบบเปลี่ยนแปลงไม่ได้ (immutable reference) ที่ชี้ไปยังค่าในเวกเตอร์ เนื่องจากการเรียกเมธอด `iter` จะสร้างอิเทอเรเตอร์ที่วนซ้ำบนเรเฟอเรนซ์แบบเปลี่ยนแปลงไม่ได้ แต่หากเราต้องการสร้างอิเทอเรเตอร์ที่รับสิทธิ์ความเป็นเจ้าของ `v1` และส่งคืนค่าที่เป็นเจ้าของโดยตรง เราสามารถเรียกใช้เมธอด `into_iter` แทน `iter` ได้ ในทำนองเดียวกัน หากเราต้องการวนซ้ำเพื่อแก้ไขข้อมูลผ่านเรเฟอเรนซ์แบบเปลี่ยนแปลงได้ เราก็สามารถเรียกใช้เมธอด `iter_mut` แทนได้เช่นกัน

### เมธอดที่บริโภคอิเทอเรเตอร์

เทรต `Iterator` มีเมธอดต่างๆ มากมายที่มีการอิมพลีเมนต์ค่าเริ่มต้นจากไลบรารีมาตรฐาน คุณสามารถเรียนรู้เกี่ยวกับเมธอดเหล่านี้ได้โดยดูในเอกสาร API ของไลบรารีมาตรฐานสำหรับเทรต `Iterator` เมธอดเหล่านี้บางตัวเรียกเมธอด `next` ในนิยามของมัน ซึ่งเป็นเหตุผลว่าทำไมคุณจึงต้องอิมพลีเมนต์เมธอด `next` เมื่ออิมพลีเมนต์เทรต `Iterator`

เมธอดที่เรียกใช้ `next` ภายในตัวเองจะเรียกว่า _ตัวปรับที่ดึงใช้ข้อมูลจนหมด (consuming adaptors)_ เนื่องจากการเรียกเมธอดเหล่านี้จะดึงข้อมูลจากอิเทอเรเตอร์ไปจนหมด ตัวอย่างหนึ่งคือเมธอด `sum` ซึ่งจะรับสิทธิ์ความเป็นเจ้าของของอิเทอเรเตอร์ และวนซ้ำผ่านสมาชิกแต่ละตัวโดยเรียก `next` ซ้ำๆ จึงถือเป็นการดึงใช้ข้อมูลจากอิเทอเรเตอร์จนหมด ในระหว่างที่วนซ้ำ มันจะนำสมาชิกแต่ละตัวมาบวกสะสมเข้าด้วยกัน แล้วส่งคืนผลรวมออกมาเมื่อวนซ้ำจนเสร็จสมบูรณ์ ลิสติ้ง 13-13 แสดงตัวอย่างการทดสอบการใช้งานเมธอด `sum`

คุณสามารถเชื่อมโยง (chain) การเรียกตัวปรับอิเทอเรเตอร์หลายตัวต่อกันเป็นทอดๆ เพื่อทำงานที่ซับซ้อนได้อย่างเป็นระเบียบและอ่านเข้าใจง่าย แต่เนื่องจากอิเทอเรเตอร์ทั้งหมดทำงานแบบเลซี่ คุณจึงต้องเรียกเมธอดตัวปรับที่ดึงใช้ข้อมูล (consuming adaptor) ตัวใดตัวหนึ่งปิดท้ายเสมอ เพื่อให้เกิดการประมวลผลและได้ผลลัพธ์จากการเชื่อมโยงตัวปรับอิเทอเรเตอร์เหล่านั้นออกมา

### โคลเชอร์ที่จับสภาพแวดล้อมของมัน

ตัวปรับอิเทอเรเตอร์หลายตัวรับโคลเชอร์เป็นอาร์กิวเมนต์ และโดยทั่วไปโคลเชอร์ที่เราส่งเข้าไปก็มักจะเป็นโคลเชอร์ที่จับค่าจากสภาพแวดล้อมของมัน

สำหรับตัวอย่างนี้ เราจะใช้เมธอด `filter` ซึ่งรับโคลเชอร์เข้ามา โดยโคลเชอร์จะได้รับสมาชิกหนึ่งตัวจากอิเทอเรเตอร์และส่งคืนค่าเป็นบูลีน (`bool`) หากโคลเชอร์ส่งคืนค่า `true` สมาชิกนั้นจะถูกเก็บไว้ในอิเทอเรเตอร์ตัวใหม่ที่ `filter` สร้างขึ้น แต่หากโคลเชอร์ส่งคืนค่า `false` สมาชิกนั้นจะถูกคัดทิ้งไป
