## โครงสร้างควบคุมโฟลว์ `match`

Rust มีโครงสร้างการควบคุมโฟลว์ (control flow) ที่ทรงพลังอย่างยิ่งชื่อ `match` ที่ช่วยให้คุณเปรียบเทียบค่ากับชุดของแพตเทิร์น (pattern) แล้วรันโค้ดตามแพตเทิร์นที่จับคู่ได้ แพตเทิร์นสามารถประกอบขึ้นจากค่าลิเทอรัล (literal value) ชื่อตัวแปร ไวลด์การ์ด (wildcard) และอื่นๆ อีกมากมาย [บทที่ 19][ch19-00-patterns]<!-- ignore --> ครอบคลุมแพตเทิร์นชนิดต่างๆ ทั้งหมดและสิ่งที่มันทำ พลังของ `match` มาจากความสามารถในการแสดงออกของแพตเทิร์นและข้อเท็จจริงที่ว่าคอมไพเลอร์ยืนยันว่ากรณีที่เป็นไปได้ทั้งหมดได้รับการจัดการแล้ว

ลองคิดว่าเอ็กซ์เพรสชัน `match` เปรียบเสมือนเครื่องคัดแยกเหรียญ: เหรียญจะไถลลงมาตามรางที่มีรูขนาดต่างๆ กันตลอดทาง และแต่ละเหรียญจะตกลงผ่านรูแรกที่มันเจอที่มันใส่พอดี ในทำนองเดียวกัน ค่าต่างๆ จะผ่านแพตเทิร์นแต่ละตัวใน `match` และเมื่อถึงแพตเทิร์นแรกที่ค่า “ใส่พอดี” ค่านั้นจะตกลงไปในบล็อกโค้ดที่เชื่อมโยงเพื่อใช้งานระหว่างการทำงาน

เมื่อพูดถึงเหรียญแล้ว มาใช้เหรียญเป็นตัวอย่างในการใช้ `match` กัน! เราสามารถเขียนฟังก์ชันที่รับเหรียญสหรัฐฯ ที่ไม่รู้จัก แล้วตัดสินว่ามันคือเหรียญอะไรและคืนค่าของมันเป็นหน่วยเซนต์ คล้ายกับเครื่องนับเหรียญ ดังที่แสดงในลิสติ้ง 6-3

มาแยกส่วนประกอบของ `match` ในฟังก์ชัน `value_in_cents` กัน ก่อนอื่น เราระบุคำสงวน `match` ตามด้วยเอ็กซ์เพรสชัน ซึ่งในกรณีนี้คือค่า `coin` สิ่งนี้ดูคล้ายกับเอ็กซ์เพรสชันแบบมีเงื่อนไขที่ใช้กับ `if` มาก แต่มีความแตกต่างที่สำคัญ: กับ `if` เงื่อนไขต้องประเมินค่าเป็นบูลีน (boolean) แต่ในที่นี้มันเป็นชนิดใดก็ได้ ชนิดของ `coin` ในตัวอย่างนี้คือ enum `Coin` ที่เรานิยามไว้ในบรรทัดแรก

ถัดมาคืออาร์ม (arm) ของ `match` อาร์มหนึ่งมีสองส่วน: แพตเทิร์นและโค้ด อาร์มแรกในที่นี้มีแพตเทิร์นซึ่งก็คือค่า `Coin::Penny` แล้วตามด้วยตัวดำเนินการ (operator) `=>` ที่คั่นระหว่างแพตเทิร์นกับโค้ดที่จะรัน โค้ดในกรณีนี้คือค่า `1` เฉยๆ แต่ละอาร์มถูกคั่นจากอาร์มถัดไปด้วยเครื่องหมายจุลภาค

เมื่อเอ็กซ์เพรสชัน `match` ทำงาน มันจะเปรียบเทียบค่าผลลัพธ์กับแพตเทิร์นของแต่ละอาร์มตามลำดับ หากแพตเทิร์นจับคู่กับค่าได้ โค้ดที่เชื่อมโยงกับแพตเทิร์นนั้นจะถูกรัน หากแพตเทิร์นนั้นไม่จับคู่กับค่า การทำงานจะดำเนินต่อไปยังอาร์มถัดไป คล้ายกับในเครื่องคัดแยกเหรียญ เราสามารถมีอาร์มได้มากเท่าที่เราต้องการ: ในลิสติ้ง 6-3 `match` ของเรามีสี่อาร์ม

โค้ดที่เชื่อมโยงกับแต่ละอาร์มเป็นเอ็กซ์เพรสชัน และค่าผลลัพธ์ของเอ็กซ์เพรสชันในอาร์มที่จับคู่ได้คือค่าที่ถูกคืนกลับสำหรับเอ็กซ์เพรสชัน `match` ทั้งหมด

เรามักไม่ใช้วงเล็บปีกกาหากโค้ดของอาร์ม match สั้น อย่างในลิสติ้ง 6-3 ที่แต่ละอาร์มแค่คืนค่าออกมา หากคุณต้องการรันโค้ดหลายบรรทัดในอาร์ม match คุณต้องใช้วงเล็บปีกกา และเครื่องหมายจุลภาคที่ตามหลังอาร์มก็เป็นตัวเลือกเสริม ตัวอย่างเช่น โค้ดต่อไปนี้จะพิมพ์ “Lucky penny!” ทุกครั้งที่เมธอดถูกเรียกด้วย `Coin::Penny` แต่ก็ยังคืนค่าสุดท้ายของบล็อกคือ `1`:

### แพตเทิร์นที่ผูกกับค่า

คุณสมบัติที่มีประโยชน์อีกอย่างของอาร์ม match คือมันสามารถผูกกับส่วนต่างๆ ของค่าที่จับคู่กับแพตเทิร์นได้ นี่คือวิธีที่เราสามารถดึงค่าออกจากวาเรียนต์ของ enum ได้

เป็นตัวอย่าง ลองเปลี่ยนวาเรียนต์หนึ่งของ enum เราให้เก็บข้อมูลไว้ข้างใน ตั้งแต่ปี 1999 ถึง 2008 สหรัฐอเมริกาได้ผลิตเหรียญควอเตอร์ที่มีลวดลายต่างกันสำหรับแต่ละรัฐใน 50 รัฐที่ด้านหนึ่ง ไม่มีเหรียญอื่นที่มีลวดลายของรัฐ ดังนั้นมีเพียงควอเตอร์เท่านั้นที่มีค่าเพิ่มเติมนี้ เราสามารถเพิ่มข้อมูลนี้ลงใน `enum` ของเราได้โดยเปลี่ยนวาเรียนต์ `Quarter` ให้มีค่า `UsState` จัดเก็บอยู่ข้างใน ซึ่งเราได้ทำแล้วในลิสติ้ง 6-4

### แพตเทิร์น `match` ของ `Option<T>`

ในหัวข้อก่อนหน้านี้ เราต้องการดึงค่า `T` ที่อยู่ภายในออกมาจากกรณี `Some` เมื่อใช้ `Option<T>` เราก็สามารถจัดการ `Option<T>` ได้โดยใช้ `match` เช่นเดียวกับที่เราทำกับ enum `Coin`! แทนที่จะเปรียบเทียบเหรียญ เราจะเปรียบเทียบวาเรียนต์ของ `Option<T>` แต่การทำงานของเอ็กซ์เพรสชัน `match` ยังคงเหมือนเดิม

สมมติว่าเราต้องการเขียนฟังก์ชันที่รับ `Option<i32>` และหากมีค่าอยู่ข้างใน ให้บวก 1 เข้ากับค่านั้น หากไม่มีค่าอยู่ข้างใน ฟังก์ชันควรคืนค่า `None` และไม่พยายามดำเนินการใดๆ

ฟังก์ชันนี้เขียนได้ง่ายมากด้วย `match` และจะมีหน้าตาดังในลิสติ้ง 6-5

การรวม `match` เข้ากับ enum มีประโยชน์ในหลายสถานการณ์ คุณจะเห็นแพตเทิร์นนี้บ่อยมากในโค้ด Rust: ใช้ `match` กับ enum ผูกตัวแปรกับข้อมูลข้างใน แล้วรันโค้ดตามข้อมูลนั้น ตอนแรกมันอาจยุ่งยากสักหน่อย แต่เมื่อคุณคุ้นเคยกับมันแล้ว คุณจะอยากให้ทุกภาษามีสิ่งนี้ มันเป็นสิ่งที่ผู้ใช้ชื่นชอบมาโดยตลอด

สำหรับสองอาร์มแรก แพตเทิร์นคือค่าลิเทอรัล `3` และ `7` สำหรับอาร์มสุดท้ายที่ครอบคลุมค่าที่เป็นไปได้อื่นๆ ทั้งหมด แพตเทิร์นคือตัวแปรที่เราเลือกตั้งชื่อว่า `other` โค้ดที่รันสำหรับอาร์ม `other` ใช้ตัวแปรนั้นโดยส่งมันไปยังฟังก์ชัน `move_player`

โค้ดนี้คอมไพล์ผ่าน แม้ว่าเราจะไม่ได้ระบุค่าที่เป็นไปได้ทั้งหมดที่ `u8` สามารถมีได้ เพราะแพตเทิร์นสุดท้ายจะจับคู่กับค่าทั้งหมดที่ไม่ได้ระบุไว้โดยเฉพาะ แพตเทิร์นแบบครอบคลุมทั้งหมดนี้ตอบสนองข้อกำหนดที่ว่า `match` ต้องครบถ้วนทุกกรณี โปรดสังเกตว่าเราต้องวางอาร์มแบบครอบคลุมทั้งหมดไว้ท้ายสุด เพราะแพตเทิร์นถูกประเมินตามลำดับ หากเราวางอาร์มแบบครอบคลุมทั้งหมดไว้ก่อนหน้านี้ อาร์มอื่นๆ จะไม่ถูกรันเลย ดังนั้น Rust จะออกคำเตือน (warning) ให้เราหากเราเพิ่มอาร์มต่อจากอาร์มแบบครอบคลุมทั้งหมด!

Rust ยังมีแพตเทิร์นที่เราใช้ได้เมื่อเราต้องการครอบคลุมทั้งหมดแต่ไม่ต้องการ_ใช้_ค่าในแพตเทิร์นนั้น: `_` เป็นแพตเทิร์นพิเศษที่จับคู่กับค่าใดก็ได้และไม่ผูกกับค่านั้น สิ่งนี้บอก Rust ว่าเราจะไม่ใช้ค่านั้น ดังนั้น Rust จะไม่เตือนเราเกี่ยวกับตัวแปรที่ไม่ได้ใช้งาน

มาเปลี่ยนกฎของเกมกัน: ตอนนี้ หากคุณทอยได้อะไรนอกจาก 3 หรือ 7 คุณต้องทอยใหม่ เราไม่จำเป็นต้องใช้ค่าที่ครอบคลุมทั้งหมดอีกต่อไป เราจึงเปลี่ยนโค้ดของเราให้ใช้ `_` แทนตัวแปรชื่อ `other` ได้:

```rust
{{#rustdoc_include ../listings/ch06-enums-and-pattern-matching/no-listing-16-underscore-catchall/src/main.rs:here}}
```

ตัวอย่างนี้ยังตอบสนองข้อกำหนดเรื่องความครบถ้วนทุกกรณีด้วย เพราะเรากำลังเพิกเฉยต่อค่าอื่นๆ ทั้งหมดในอาร์มสุดท้ายอย่างชัดแจ้ง เราไม่ได้ลืมอะไรเลย

สุดท้าย เราจะเปลี่ยนกฎของเกมอีกครั้งเพื่อไม่ให้มีอะไรเกิดขึ้นในตาของคุณหากคุณทอยได้อะไรนอกจาก 3 หรือ 7 เราสามารถแสดงสิ่งนั้นได้โดยใช้ค่ายูนิต (unit value) (ชนิดทูเพิลว่างเปล่าที่เราได้กล่าวถึงในหัวข้อ[“ชนิดทูเพิล”][tuples]<!-- ignore -->) เป็นโค้ดที่ใช้กับอาร์ม `_`:

```rust

```

ในที่นี้ เรากำลังบอก Rust อย่างชัดแจ้งว่าเราจะไม่ใช้ค่าอื่นใดที่จับคู่กับแพตเทิร์นในอาร์มก่อนหน้านี้ไม่ได้ และเราไม่ต้องการรันโค้ดใดๆ ในกรณีนี้

ยังมีเรื่องแพตเทิร์นและการจับคู่แพตเทิร์น (pattern matching) เพิ่มเติมที่เราจะครอบคลุมใน[บทที่ 19][ch19-00-patterns]<!-- ignore --> สำหรับตอนนี้ เราจะไปต่อยังวากยสัมพันธ์ `if let` ซึ่งมีประโยชน์ในสถานการณ์ที่เอ็กซ์เพรสชัน `match` ยืดยาวสักหน่อย
