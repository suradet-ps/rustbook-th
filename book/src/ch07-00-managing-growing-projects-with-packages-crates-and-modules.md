# แพ็กเกจ เครต และมอดูล

เมื่อคุณเขียนโปรแกรมขนาดใหญ่ การจัดระเบียบโค้ดของคุณจะยิ่งสำคัญขึ้นเรื่อยๆ การจัดกลุ่มฟังก์ชันการทำงานที่เกี่ยวข้องเข้าด้วยกันและการแยกโค้ดที่มีฟีเจอร์แตกต่างกันออกจากกันจะช่วยให้คุณเห็นชัดเจนว่าควรไปหาโค้ดที่อิมพลีเมนต์ฟีเจอร์หนึ่งๆ ที่ใด และควรไปแก้ไขการทำงานของฟีเจอร์ที่ใด

โปรแกรมที่เราเขียนมาจนถึงตอนนี้อยู่ในมอดูล (module) เดียวในไฟล์เดียว เมื่อโปรเจกต์เติบโตขึ้น คุณควรจัดระเบียบโค้ดโดยแยกมันออกเป็นหลายมอดูลแล้วจึงแยกออกเป็นหลายไฟล์ แพ็กเกจ (package) หนึ่งๆ สามารถบรรจุเครตไบนารี (binary crate) ได้หลายตัว และอาจมีเครตไลบรารี (library crate) หนึ่งตัวได้ เมื่อแพ็กเกจเติบโตขึ้น คุณสามารถแยกบางส่วนออกไปเป็นเครตแยกต่างหากซึ่งกลายเป็นดีเพนเดนซี (dependency) ภายนอก บทนี้ครอบคลุมเทคนิคเหล่านี้ทั้งหมด สำหรับโปรเจกต์ขนาดใหญ่มากที่ประกอบด้วยชุดของแพ็กเกจที่มีความสัมพันธ์กันและพัฒนาร่วมกัน Cargo มีเวิร์กสเปซ (workspace) ให้ใช้ ซึ่งเราจะพูดถึงใน[“เวิร์กสเปซของ Cargo”][workspaces]<!-- ignore --> ในบทที่ 14

เราจะพูดคุยถึงการห่อหุ้มรายละเอียดการอิมพลีเมนต์ด้วย ซึ่งช่วยให้คุณนำโค้ดกลับมาใช้ซ้ำในระดับที่สูงขึ้น: เมื่อคุณอิมพลีเมนต์การดำเนินการหนึ่งๆ แล้ว โค้ดอื่นสามารถเรียกโค้ดของคุณผ่านส่วนติดต่อสาธารณะ (public) ของมันโดยไม่จำเป็นต้องรู้ว่าการอิมพลีเมนต์นั้นทำงานอย่างไร วิธีที่คุณเขียนโค้ดเป็นตัวกำหนดว่าส่วนใดเป็นแบบสาธารณะให้โค้ดอื่นนำไปใช้ และส่วนใดเป็นรายละเอียดการอิมพลีเมนต์แบบส่วนตัว (private) ที่คุณสงวนสิทธิ์ในการเปลี่ยนแปลง นี่เป็นอีกวิธีหนึ่งในการจำกัดปริมาณรายละเอียดที่คุณต้องเก็บไว้ในหัว

แนวคิดที่เกี่ยวข้องอีกอย่างหนึ่งคือสโคป (scope): บริบทที่ซ้อนกันอยู่ซึ่งโค้ดถูกเขียนขึ้นมามีชุดของชื่อที่ถูกนิยามว่า “อยู่ในสโคป” เมื่ออ่าน เขียน และคอมไพล์โค้ด โปรแกรมเมอร์และคอมไพเลอร์จำเป็นต้องรู้ว่าชื่อหนึ่งๆ ณ จุดหนึ่งๆ อ้างถึงตัวแปร ฟังก์ชัน struct enum มอดูล ค่าคงที่ หรือรายการอื่นใด และรู้ว่ารายการนั้นหมายถึงอะไร คุณสามารถสร้างสโคปและเปลี่ยนว่าชื่อใดอยู่หรือไม่อยู่ในสโคป คุณไม่สามารถมีสองรายการที่ใช้ชื่อเดียวกันในสโคปเดียวกันได้ และมีเครื่องมือให้ใช้ในการแก้ไขข้อขัดแย้งของชื่อ

Rust มีฟีเจอร์หลายอย่างที่ช่วยให้คุณจัดการการจัดระเบียบโค้ดของคุณ รวมถึงรายละเอียดใดที่ถูกเปิดเผย รายละเอียดใดที่เป็นแบบส่วนตัว และชื่อใดอยู่ในสโคปใดในโปรแกรมของคุณ ฟีเจอร์เหล่านี้ ซึ่งบางครั้งเรียกโดยรวมว่า _ระบบมอดูล_ (module system) ได้แก่:

* **แพ็กเกจ**: ฟีเจอร์ของ Cargo ที่ช่วยให้คุณบิลด์ ทดสอบ และแชร์เครต
* **เครต**: ต้นไม้ของมอดูลที่สร้างไลบรารีหรือไฟล์รันได้
* **มอดูลและ use**: ให้คุณควบคุมการจัดระเบียบ สโคป และความเป็นส่วนตัว (privacy) ของพาธ (path)
* **พาธ**: วิธีตั้งชื่อรายการ เช่น struct ฟังก์ชัน หรือมอดูล

ในบทนี้ เราจะครอบคลุมฟีเจอร์เหล่านี้ทั้งหมด พูดคุยว่ามันทำงานร่วมกันอย่างไร และอธิบายวิธีใช้มันเพื่อจัดการสโคป เมื่อจบบทนี้ คุณควรมีความเข้าใจระบบมอดูลอย่างมั่นคงและสามารถทำงานกับสโคปได้อย่างมืออาชีพ!
