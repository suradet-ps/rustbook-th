# แพ็กเกจ เครต และมอดูล

เมื่อโปรแกรมที่คุณเขียนเริ่มมีขนาดใหญ่ขึ้น การจัดระเบียบโครงสร้างโค้ดจะยิ่งทวีความสำคัญมากยิ่งขึ้น การจัดกลุ่มการทำงานที่เกี่ยวข้องกันไว้ด้วยกัน และการแยกส่วนโค้ดที่มีหน้าที่การทำงานต่างกันออกจากกัน จะช่วยให้คุณค้นหาได้ง่ายขึ้นว่าโค้ดที่ทำหน้าที่ในฟีเจอร์ใดฟีเจอร์หนึ่งอยู่ที่ไหน และควรเข้าไปแก้ไขจุดใดเมื่อต้องการปรับเปลี่ยนพฤติกรรมการทำงานของฟีเจอร์นั้นๆ

โปรแกรมทั้งหมดที่เราเขียนมาจนถึงจุดนี้ ล้วนเขียนอยู่ภายในมอดูลเดียวและรวมอยู่ในไฟล์เดียว แต่เมื่อโปรเจกต์เติบโตขึ้น เราควรจัดระเบียบโค้ดโดยแยกออกเป็นหลายๆ มอดูล และกระจายออกเป็นหลายๆ ไฟล์ตามลำดับ โดยแพ็กเกจ (package) หนึ่งแพ็กเกจสามารถบรรจุเครตไบนารี (binary crates) ได้หลายตัว และสามารถมีเครตไลบรารี (library crate) ได้อย่างมากที่สุดหนึ่งตัว และเมื่อแพ็กเกจเริ่มมีขนาดใหญ่ขึ้นอีก คุณก็สามารถแยกส่วนการทำงานบางส่วนออกมาเป็นเครตต่างหาก เพื่อใช้เป็นดีเพนเดนซีภายนอก (external dependencies) ได้ ซึ่งในบทนี้จะครอบคลุมเทคนิคเหล่านี้ทั้งหมด สำหรับโปรเจกต์ขนาดใหญ่มากที่ประกอบขึ้นจากชุดของแพ็กเกจหลายตัวที่เกี่ยวข้องกันและพัฒนาควบคู่ไปด้วยกัน ทาง Cargo ก็มีฟีเจอร์เวิร์กสเปซ (workspaces) มารองรับ ซึ่งเราจะได้เรียนรู้กันในหัวข้อ [“เวิร์กสเปซของ Cargo”][workspaces]<!-- ignore --> ในบทที่ 14

นอกจากนี้ เรายังจะได้พูดถึงเรื่องการห่อหุ้มรายละเอียดการทำงานภายใน (encapsulation) ซึ่งช่วยให้เราสามารถนำโค้ดกลับมาใช้ซ้ำในระดับที่สูงขึ้นได้: เมื่อเราเขียนการทำงานฟังก์ชันหนึ่งเสร็จเรียบร้อยแล้ว โค้ดส่วนอื่นๆ ก็สามารถเรียกใช้ฟังก์ชันดังกล่าวผ่านทางอินเทอร์เฟซสาธารณะ (public interface) ได้ทันที โดยไม่จำเป็นต้องรู้ลึกไปถึงรายละเอียดการทำงานเบื้องหลัง วิธีการเขียนโค้ดของคุณจะเป็นตัวกำหนดเองว่า ส่วนใดควรเปิดเผยเป็นสาธารณะ (public) เพื่อให้โค้ดภายนอกเรียกใช้งานได้ และส่วนใดควรเก็บไว้เป็นรายละเอียดภายในแบบส่วนตัว (private) เพื่อให้คุณมีอิสระในการปรับปรุงแก้ไขการทำงานได้ในอนาคต ซึ่งนี่เป็นอีกหนึ่งวิธีที่ช่วยลดภาระทางความคิดที่คุณต้องคอยจดจำลงไปได้อย่างมาก

อีกแนวคิดหนึ่งที่เกี่ยวข้องอย่างใกล้ชิดคือเรื่องของ ขอบเขตตัวแปรและชื่อ หรือ **สโคป (scope)**: โดยบริบทที่ซ้อนกันอยู่ของโค้ดจะมีชุดของชื่อต่างๆ ที่ถือว่า “อยู่ในสโคป” (in scope) ในเวลาที่อ่าน เขียน และคอมไพล์โค้ด ทั้งโปรแกรมเมอร์และคอมไพเลอร์จำเป็นต้องรู้ได้อย่างชัดเจนว่า ชื่อหนึ่งๆ ณ จุดใดจุดหนึ่งกำลังอ้างอิงถึงตัวแปร, ฟังก์ชัน, struct, enum, มอดูล, ค่าคงที่ หรือไอเทมใด และไอเทมนั้นมีความหมายอย่างไร คุณสามารถสร้างสโคปใหม่ๆ ขึ้นมา และกำหนดได้ว่าชื่อใดจะอยู่ภายในหรืออยู่นอกสโคป โดยคุณจะไม่สามารถตั้งชื่อไอเทม 2 ตัวให้ซ้ำกันภายในสโคปเดียวกันได้ ซึ่ง Rust ก็มีเครื่องมือที่ช่วยแก้ไขปัญหาเมื่อเกิดความขัดแย้งของชื่อไว้ให้พร้อมสรรพ

Rust มีฟีเจอร์มากมายที่ช่วยให้คุณจัดการโครงสร้างองค์ประกอบของโค้ดได้อย่างเป็นระบบ ครอบคลุมทั้งเรื่องการกำหนดว่ารายละเอียดใดควรเปิดเผย รายละเอียดใดควรเป็นแบบส่วนตัว และมีชื่อใดบ้างที่สามารถเข้าถึงได้ในแต่ละสโคปของโปรแกรม โดยกลุ่มฟีเจอร์เหล่านี้ มักถูกเรียกโดยรวมว่า **ระบบมอดูล (module system)** ซึ่งประกอบด้วย:

* **แพ็กเกจ (Packages)**: ฟีเจอร์ของ Cargo ที่ช่วยให้คุณสามารถบิลด์, ทดสอบ และเผยแพร่แบ่งปันเครตต่างๆ ได้
* **เครต (Crates)**: โครงสร้างแบบต้นไม้ของมอดูลที่คอมไพล์ออกมาเป็นไลบรารีหรือไฟล์รันไบนารี (executable)
* **มอดูล (Modules) และ use**: เครื่องมือที่ช่วยให้คุณควบคุมการจัดโครงสร้าง, สโคป และความเป็นส่วนตัว (privacy) ของพาธต่างๆ
* **พาธ (Paths)**: วิธีการระบุชื่อเพื่ออ้างอิงไปยังไอเทมต่างๆ เช่น struct, ฟังก์ชัน หรือมอดูล

ในบทนี้ เราจะมาเรียนรู้ฟีเจอร์เหล่านี้ทั้งหมด พร้อมทั้งสำรวจว่าแต่ละส่วนทำงานประสานร่วมกันอย่างไร และอธิบายวิธีนำฟีเจอร์เหล่านี้ไปใช้ในการจัดการสโคป เมื่ออ่านจบบทนี้ คุณจะมีความเข้าใจระบบมอดูลอย่างลึกซึ้งและสามารถจัดการกับสโคปในโค้ดได้อย่างมั่นใจดั่งมืออาชีพ!
