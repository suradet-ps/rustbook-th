# เขียนโปรแกรมเกมทายตัวเลข

มาเริ่มต้นเรียนรู้ Rust ผ่านการลงมือพัฒนาโปรเจกต์จริงไปด้วยกัน! บทนี้จะแนะนำให้คุณรู้จักแนวคิดพื้นฐานที่สำคัญหลากหลายประการของ Rust โดยแสดงให้เห็นวิธีนำไปใช้งานจริงในโปรแกรม คุณจะได้เรียนรู้เกี่ยวกับคำสำคัญ `let`, `match`, เมธอด (method), ฟังก์ชันประจำชนิดข้อมูล (associated function), การเรียกใช้เครตภายนอก (external crates) และอื่นๆ อีกมากมาย! ซึ่งในบทต่อๆ ไป เราจะได้เจาะลึกแต่ละแนวคิดอย่างละเอียด ส่วนในบทนี้ เราจะเน้นการฝึกฝนและทำความคุ้นเคยกับพื้นฐานเป็นหลัก

เราจะร่วมกันสร้างโจทย์คลาสสิกสำหรับผู้เริ่มต้นเขียนโปรแกรม นั่นคือ "เกมทายตัวเลข" โดยมีกติกาการทำงานดังนี้: โปรแกรมจะสุ่มจำนวนเต็ม (integer) ระหว่าง 1 ถึง 100 ขึ้นมาหนึ่งตัว จากนั้นจะแจ้งให้ผู้เล่นป้อนตัวเลขที่ต้องการทาย เมื่อผู้เล่นป้อนตัวเลขแล้ว โปรแกรมจะบอกว่าตัวเลขที่ทายนั้นน้อยเกินไปหรือมากเกินไป หากทายถูกต้อง โปรแกรมจะแสดงข้อความแสดงความยินดีและสิ้นสุดการทำงาน

## การตั้งค่าโปรเจกต์ใหม่

ในการเริ่มต้นโปรเจกต์ใหม่ ให้เปิดเทอร์มินัลไปยังไดเรกทอรี _projects_ ที่คุณสร้างไว้ในบทที่ 1 แล้วสร้างโปรเจกต์ใหม่ด้วย Cargo ดังนี้:

### การเก็บค่าด้วยตัวแปร

ถัดไป เราจะสร้าง_ตัวแปร_ขึ้นมาเพื่อใช้เก็บค่าอินพุตของผู้เล่น ดังนี้:

```rust,ignore
{{#rustdoc_include ../listings/ch02-guessing-game-tutorial/listing-02-01/src/main.rs:string}}
```

ตอนนี้โปรแกรมเริ่มน่าสนใจขึ้นแล้ว! มีหลายสิ่งเกิดขึ้นในบรรทัดสั้นๆ นี้ เราใช้คำสั่ง `let` ในการประกาศสร้างตัวแปร ลองดูตัวอย่างนี้:

```rust,ignore
let apples = 5;
```

บรรทัดนี้จะสร้างตัวแปรใหม่ชื่อว่า `apples` และผูกค่า `5` เข้ากับตัวแปร ใน Rust ตัวแปรทุกตัวจะเป็นแบบเปลี่ยนแปลงค่าไม่ได้ (immutable) โดยค่าเริ่มต้น หมายความว่าเมื่อกำหนดค่าเริ่มต้นให้แล้ว จะไม่สามารถเปลี่ยนค่านั้นได้อีก เราจะเจาะลึกแนวคิดนี้ในหัวข้อ [“ตัวแปรและความสามารถในการเปลี่ยนแปลงค่า”][variables-and-mutability]<!-- ignore --> ในบทที่ 3 หากต้องการให้ตัวแปรสามารถเปลี่ยนค่าได้ (mutable) เราจะใส่คำว่า `mut` ไว้ข้างหน้าชื่อตัวแปร:

```rust,ignore
let apples = 5; // immutable
let mut bananas = 5; // mutable
```

> หมายเหตุ: ไวยากรณ์ `//` เป็นจุดเริ่มต้นของการเขียนคอมเมนต์ (comment) ซึ่งจะดำเนินไปจนจบบรรทัด โดยคอมไพเลอร์ Rust จะมองข้ามข้อความในคอมเมนต์ทั้งหมด เราจะพูดถึงคอมเมนต์อย่างละเอียดใน[บทที่ 3][comments]<!-- ignore -->

กลับมาดูที่โปรแกรมเกมทายตัวเลข ตอนนี้คุณทราบแล้วว่า `let mut guess` คือการประกาศตัวแปรที่เปลี่ยนแปลงค่าได้ชื่อว่า `guess` เครื่องหมายเท่ากับ (`=`) บอก Rust ว่าเราต้องการผูกค่าบางอย่างเข้ากับตัวแปร ณ จุดนี้ โดยทางด้านขวาของเครื่องหมายเท่ากับคือค่าที่จะนำมาผูกกับ `guess` ซึ่งได้มาจากผลลัพธ์ของการเรียก `String::new` อันเป็นฟังก์ชันที่สร้างอินสแตนซ์ใหม่ของชนิดข้อมูล `String` โดย [`String`][string]<!-- ignore --> เป็นชนิดข้อมูลสตริงที่ไลบรารีมาตรฐานจัดเตรียมไว้ ซึ่งสามารถปรับขยายขนาดได้และเข้ารหัสด้วย UTF-8

สัญลักษณ์ `::` ใน `String::new` บ่งบอกว่า `new` เป็นฟังก์ชันประจำชนิดข้อมูล (associated function) ของชนิด `String` โดย_ฟังก์ชันประจำชนิดข้อมูล_คือฟังก์ชันที่อิมพลีเมนต์อยู่บนชนิดข้อมูลนั้นๆ ซึ่งในที่นี้คือ `String` ฟังก์ชัน `new` จะสร้างสตริงใหม่ที่ว่างเปล่าขึ้นมา คุณจะพบเห็นฟังก์ชันชื่อ `new` ได้บ่อยครั้งในชนิดข้อมูลต่างๆ ของ Rust เนื่องจากเป็นชื่อมาตรฐานที่นิยมใช้สำหรับฟังก์ชันที่สร้างค่าใหม่ของชนิดข้อมูลนั้นๆ

สรุปแล้ว บรรทัด `let mut guess = String::new();` คือการประกาศตัวแปรที่แก้ไขค่าได้ ซึ่งปัจจุบันถือครองอินสแตนซ์ของสตริงว่างตัวใหม่อยู่ เห็นไหมว่าบรรทัดเดียวมีรายละเอียดซ่อนอยู่ไม่น้อยเลย!

### การรับอินพุตจากผู้ใช้

จำได้ไหมว่าเราได้นำเข้าฟังก์ชันอินพุต/เอาต์พุตจากไลบรารีมาตรฐานด้วย `use std::io;` ไว้ที่บรรทัดแรกของโปรแกรม คราวนี้เราจะเรียกฟังก์ชัน `stdin` จากมอดูล `io` เพื่อช่วยจัดการการรับอินพุตจากผู้ใช้:

```rust,ignore
{{#rustdoc_include ../listings/ch02-guessing-game-tutorial/listing-02-01/src/main.rs:read}}
```

หากเราไม่ได้นำเข้ามอดูล `io` ด้วย `use std::io;` ไว้ที่ตอนต้น เราก็ยังสามารถเรียกใช้ฟังก์ชันนี้ได้โดยเขียนพาธเต็มว่า `std::io::stdin` โดยฟังก์ชัน `stdin` จะส่งกลับอินสแตนซ์ของ [`std::io::Stdin`][iostdin]<!-- ignore --> ซึ่งเป็นชนิดข้อมูลที่เป็นตัวแทนของช่องทางอินพุตมาตรฐาน (standard input handle) ในเทอร์มินัลของคุณ

ถัดมา ส่วน `.read_line(&mut guess)` จะเรียกเมธอด [`read_line`][read_line]<!-- ignore --> บนแฮนเดิลอินพุตมาตรฐานเพื่อรอรับข้อมูลจากผู้ใช้ และเราได้ส่ง `&mut guess` เข้าไปเป็นอาร์กิวเมนต์ให้กับ `read_line` เพื่อระบุว่าจะให้นำข้อความที่ผู้ใช้พิมพ์ไปจัดเก็บไว้ในสตริงใด หน้าที่ของ `read_line` คือรับสิ่งที่ผู้ใช้พิมพ์จากช่องทางอินพุตมาตรฐาน แล้วนำไปต่อท้าย (append) สตริงที่ส่งเข้าไป (โดยไม่เขียนทับข้อมูลเดิม) เราจึงต้องส่งสตริงนั้นเข้าไปเป็นอาร์กิวเมนต์ และอาร์กิวเมนต์สตริงนี้จำเป็นต้องเป็นแบบที่เปลี่ยนแปลงค่าได้ (`mut`) เพื่อให้เมธอดสามารถแก้ไขเพิ่มเนื้อหาลงไปในสตริงได้

สัญลักษณ์ `&` ด้านหน้าบ่งบอกว่าอาร์กิวเมนต์นี้เป็น_เรเฟอเรนซ์_ (reference) ซึ่งเป็นกลไกที่เปิดให้โค้ดหลายๆ จุดสามารถเข้าถึงข้อมูลชิ้นเดียวกันได้ โดยไม่ต้องคัดลอกข้อมูลนั้นซ้ำซ้อนในหน่วยความจำ เรเฟอเรนซ์เป็นฟีเจอร์ที่สำคัญและซับซ้อน แต่จุดเด่นอย่างยิ่งของ Rust คือการออกแบบให้การใช้งานเรเฟอเรนซ์มีความปลอดภัยและสะดวกสบาย คุณไม่จำเป็นต้องกังวลกับรายละเอียดเชิงลึกในตอนนี้เพื่อทำโปรแกรมนี้ให้เสร็จ สิ่งที่คุณต้องทราบเบื้องต้นคือ เรเฟอเรนซ์ก็เหมือนกับตัวแปร กล่าวคือเป็นแบบเปลี่ยนแปลงค่าไม่ได้โดยค่าเริ่มต้น ดังนั้นเราจึงต้องเขียน `&mut guess` แทนที่จะเป็น `&guess` เพื่อเปิดให้สามารถแก้ไขค่าในตัวแปรเป้าหมายได้ (บทที่ 4 จะอธิบายเรื่องเรเฟอเรนซ์อย่างละเอียด)

```rust,ignore
{{#rustdoc_include ../listings/ch02-guessing-game-tutorial/listing-02-01/src/main.rs:expect}}

io::stdin().read_line(&mut guess).expect("Failed to read line");
```

ทว่าการเขียนคำสั่งยาวๆ ติดกันในบรรทัดเดียวทำให้โค้ดอ่านยาก การแยกบรรทัดและจัดย่อหน้าเว้นวรรคเมื่อเรียกใช้เมธอดต่อเนื่องด้วยไวยากรณ์ `.method_name()` จึงเป็นแนวทางที่ช่วยให้อ่านโค้ดได้ง่ายและสบายตากว่ามาก ตอนนี้มาดูกันว่าบรรทัดนี้ทำหน้าที่อะไร

ดังที่ได้อธิบายไปแล้วว่า `read_line` จะนำข้อความที่ผู้ใช้พิมพ์ไปใส่ไว้ในสตริงที่เราส่งเข้าไป แต่ยิ่งไปกว่านั้น เมธอดนี้ยังส่งคืนค่าชนิด `Result` กลับมาด้วย โดย [`Result`][result]<!-- ignore --> เป็นชนิดข้อมูลแบบ[_อีนูเมอเรชัน_ (enumeration)][enums]<!-- ignore --> หรือที่เรียกสั้นๆ ว่า _enum_ ซึ่งเป็นชนิดข้อมูลที่สามารถมีสถานะได้หลากหลายรูปแบบตามที่กำหนดไว้ และเราเรียกแต่ละสถานะที่เป็นไปได้ว่า _วาเรียนต์_ (variant)

[บทที่ 6][enums]<!-- ignore --> จะอธิบายเรื่อง enum อย่างละเอียด สำหรับตอนนี้ จุดประสงค์หลักของชนิด `Result` คือการใช้สื่อสารและจัดการกับข้อมูลเกี่ยวกับข้อผิดพลาด (error handling)

วาเรียนต์ของ `Result` ประกอบด้วย `Ok` และ `Err` โดยวาเรียนต์ `Ok` บ่งบอกว่าการทำงานสำเร็จเรียบร้อย และภายในจะบรรจุค่าผลลัพธ์ที่ได้จากการทำงานนั้น ส่วนวาเรียนต์ `Err` บ่งบอกว่าเกิดความล้มเหลว และภายในจะบรรจุข้อมูลที่อธิบายว่าเกิดข้อผิดพลาดขึ้นอย่างไรหรือเพราะเหตุใด

ค่าชนิด `Result` ก็เหมือนกับชนิดข้อมูลอื่นๆ ใน Rust ตรงที่มีเมธอดต่างๆ ที่นิยามไว้ให้ใช้งาน โดยอินสแตนซ์ของ `Result` จะมี[เมธอด `expect`][expect]<!-- ignore --> ให้คุณเรียกใช้ หากอินสแตนซ์ของ `Result` นั้นเป็นค่า `Err` เมธอด `expect` จะทำให้โปรแกรมหยุดทำงานกะทันหัน (crash/panic) พร้อมทั้งแสดงข้อความที่คุณระบุไว้ในอาร์กิวเมนต์ของ `expect` ออกมา หากเมธอด `read_line` ส่งค่า `Err` กลับมา มักเกิดจากข้อผิดพลาดในระดับระบบปฏิบัติการ แต่หากอินสแตนซ์ของ `Result` เป็นค่า `Ok` เมธอด `expect` จะดึงค่าผลลัพธ์ที่อยู่ภายใน `Ok` ออกมาให้คุณนำไปใช้งานต่อทันที ซึ่งในกรณีนี้ ค่าดังกล่าวคือจำนวนไบต์ของข้อความที่ผู้ใช้ป้อนเข้ามา

หากคุณไม่เรียกใช้ `expect` โปรแกรมจะยังคงคอมไพล์ผ่านได้ แต่คุณจะได้รับข้อความคำเตือน (warning) จากคอมไพเลอร์:

```console
{{#include ../listings/ch02-guessing-game-tutorial/no-listing-02-without-expect/output.txt}}
```

Rust ส่งสัญญาณเตือนว่าคุณยังไม่ได้นำค่า `Result` ที่ได้จาก `read_line` ไปใช้งาน ซึ่งหมายความว่าโปรแกรมของคุณยังไม่ได้จัดการกับกรณีที่อาจเกิดข้อผิดพลาดขึ้น

วิธีแก้ไขคำเตือนที่ถูกต้องคือการเขียนโค้ดเพื่อจัดการข้อผิดพลาดอย่างเหมาะสม แต่สำหรับโปรแกรมตัวอย่างนี้ เราตั้งใจให้โปรแกรมหยุดทำงานทันทีหากเกิดปัญหาขึ้น การใช้ `expect` จึงตอบโจทย์ได้เป็นอย่างดี คุณจะได้เรียนรู้วิธีการกู้คืนและจัดการข้อผิดพลาดอย่างเต็มรูปแบบใน[บทที่ 9][recover]<!-- ignore -->

บรรทัดนี้ทำหน้าที่พิมพ์ข้อความสตริงที่เก็บคำทายของผู้เล่นออกมา โดยเครื่องหมายปีกกา `{}` ทำหน้าที่เป็นตัวยึดตำแหน่ง (placeholder) ให้จินตนาการว่า `{}` เหมือนก้ามปูน้อยๆ ของเจ้าปู Ferris ที่ช่วยจับค่ามาวางไว้ตรงจุดนี้ เมื่อต้องการพิมพ์ค่าของตัวแปร คุณสามารถใส่ชื่อตัวแปรไว้ในปีกกาได้โดยตรง และเมื่อต้องการพิมพ์ผลลัพธ์จากการประเมินค่านิพจน์ (expression) ให้ใส่วงเล็บปีกกาเปล่า `{}` ไว้ในสตริงรูปแบบ (format string) แล้วตามด้วยรายการนิพจน์ที่คั่นด้วยเครื่องหมายจุลภาคต่อท้ายสตริง เพื่อนำค่ามาแสดงตามลำดับของตัวยึดตำแหน่ง การพิมพ์ทั้งตัวแปรและผลลัพธ์ของนิพจน์ในคำสั่ง `println!` บรรทัดเดียวจะมีรูปแบบดังนี้:

```rust
let x = 5;
let y = 10;

println!("x = {x} and y + 2 = {}", y + 2);
```

โค้ดนี้จะพิมพ์ผลลัพธ์ว่า `x = 5 and y + 2 = 12`

### เพิ่มฟังก์ชันการทำงานด้วยเครต

จำได้ไหมว่าเครต (crate) คือชุดของไฟล์ซอร์สโค้ดในภาษา Rust โปรเจกต์ที่เรากำลังพัฒนานี้เรียกว่าเครตไบนารี (binary crate) ซึ่งสามารถคอมไพล์ออกมาเป็นไฟล์โปรแกรมที่รันได้ (executable) ส่วนเครต `rand` จัดเป็นเครตไลบรารี (library crate) ซึ่งประกอบด้วยโค้ดที่สร้างขึ้นเพื่อให้โปรแกรมอื่นนำไปใช้ต่อ และไม่สามารถสั่งรันได้ด้วยตัวมันเอง

การที่ Cargo ช่วยบริหารจัดการเครตภายนอกได้อย่างราบรื่นคือจุดเด่นที่ทำให้เครื่องมือนี้ยอดเยี่ยมอย่างยิ่ง ก่อนที่เราจะสามารถเรียกใช้ฟังก์ชันจาก `rand` ได้ เราจำเป็นต้องแก้ไขไฟล์ _Cargo.toml_ เพื่อเพิ่มเครต `rand` เข้ามาเป็นดีเพนเดนซีเสียก่อน เปิดไฟล์นั้นขึ้นมาแล้วเพิ่มข้อความต่อไปนี้ไว้ด้านล่างใต้หัวข้อ `[dependencies]` ที่ Cargo สร้างไว้ให้ โปรดระบุชื่อ `rand` และหมายเลขเวอร์ชันให้ตรงกับที่ระบุไว้นี้ทุกประการ เพื่อให้โค้ดตัวอย่างในบทเรียนทำงานได้อย่างถูกต้อง:

#### การรับประกันผลการบิลด์ที่เหมือนเดิมทุกครั้ง

Cargo มีกลไกที่ช่วยรับประกันว่าผลลัพธ์จากการบิลด์โค้ดของคุณจะคงเดิมเสมอ ไม่ว่าคุณหรือใครก็ตามจะบิลด์โค้ดนี้เมื่อใด: Cargo จะยึดตามเวอร์ชันของดีเพนเดนซีที่บันทึกไว้เสมอ จนกว่าคุณจะสั่งอัปเกรดอย่างชัดเจน ตัวอย่างเช่น สมมติว่าสัปดาห์หน้ามีเครต `rand` เวอร์ชัน 0.10.2 ปล่อยออกมา แม้ว่าเวอร์ชันนั้นจะมีการแก้ไขบั๊กที่สำคัญ แต่ก็อาจมีข้อผิดพลาดใหม่ (regression) ที่ส่งผลกระทบต่อโค้ดของคุณได้ เพื่อป้องกันปัญหานี้ Rust จะสร้างไฟล์ _Cargo.lock_ ขึ้นมาในการรัน `cargo build` ครั้งแรก ซึ่งในตอนนี้คุณจะพบไฟล์นี้อยู่ในไดเรกทอรี _guessing_game_ เช่นกัน

เมื่อคุณสั่งบิลด์โปรเจกต์เป็นครั้งแรก Cargo จะคำนวณเวอร์ชันของดีเพนเดนซีทั้งหมดที่ตรงตามเงื่อนไข แล้วบันทึกเวอร์ชันที่แน่นอนเหล่านั้นลงในไฟล์ _Cargo.lock_ และเมื่อสั่งบิลด์ในครั้งต่อๆ ไป Cargo จะตรวจพบว่ามีไฟล์ _Cargo.lock_ อยู่แล้ว จึงเลือกใช้เวอร์ชันตามที่ระบุไว้ในไฟล์ทันทีโดยไม่ต้องคำนวณเวอร์ชันใหม่อีก กลไกนี้ทำให้ผลการบิลด์ของโปรเจกต์มีความแน่นอนและทำซ้ำได้ (reproducible builds) เสมอ นั่นหมายความว่าโปรเจกต์ของคุณจะยังคงใช้เวอร์ชัน 0.10.1 ต่อไปจนกว่าคุณจะสั่งอัปเกรดด้วยตนเอง และเนื่องจากไฟล์ _Cargo.lock_ มีความสำคัญต่อการรักษาความสม่ำเสมอของโปรเจกต์ จึงเป็นแนวปฏิบัติที่ดีที่จะบันทึกไฟล์นี้ลงในระบบควบคุมเวอร์ชัน (Git) ร่วมกับซอร์สโค้ดเสมอ

#### การอัปเดตเครตเพื่อรับเวอร์ชันใหม่

เมื่อคุณ_ต้องการ_อัปเดตเวอร์ชันของเครตจริงๆ Cargo มีคำสั่ง `update` ซึ่งจะข้ามการตรวจสอบจากไฟล์ _Cargo.lock_ แล้วค้นหาเวอร์ชันล่าสุดที่ยังคงสอดคล้องกับเงื่อนไขใน _Cargo.toml_ จากนั้นจึงบันทึกเวอร์ชันใหม่เหล่านั้นลงใน _Cargo.lock_ ให้โดยอัตโนมัติ โดยค่าเริ่มต้น Cargo จะมองหาเฉพาะเวอร์ชันที่มากกว่า 0.10.1 แต่ยังน้อยกว่า 0.11.0 หากเครต `rand` มีการปล่อยเวอร์ชันใหม่ 2 รุ่น ได้แก่ 0.10.2 และ 0.999.0 เมื่อคุณรันคำสั่ง `cargo update` จะปรากฏข้อความดังนี้:

Cargo จะไม่ข้ามไปใช้เวอร์ชัน 0.999.0 และเมื่อตรวจดูในไฟล์ _Cargo.lock_ คุณจะพบว่าเวอร์ชันของเครต `rand` ได้รับการปรับเป็น 0.10.2 เรียบร้อยแล้ว หากคุณต้องการเปลี่ยนไปใช้ `rand` เวอร์ชัน 0.999.0 หรือรุ่นใดๆ ในตระกูล 0.999._x_ คุณจะต้องเข้าไปแก้ไขไฟล์ _Cargo.toml_ โดยตรงดังนี้ (โปรดอย่าเพิ่งแก้ไขตามนี้จริงๆ เนื่องจากตัวอย่างโค้ดถัดไปถูกเขียนขึ้นสำหรับ `rand` เวอร์ชัน 0.10):

```toml
[dependencies]
rand = "0.999.0"
```

เมื่อคุณสั่งรัน `cargo build` ในครั้งต่อไป Cargo จะอัปเดตข้อมูลเรจิสทรีและประเมินข้อกำหนดของ `rand` ใหม่ตามเวอร์ชันที่คุณระบุ

ยังมีรายละเอียดอีกมากมายเกี่ยวกับ [Cargo][doccargo]<!-- ignore --> และ[ระบบนิเวศของมัน][doccratesio]<!-- ignore --> ซึ่งเราจะได้เจาะลึกกันในบทที่ 14 แต่สำหรับตอนนี้ เท่านี้ก็เพียงพอแล้วสำหรับการเริ่มต้น Cargo ช่วยให้การนำไลบรารีภายนอกมาใช้งานเป็นเรื่องง่ายดาย ส่งผลให้นักพัฒนา Rust นิยมแยกโครงสร้างโปรเจกต์ออกเป็นแพ็กเกจย่อยๆ ที่ประกอบเข้าด้วยกันได้อย่างลงตัว

ขั้นแรก เราเพิ่มบรรทัด `use rand::prelude::*;` เข้ามา โดยมอดูล `prelude` จะรวบรวมฟังก์ชันและเทรตที่นิยมใช้งานบ่อยที่สุดของเครต `rand` ไว้ และคำสั่ง `use` จะช่วยนำรายการเหล่านั้นเข้ามาสู่สโคปของโปรแกรมเพื่อให้พร้อมเรียกใช้ได้ทันที

ถัดมา เราเพิ่มโค้ดอีก 2 บรรทัดในฟังก์ชัน `main` บรรทัดแรกคือการเรียกฟังก์ชัน `rand::rng` ซึ่งจะส่งกลับตัวสร้างตัวเลขสุ่ม (random number generator) เฉพาะตัวที่เราจะใช้งาน ซึ่งทำงานอยู่ภายในเธรด (thread) ปัจจุบัน และได้รับการกำหนดค่าตั้งต้น (seed) มาจากระบบปฏิบัติการ จากนั้นเราจึงเรียกเมธอด `random_range` บนตัวสร้างตัวเลขสุ่มดังกล่าว โดยเมธอดนี้ถูกนิยามไว้ในเทรต `RngExt` ซึ่งเป็นส่วนหนึ่งของมอดูล `rand::prelude` ที่เรานำเข้ามาด้วย `use rand::prelude::*;` นั่นเอง เมธอด `random_range` จะรับนิพจน์แบบช่วง (range expression) เข้ามาเป็นอาร์กิวเมนต์ เพื่อสร้างตัวเลขสุ่มที่อยู่ภายในขอบเขตนั้น นิพจน์แบบช่วงที่เราเลือกใช้ในที่นี้อยู่ในรูปแบบ `start..=end` ซึ่งนับรวมทั้งค่าขอบเขตล่างและขอบเขตบนด้วย ดังนั้นการระบุ `1..=100` จึงหมายถึงการขอตัวเลขสุ่มระหว่าง 1 ถึง 100

> หมายเหตุ: ในการใช้งานจริง คงไม่มีใครสามารถจดจำได้ทั้งหมดว่าจะต้องนำเข้าสิ่งใดหรือเรียกใช้เมธอดไหนจากเครตภายนอก ด้วยเหตุนี้ เครตแต่ละตัวจึงมักจัดทำเอกสารคู่มือพร้อมตัวอย่างการใช้งานไว้อย่างละเอียด อีกหนึ่งฟีเจอร์ที่ยอดเยี่ยมของ Cargo คือคำสั่ง `cargo doc --open` ซึ่งจะทำการบิลด์เอกสารคู่มือของดีเพนเดนซีทั้งหมดในเครื่องของคุณ แล้วเปิดขึ้นมาบนเว็บเบราว์เซอร์ให้โดยอัตโนมัติ หากคุณสนใจศึกษาความสามารถอื่นๆ ของเครต `rand` สามารถรันคำสั่ง `cargo doc --open` แล้วคลิกเลือก `rand` จากแถบเมนูด้านซ้ายเพื่ออ่านเพิ่มเติมได้ทันที

อันดับแรก เราเพิ่มคำสั่ง `use` อีกหนึ่งรายการ เพื่อนำชนิดข้อมูล `std::cmp::Ordering` จากไลบรารีมาตรฐานเข้ามาสู่สโคป ชนิด `Ordering` เป็น enum อีกตัวหนึ่งที่มีวาเรียนต์ให้ใช้งาน 3 ค่า ได้แก่ `Less`, `Greater` และ `Equal` ซึ่งเป็นผลลัพธ์ที่เป็นไปได้ทั้งหมดเมื่อนำค่าสองค่ามาเปรียบเทียบกัน

จากนั้น เราเพิ่มโค้ดใหม่อีก 5 บรรทัดที่ด้านล่างซึ่งมีการเรียกใช้ชนิด `Ordering` โดยเมธอด `cmp` จะเปรียบเทียบค่าสองค่าเข้าด้วยกัน และสามารถเรียกใช้ได้กับข้อมูลทุกชนิดที่รองรับการเปรียบเทียบ เมธอดนี้จะรับเรเฟอเรนซ์ของค่าที่ต้องการเปรียบเทียบด้วยเข้ามาเป็นอาร์กิวเมนต์ ในที่นี้คือการนำ `guess` ไปเปรียบเทียบกับ `secret_number` แล้วส่งคืนวาเรียนต์ของ enum `Ordering` ที่เรานำเข้ามาด้วยคำสั่ง `use` กลับออกมา เราจะใช้นิพจน์ [`match`][match]<!-- ignore --> ในการตัดสินใจว่าควรทำสิ่งใดต่อไป โดยพิจารณาจากวาเรียนต์ของ `Ordering` ที่ได้จากการเปรียบเทียบค่าระหว่าง `guess` กับ `secret_number`

นิพจน์ `match` ประกอบด้วย_อาร์ม_หรือกิ่งกรณี (arms) หลายๆ กิ่ง โดยในแต่ละอาร์มจะประกอบด้วย_รูปแบบ_ (pattern) ที่ใช้สำหรับจับคู่เงื่อนไข และโค้ดที่จะทำงานหากค่านั้นตรงกับรูปแบบดังกล่าว คอมไพเลอร์ Rust จะนำค่าที่ส่งให้ `match` มาตรวจสอบเปรียบเทียบกับรูปแบบของแต่ละอาร์มเรียงตามลำดับจากบนลงล่าง ทั้งนี้ รูปแบบและโครงสร้าง `match` ถือเป็นฟีเจอร์อันทรงพลังอย่างยิ่งของ Rust เพราะช่วยให้คุณสามารถครอบคลุมทุกสถานการณ์ที่โค้ดอาจพบเจอได้อย่างรอบคอบ และมั่นใจได้ว่าจะไม่มีกรณีใดถูกละเลย ซึ่งเราจะกล่าวถึงฟีเจอร์เหล่านี้อย่างละเอียดในบทที่ 6 และบทที่ 19 ตามลำดับ

ลองมาติดตามการทำงานของนิพจน์ `match` ในตัวอย่างนี้กัน สมมติว่าผู้เล่นทายเลข 50 และตัวเลขลับที่สุ่มได้ในรอบนี้คือ 38

เมื่อโปรแกรมนำ 50 ไปเปรียบเทียบกับ 38 เมธอด `cmp` จะส่งค่า `Ordering::Greater` กลับมา เนื่องจาก 50 มีค่ามากกว่า 38 นิพจน์ `match` จึงได้รับค่า `Ordering::Greater` แล้วเริ่มตรวจสอบรูปแบบในแต่ละอาร์ม โดยเริ่มจากอาร์มแรกคือ `Ordering::Less` ซึ่งพบว่าไม่ตรงกัน จึงข้ามไปยังอาร์มถัดไป รูปแบบของอาร์มถัดมาคือ `Ordering::Greater` ซึ่ง_ตรงกัน_พอดีกับค่าที่ได้รับ! โค้ดในอาร์มนั้นจึงเริ่มทำงานและพิมพ์ข้อความ `Too big!` ออกทางหน้าจอ เมื่อการจับคู่ในนิพจน์ `match` สำเร็จเรียบร้อยแล้ว การทำงานของโครงสร้าง `match` จะสิ้นสุดลงทันที จึงไม่มีการตรวจสอบอาร์มที่เหลือต่อในสถานการณ์นี้

ใจความสำคัญของข้อผิดพลาดระบุว่าเกิดปัญหา_ชนิดข้อมูลไม่ตรงกัน_ (mismatched types) เนื่องจาก Rust เป็นภาษาที่มีระบบชนิดข้อมูลแบบสแตติกที่เข้มงวด (strongly typed) อย่างไรก็ตาม Rust ก็มีระบบอนุมานชนิดข้อมูล (type inference) ที่ชาญฉลาด เมื่อเราเขียน `let mut guess = String::new()` คอมไพเลอร์สามารถอนุมานได้เองว่า `guess` ควรเป็นชนิด `String` จึงไม่ได้บังคับให้เราต้องระบุชนิดข้อมูลด้วยตนเอง ในทางตรงกันข้าม ตัวแปร `secret_number` มีชนิดข้อมูลเป็นตัวเลข ซึ่ง Rust มีชนิดข้อมูลตัวเลขหลายแบบที่สามารถเก็บค่า 1 ถึง 100 ได้ เช่น `i32` (จำนวนเต็ม 32 บิตแบบมีเครื่องหมาย), `u32` (จำนวนเต็ม 32 บิตแบบไม่มีเครื่องหมาย), `i64` (จำนวนเต็ม 64 บิต) และอื่นๆ หากเราไม่ได้ระบุไว้เป็นอย่างอื่น Rust จะกำหนดให้เป็นชนิด `i32` ตามค่าเริ่มต้น ซึ่งทำให้ `secret_number` มีชนิดเป็น `i32` เว้นแต่เราจะใส่ข้อมูลชนิดอื่นที่ทำให้คอมไพเลอร์อนุมานเป็นชนิดอื่นแทน สาเหตุของข้อผิดพลาดในครั้งนี้จึงเกิดจากการที่ Rust ไม่อนุญาตให้นำสตริง (`String`) มาเปรียบเทียบกับชนิดข้อมูลตัวเลขโดยตรงได้นั่นเอง

ดังนั้น เราจึงต้องแปลงค่า `String` ที่อ่านเข้ามาจากผู้ใช้ให้กลายเป็นชนิดข้อมูลตัวเลขเสียก่อน เพื่อให้สามารถนำไปเปรียบเทียบเชิงตัวเลขกับ `secret_number` ได้ เราทำสิ่งนี้ได้โดยการเพิ่มบรรทัดต่อไปนี้เข้าไปในฟังก์ชัน `main`:

เราประกาศตัวแปรชื่อ `guess` ขึ้นมาใหม่อีกครั้ง แต่โปรแกรมของเรามีตัวแปรชื่อ `guess` อยู่แล้วไม่ใช่หรือ? ใช่แล้ว! แต่ใน Rust เรามีความสามารถในการประกาศตัวแปรใหม่ที่มีชื่อซ้ำกับตัวแปรเดิมได้ ซึ่งเรียกว่า_การบดบังตัวแปร_ (shadowing) ฟีเจอร์นี้ช่วยให้เราสามารถนำชื่อตัวแปร `guess` กลับมาใช้ซ้ำได้ โดยไม่ต้องคอยตั้งชื่อตัวแปรใหม่ที่ไม่ซ้ำกัน เช่น `guess_str` กับ `guess` เราจะกล่าวถึงเรื่องนี้โดยละเอียดใน[บทที่ 3][shadowing]<!-- ignore --> แต่สำหรับตอนนี้ ให้จำไว้ว่าฟีเจอร์นี้มักถูกนำมาใช้บ่อยครั้งเมื่อเราต้องการแปลงค่าจากชนิดข้อมูลหนึ่งไปเป็นอีกชนิดหนึ่ง

เราผูกตัวแปรใหม่นี้เข้ากับผลลัพธ์ของนิพจน์ `guess.trim().parse()` โดย `guess` ในนิพจน์นี้หมายถึงตัวแปร `guess` ตัวเดิมที่เก็บสตริงอินพุตไว้ เมธอด `trim` บนอินสแตนซ์ของ `String` จะช่วยตัดช่องว่างทั้งหมดที่อยู่บริเวณหัวและท้ายข้อความออก ซึ่งจำเป็นต้องทำก่อนจะแปลงสตริงไปเป็น `u32` ที่รองรับเฉพาะตัวเลขเท่านั้น เนื่องจากเวลาที่ผู้ใช้พิมพ์ตัวเลขแล้วกด <kbd>Enter</kbd> เมธอด `read_line` จะบันทึกอักขระขึ้นบรรทัดใหม่ติดมาด้วยเสมอ ตัวอย่างเช่น หากผู้ใช้พิมพ์ <kbd>5</kbd> แล้วกด <kbd>Enter</kbd> ตัวแปร `guess` จะมีค่าเป็น `5\n` (บน Windows การกด <kbd>Enter</kbd> จะให้ผลเป็น carriage return และ newline คือ `\r\n`) เมธอด `trim` จึงทำหน้าที่ตัด `\n` หรือ `\r\n` ทิ้งไป ทำให้เหลือเพียงข้อความ `5` เท่านั้น

เมธอด [`parse` บนสตริง][parse]<!-- ignore --> ทำหน้าที่แปลงข้อความสตริงให้เป็นชนิดข้อมูลอื่น ในกรณีนี้ เราใช้เพื่อแปลงสตริงเป็นตัวเลข โดยเราต้องระบุชนิดข้อมูลตัวเลขที่ต้องการให้ชัดเจนด้วย `let guess: u32` เครื่องหมายโคลอน (`:`) หลังชื่อ `guess` จะบอกคอมไพเลอร์ว่าเรากำลังระบุชนิดข้อมูล (type annotation) ให้กับตัวแปร ทั้งนี้ Rust มีชนิดข้อมูลตัวเลขพื้นฐานหลายประเภท โดย `u32` คือจำนวนเต็ม 32 บิตแบบไม่มีเครื่องหมาย ซึ่งเหมาะอย่างยิ่งสำหรับเก็บตัวเลขจำนวนเต็มบวกขนาดเล็ก คุณจะได้ศึกษาชนิดตัวเลขอื่นๆ เพิ่มเติมใน[บทที่ 3][integers]<!-- ignore -->

นอกจากนี้ การระบุชนิด `u32` ให้กับตัวแปรและนำไปเปรียบเทียบกับ `secret_number` ยังส่งผลให้คอมไพเลอร์ Rust อนุมานให้ `secret_number` มีชนิดข้อมูลเป็น `u32` ตามไปด้วยโดยอัตโนมัติ ทำให้ตอนนี้การเปรียบเทียบเกิดขึ้นระหว่างค่าของชนิดข้อมูลเดียวกันแล้ว!

เนื่องจากเมธอด `parse` จะแปลงค่าได้สำเร็จเฉพาะกับข้อความที่เป็นตัวเลขจริงๆ เท่านั้น การเรียกใช้จึงมีโอกาสเกิดข้อผิดพลาดได้ง่าย เช่น หากสตริงมีข้อความอย่าง `A👍%` เมธอดนี้จะไม่สามารถแปลงเป็นตัวเลขได้ ด้วยเหตุนี้ `parse` จึงส่งผลลัพธ์กลับมาเป็นชนิด `Result` เช่นเดียวกับที่เมธอด `read_line` ทำ (ดังที่ได้อธิบายไว้ในหัวข้อ [“การจัดการความล้มเหลวที่อาจเกิดขึ้นด้วย `Result`”](#การจัดการความลมเหลวทีอาจเกิดขึนดวย-result)<!-- ignore -->) เราจึงสามารถจัดการผลลัพธ์ของ `Result` ได้ด้วยวิธีเดิม นั่นคือการเรียกเมธอด `expect` หาก `parse` ส่งคืนวาเรียนต์ `Err` เนื่องจากแปลงตัวเลขไม่สำเร็จ เมธอด `expect` จะทำให้โปรแกรมหยุดทำงานพร้อมแสดงข้อความเตือนที่เรากำหนดไว้ แต่หาก `parse` แปลงสตริงเป็นตัวเลขได้สำเร็จ จะส่งคืนวาเรียนต์ `Ok` และ `expect` จะดึงค่าตัวเลขที่อยู่ภายในออกมาให้เรานำไปใช้งานต่อได้อย่างราบรื่น

เราเปลี่ยนจากการเรียกใช้ `expect` มาใช้นิพจน์ `match` แทน เพื่อเปลี่ยนจากการหยุดทำงานเมื่อเกิดข้อผิดพลาด มาเป็นการควบคุมและจัดการข้อผิดพลาดด้วยตนเอง จำได้ไหมว่า `parse` จะส่งผลลัพธ์เป็นชนิด `Result` ซึ่งเป็น enum ที่มีวาเรียนต์คือ `Ok` และ `Err` เราจึงสามารถใช้ `match` เพื่อตรวจสอบผลลัพธ์ได้ในลักษณะเดียวกับที่เราเคยทำกับผลลัพธ์ `Ordering` จากเมธอด `cmp`

หาก `parse` แปลงสตริงเป็นตัวเลขได้สำเร็จ จะส่งคืนค่า `Ok` ที่บรรจุตัวเลขผลลัพธ์ไว้ ซึ่งจะตรงกับรูปแบบในอาร์มแรกของ `match` และทำให้นิพจน์ `match` ส่งคืนค่า `num` ที่ได้ออกมา ค่าตัวเลขนั้นจึงถูกนำไปจัดเก็บไว้ในตัวแปร `guess` ตัวใหม่ที่เราสร้างขึ้นได้อย่างสมบูรณ์

แต่หาก `parse` _ไม่_สามารถแปลงสตริงเป็นตัวเลขได้ จะส่งคืนค่า `Err` ที่บรรจุรายละเอียดของข้อผิดพลาดออกมา ซึ่งค่า `Err` นี้จะไม่ตรงกับรูปแบบ `Ok(num)` ในอาร์มแรก แต่จะไปตรงกับรูปแบบ `Err(_)` ในอาร์มที่สองแทน โดยสัญลักษณ์ขีดล่าง `_` ทำหน้าที่เป็นรูปแบบที่จับคู่ได้กับทุกค่า (catch-all) ในตัวอย่างนี้เราบอกว่าต้องการจับคู่กับค่า `Err` ทั้งหมดโดยไม่สนใจว่าภายในจะมีข้อมูลข้อผิดพลาดอะไรอยู่ จากนั้นโปรแกรมจะรันคำสั่งในอาร์มที่สอง นั่นคือ `continue` ซึ่งสั่งให้ข้ามไปยังรอบการวนซ้ำ (iteration) ถัดไปของ `loop` ทันที และแสดงข้อความขอคำทายใหม่อีกครั้ง ทำให้โปรแกรมสามารถมองข้ามข้อมูลที่ไม่ถูกต้องได้อย่างนุ่มนวลโดยไม่หยุดทำงานกะทันหัน!

## สรุป

โปรเจกต์นี้เป็นการปูพื้นฐานภาคปฏิบัติที่ช่วยแนะนำให้คุณรู้จักกับแนวคิดใหม่ๆ มากมายในภาษา Rust เช่น คำสั่ง `let`, `match`, ฟังก์ชัน, การเรียกใช้งานเครตภายนอก และอื่นๆ อีกมากมาย ในบทต่อๆ ไป คุณจะได้ศึกษาแต่ละแนวคิดเหล่านี้ในมิติที่ลึกซึ้งยิ่งขึ้น โดยในบทที่ 3 จะครอบคลุมแนวคิดพื้นฐานที่มีในภาษาโปรแกรมทั่วไป เช่น ตัวแปร, ชนิดข้อมูล (data types) และฟังก์ชัน พร้อมแสดงวิธีเขียนสิ่งเหล่านี้ใน Rust บทที่ 4 จะพาไปเจาะลึกระบบสิทธิ์ความเป็นเจ้าของ (ownership) ซึ่งเป็นฟีเจอร์อันโดดเด่นที่ทำให้ Rust แตกต่างจากภาษาอื่นๆ บทที่ 5 จะอธิบาย struct และเมธอด ส่วนบทที่ 6 จะอธิบายการทำงานของ enum อย่างละเอียด
