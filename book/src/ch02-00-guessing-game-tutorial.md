# เขียนโปรแกรมเกมทายตัวเลข

มาเริ่มต้นกับ Rust ด้วยการลงมือทำโปรเจกต์แบบลงมือปฏิบัติจริงไปด้วยกัน! บทนี้จะแนะนำแนวคิดทั่วไปหลายประการของ Rust ให้คุณรู้จัก โดยแสดงวิธีนำแนวคิดเหล่านั้นไปใช้ในโปรแกรมจริง คุณจะได้เรียนรู้เกี่ยวกับ `let`, `match`, เมธอด (method), ฟังก์ชันที่เชื่อมโยงกับชนิดข้อมูล (associated function), เครตภายนอก (crate) และอื่นๆ อีกมากมาย! ในบทต่อๆ ไป เราจะสำรวจแนวคิดเหล่านี้ในรายละเอียดมากขึ้น ในบทนี้ คุณจะได้ฝึกฝนพื้นฐานเท่านั้น

เราจะลงมือสร้างโจทย์ปัญหาการเขียนโปรแกรมคลาสสิกสำหรับผู้เริ่มต้น นั่นคือเกมทายตัวเลข โดยมีหลักการทำงานดังนี้ โปรแกรมจะสุ่มจำนวนเต็ม (integer) ระหว่าง 1 ถึง 100 จากนั้นจะแจ้งให้ผู้เล่นป้อนคำทาย หลังจากป้อนคำทายแล้ว โปรแกรมจะระบุว่าคำทายนั้นต่ำเกินไปหรือสูงเกินไป หากคำทายถูกต้อง เกมจะพิมพ์ข้อความแสดงความยินดีและจบการทำงาน

## การตั้งค่าโปรเจกต์ใหม่

ในการตั้งค่าโปรเจกต์ใหม่ ให้ไปที่ไดเรกทอรี _projects_ ที่คุณสร้างไว้ในบทที่ 1 แล้วสร้างโปรเจกต์ใหม่โดยใช้ Cargo ดังนี้:

### การเก็บค่าด้วยตัวแปร

ถัดไป เราจะสร้าง_ตัวแปร_เพื่อเก็บอินพุตของผู้ใช้ ดังนี้:

```rust,ignore
{{#rustdoc_include ../listings/ch02-guessing-game-tutorial/listing-02-01/src/main.rs:string}}
```

ตอนนี้โปรแกรมเริ่มน่าสนใจแล้ว! มีหลายอย่างเกิดขึ้นในบรรทัดเล็กๆ นี้ เราใช้สเตตเมนต์ `let` เพื่อสร้างตัวแปร นี่คืออีกตัวอย่างหนึ่ง:

```rust,ignore
let apples = 5;
```

บรรทัดนี้สร้างตัวแปรใหม่ชื่อ `apples` และผูกมันเข้ากับค่า `5` ใน Rust ตัวแปรเป็นแบบเปลี่ยนแปลงไม่ได้ (immutable) โดยค่าเริ่มต้น หมายความว่าเมื่อเรากำหนดค่าให้ตัวแปรแล้ว ค่านั้นจะไม่เปลี่ยน เราจะพูดถึงแนวคิดนี้โดยละเอียดในหัวข้อ[“ตัวแปรและความสามารถในการเปลี่ยนแปลงค่า”][variables-and-mutability]<!-- ignore --> ในบทที่ 3 การทำให้ตัวแปรเปลี่ยนแปลงได้ (mutable) เราจะเติม `mut` ไว้หน้าชื่อตัวแปร:

```rust,ignore
let apples = 5; // immutable
let mut bananas = 5; // mutable
```

> หมายเหตุ: วากยสัมพันธ์ `//` เริ่มคอมเมนต์ (comment) ที่ต่อเนื่องไปจนจบบรรทัด Rust มองข้ามทุกอย่างในคอมเมนต์ เราจะพูดถึงคอมเมนต์โดยละเอียดเพิ่มเติมใน[บทที่ 3][comments]<!-- ignore -->

กลับมาที่โปรแกรมเกมทายตัวเลข ตอนนี้คุณรู้แล้วว่า `let mut guess` จะสร้างตัวแปรที่เปลี่ยนแปลงได้ชื่อ `guess` เครื่องหมายเท่ากับ (`=`) บอก Rust ว่าเราต้องการผูกบางสิ่งเข้ากับตัวแปรตอนนี้ ทางด้านขวาของเครื่องหมายเท่ากับคือค่าที่ `guess` ถูกผูกไว้ ซึ่งเป็นผลลัพธ์จากการเรียก `String::new` ฟังก์ชันที่คืนอินสแตนซ์ (instance) ใหม่ของ `String` [`String`][string]<!-- ignore --> เป็นชนิดสตริงที่ไลบรารีมาตรฐานจัดเตรียมไว้ ซึ่งเป็นข้อความที่ขยายขนาดได้และเข้ารหัสแบบ UTF-8

วากยสัมพันธ์ `::` ในบรรทัด `::new` บ่งชี้ว่า `new` เป็นฟังก์ชันที่เชื่อมโยงกับชนิดข้อมูลของชนิด `String` _ฟังก์ชันที่เชื่อมโยงกับชนิดข้อมูล_คือฟังก์ชันที่ถูกอิมพลีเมนต์บนชนิดข้อมูลหนึ่ง ในกรณีนี้คือ `String` ฟังก์ชัน `new` นี้สร้างสตริงใหม่ที่ว่างเปล่า คุณจะพบฟังก์ชัน `new` ในชนิดข้อมูลหลายชนิด เพราะเป็นชื่อที่ใช้กันทั่วไปสำหรับฟังก์ชันที่สร้างค่าใหม่ขึ้นมาสักอย่าง

โดยสรุปแล้ว บรรทัด `let mut guess = String::new();` ได้สร้างตัวแปรที่เปลี่ยนแปลงได้ซึ่งปัจจุบันผูกอยู่กับอินสแตนซ์ใหม่ที่ว่างเปล่าของ `String` เฮ้อ!

### การรับอินพุตจากผู้ใช้

ย้อนกลับไปว่าเราได้นำฟังก์ชันการทำงานอินพุต/เอาต์พุตจากไลบรารีมาตรฐานเข้ามาด้วย `use std::io;` ในบรรทัดแรกของโปรแกรม ตอนนี้เราจะเรียกฟังก์ชัน `stdin` จากมอดูล (module) `io` ซึ่งจะช่วยให้เราจัดการอินพุตจากผู้ใช้ได้:

```rust,ignore
{{#rustdoc_include ../listings/ch02-guessing-game-tutorial/listing-02-01/src/main.rs:read}}
```

หากเราไม่ได้นำเข้ามอดูล `io` ด้วย `use std::io;` ตอนต้นของโปรแกรม เราก็ยังสามารถใช้ฟังก์ชันนี้ได้โดยเขียนการเรียกฟังก์ชันเป็น `std::io::stdin` ฟังก์ชัน `stdin` คืนอินสแตนซ์ของ [`std::io::Stdin`][iostdin]<!-- ignore --> ซึ่งเป็นชนิดข้อมูลที่เป็นตัวแทนแฮนเดิล (handle) ไปยังอินพุตมาตรฐานของเทอร์มินัลของคุณ

ถัดไป บรรทัด `.read_line(&mut guess)` เรียกเมธอด [`read_line`][read_line]<!--
ignore --> บนแฮนเดิลอินพุตมาตรฐานเพื่อรับอินพุตจากผู้ใช้ เรายังส่ง `&mut guess` เป็นอาร์กิวเมนต์ให้ `read_line` เพื่อบอกว่าควรเก็บอินพุตของผู้ใช้ไว้ในสตริงใด หน้าที่ทั้งหมดของ `read_line` คือรับสิ่งที่ผู้ใช้พิมพ์เข้าสู่อินพุตมาตรฐานแล้วต่อท้ายสิ่งนั้นเข้าไปในสตริง (โดยไม่เขียนทับเนื้อหาเดิม) เราจึงส่งสตริงนั้นเป็นอาร์กิวเมนต์ อาร์กิวเมนต์ที่เป็นสตริงจำเป็นต้องเปลี่ยนแปลงได้เพื่อให้เมธอดสามารถเปลี่ยนเนื้อหาของสตริงได้

เครื่องหมาย `&` บ่งชี้ว่าอาร์กิวเมนต์นี้เป็น_เรเฟอเรนซ์_ (reference) ซึ่งให้วิธีที่ทำให้โค้ดหลายส่วนของคุณเข้าถึงข้อมูลชิ้นเดียวกันได้โดยไม่ต้องคัดลอกข้อมูลนั้นเข้าไปในหน่วยความจำหลายครั้ง เรเฟอเรนซ์เป็นฟีเจอร์ที่ซับซ้อน และข้อได้เปรียบสำคัญประการหนึ่งของ Rust คือความปลอดภัยและความง่ายในการใช้เรเฟอเรนซ์ คุณไม่จำเป็นต้องรู้รายละเอียดเหล่านี้มากนักเพื่อทำโปรแกรมนี้ให้เสร็จ สำหรับตอนนี้ สิ่งเดียวที่คุณต้องรู้คือ เช่นเดียวกับตัวแปร เรเฟอเรนซ์เป็นแบบเปลี่ยนแปลงไม่ได้โดยค่าเริ่มต้น ดังนั้น คุณจึงต้องเขียน `&mut guess` แทน `&guess` เพื่อทำให้มันเปลี่ยนแปลงได้ (บทที่ 4 จะอธิบายเรเฟอเรนซ์อย่างละเอียดยิ่งขึ้น)

### การจัดการความล้มเหลวที่อาจเกิดขึ้นด้วย `Result`

เรายังคงทำงานกับบรรทัดโค้ดนี้อยู่ ตอนนี้เรากำลังพูดถึงบรรทัดที่สามของข้อความ แต่โปรดสังเกตว่ามันยังเป็นส่วนหนึ่งของบรรทัดโค้ดเชิงตรรกะเพียงบรรทัดเดียว ส่วนถัดไปคือเมธอดนี้:

```rust,ignore
{{#rustdoc_include ../listings/ch02-guessing-game-tutorial/listing-02-01/src/main.rs:expect}}
```

เราสามารถเขียนโค้ดนี้เป็นแบบนี้ก็ได้:

```rust,ignore
io::stdin().read_line(&mut guess).expect("Failed to read line");
```

อย่างไรก็ตาม บรรทัดยาวๆ เพียงบรรทัดเดียวนั้นอ่านยาก จึงเป็นการดีที่สุดที่จะแบ่งมันออก มักเป็นเรื่องฉลาดที่จะเพิ่มการขึ้นบรรทัดใหม่และช่องว่างอื่นๆ เพื่อช่วยแยกบรรทัดยาวๆ เมื่อคุณเรียกเมธอดด้วยวากยสัมพันธ์ `.method_name()` ตอนนี้มาพูดกันว่าบรรทัดนี้ทำอะไร

ดังที่กล่าวไว้ก่อนหน้านี้ `read_line` นำสิ่งที่ผู้ใช้ป้อนไปใส่ในสตริงที่เราส่งให้ แต่ยังคืนค่า `Result` กลับมาด้วย [`Result`][result]<!--
ignore --> เป็น[_อีนูเมอเรชัน_ (enumeration)][enums]<!-- ignore --> ซึ่งมักเรียกกันว่า _enum_ นั่นคือชนิดข้อมูลที่สามารถอยู่ในสถานะใดสถานะหนึ่งจากหลายสถานะที่เป็นไปได้ เราเรียกแต่ละสถานะที่เป็นไปได้ว่า _วาเรียนต์_ (variant)

[บทที่ 6][enums]<!-- ignore --> จะกล่าวถึง enum ในรายละเอียดมากขึ้น จุดประสงค์ของชนิด `Result` เหล่านี้คือการเข้ารหัสข้อมูลการจัดการข้อผิดพลาด (error handling)

วาเรียนต์ของ `Result` คือ `Ok` และ `Err` วาเรียนต์ `Ok` บ่งชี้ว่าการดำเนินการสำเร็จ และบรรจุค่าที่สร้างขึ้นได้สำเร็จ วาเรียนต์ `Err` หมายความว่าการดำเนินการล้มเหลว และบรรจุข้อมูลว่าการดำเนินการล้มเหลวอย่างไรหรือเพราะเหตุใด

ค่าของชนิด `Result` เช่นเดียวกับค่าของชนิดใดๆ มีเมธอดที่นิยามไว้บนค่าเหล่านั้น อินสแตนซ์ของ `Result` มี[เมธอด `expect`][expect]<!-- ignore --> ที่คุณเรียกได้ ถ้าอินสแตนซ์ของ `Result` นี้เป็นค่า `Err` `expect` จะทำให้โปรแกรมหยุดทำงานและแสดงข้อความที่คุณส่งเป็นอาร์กิวเมนต์ให้ `expect` ถ้าเมธอด `read_line` คืนค่า `Err` มันมักจะเป็นผลมาจากข้อผิดพลาดที่มาจากระบบปฏิบัติการเบื้องล่าง ถ้าอินสแตนซ์ของ `Result` นี้เป็นค่า `Ok` `expect` จะนำค่าที่คืนกลับ (return value) ที่ `Ok` ถืออยู่มาให้คุณเพียงค่านั้น เพื่อให้คุณนำไปใช้ได้ ในกรณีนี้ ค่านั้นคือจำนวนไบต์ในอินพุตของผู้ใช้

ถ้าคุณไม่เรียก `expect` โปรแกรมจะคอมไพล์ผ่าน แต่คุณจะได้รับคำเตือน (warning):

```console
{{#include ../listings/ch02-guessing-game-tutorial/no-listing-02-without-expect/output.txt}}
```

Rust เตือนว่าคุณยังไม่ได้ใช้ค่า `Result` ที่คืนมาจาก `read_line` ซึ่งบ่งชี้ว่าโปรแกรมยังไม่ได้จัดการข้อผิดพลาดที่อาจเกิดขึ้น

วิธีที่ถูกต้องในการระงับคำเตือนคือเขียนโค้ดจัดการข้อผิดพลาดจริงๆ แต่ในกรณีของเรา เราต้องการให้โปรแกรมนี้หยุดทำงานเมื่อเกิดปัญหา เราจึงใช้ `expect` ได้ คุณจะได้เรียนรู้เกี่ยวกับการกู้คืนจากข้อผิดพลาดใน[บทที่ 9][recover]<!-- ignore -->

```rust,ignore
{{#rustdoc_include ../listings/ch02-guessing-game-tutorial/listing-02-01/src/main.rs:print_guess}}
```

บรรทัดนี้พิมพ์สตริงที่ตอนนี้มีอินพุตของผู้ใช้อยู่ วงเล็บปีกกา `{}` เป็นตัวยึดตำแหน่ง (placeholder): ให้คิดว่า `{}` เป็นก้ามปูเล็กๆ ที่ยึดค่าหนึ่งไว้กับที่ เมื่อพิมพ์ค่าของตัวแปร ชื่อตัวแปรสามารถอยู่ในวงเล็บปีกกาได้ เมื่อพิมพ์ผลลัพธ์ของการประเมินเอ็กซ์เพรสชัน (expression) ให้วางวงเล็บปีกกาว่างในสตริงรูปแบบ (format string) จากนั้นตามหลังสตริงรูปแบบด้วยรายการเอ็กซ์เพรสชันที่คั่นด้วยเครื่องหมายจุลภาคเพื่อพิมพ์ในตัวยึดตำแหน่งวงเล็บปีกกาว่างแต่ละอันตามลำดับเดียวกัน การพิมพ์ตัวแปรและผลลัพธ์ของเอ็กซ์เพรสชันในการเรียก `println!` ครั้งเดียวจะมีหน้าตาดังนี้:

```rust
let x = 5;
let y = 10;

println!("x = {x} and y + 2 = {}", y + 2);
```

โค้ดนี้จะพิมพ์ `x = 5 and y + 2 = 12`

### เพิ่มฟังก์ชันการทำงานด้วยเครต

จำไว้ว่าเครตคือชุดรวมของไฟล์ซอร์สโค้ด Rust โปรเจกต์ที่เราสร้างมาตลอดนี้เป็นเครตไบนารี (binary crate) ซึ่งเป็นไฟล์รันได้ (executable) เครต `rand` เป็นเครตไลบรารี (library crate) ซึ่งมีโค้ดที่ตั้งใจไว้ให้ใช้ในโปรแกรมอื่นและไม่สามารถรันได้ด้วยตัวเอง

การประสานงานของ Cargo กับเครตภายนอกคือจุดที่ Cargo โดดเด่นอย่างแท้จริง ก่อนที่เราจะเขียนโค้ดที่ใช้ `rand` ได้ เราจำเป็นต้องแก้ไขไฟล์ _Cargo.toml_ เพื่อเพิ่มเครต `rand` เป็นดีเพนเดนซี (dependency) เปิดไฟล์นั้นตอนนี้แล้วเพิ่มบรรทัดต่อไปนี้ไว้ด้านล่าง ใต้หัวข้อส่วน `[dependencies]` ที่ Cargo สร้างให้คุณ อย่าลืมระบุ `rand` ให้เหมือนกับที่เราเขียนไว้ที่นี่ทุกประการ พร้อมหมายเลขเวอร์ชันนี้ มิฉะนั้นตัวอย่างโค้ดในบทเรียนนี้อาจไม่ทำงาน:

เมื่อเรารวมดีเพนเดนซีภายนอกเข้ามา Cargo จะดึงเวอร์ชันล่าสุดของทุกสิ่งที่ดีเพนเดนซีนั้นต้องการจาก_เรจิสทรี_ (registry) ซึ่งเป็นสำเนาข้อมูลจาก [Crates.io][cratesio] Crates.io คือที่ที่ผู้คนในระบบนิเวศ Rust โพสต์โปรเจกต์ Rust แบบโอเพนซอร์สของตนเพื่อให้ผู้อื่นนำไปใช้

#### การรับประกันบิลด์ที่ทำซ้ำได้

Cargo มีกลไกที่รับประกันว่าคุณสามารถสร้างอาร์ติแฟกต์ (artifact) เดิมขึ้นมาใหม่ได้ทุกครั้งที่คุณหรือคนอื่นบิลด์โค้ดของคุณ: Cargo จะใช้เฉพาะเวอร์ชันของดีเพนเดนซีที่คุณระบุไว้เท่านั้น จนกว่าคุณจะระบุเป็นอย่างอื่น ตัวอย่างเช่น สมมติว่าสัปดาห์หน้าเวอร์ชัน 0.10.2 ของเครต `rand` ออกมา และเวอร์ชันนั้นมีการแก้บั๊ก (bug fix) ที่สำคัญ แต่ก็มีรีเกรสชัน (regression) ที่จะทำให้โค้ดของคุณพังด้วย เพื่อจัดการกับเรื่องนี้ Rust จะสร้างไฟล์ _Cargo.lock_ ในครั้งแรกที่คุณรัน `cargo build` ดังนั้นตอนนี้เราจึงมีไฟล์นี้อยู่ในไดเรกทอรี _guessing_game_

เมื่อคุณบิลด์โปรเจกต์เป็นครั้งแรก Cargo จะคำนวณเวอร์ชันทั้งหมดของดีเพนเดนซีที่ตรงตามเกณฑ์ แล้วเขียนเวอร์ชันเหล่านั้นลงในไฟล์ _Cargo.lock_ เมื่อคุณบิลด์โปรเจกต์ในอนาคต Cargo จะเห็นว่าไฟล์ _Cargo.lock_ มีอยู่แล้ว และจะใช้เวอร์ชันที่ระบุไว้ในนั้นแทนที่จะทำงานทั้งหมดเพื่อคำนวณเวอร์ชันอีกครั้ง วิธีนี้ทำให้คุณได้บิลด์ที่ทำซ้ำได้โดยอัตโนมัติ กล่าวอีกนัยหนึ่ง โปรเจกต์ของคุณจะคงอยู่ที่ 0.10.1 จนกว่าคุณจะอัปเกรดอย่างชัดแจ้ง ต้องขอบคุณไฟล์ _Cargo.lock_ เพราะไฟล์ _Cargo.lock_ มีความสำคัญต่อบิลด์ที่ทำซ้ำได้ มันจึงมักถูกเก็บเข้าไปในระบบควบคุมซอร์สโค้ด (source control) พร้อมกับโค้ดส่วนที่เหลือในโปรเจกต์ของคุณ

#### การอัปเดตเครตเพื่อให้ได้เวอร์ชันใหม่

เมื่อคุณ_ต้องการ_อัปเดตเครตจริงๆ Cargo มีคำสั่ง `update` ซึ่งจะไม่สนใจไฟล์ _Cargo.lock_ และคำนวณเวอร์ชันล่าสุดทั้งหมดที่ตรงกับข้อกำหนดของคุณใน _Cargo.toml_ จากนั้น Cargo จะเขียนเวอร์ชันเหล่านั้นลงในไฟล์ _Cargo.lock_ มิฉะนั้น โดยค่าเริ่มต้น Cargo จะมองหาเฉพาะเวอร์ชันที่มากกว่า 0.10.1 และน้อยกว่า 0.11.0 หากเครต `rand` ได้ปล่อยเวอร์ชันใหม่สองเวอร์ชันคือ 0.10.2 และ 0.999.0 คุณจะเห็นข้อความต่อไปนี้หากคุณรัน `cargo update`:


ก่อนอื่น เราเพิ่มสเตตเมนต์ (statement) `use` อีกหนึ่งรายการ เพื่อนำชนิดที่ชื่อ `std::cmp::Ordering` จากไลบรารีมาตรฐานเข้าสู่สโคป (scope) ชนิด `Ordering` เป็น enum อีกตัวหนึ่งและมีวาเรียนต์ (variant) ได้แก่ `Less`, `Greater` และ `Equal` ทั้งสามค่านี้คือผลลัพธ์ที่เป็นไปได้เมื่อคุณเปรียบเทียบค่าสองค่า

จากนั้น เราเพิ่มบรรทัดใหม่ห้าบรรทัดที่ด้านล่างซึ่งใช้ชนิด `Ordering` เมธอด (method) `cmp` เปรียบเทียบค่าสองค่าและเรียกใช้ได้กับทุกสิ่งที่เปรียบเทียบกันได้ มันรับเรเฟอเรนซ์ (reference) ไปยังสิ่งที่คุณต้องการเปรียบเทียบด้วย ในที่นี้ มันกำลังเปรียบเทียบ `guess` กับ `secret_number` จากนั้นมันจะคืนวาเรียนต์ของ enum `Ordering` ที่เรานำเข้าสโคปด้วยสเตตเมนต์ `use` เราจะใช้เอ็กซ์เพรสชัน (expression) [`match`][match]<!-- ignore --> เพื่อตัดสินใจว่าจะทำอะไรต่อไป โดยพิจารณาจากวาเรียนต์ของ `Ordering` ที่ถูกคืนกลับมาจากการเรียก `cmp` ด้วยค่าใน `guess` และ `secret_number`

เอ็กซ์เพรสชัน `match` ประกอบขึ้นจาก_อาร์ม_ (arm) อาร์มหนึ่งประกอบด้วย_แพตเทิร์น_ (pattern) ที่จะใช้จับคู่ และโค้ดที่ควรถูกรันหากค่าที่ให้กับ `match` เข้ากับแพตเทิร์นของอาร์มนั้น Rust จะนำค่าที่ให้กับ `match` มาพิจารณาแพตเทิร์นของแต่ละอาร์มตามลำดับ แพตเทิร์นและโครงสร้าง `match` เป็นฟีเจอร์ที่ทรงพลังของ Rust เพราะมันให้คุณแสดงสถานการณ์ต่างๆ ที่โค้ดของคุณอาจพบเจอ และทำให้แน่ใจว่าคุณจัดการกับทุกสถานการณ์ ฟีเจอร์เหล่านี้จะกล่าวถึงอย่างละเอียดในบทที่ 6 และบทที่ 19 ตามลำดับ

มาดูตัวอย่างของเอ็กซ์เพรสชัน `match` ที่เราใช้ในที่นี้กัน สมมติว่าผู้ใช้ทาย 50 และตัวเลขลับที่สุ่มได้ในครั้งนี้คือ 38

เมื่อโค้ดเปรียบเทียบ 50 กับ 38 เมธอด `cmp` จะคืนค่า `Ordering::Greater` เพราะ 50 มากกว่า 38 เอ็กซ์เพรสชัน `match` จะได้รับค่า `Ordering::Greater` แล้วเริ่มตรวจแพตเทิร์นของแต่ละอาร์ม มันดูแพตเทิร์นของอาร์มแรกคือ `Ordering::Less` และเห็นว่าค่า `Ordering::Greater` ไม่ตรงกับ `Ordering::Less` จึงข้ามโค้ดในอาร์มนั้นไปยังอาร์มถัดไป แพตเทิร์นของอาร์มถัดไปคือ `Ordering::Greater` ซึ่ง_ตรงกัน_กับ `Ordering::Greater`! โค้ดที่เชื่อมโยงในอาร์มนั้นจะทำงานและพิมพ์ `Too big!` ออกทางหน้าจอ เอ็กซ์เพรสชัน `match` จะสิ้นสุดลงหลังการจับคู่สำเร็จครั้งแรก ดังนั้นในสถานการณ์นี้มันจะไม่พิจารณาอาร์มสุดท้าย

ใจความหลักของข้อผิดพลาดระบุว่ามี_ชนิดที่ไม่ตรงกัน_ (mismatched types) Rust มีระบบชนิดข้อมูลแบบสแตติกที่เข้มงวด อย่างไรก็ตาม มันก็ยังมีการอนุมานชนิดข้อมูล (type inference) ด้วย เมื่อเราเขียน `let mut guess = String::new()` Rust สามารถอนุมานได้ว่า `guess` ควรเป็น `String` และไม่ได้บังคับให้เราเขียนชนิด ในทางกลับกัน `secret_number` เป็นชนิดตัวเลข ชนิดตัวเลขบางชนิดของ Rust สามารถมีค่าระหว่าง 1 ถึง 100 ได้ ได้แก่ `i32` ซึ่งเป็นตัวเลข 32 บิต; `u32` ซึ่งเป็นจำนวนเต็ม (integer) 32 บิตแบบไม่มีเครื่องหมาย; `i64` ซึ่งเป็นตัวเลข 64 บิต; รวมถึงชนิดอื่นๆ ด้วย หากไม่ระบุเป็นอย่างอื่น Rust จะใช้ `i32` เป็นค่าเริ่มต้น ซึ่งเป็นชนิดของ `secret_number` เว้นแต่คุณจะเพิ่มข้อมูลชนิดในที่อื่นที่ทำให้ Rust อนุมานชนิดตัวเลขที่แตกต่างออกไป สาเหตุของข้อผิดพลาดคือ Rust ไม่สามารถเปรียบเทียบสตริง (string) กับชนิดตัวเลขได้

ท้ายที่สุด เราต้องการแปลง `String` ที่โปรแกรมอ่านเป็นอินพุตให้เป็นชนิดตัวเลข เพื่อให้เราสามารถเปรียบเทียบมันกับตัวเลขลับในเชิงตัวเลขได้ เราทำเช่นนั้นโดยเพิ่มบรรทัดนี้ลงในบอดี้ (body) ของฟังก์ชัน (function) `main`:

บรรทัดนั้นคือ:

```rust,ignore
let guess: u32 = guess.trim().parse().expect("Please type a number!");
```

เราสร้างตัวแปร (variable) ชื่อ `guess` แต่เดี๋ยวก่อน โปรแกรมไม่ได้มีตัวแปรชื่อ `guess` อยู่แล้วหรือ? มีอยู่แล้ว แต่ด้วยความช่วยเหลือของ Rust เราสามารถบังเงาค่าก่อนหน้าของ `guess` ด้วยค่าใหม่ได้ _การบังเงา_ (shadowing) ช่วยให้เราใช้ชื่อตัวแปร `guess` ซ้ำได้ แทนที่จะบังคับให้เราสร้างตัวแปรที่ไม่ซ้ำกันสองตัว เช่น `guess_str` และ `guess` เป็นต้น เราจะกล่าวถึงเรื่องนี้ในรายละเอียดเพิ่มเติมใน[บทที่ 3][shadowing]<!-- ignore --> แต่สำหรับตอนนี้ ขอให้รู้ว่าฟีเจอร์นี้มักถูกใช้เมื่อคุณต้องการแปลงค่าจากชนิดหนึ่งไปยังอีกชนิดหนึ่ง

เราผูกตัวแปรใหม่นี้เข้ากับเอ็กซ์เพรสชัน `guess.trim().parse()` ตัว `guess` ในเอ็กซ์เพรสชันอ้างถึงตัวแปร `guess` ตัวเดิมที่บรรจุอินพุตไว้ในรูปสตริง เมธอด `trim` บนอินสแตนซ์ของ `String` จะตัดช่องว่างใดๆ ที่อยู่ตอนต้นและตอนท้ายออก ซึ่งเราจำเป็นต้องทำก่อนที่เราจะแปลงสตริงเป็น `u32` ซึ่งบรรจุได้เฉพาะข้อมูลตัวเลขเท่านั้น ผู้ใช้ต้องกด <kbd>enter</kbd> เพื่อให้ `read_line` ทำงานสำเร็จและป้อนคำทายของตนเอง ซึ่งจะเพิ่มอักขระขึ้นบรรทัดใหม่เข้าไปในสตริง ตัวอย่างเช่น หากผู้ใช้พิมพ์ <kbd>5</kbd> แล้วกด <kbd>enter</kbd> `guess` จะมีลักษณะเช่นนี้: `5\n` โดย `\n` แทน “การขึ้นบรรทัดใหม่” (บน Windows การกด <kbd>enter</kbd> จะให้ผลเป็น carriage return และ newline คือ `\r\n`) เมธอด `trim` จะตัด `\n` หรือ `\r\n` ออก เหลือเพียง `5`

เมธอด [`parse` บนสตริง][parse]<!-- ignore --> แปลงสตริงให้เป็นอีกชนิดหนึ่ง ในที่นี้ เราใช้มันเพื่อแปลงจากสตริงเป็นตัวเลข เราจำเป็นต้องบอก Rust ว่าต้องการชนิดตัวเลขใดอย่างแน่ชัด โดยใช้ `let guess: u32` เครื่องหมายโคลอน (`:`) หลัง `guess` บอก Rust ว่าเรากำลังจะระบุชนิดข้อมูล (type annotation) ให้กับตัวแปร Rust มีชนิดตัวเลขที่มีมาให้ในตัวอยู่ไม่กี่ชนิด โดย `u32` ที่เห็นในที่นี้เป็นจำนวนเต็ม 32 บิตแบบไม่มีเครื่องหมาย มันเป็นตัวเลือกเริ่มต้นที่ดีสำหรับตัวเลขบวกที่มีค่าน้อย คุณจะได้เรียนรู้เกี่ยวกับชนิดตัวเลขอื่นๆ ใน[บทที่ 3][integers]<!-- ignore -->

นอกจากนี้ การระบุ `u32` ในโปรแกรมตัวอย่างนี้และการเปรียบเทียบกับ `secret_number` ยังหมายความว่า Rust จะอนุมานว่า `secret_number` ควรเป็น `u32` เช่นกัน ดังนั้นตอนนี้การเปรียบเทียบจะเกิดขึ้นระหว่างค่าสองค่าที่มีชนิดเดียวกัน!

เมธอด `parse` ทำงานได้เฉพาะกับอักขระที่สามารถแปลงเป็นตัวเลขได้ตามหลักตรรกะเท่านั้น จึงทำให้เกิดข้อผิดพลาดได้ง่าย ตัวอย่างเช่น หากสตริงมี `A👍%` ก็จะไม่มีทางแปลงมันเป็นตัวเลขได้ เพราะมันอาจล้มเหลวได้ เมธอด `parse` จึงคืนค่าชนิด `Result` เช่นเดียวกับที่เมธอด `read_line` ทำ (ซึ่งกล่าวถึงก่อนหน้านี้ใน[“การจัดการกับความล้มเหลวที่อาจเกิดขึ้นด้วย `Result`”](#handling-potential-failure-with-result)<!-- ignore -->) เราจะจัดการ `Result` นี้ในลักษณะเดียวกันโดยใช้เมธอด `expect` อีกครั้ง หาก `parse` คืนค่า `Result` วาเรียนต์ `Err` เพราะไม่สามารถสร้างตัวเลขจากสตริงได้ การเรียก `expect` จะทำให้เกมแครชและพิมพ์ข้อความที่เราให้ไว้ หาก `parse` สามารถแปลงสตริงเป็นตัวเลขได้สำเร็จ มันจะคืนวาเรียนต์ `Ok` ของ `Result` และ `expect` จะคืนตัวเลขที่เราต้องการจากค่า `Ok` นั้น

เราเปลี่ยนจากการเรียก `expect` มาเป็นเอ็กซ์เพรสชัน `match` เพื่อเปลี่ยนจากการแครชเมื่อเกิดข้อผิดพลาดไปเป็นการจัดการข้อผิดพลาด จำไว้ว่า `parse` คืนค่าชนิด `Result` และ `Result` เป็น enum ที่มีวาเรียนต์ `Ok` และ `Err` เรากำลังใช้เอ็กซ์เพรสชัน `match` ในที่นี้ เช่นเดียวกับที่เราทำกับผลลัพธ์ `Ordering` ของเมธอด `cmp`

หาก `parse` สามารถเปลี่ยนสตริงเป็นตัวเลขได้สำเร็จ มันจะคืนค่า `Ok` ที่บรรจุตัวเลขที่เป็นผลลัพธ์ ค่า `Ok` นั้นจะตรงกับแพตเทิร์นของอาร์มแรก และเอ็กซ์เพรสชัน `match` จะคืนค่า `num` ที่ `parse` สร้างขึ้นและใส่ไว้ในค่า `Ok` ตัวเลขนั้นจะไปลงเอยในตำแหน่งที่เราต้องการพอดีในตัวแปร `guess` ตัวใหม่ที่เรากำลังสร้าง

หาก `parse` _ไม่_ สามารถเปลี่ยนสตริงเป็นตัวเลขได้ มันจะคืนค่า `Err` ที่บรรจุข้อมูลเพิ่มเติมเกี่ยวกับข้อผิดพลาด ค่า `Err` ไม่ตรงกับแพตเทิร์น `Ok(num)` ในอาร์มแรกของ `match` แต่ตรงกับแพตเทิร์น `Err(_)` ในอาร์มที่สอง เครื่องหมายขีดล่าง `_` เป็นค่าที่จับคู่ได้กับทุกกรณี ในตัวอย่างนี้ เรากำลังบอกว่าเราต้องการจับคู่ค่า `Err` ทั้งหมด ไม่ว่ามันจะมีข้อมูลอะไรอยู่ข้างในก็ตาม ดังนั้น โปรแกรมจะรันโค้ดของอาร์มที่สองคือ `continue` ซึ่งสั่งให้โปรแกรมไปยังการวนซ้ำ (iteration) ครั้งถัดไปของ `loop` และขอให้ทายใหม่ ดังนั้นในทางปฏิบัติแล้ว โปรแกรมจะเพิกเฉยต่อข้อผิดพลาดทั้งหมดที่ `parse` อาจพบเจอ!

## สรุป

โปรเจกต์นี้เป็นวิธีแบบลงมือปฏิบัติเพื่อแนะนำแนวคิดใหม่ๆ มากมายของ Rust ให้คุณรู้จัก ได้แก่ `let`, `match`, ฟังก์ชัน การใช้เครต (crate) ภายนอก และอื่นๆ อีกมาก ในอีกไม่กี่บทถัดไป คุณจะได้เรียนรู้แนวคิดเหล่านี้ในรายละเอียดเพิ่มเติม บทที่ 3 ครอบคลุมแนวคิดที่ภาษาโปรแกรมส่วนใหญ่มี เช่น ตัวแปร ชนิดข้อมูล (data type) และฟังก์ชัน พร้อมทั้งแสดงวิธีใช้แนวคิดเหล่านี้ใน Rust บทที่ 4 สำรวจความเป็นเจ้าของ (ownership) ซึ่งเป็นฟีเจอร์ที่ทำให้ Rust แตกต่างจากภาษาอื่น บทที่ 5 อภิปรายเรื่อง struct และวากยสัมพันธ์ของเมธอด และบทที่ 6 อธิบายว่า enum ทำงานอย่างไร
