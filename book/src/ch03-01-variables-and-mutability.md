## ตัวแปรและความสามารถในการเปลี่ยนแปลงค่า

ดังที่กล่าวไว้ในหัวข้อ[“การเก็บค่าด้วยตัวแปร”][storing-values-with-variables]<!-- ignore --> ตัวแปรต่างๆ จะเป็นแบบเปลี่ยนแปลงไม่ได้ (immutable) โดยค่าเริ่มต้น นี่เป็นหนึ่งในหลายๆ การกระตุ้นเตือนของ Rust ที่ช่วยให้คุณเขียนโค้ดในลักษณะที่ใช้ประโยชน์จากความปลอดภัยและการทำงานพร้อมกันที่ง่ายดายซึ่ง Rust มอบให้ อย่างไรก็ตาม คุณยังมีตัวเลือกในการทำให้ตัวแปรของคุณเปลี่ยนแปลงได้ (mutable) มาสำรวจกันว่า Rust สนับสนุนให้คุณเลือกใช้ความเปลี่ยนแปลงไม่ได้อย่างไรและเพราะเหตุใด และทำไมบางครั้งคุณอาจอยากเลือกที่จะไม่ทำตาม

เมื่อตัวแปรเป็นแบบเปลี่ยนแปลงไม่ได้ เมื่อผูกค่าเข้ากับชื่อแล้ว คุณจะไม่สามารถเปลี่ยนค่านั้นได้ เพื่อสาธิตเรื่องนี้ ให้สร้างโปรเจกต์ใหม่ชื่อ _variables_ ในไดเรกทอรี _projects_ ของคุณโดยใช้ `cargo new variables`

จากนั้น ในไดเรกทอรี _variables_ ใหม่ของคุณ ให้เปิด _src/main.rs_ และแทนที่โค้ดของมันด้วยโค้ดต่อไปนี้ ซึ่งยังไม่คอมไพล์ผ่านในตอนนี้

<span class="filename">ชื่อไฟล์: src/main.rs</span>

```rust,ignore,does_not_compile
{{#rustdoc_include ../listings/ch03-common-programming-concepts/no-listing-01-variables-are-immutable/src/main.rs}}
```

บันทึกและรันโปรแกรมโดยใช้ `cargo run` คุณควรได้รับข้อความแสดงข้อผิดพลาดเกี่ยวกับข้อผิดพลาดด้านความเปลี่ยนแปลงไม่ได้ ดังที่แสดงในเอาต์พุตนี้:

```console
{{#include ../listings/ch03-common-programming-concepts/no-listing-01-variables-are-immutable/output.txt}}
```

ตัวอย่างนี้แสดงให้เห็นว่าคอมไพเลอร์ช่วยคุณหาข้อผิดพลาดในโปรแกรมของคุณได้อย่างไร ข้อผิดพลาดจากคอมไพเลอร์อาจทำให้หงุดหงิดได้ แต่จริงๆ แล้วมันเพียงหมายความว่าโปรแกรมของคุณยังไม่ได้ทำสิ่งที่คุณต้องการอย่างปลอดภัยเท่านั้น ไม่ได้หมายความว่าคุณเป็นโปรแกรมเมอร์ที่แย่! ชาว Rustacean ที่มีประสบการณ์ก็ยังได้รับข้อผิดพลาดจากคอมไพเลอร์อยู่ดี

คุณได้รับข้อความแสดงข้อผิดพลาด `` cannot assign twice to immutable variable `x` `` เนื่องจากคุณพยายามกำหนดค่าให้กับตัวแปร `x` ที่เปลี่ยนแปลงไม่ได้เป็นครั้งที่สอง

สิ่งสำคัญคือเราจะได้รับข้อผิดพลาดตั้งแต่ตอนคอมไพล์เมื่อเราพยายามเปลี่ยนค่าที่ถูกกำหนดไว้ให้เปลี่ยนแปลงไม่ได้ เพราะสถานการณ์เช่นนี้สามารถนำไปสู่บั๊กได้ หากโค้ดส่วนหนึ่งของเราทำงานบนสมมติฐานว่าค่าหนึ่งจะไม่มีวันเปลี่ยนแปลง แต่โค้ดอีกส่วนหนึ่งของเราเปลี่ยนค่านั้น เป็นไปได้ว่าโค้ดส่วนแรกจะไม่ทำงานอย่างที่มันถูกออกแบบไว้ สาเหตุของบั๊กประเภทนี้เป็นเรื่องยากที่จะตามหาหลังเกิดเหตุ โดยเฉพาะเมื่อโค้ดส่วนหลังเปลี่ยนค่าเพียง_บางครั้ง_เท่านั้น คอมไพเลอร์ Rust รับประกันว่าเมื่อคุณระบุว่าค่าหนึ่งจะไม่เปลี่ยนแปลง มันจะไม่เปลี่ยนแปลงจริงๆ คุณจึงไม่ต้องคอยติดตามมันเอง โค้ดของคุณจึงเข้าใจได้ง่ายขึ้น

แต่ความสามารถในการเปลี่ยนแปลงค่า (mutability) ก็มีประโยชน์มากและทำให้เขียนโค้ดได้สะดวกขึ้น แม้ว่าตัวแปรจะเป็นแบบเปลี่ยนแปลงไม่ได้โดยค่าเริ่มต้น คุณสามารถทำให้มันเปลี่ยนแปลงได้โดยเติม `mut` ไว้หน้าชื่อตัวแปรอย่างที่คุณทำใน[บทที่ 2][storing-values-with-variables]<!-- ignore --> การเติม `mut` ยังสื่อเจตนาไปยังผู้อ่านโค้ดในอนาคต โดยบ่งชี้ว่าโค้ดส่วนอื่นๆ จะเปลี่ยนค่าของตัวแปรนี้

```rust

```

### การประกาศค่าคงที่

เช่นเดียวกับตัวแปรที่เปลี่ยนแปลงไม่ได้ _ค่าคงที่_ (constant) คือค่าที่ผูกกับชื่อและไม่ได้รับอนุญาตให้เปลี่ยนแปลง แต่มีความแตกต่างเล็กน้อยระหว่างค่าคงที่กับตัวแปร

ประการแรก คุณไม่ได้รับอนุญาตให้ใช้ `mut` กับค่าคงที่ ค่าคงที่ไม่ได้เป็นเพียงแบบเปลี่ยนแปลงไม่ได้โดยค่าเริ่มต้นเท่านั้น แต่เป็นแบบเปลี่ยนแปลงไม่ได้เสมอ คุณประกาศค่าคงที่โดยใช้คำสงวน `const` แทนคำสงวน `let` และชนิดของค่า_ต้อง_ถูกระบุ เราจะกล่าวถึงชนิดข้อมูล (data type) และการระบุชนิดข้อมูล (type annotation) ในหัวข้อถัดไป [“ชนิดข้อมูล”][data-types]<!-- ignore --> ดังนั้นไม่ต้องกังวลกับรายละเอียดตอนนี้ เพียงแค่รู้ว่าคุณต้องระบุชนิดเสมอ

ค่าคงที่สามารถประกาศได้ในสโคป (scope) ใดก็ได้ รวมถึงสโคปโกลบอล ซึ่งทำให้มันมีประโยชน์สำหรับค่าที่โค้ดหลายส่วนจำเป็นต้องรู้

ความแตกต่างข้อสุดท้ายคือ ค่าคงที่สามารถถูกกำหนดให้เป็นได้เพียงเอ็กซ์เพรสชันค่าคงที่ (constant expression) เท่านั้น ไม่ใช่ผลลัพธ์ของค่าที่คำนวณได้เฉพาะตอนรันไทม์ (runtime)

นี่คือตัวอย่างการประกาศค่าคงที่:

```rust
const THREE_HOURS_IN_SECONDS: u32 = 60 * 60 * 3;
```

ชื่อของค่าคงที่คือ `THREE_HOURS_IN_SECONDS` และค่าของมันถูกกำหนดเป็นผลลัพธ์ของการคูณ 60 (จำนวนวินาทีในหนึ่งนาที) ด้วย 60 (จำนวนนาทีในหนึ่งชั่วโมง) ด้วย 3 (จำนวนชั่วโมงที่เราต้องการนับในโปรแกรมนี้) ธรรมเนียมการตั้งชื่อค่าคงที่ของ Rust คือใช้ตัวพิมพ์ใหญ่ทั้งหมดโดยมีขีดล่างคั่นระหว่างคำ คอมไพเลอร์สามารถประเมินการดำเนินการได้จำนวนจำกัดตอนคอมไพล์ ซึ่งทำให้เราเลือกเขียนค่านี้ออกมาในแบบที่เข้าใจและตรวจสอบได้ง่ายกว่า แทนที่จะกำหนดค่าคงที่นี้เป็นค่า 10,800 ดู[หัวข้อเกี่ยวกับการประเมินค่าคงที่ใน Rust Reference][const-eval] สำหรับข้อมูลเพิ่มเติมเกี่ยวกับการดำเนินการใดบ้างที่ใช้ได้เมื่อประกาศค่าคงที่

ค่าคงที่มีผลใช้ได้ตลอดเวลาที่โปรแกรมรัน ภายในสโคปที่มันถูกประกาศ คุณสมบัตินี้ทำให้ค่าคงที่มีประโยชน์สำหรับค่าในโดเมนของแอปพลิเคชันของคุณที่โปรแกรมหลายส่วนอาจจำเป็นต้องรู้ เช่น จำนวนคะแนนสูงสุดที่ผู้เล่นเกมคนใดก็ตามได้รับอนุญาตให้ทำได้ หรือความเร็วแสง

การตั้งชื่อค่าที่ฝังตายตัว (hardcoded) ซึ่งใช้ทั่วโปรแกรมของคุณให้เป็นค่าคงที่นั้นมีประโยชน์ในการสื่อความหมายของค่านั้นไปยังผู้ดูแลโค้ดในอนาคต มันยังช่วยให้คุณมีตำแหน่งเดียวในโค้ดที่ต้องแก้ไข หากค่าที่ฝังตายตัวนั้นจำเป็นต้องอัปเดตในอนาคต

### การบังเงา

อย่างที่คุณเห็นในบทเรียนเกมทายตัวเลขใน[บทที่ 2][comparing-the-guess-to-the-secret-number]<!-- ignore --> คุณสามารถประกาศตัวแปรใหม่ที่มีชื่อเดียวกันกับตัวแปรก่อนหน้าได้ ชาว Rustacean กล่าวว่าตัวแปรแรก_ถูกบังเงา_ (shadowed) โดยตัวแปรที่สอง ซึ่งหมายความว่าตัวแปรที่สองคือสิ่งที่คอมไพเลอร์จะเห็นเมื่อคุณใช้ชื่อของตัวแปรนี้ ในทางปฏิบัติ ตัวแปรที่สองบดบังตัวแปรแรก โดยรับการใช้ชื่อตัวแปรทั้งหมดมาเป็นของตัวเอง จนกว่ามันเองจะถูกบังเงาหรือสโคปสิ้นสุดลง เราสามารถบังเงาตัวแปรได้โดยใช้ชื่อตัวแปรเดิมและใช้คำสงวน `let` ซ้ำดังนี้:
