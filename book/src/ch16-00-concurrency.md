# การทำงานพร้อมกันอย่างไร้ความกลัว

การจัดการกับการเขียนโปรแกรมแบบทำงานพร้อมกันอย่างปลอดภัยและมีประสิทธิภาพเป็นอีกหนึ่งเป้าหมายสำคัญของ Rust _การเขียนโปรแกรมแบบทำงานพร้อมกัน_ (concurrent programming) ซึ่งส่วนต่างๆ ของโปรแกรมทำงานอย่างเป็นอิสระต่อกัน และ_การเขียนโปรแกรมแบบขนาน_ (parallel programming) ซึ่งส่วนต่างๆ ของโปรแกรมทำงานในเวลาเดียวกัน กำลังทวีความสำคัญมากขึ้นเรื่อยๆ เนื่องจากคอมพิวเตอร์ในปัจจุบันใช้ประโยชน์จากหน่วยประมวลผลหลายตัว (multiple processors) มากขึ้น ในอดีต การเขียนโปรแกรมในบริบทเหล่านี้มักจะทำได้ยากและเกิดข้อผิดพลาดได้ง่าย Rust จึงมุ่งหวังที่จะเปลี่ยนแปลงสิ่งนั้น

ในตอนแรก ทีมงานของ Rust คิดว่าการรับประกันความปลอดภัยของหน่วยความจำและการป้องกันปัญหาจากการทำงานพร้อมกันเป็นความท้าทายสองเรื่องที่แยกจากกันและต้องแก้ด้วยวิธีที่ต่างกัน แต่เมื่อเวลาผ่านไป ทีมงานกลับพบว่าระบบความเป็นเจ้าของ (ownership) และระบบชนิดข้อมูล (type system) นั้นเป็นชุดเครื่องมืออันทรงพลังที่ช่วยจัดการทั้งความปลอดภัยของหน่วยความจำ_และ_ปัญหาจากการทำงานพร้อมกันไปพร้อมกันได้! ด้วยการใช้ประโยชน์จากระบบความเป็นเจ้าของและการตรวจสอบชนิดข้อมูล ข้อผิดพลาดจากการทำงานพร้อมกันหลายอย่างจึงกลายเป็นข้อผิดพลาดตั้งแต่ตอนคอมไพล์ (compile-time error) แทนที่จะหลุดไปเป็นข้อผิดพลาดตอนรันไทม์ (runtime error) ดังนั้น แทนที่จะต้องเสียเวลามากมายไปกับการพยายามจำลองสถานการณ์เพื่อหาสาเหตุของบั๊กจากการทำงานพร้อมกันที่เกิดขึ้นตอนรันไทม์ โค้ดที่ไม่ถูกต้องจะไม่สามารถคอมไพล์ผ่านได้เลย พร้อมทั้งแจ้งข้อผิดพลาดที่อธิบายปัญหาออกมาอย่างชัดเจน ส่งผลให้คุณสามารถแก้ไขโค้ดได้ทันทีในระหว่างพัฒนา แทนที่จะต้องมารอแก้หลังจากนำขึ้นใช้งานจริงบนระบบโปรดักชันแล้ว เราจึงเรียกแง่มุมนี้ของ Rust ว่า_การทำงานพร้อมกันอย่างไร้ความกลัว_ (fearless concurrency) ซึ่งช่วยให้คุณเขียนโค้ดที่ปราศจากบั๊กที่ซ่อนเร้น และสามารถรีแฟกเตอร์โค้ดได้อย่างง่ายดายโดยไม่เผลอสร้างบั๊กใหม่ขึ้นมา

> หมายเหตุ: เพื่อความกระชับและเข้าใจง่าย เราจะเรียกปัญหาเหล่านี้โดยรวมว่า_การทำงานพร้อมกัน_ (concurrent) แทนที่จะต้องระบุอย่างละเอียดทุกครั้งว่าเป็น_การทำงานพร้อมกันและ/หรือการประมวลผลแบบขนาน_ (concurrent and/or parallel) ดังนั้นสำหรับในบทนี้ ขอให้คุณทำความเข้าใจในใจว่าหมายถึง_การทำงานพร้อมกันและ/หรือการประมวลผลแบบขนาน_ ทุกครั้งที่เราใช้คำว่า_การทำงานพร้อมกัน_ ส่วนในบทถัดไปซึ่งความแตกต่างระหว่างสองคำนี้มีความสำคัญมากขึ้น เราจะระบุให้เจาะจงยิ่งขึ้น

หลายภาษาโปรแกรมมีแนวทางที่ยึดติดหรือจำกัดวิธีแก้ปัญหาสำหรับการจัดการกับการทำงานพร้อมกัน ตัวอย่างเช่น ภาษา Erlang มีฟังก์ชันการทำงานที่ยอดเยี่ยมสำหรับการทำงานพร้อมกันแบบส่งผ่านข้อความ (message-passing) แต่กลับมีเพียงวิธีที่ยุ่งยากและคลุมเครือในการแชร์สถานะระหว่างเธรด (threads) การสนับสนุนเพียงแค่บางส่วนของแนวทางแก้ปัญหาที่เป็นไปได้นั้นถือเป็นกลยุทธ์ที่สมเหตุสมผลสำหรับภาษาระดับสูง (higher-level languages) เพราะภาษาระดับสูงเน้นการยอมสละการควบคุมบางอย่างเพื่อแลกกับเลเยอร์นามธรรม (abstraction) ที่สะดวกสบายกว่า อย่างไรก็ตาม ภาษาในระดับล่างกว่า (lower-level languages) มักถูกคาดหวังว่าจะต้องมอบแนวทางแก้ปัญหาที่มีประสิทธิภาพสูงสุดในทุกสถานการณ์ และมีเลเยอร์นามธรรมครอบฮาร์ดแวร์ให้น้อยที่สุด ด้วยเหตุนี้ Rust จึงมีเครื่องมือที่หลากหลายให้เลือกใช้ในการจำลองและแก้ปัญหาตามความเหมาะสมกับสถานการณ์และความต้องการของคุณ

นี่คือหัวข้อต่างๆ ที่เราจะครอบคลุมในบทนี้:

- วิธีสร้างเธรดเพื่อรันโค้ดหลายส่วนในเวลาเดียวกัน
- การทำงานพร้อมกันแบบ_ส่งผ่านข้อความ_ (message passing) โดยให้แชนเนล (channels) ส่งข้อความระหว่างเธรด
- การทำงานพร้อมกันแบบ_ใช้สถานะร่วมกัน_ (shared state) โดยให้หลายเธรดสามารถเข้าถึงข้อมูลชิ้นเดียวกันได้
- เทรต `Sync` และ `Send` ซึ่งขยายการรับประกันด้านการทำงานพร้อมกันของ Rust ไปยังชนิดข้อมูลที่ผู้ใช้กำหนดขึ้นเอง รวมถึงชนิดข้อมูลที่ไลบรารีมาตรฐานจัดเตรียมไว้
