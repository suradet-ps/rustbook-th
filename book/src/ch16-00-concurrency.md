# การทำงานพร้อมกันอย่างไร้ความกลัว

การจัดการกับการเขียนโปรแกรมแบบทำงานพร้อมกันอย่างปลอดภัยและมีประสิทธิภาพเป็นอีกหนึ่งเป้าหมายสำคัญของ Rust _การเขียนโปรแกรมแบบทำงานพร้อมกัน_ (concurrent programming) ซึ่งส่วนต่างๆ ของโปรแกรมทำงานอย่างเป็นอิสระต่อกัน และ_การเขียนโปรแกรมแบบทำงานขนาน_ (parallel programming) ซึ่งส่วนต่างๆ ของโปรแกรมทำงานในเวลาเดียวกัน กำลังมีความสำคัญมากขึ้นเรื่อยๆ เมื่อคอมพิวเตอร์จำนวนมากขึ้นใช้ประโยชน์จากโปรเซสเซอร์หลายตัวของมัน ในอดีต การเขียนโปรแกรมในบริบทเหล่านี้เป็นเรื่องยากและเกิดข้อผิดพลาดได้ง่าย Rust หวังที่จะเปลี่ยนแปลงสิ่งนั้น

ในตอนแรก ทีม Rust คิดว่าการรับประกันความปลอดภัยของหน่วยความจำและการป้องกันปัญหาจากการทำงานพร้อมกันเป็นความท้าทายสองอย่างที่แยกจากกันซึ่งต้องแก้ไขด้วยวิธีที่แตกต่างกัน เมื่อเวลาผ่านไป ทีมได้ค้นพบว่าระบบความเป็นเจ้าของและระบบชนิดข้อมูลเป็นชุดเครื่องมืออันทรงพลังที่ช่วยจัดการความปลอดภัยของหน่วยความจำ_และ_ปัญหาจากการทำงานพร้อมกัน! ด้วยการใช้ประโยชน์จากความเป็นเจ้าของและการตรวจสอบชนิดข้อมูล ข้อผิดพลาดจากการทำงานพร้อมกันหลายอย่างจึงกลายเป็นข้อผิดพลาดตอนคอมไพล์ใน Rust แทนที่จะเป็นข้อผิดพลาดตอนรันไทม์ ดังนั้น แทนที่จะทำให้คุณต้องเสียเวลามหาศาลไปกับการพยายามจำลองสถานการณ์ที่แน่ชัดซึ่งบั๊กจากการทำงานพร้อมกันตอนรันไทม์เกิดขึ้น โค้ดที่ไม่ถูกต้องจะปฏิเสธที่จะคอมไพล์และแสดงข้อผิดพลาดที่อธิบายปัญหาได้ ผลก็คือ คุณสามารถแก้ไขโค้ดของคุณได้ขณะที่คุณกำลังทำงานกับมัน แทนที่จะต้องแก้หลังจากที่มันถูกส่งขึ้นโปรดักชันไปแล้ว เราได้ตั้งชื่อเล่นให้แง่มุมนี้ของ Rust ว่า_การทำงานพร้อมกันอย่างไร้ความกลัว_ (fearless concurrency) การทำงานพร้อมกันอย่างไร้ความกลัวช่วยให้คุณเขียนโค้ดที่ปราศจากบั๊กที่หาเจอยากและรีแฟกเตอร์ได้ง่ายโดยไม่ก่อให้เกิดบั๊กใหม่

> หมายเหตุ: เพื่อความเรียบง่าย เราจะเรียกปัญหาหลายอย่างว่า_การทำงานพร้อมกัน_ แทนที่จะ
> ระบุให้แม่นยำกว่านี้ว่า_การทำงานพร้อมกันและ/หรือการทำงานขนาน_ สำหรับบทนี้ โปรดแทนที่
> _การทำงานพร้อมกันและ/หรือการทำงานขนาน_ในใจของคุณทุกครั้งที่เราใช้_การทำงานพร้อมกัน_
> ในบทถัดไป ซึ่งความแตกต่างนี้สำคัญมากกว่า เราจะระบุให้เฉพาะเจาะจงมากขึ้น

หลายภาษามีจุดยืนที่ตายตัวเกี่ยวกับวิธีแก้ที่มันเสนอสำหรับจัดการปัญหาจากการทำงานพร้อมกัน ตัวอย่างเช่น Erlang มีฟังก์ชันการทำงานอันสง่างามสำหรับการทำงานพร้อมกันแบบส่งผ่านข้อความ แต่มีเพียงวิธีที่คลุมเครือในการแชร์สถานะระหว่างเธรด (thread) การสนับสนุนเพียงชุดย่อยของวิธีแก้ที่เป็นไปได้เป็นกลยุทธ์ที่สมเหตุสมผลสำหรับภาษาในระดับสูง เพราะภาษาในระดับสูงสัญญาว่าจะให้ประโยชน์จากการยอมสละการควบคุมบางส่วนเพื่อแลกกับนามธรรม อย่างไรก็ตาม ภาษาในระดับต่ำกว่าถูกคาดหวังว่าจะจัดเตรียมวิธีแก้ที่มีประสิทธิภาพดีที่สุดในทุกสถานการณ์และมีนามธรรมที่ห่อหุ้มฮาร์ดแวร์น้อยกว่า ดังนั้น Rust จึงเสนอเครื่องมือหลากหลายสำหรับจำลองปัญหาในวิธีที่เหมาะสมกับสถานการณ์และความต้องการของคุณ

นี่คือหัวข้อต่างๆ ที่เราจะครอบคลุมในบทนี้:

- วิธีสร้างเธรดเพื่อรันโค้ดหลายส่วนในเวลาเดียวกัน
- การทำงานพร้อมกันแบบ_ส่งผ่านข้อความ_ (message passing) โดยที่แชนเนล (channel) ส่งข้อความระหว่างเธรด
- การทำงานพร้อมกันแบบ_ใช้สถานะร่วมกัน_ (shared state) โดยที่หลายเธรดเข้าถึงข้อมูลชิ้นหนึ่งได้
- เทรต (trait) `Sync` และ `Send` ซึ่งขยายการรับประกันด้านการทำงานพร้อมกันของ Rust ไปยังชนิดข้อมูลที่ผู้ใช้กำหนดเองและชนิดข้อมูลที่ไลบรารีมาตรฐานจัดเตรียมไว้ด้วย
