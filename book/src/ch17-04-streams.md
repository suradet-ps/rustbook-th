## สตรีม: ฟิวเจอร์ที่เรียงต่อกันเป็นลำดับ

ย้อนนึกถึงวิธีที่เราใช้ตัวรับของแชนเนลแบบ async ไปก่อนหน้านี้ในบทนี้ที่หัวข้อ[“การส่งผ่านข้อความ”][17-02-messages]<!-- ignore --> เมธอด `recv` แบบ async จะให้ลำดับของรายการข้อมูลออกมาตามช่วงเวลา ซึ่งนี่เป็นตัวอย่างหนึ่งของรูปแบบการทำงานที่กว้างกว่ามากที่เรียกว่า_สตรีม_ (stream) แนวคิดหลายอย่างสามารถแสดงออกมาในรูปของสตรีมได้อย่างเป็นธรรมชาติ เช่น ข้อมูลที่ทยอยพร้อมใช้งานในคิว, ชิ้นส่วนข้อมูลที่ค่อยๆ ถูกดึงมาจากระบบไฟล์เมื่อชุดข้อมูลทั้งหมดมีขนาดใหญ่เกินกว่าจะเก็บไว้ในหน่วยความจำของคอมพิวเตอร์ได้ทั้งหมด, หรือข้อมูลที่ทยอยส่งมาผ่านเครือข่ายตามลำดับเวลา และเนื่องจากสตรีมก็คือฟิวเจอร์ชนิดหนึ่ง เราจึงสามารถใช้สตรีมร่วมกับฟิวเจอร์ชนิดอื่นๆ และนำมารวมเข้าด้วยกันในวิธีที่น่าสนใจได้ ตัวอย่างเช่น เราสามารถรวมอีเวนต์เป็นชุด (batch) เพื่อหลีกเลี่ยงการส่งคำขอผ่านเครือข่ายบ่อยเกินไป, ตั้งไทม์เอาต์ให้กับลำดับของการทำงานที่ใช้เวลานาน, หรือจำกัดอัตราการเกิดอีเวนต์บนหน้าจอผู้ใช้ (throttle) เพื่อหลีกเลี่ยงการประมวลผลที่ไม่จำเป็น

เราเคยเห็นลำดับของข้อมูลกันไปแล้วในบทที่ 13 เมื่อเราศึกษาเทรต `Iterator` ในหัวข้อ[“เทรต `Iterator` และเมธอด `next`”][iterator-trait]<!--
ignore --> แต่มีความแตกต่างอยู่สองประการระหว่างอิเทอเรเตอร์ (iterator) กับตัวรับของแชนเนลแบบ async ประการแรกคือเรื่องของเวลา: อิเทอเรเตอร์เป็นแบบซิงโครนัส ในขณะที่ตัวรับของแชนเนลเป็นแบบอะซิงโครนัส ประการที่สองคือ API: เมื่อทำงานกับ `Iterator` โดยตรง เราจะเรียกเมธอด `next` แบบซิงโครนัสของมัน แต่สำหรับสตรีมของ `trpl::Receiver` เราเรียกเมธอด `recv` ซึ่งเป็นแบบอะซิงโครนัสแทน นอกเหนือจากนั้นแล้ว API ทั้งสองแบบให้ความรู้สึกที่คล้ายกันมาก และความคล้ายคลึงนั้นก็ไม่ใช่เรื่องบังเอิญ สตรีมเปรียบเสมือนรูปแบบอะซิงโครนัสของการวนซ้ำ (iteration) อย่างไรก็ตาม ในขณะที่ `trpl::Receiver` เจาะจงเฉพาะการรอรับข้อความ แต่ API ของสตรีมสำหรับใช้งานทั่วไปนั้นครอบคลุมกว้างกว่ามาก: มันจะจัดเตรียมข้อมูลตัวถัดไปเหมือนกับที่ `Iterator` ทำ แต่ทำในแบบอะซิงโครนัส

ความคล้ายคลึงกันระหว่างอิเทอเรเตอร์กับสตรีมใน Rust ทำให้เราสามารถสร้างสตรีมขึ้นมาจากอิเทอเรเตอร์ใดๆ ก็ได้ เช่นเดียวกับอิเทอเรเตอร์ เราสามารถทำงานกับสตรีมได้โดยการเรียกเมธอด `next` ของมันแล้ว await เพื่อรอรับเอาต์พุต ดังแสดงในลิสติ้ง 17-21 ซึ่งในตอนนี้จะยังคอมไพล์ไม่ผ่าน

ดังที่เอาต์พุตนี้ได้อธิบายไว้ สาเหตุของข้อผิดพลาดจากคอมไพเลอร์ก็คือ เราจำเป็นต้องมีเทรตที่ถูกต้องอยู่ในสโคป (scope) เพื่อให้สามารถใช้เมธอด `next` ได้ จากสิ่งที่เราพูดคุยกันมา คุณอาจคาดหวังว่าเทรตดังกล่าวน่าจะเป็น `Stream` แต่ในความเป็นจริงแล้วมันคือ `StreamExt` คำว่า `Ext` นั้นย่อมาจาก _extension_ (ส่วนขยาย) ซึ่งเป็นแพตเทิร์นที่พบได้ทั่วไปในชุมชน Rust สำหรับใช้ขยายขีดความสามารถของเทรตหนึ่งด้วยอีกเทรตหนึ่ง

เทรต `Stream` นิยามอินเทอร์เฟซระดับต่ำที่รวมเทรต `Iterator` และ `Future` เข้าด้วยกันอย่างลงตัว ส่วน `StreamExt` จะเตรียมชุด API ระดับสูงกว่าไว้บนพื้นฐานของ `Stream` ซึ่งรวมถึงเมธอด `next` ตลอดจนเมธอดอรรถประโยชน์อื่นๆ ที่คล้ายกับเมธอดที่เทรต `Iterator` มีให้ ปัจจุบัน `Stream` และ `StreamExt` ยังไม่ได้เป็นส่วนหนึ่งของไลบรารีมาตรฐานของ Rust แต่เครตส่วนใหญ่ในระบบนิเวศต่างก็นิยามและใช้งานในรูปแบบที่คล้ายคลึงกันนี้
