## สตรีม: ฟิวเจอร์ที่เรียงต่อกันเป็นลำดับ

ย้อนนึกว่าเราใช้ตัวรับของแชนเนล (channel) แบบ async ของเรากันอย่างไรตอนต้นบทนี้ในหัวข้อ[“การส่งผ่านข้อความ”][17-02-messages]<!-- ignore --> เมธอด `recv` แบบ async สร้างลำดับของรายการเมื่อเวลาผ่านไป นี่เป็นตัวอย่างของแพตเทิร์นทั่วไปกว่ามากที่รู้จักกันในชื่อ_สตรีม_ (stream) แนวคิดมากมายถูกแทนได้อย่างเป็นธรรมชาติในรูปของสตรีม: รายการที่ทยอยพร้อมใช้งานในคิว, ข้อมูลทีละส่วนที่ถูกดึงจากระบบไฟล์แบบเพิ่มขึ้นทีละน้อยเมื่อชุดข้อมูลทั้งหมดใหญ่เกินกว่าหน่วยความจำของคอมพิวเตอร์, หรือข้อมูลที่มาถึงผ่านเครือข่ายเมื่อเวลาผ่านไป เพราะสตรีมเป็นฟิวเจอร์ (future) เราจึงใช้มันกับฟิวเจอร์ชนิดอื่นใดก็ได้และรวมมันเข้าด้วยกันในวิธีที่น่าสนใจ ตัวอย่างเช่น เราสามารถรวบรวมอีเวนต์เป็นชุดเพื่อหลีกเลี่ยงการเรียกเครือข่ายมากเกินไป ตั้งไทม์เอาต์ให้กับลำดับของการดำเนินการที่ใช้เวลานาน หรือจำกัดอัตราเหตุการณ์ของส่วนติดต่อผู้ใช้เพื่อหลีกเลี่ยงการทำงานที่ไม่จำเป็น

เราได้เห็นลำดับของรายการไปแล้วในบทที่ 13 เมื่อเราดูเทรต (trait) Iterator ในหัวข้อ[“เทรต `Iterator` และเมธอด `next`”][iterator-trait]<!--
ignore --> แต่มีความแตกต่างสองประการระหว่างอิเทอเรเตอร์ (iterator) กับตัวรับของแชนเนลแบบ async ความแตกต่างประการแรกคือเวลา: อิเทอเรเตอร์เป็นแบบซิงโครนัส ขณะที่ตัวรับของแชนเนลเป็นแบบอะซิงโครนัส (asynchronous) ความแตกต่างประการที่สองคือ API เมื่อทำงานกับ `Iterator` โดยตรง เราเรียกเมธอด `next` แบบซิงโครนัสของมัน แต่กับสตรีม `trpl::Receiver` โดยเฉพาะ เราเรียกเมธอด `recv` แบบอะซิงโครนัสแทน นอกจากนั้น API เหล่านี้ให้ความรู้สึกคล้ายกันมาก และความคล้ายกันนั้นไม่ใช่เรื่องบังเอิญ สตรีมก็เหมือนรูปแบบหนึ่งของการวนซ้ำแบบอะซิงโครนัส อย่างไรก็ตาม ในขณะที่ `trpl::Receiver` รอรับข้อความโดยเฉพาะ แต่ API ของสตรีมแบบเอนกประสงค์นั้นกว้างกว่ามาก: มันจัดเตรียมรายการถัดไปเหมือนที่ `Iterator` ทำ แต่เป็นแบบอะซิงโครนัส

ความคล้ายกันระหว่างอิเทอเรเตอร์กับสตรีมใน Rust หมายความว่าเราสร้างสตรีมจากอิเทอเรเตอร์ใดก็ได้จริงๆ เช่นเดียวกับอิเทอเรเตอร์ เราทำงานกับสตรีมได้โดยเรียกเมธอด `next` ของมันแล้ว await เอาต์พุต ดังในลิสติ้ง 17-21 ซึ่งยังคอมไพล์ไม่ผ่านในตอนนี้

เราเริ่มด้วยอาร์เรย์ของตัวเลข ซึ่งเราแปลงเป็นอิเทอเรเตอร์แล้วเรียก `map` เพื่อเพิ่มค่าทั้งหมดเป็นสองเท่า จากนั้นเราแปลงอิเทอเรเตอร์เป็นสตรีมโดยใช้ฟังก์ชัน `trpl::stream_from_iter` ต่อไปเราวนลูปผ่านรายการต่างๆ ในสตรีมเมื่อมันมาถึงด้วยลูป `while let`

อย่างที่เอาต์พุตนี้อธิบาย เหตุผลของข้อผิดพลาดของคอมไพเลอร์ก็คือเราจำเป็นต้องมีเทรตที่ถูกต้องอยู่ในสโคป (scope) เพื่อให้ใช้เมธอด `next` ได้ จากที่เราอภิปรายกันมา คุณอาจคาดหมายได้อย่างสมเหตุสมผลว่าเทรตนั้นคือ `Stream` แต่ที่จริงมันคือ `StreamExt` `Ext` ย่อมาจาก_ส่วนขยาย_ (extension) และเป็นแพตเทิร์นที่พบได้ทั่วไปในชุมชน Rust สำหรับการขยายเทรตหนึ่งด้วยอีกเทรตหนึ่ง

เทรต `Stream` นิยามอินเทอร์เฟซระดับต่ำที่รวมเทรต `Iterator` และ `Future` เข้าด้วยกันอย่างได้ผล `StreamExt` จัดเตรียมชุด API ระดับสูงกว่าบนพื้นฐานของ `Stream` รวมถึงเมธอด `next` ตลอดจนเมธอดอรรถประโยชน์อื่นๆ ที่คล้ายกับเมธอดที่เทรต `Iterator` จัดเตรียมไว้ `Stream` และ `StreamExt` ยังไม่เป็นส่วนหนึ่งของไลบรารีมาตรฐานของ Rust แต่เครตในระบบนิเวศส่วนใหญ่ใช้คำนิยามที่คล้ายกัน
