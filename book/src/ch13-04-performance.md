## ประสิทธิภาพของลูปเทียบกับอิเทอเรเตอร์

ในการตัดสินใจว่าจะใช้ลูปหรืออิเทอเรเตอร์ คุณจำเป็นต้องรู้ว่าการอิมพลีเมนต์ใดเร็วกว่า: เวอร์ชันของฟังก์ชัน `search` ที่ใช้ลูป `for` อย่างชัดเจน หรือเวอร์ชันที่ใช้อิเทอเรเตอร์ (iterator)

เราได้รันการวัดประสิทธิภาพ (benchmark) โดยโหลดเนื้อหาทั้งหมดของ _The Adventures of Sherlock Holmes_ ของเซอร์อาร์เธอร์ โคนัน ดอยล์ เข้าไปใน `String` แล้วค้นหาคำว่า _the_ ในเนื้อหา นี่คือผลลัพธ์ของการวัดประสิทธิภาพบนเวอร์ชันของ `search` ที่ใช้ลูป `for` และเวอร์ชันที่ใช้อิเทอเรเตอร์:

```text
test bench_search_for  ... bench:  19,620,300 ns/iter (+/- 915,700)
test bench_search_iter ... bench:  19,234,900 ns/iter (+/- 657,200)
```

การอิมพลีเมนต์ทั้งสองมีประสิทธิภาพใกล้เคียงกัน! เราจะไม่อธิบายโค้ดวัดประสิทธิภาพตรงนี้ เพราะจุดประสงค์ไม่ใช่เพื่อพิสูจน์ว่าเวอร์ชันทั้งสองเทียบเท่ากัน แต่เพื่อให้ได้ความเข้าใจโดยรวมว่าการอิมพลีเมนต์ทั้งสองนี้เปรียบเทียบกันอย่างไรในแง่ประสิทธิภาพ

สำหรับการวัดประสิทธิภาพที่ครอบคลุมยิ่งขึ้น คุณควรทดลองใช้ข้อความต่างๆ ที่มีขนาดต่างๆ กันเป็น `contents` ใช้คำต่างๆ และคำที่มีความยาวต่างๆ กันเป็น `query` และรูปแบบอื่นๆ อีกมากมาย จุดประสงค์คือ: อิเทอเรเตอร์ แม้จะเป็นนามธรรมระดับสูง แต่ถูกคอมไพล์ลงมาเป็นโค้ดที่ใกล้เคียงกับที่คุณจะเขียนโค้ดระดับต่ำด้วยตัวเอง อิเทอเรเตอร์เป็นหนึ่งใน_นามธรรมไร้ต้นทุน_ (zero-cost abstractions) ของ Rust ซึ่งเราหมายความว่าการใช้นามธรรมนี้ไม่เพิ่มภาระ (overhead) ใดๆ ต่อรันไทม์ สิ่งนี้เปรียบได้กับวิธีที่ Bjarne Stroustrup ผู้ออกแบบและผู้อิมพลีเมนต์ C++ คนแรก นิยาม zero-overhead ในสุนทรพจน์หลักของเขาในงาน ETAPS ปี 2012 ชื่อ “Foundations of C++”:

> โดยทั่วไปแล้ว การอิมพลีเมนต์ C++ ปฏิบัติตามหลักการ zero-overhead: สิ่งที่คุณไม่ได้ใช้ คุณก็ไม่ต้องจ่าย และยิ่งกว่านั้น: สิ่งที่คุณใช้ คุณก็ไม่สามารถเขียนโค้ดให้ดีกว่านี้ได้แล้ว

ในหลายกรณี โค้ด Rust ที่ใช้อิเทอเรเตอร์คอมไพล์เป็นแอสเซมบลีเดียวกันกับที่คุณจะเขียนด้วยมือ การปรับให้เหมาะสม (optimization) เช่นการคลี่ลูป (loop unrolling) และการกำจัดการตรวจสอบขอบเขต (bounds checking) ในการเข้าถึงอาร์เรย์จะถูกนำมาใช้ และทำให้โค้ดที่ได้มีประสิทธิภาพสูงมาก ตอนนี้คุณรู้แล้ว คุณจึงใช้อิเทอเรเตอร์และโคลเชอร์ (closure) ได้อย่างไร้ความกลัว! มันทำให้โค้ดดูเหมือนอยู่ในระดับสูงขึ้น แต่ไม่ทำให้เกิดการสูญเสียประสิทธิภาพตอนรันไทม์จากการทำเช่นนั้น

## บทสรุป

โคลเชอร์และอิเทอเรเตอร์เป็นฟีเจอร์ของ Rust ที่ได้แรงบันดาลใจจากแนวคิดของภาษาที่เน้นการเขียนโปรแกรมเชิงฟังก์ชัน (functional programming) พวกมันมีส่วนช่วยความสามารถของ Rust ในการแสดงแนวคิดระดับสูงอย่างชัดเจนโดยยังคงประสิทธิภาพแบบโค้ดระดับต่ำ การอิมพลีเมนต์ของโคลเชอร์และอิเทอเรเตอร์เป็นเช่นนั้นจนประสิทธิภาพตอนรันไทม์ไม่ได้รับผลกระทบ นี่เป็นส่วนหนึ่งของเป้าหมายของ Rust ที่มุ่งมั่นจัดหานามธรรมไร้ต้นทุน

ตอนนี้เราได้ปรับปรุงความสามารถในการแสดงออกของโปรเจกต์ I/O ของเราแล้ว มาดูฟีเจอร์เพิ่มเติมบางอย่างของ `cargo` ที่จะช่วยให้เราแบ่งปันโปรเจกต์กับโลกกัน
