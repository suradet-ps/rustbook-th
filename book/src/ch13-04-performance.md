## ประสิทธิภาพของลูปเทียบกับอิเทอเรเตอร์

ในการตัดสินใจว่าจะเลือกใช้ลูปหรืออิเทอเรเตอร์ คุณอาจอยากทราบว่าการอิมพลีเมนต์แบบไหนทำงานได้เร็วกว่ากัน: ระหว่างเวอร์ชันของฟังก์ชัน `search` ที่เขียนลูป `for` ไว้อย่างชัดเจน กับเวอร์ชันที่หันมาใช้อิเทอเรเตอร์ (iterator)

เราได้ทำการทดสอบวัดประสิทธิภาพ (benchmark) โดยโหลดเนื้อหาทั้งหมดของหนังสือเรื่อง _The Adventures of Sherlock Holmes_ ของเซอร์อาร์เธอร์ โคนัน ดอยล์ เข้าไปใน `String` แล้วสั่งค้นหาคำว่า _the_ ในเนื้อหาทั้งหมด และนี่คือผลลัพธ์การวัดประสิทธิภาพระหว่างฟังก์ชัน `search` ที่ใช้ลูป `for` เทียบกับเวอร์ชันที่ใช้อิเทอเรเตอร์:

```text
test bench_search_for  ... bench:  19,620,300 ns/iter (+/- 915,700)
test bench_search_iter ... bench:  19,234,900 ns/iter (+/- 657,200)
```

การอิมพลีเมนต์ทั้งสองแบบให้ประสิทธิภาพที่ใกล้เคียงกันมาก! เราจะไม่ลงลึกในโค้ดของการวัดประสิทธิภาพตรงนี้ เพราะเป้าหมายไม่ใช่การพิสูจน์ว่าทั้งสองแบบมีความเท่ากันทุกประการ แต่เพื่อให้เห็นภาพรวมว่าทั้งสองวิธีนี้เทียบเคียงกันอย่างไรในแง่ของความเร็ว

หากต้องการวัดประสิทธิภาพอย่างครอบคลุมรอบด้านยิ่งขึ้น คุณอาจต้องทดสอบกับข้อความหลากขนาดใน `contents`, ทดสอบคำค้นหลายรูปแบบและมีความยาวต่างกันใน `query` รวมถึงรูปแบบตัวแปรอื่น ๆ อีกมากมาย แต่ประเด็นสำคัญมีอยู่ว่า: แม้ว่าอิเทอเรเตอร์จะเป็นแนวคิดแบบนามธรรมระดับสูง (high-level abstraction) แต่มันกลับถูกคอมไพล์ลงมาเป็นโค้ดที่มีประสิทธิภาพเทียบเท่ากับการที่คุณเขียนโค้ดระดับล่างด้วยตนเอง อิเทอเรเตอร์จึงจัดเป็นหนึ่งใน_นามธรรมไร้ต้นทุน_ (zero-cost abstractions) ของ Rust ซึ่งหมายความว่า การเรียกใช้นามธรรมเหล่านี้จะไม่ก่อให้เกิดภาระงานเพิ่มเติม (runtime overhead) ตอนรันไทม์เลยแม้แต่น้อย สิ่งนี้สอดคล้องกับคำนิยามของหลักการ zero-overhead ที่ Bjarne Stroustrup ผู้ริเริ่มออกแบบและพัฒนาภาษา C++ ได้เคยกล่าวไว้ในสุนทรพจน์หลักงาน ETAPS ปี 2012 หัวข้อ “Foundations of C++”:

> โดยทั่วไปแล้ว การอิมพลีเมนต์ของ C++ จะยึดถือหลักการ zero-overhead นั่นคือ: สิ่งที่คุณไม่ได้ใช้งาน คุณก็ไม่ต้องจ่ายต้นทุนให้มัน และยิ่งไปกว่านั้น: สิ่งที่คุณนำมาใช้งาน คุณก็ไม่สามารถเขียนโค้ดให้ดีกว่านี้ได้แล้ว

ในหลาย ๆ กรณี โค้ดภาษา Rust ที่ใช้อิเทอเรเตอร์สามารถคอมไพล์ออกมาเป็นโค้ดภาษาแอสเซมบลีที่เหมือนกับโค้ดที่คุณเขียนปรับแต่งด้วยมือทุกประการ การปรับแต่งระดับคอมไพเลอร์ (optimization) เช่น การคลี่ลูป (loop unrolling) และการตัดการตรวจสอบขอบเขต (eliminating bounds checking) ในการเข้าถึงอาร์เรย์ จะถูกนำมาประยุกต์ใช้อัตโนมัติ ทำให้โค้ดที่ได้มีประสิทธิภาพการทำงานสูงอย่างยิ่ง เมื่อทราบเช่นนี้แล้ว คุณจึงสามารถใช้งานอิเทอเรเตอร์และโคลเชอร์ (closure) ได้อย่างมั่นใจไร้กังวล! เพราะพวกมันช่วยให้โค้ดของคุณดูเป็นระเบียบและอ่านเข้าใจง่ายในระดับสูง โดยไม่สูญเสียความเร็วและประสิทธิภาพการทำงานตอนรันไทม์เลยแม้แต่น้อย

## บทสรุป

โคลเชอร์และอิเทอเรเตอร์เป็นฟีเจอร์ของ Rust ที่ได้รับแรงบันดาลใจมาจากแนวคิดของการเขียนโปรแกรมเชิงฟังก์ชัน (functional programming) ฟีเจอร์ทั้งสองนี้ช่วยเสริมพลังให้ภาษา Rust สามารถถ่ายทอดแนวคิดการทำงานระดับสูงได้อย่างชัดเจนและกระชับ โดยยังคงรักษาประสิทธิภาพความเร็วระดับโค้ดระดับล่างไว้ได้อย่างยอดเยี่ยม การอิมพลีเมนต์โคลเชอร์และอิเทอเรเตอร์ใน Rust ถูกออกแบบมาอย่างพิถีพิถันจนไม่ส่งผลกระทบต่อประสิทธิภาพตอนรันไทม์เลย ซึ่งทั้งหมดนี้เป็นส่วนหนึ่งของเป้าหมายหลักใน Rust ที่มุ่งมั่นส่งมอบนามธรรมไร้ต้นทุน (zero-cost abstractions) ให้แก่นักพัฒนาเสมอมา

เมื่อเราได้ยกระดับความชัดเจนและสละสลวยให้กับโค้ดในโปรเจกต์ I/O ของเราเรียบร้อยแล้ว ในบทถัดไป เราจะไปทำความรู้จักกับฟีเจอร์เพิ่มเติมของ `cargo` ที่จะช่วยให้เราสามารถเผยแพร่และแบ่งปันโปรเจกต์ของเราสู่สายตาชาวโลกได้
