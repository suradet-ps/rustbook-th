## เมธอด

_เมธอด_ (method) มีความคล้ายคลึงกับฟังก์ชันอย่างมาก: เราประกาศด้วยคีย์เวิร์ด `fn` ตามด้วยชื่อ สามารถรับพารามิเตอร์ (parameter) และคืนค่า (return value) ได้ รวมถึงมีบล็อกคำสั่งที่ทำงานเมื่อถูกเรียกใช้จากที่อื่น แต่สิ่งที่ต่างจากฟังก์ชันทั่วไปคือ เมธอดจะถูกนิยามขึ้นภายในบริบทของ `struct` (หรือ `enum` หรือเทรตออบเจกต์ ซึ่งเราจะกล่าวถึงใน [บทที่ 6][enums]<!-- ignore --> และ [บทที่ 18][trait-objects]<!-- ignore --> ตามลำดับ) และพารามิเตอร์ตัวแรกของเมธอดจะต้องเป็น `self` เสมอ ซึ่งทำหน้าที่แทนอินสแตนซ์ของ `struct` ที่เมธอดนั้นกำลังถูกเรียกใช้งาน

ในลายเซ็นของเมธอด `area` เราใช้ `&self` แทน `rectangle: &Rectangle` ซึ่งแท้จริงแล้ว `&self` เป็นรูปย่อของ `self: &Self` โดยภายในบล็อก `impl` ชนิดข้อมูล `Self` จะเป็นชื่อเสมือน (alias) ที่แทนชนิดข้อมูลที่บล็อก `impl` นั้นสังกัดอยู่ เมธอดจะต้องมีพารามิเตอร์ตัวแรกชื่อ `self` และเป็นชนิดข้อมูล `Self` เสมอ Rust จึงอนุญาตให้เราเขียนย่อเหลือเพียงชื่อ `self` สั้นๆ ในตำแหน่งพารามิเตอร์แรกได้ โปรดสังเกตว่าเรายังคงต้องใส่เครื่องหมาย `&` ไว้ข้างหน้า `self` เพื่อระบุว่าเมธอดนี้เป็นการยืมอินสแตนซ์ `Self` มาใช้งาน เช่นเดียวกับที่เราเคยเขียน `rectangle: &Rectangle` ทั้งนี้ เมธอดสามารถเลือกที่จะรับความเป็นเจ้าของของ `self`, ยืม `self` แบบแก้ไขไม่ได้ (immutable borrow) ดังเช่นในตัวอย่างนี้, หรือยืม `self` แบบแก้ไขได้ (mutable borrow) ก็ได้เช่นเดียวกับพารามิเตอร์ตัวอื่นๆ

เราเลือกใช้ `&self` ในตัวอย่างนี้ด้วยเหตุผลเดียวกับตอนที่ใช้ `&Rectangle` ในแบบฟังก์ชัน นั่นคือเราไม่ต้องการรับความเป็นเจ้าของ และต้องการเพียงแค่อ่านข้อมูลใน struct โดยไม่ได้แก้ไขเปลี่ยนแปลงข้อมูลแต่อย่างใด หากเราต้องการให้เมธอดสามารถแก้ไขข้อมูลในอินสแตนซ์ที่เรียกใช้ได้ เราจะเปลี่ยนพารามิเตอร์แรกเป็น `&mut self` แทน ส่วนการสร้างเมธอดที่ยึดความเป็นเจ้าของของอินสแตนซ์ไปเลยด้วยการใช้เพียง `self` โดดๆ นั้นเป็นรูปแบบที่ไม่ค่อยพบบ่อยนัก โดยมักจะใช้เมื่อเมธอดนั้นทำหน้าที่แปลง `self` ให้กลายเป็นข้อมูลชนิดอื่น และคุณต้องการป้องกันไม่ให้ผู้เรียกสามารถนำอินสแตนซ์เดิมกลับมาใช้งานได้อีกหลังจากการแปลง

ประโยชน์หลักของการใช้เมธอดแทนฟังก์ชัน นอกเหนือจากความสะดวกของไวยากรณ์การเรียกใช้และไม่ต้องระบุชนิดข้อมูลของ `self` ซ้ำในทุกๆ เมธอดแล้ว ยังเป็นเรื่องของการจัดระเบียบโค้ดที่ดีเยี่ยม เพราะเราได้รวบรวมการกระทำทั้งหมดที่สามารถทำได้กับอินสแตนซ์ของชนิดข้อมูลนั้นๆ มาไว้ในบล็อก `impl` เดียวกัน ช่วยให้ผู้ที่นำโค้ดของเราไปใช้งานสามารถค้นหาความสามารถทั้งหมดของ `Rectangle` ได้จากที่เดียวอย่างเป็นระบบ

> ### ตัวดำเนินการ `->` อยู่ที่ไหน?
>
> ในภาษา C และ C++ มีการใช้ตัวดำเนินการ (operator) สองตัวที่แตกต่างกันในการเรียกใช้เมธอด กล่าวคือ คุณจะใช้เครื่องหมายจุด `.` หากคุณเรียกเมธอดบนออบเจกต์โดยตรง และจะใช้ลูกศร `->` หากคุณเรียกเมธอดผ่านพอยน์เตอร์ (pointer) ที่ชี้ไปยังออบเจกต์ ซึ่งจำเป็นต้องดีเรเฟอเรนซ์ (dereference) พอยน์เตอร์นั้นก่อน กล่าวอีกนัยหนึ่ง หาก `object` เป็นพอยน์เตอร์ คำสั่ง `object->something()` จะเทียบเท่ากับ `(*object).something()`
>
> แต่ใน Rust ไม่มีตัวดำเนินการอย่าง `->` เพราะ Rust มีฟีเจอร์ที่เรียกว่า _การสร้างเรเฟอเรนซ์และดีเรเฟอเรนซ์อัตโนมัติ_ (automatic referencing and dereferencing) ซึ่งการเรียกใช้เมธอดถือเป็นหนึ่งในไม่กี่จุดใน Rust ที่มีพฤติกรรมอำนวยความสะดวกเช่นนี้
>
> กลไกการทำงานคือ: เมื่อคุณเรียกเมธอดด้วยคำสั่ง `object.something()` Rust จะเติมเครื่องหมาย `&`, `&mut`, หรือ `*` ให้โดยอัตโนมัติเพื่อให้ `object` มีชนิดข้อมูลตรงกับลายเซ็นของเมธอดนั้นๆ กล่าวอีกนัยหนึ่ง โค้ดสองบรรทัดต่อไปนี้ทำงานเทียบเท่ากันทุกประการ:
>
> <!-- CAN'T EXTRACT SEE BUG https://github.com/rust-lang/mdBook/issues/1127 -->
>
> ```rust
> # #[derive(Debug,Copy,Clone)]
> # struct Point {
> #     x: f64,
> #     y: f64,
> # }
> #
> # impl Point {
> #    fn distance(&self, other: &Point) -> f64 {
> #        let x_squared = f64::powi(other.x - self.x, 2);
> #        let y_squared = f64::powi(other.y - self.y, 2);
> #
> #        f64::sqrt(x_squared + y_squared)
> #    }
> # }
> # let p1 = Point { x: 0.0, y: 0.0 };
> # let p2 = Point { x: 5.0, y: 6.5 };
> p1.distance(&p2);
> (&p1).distance(&p2);
> ```
>
> จะเห็นได้ว่าแบบแรกอ่านง่ายและสะอาดตากว่ามาก พฤติกรรมการจัดการเรเฟอเรนซ์อัตโนมัตินี้ทำงานได้อย่างราบรื่นเพราะเมธอดมีผู้รับการเรียก (receiver) ที่ชัดเจนเสมอ นั่นคือชนิดข้อมูลของ `self` เมื่อทราบทั้งผู้รับและชื่อของเมธอดแล้ว Rust จึงสามารถระบุได้อย่างแม่นยำว่าเมธอดนั้นต้องการแค่อ่านค่า (`&self`), ต้องการแก้ไขค่า (`&mut self`), หรือต้องการรับความเป็นเจ้าของไปเลย (`self`) การที่ Rust ช่วยจัดการเรื่องการยืมให้อัตโนมัติสำหรับตัวรับของเมธอดเช่นนี้ ถือเป็นหัวใจสำคัญที่ช่วยให้ระบบความเป็นเจ้าของมีความสะดวกสบายในการเขียนโค้ดจริงอย่างมาก

เมื่อเราสั่งรันโค้ดนี้ร่วมกับฟังก์ชัน `main` ในลิสติ้ง 5-14 เราจะได้ผลลัพธ์ตามที่ต้องการอย่างถูกต้อง เมธอดสามารถรับพารามิเตอร์ได้หลายตัว โดยระบุต่อท้ายพารามิเตอร์ `self` ในลายเซ็นของเมธอด และพารามิเตอร์เหล่านั้นจะทำงานเหมือนกับพารามิเตอร์ของฟังก์ชันทั่วไปทุกประการ

### ฟังก์ชันที่เชื่อมโยงกับชนิดข้อมูล

ฟังก์ชันทั้งหมดที่นิยามอยู่ภายในบล็อก `impl` จะเรียกว่า _ฟังก์ชันประจำชนิดข้อมูล_ หรือ _ฟังก์ชันที่เชื่อมโยงกับชนิดข้อมูล_ (associated function) เนื่องจากพวกมันมีความผูกพันอยู่กับชนิดข้อมูลที่ระบุชื่อไว้หลังคำสั่ง `impl` เราสามารถนิยามฟังก์ชันประจำชนิดข้อมูลโดยไม่ต้องมี `self` เป็นพารามิเตอร์แรกได้ (ซึ่งจะไม่ถือว่าเป็นเมธอด) เนื่องจากฟังก์ชันประเภทนี้ไม่จำเป็นต้องอาศัยอินสแตนซ์ของชนิดข้อมูลนั้นในการทำงาน ซึ่งเราเคยใช้งานฟังก์ชันในลักษณะนี้มาแล้ว เช่น ฟังก์ชัน `String::from` ที่นิยามอยู่บนชนิดข้อมูล `String`

ฟังก์ชันประจำชนิดข้อมูลที่ไม่ใช่เมธอดมักจะนิยมใช้เป็นคอนสตรัคเตอร์ (constructor) ที่ทำหน้าที่สร้างและส่งคืนอินสแตนซ์ใหม่ของ `struct` ออกมา โดยส่วนใหญ่มักจะตั้งชื่อฟังก์ชันว่า `new` แต่คำว่า `new` ไม่ใช่ชื่อพิเศษหรือคำสงวนของภาษาแต่อย่างใด ตัวอย่างเช่น เราสามารถสร้างฟังก์ชันประจำชนิดข้อมูลชื่อ `square` ที่รับพารามิเตอร์ขนาดเพียงค่าเดียว แล้วนำค่านั้นไปใช้เป็นทั้งความกว้างและความสูง เพื่อช่วยให้สร้างอินสแตนซ์ของ `Rectangle` ที่เป็นรูปสี่เหลี่ยมจัตุรัสได้อย่างสะดวก โดยไม่ต้องระบุค่าเดิมซ้ำสองครั้ง:

ในการเรียกใช้ฟังก์ชันประจำชนิดข้อมูลนี้ เราจะใช้ไวยากรณ์ `::` ร่วมกับชื่อของ struct เช่น `let sq = Rectangle::square(3);` ฟังก์ชันนี้ถูกจัดไว้ภายใต้เนมสเปซของ struct นั้นๆ โดยไวยากรณ์ `::` นี้ใช้ทั้งสำหรับการเรียกฟังก์ชันประจำชนิดข้อมูลและสำหรับการเข้าถึงเนมสเปซที่สร้างขึ้นโดยมอดูล (module) ซึ่งเราจะได้เรียนรู้เรื่องมอดูลใน [บทที่ 7][modules]<!-- ignore -->

## สรุป

`struct` ช่วยให้คุณสามารถสร้างชนิดข้อมูลกำหนดเองที่มีความหมายเฉพาะเจาะจงสำหรับโดเมนของงานคุณได้ โดยการใช้ struct คุณจะสามารถจัดกลุ่มข้อมูลที่เกี่ยวข้องกันเข้าไว้ด้วยกัน พร้อมทั้งตั้งชื่อให้กับข้อมูลแต่ละส่วนเพื่อช่วยให้โค้ดมีความชัดเจนและสื่อความหมายได้เป็นอย่างดี และในบล็อก `impl` คุณสามารถนิยามฟังก์ชันประจำชนิดข้อมูลขึ้นมาได้ โดยเมธอดก็คือฟังก์ชันประจำชนิดข้อมูลประเภทหนึ่งที่ช่วยให้คุณสามารถกำหนดพฤติกรรมการทำงานให้กับอินสแตนซ์ของ struct ได้โดยตรง

อย่างไรก็ตาม `struct` ไม่ใช่วิธีเดียวในการสร้างชนิดข้อมูลกำหนดเอง ในบทถัดไปเราจะไปศึกษาฟีเจอร์ `enum` ของ Rust เพื่อเพิ่มเครื่องมืออันทรงพลังอีกชิ้นหนึ่งให้กับคลังเครื่องมือของคุณ
