## เมธอด

เมธอด (method) มีความคล้ายคลึงกับฟังก์ชัน: เราประกาศมันด้วยคำสงวน (keyword) `fn` และชื่อ มันสามารถมีพารามิเตอร์ (parameter) และค่าที่คืนกลับ (return value) ได้ และมันมีโค้ดบางส่วนที่ทำงานเมื่อเมธอดถูกเรียกจากที่อื่น ต่างจากฟังก์ชัน ตรงที่เมธอดถูกนิยามภายในบริบทของ struct (หรือ enum หรือเทรตออบเจกต์ (trait object) ซึ่งเรากล่าวถึงใน[บทที่ 6][enums]<!-- ignore --> และ[บทที่ 18][trait-objects]<!-- ignore --> ตามลำดับ) และพารามิเตอร์ตัวแรกของมันคือ `self` เสมอ ซึ่งแทนอินสแตนซ์ (instance) ของ struct ที่เมธอดนั้นถูกเรียกใช้

ในซิกเนเจอร์ของ `area` เราใช้ `&self` แทน `rectangle: &Rectangle` อันที่จริง `&self` เป็นคำย่อของ `self: &Self` ภายในบล็อก `impl` ชนิด `Self` เป็นชื่อพ้อง (alias) ของชนิดข้อมูลที่บล็อก `impl` นั้นเป็นของมัน เมธอดต้องมีพารามิเตอร์ชื่อ `self` ชนิด `Self` เป็นพารามิเตอร์ตัวแรก ดังนั้น Rust จึงให้คุณเขียนย่อโดยใช้เพียงชื่อ `self` ในตำแหน่งพารามิเตอร์ตัวแรก โปรดสังเกตว่าเรายังต้องใช้ `&` นำหน้าคำย่อ `self` เพื่อบ่งชี้ว่าเมธอดนี้ยืมอินสแตนซ์ `Self` เช่นเดียวกับที่เราทำใน `rectangle: &Rectangle` เมธอดสามารถรับความเป็นเจ้าของ (ownership) `self` ยืม `self` แบบเปลี่ยนแปลงไม่ได้อย่างที่เราทำในที่นี้ หรือยืม `self` แบบเปลี่ยนแปลงได้ เช่นเดียวกับที่ทำได้กับพารามิเตอร์อื่นๆ ทุกตัว

เราเลือก `&self` ในที่นี้ด้วยเหตุผลเดียวกับที่เราใช้ `&Rectangle` ในเวอร์ชันฟังก์ชัน: เราไม่ต้องการรับความเป็นเจ้าของ และเราเพียงต้องการอ่านข้อมูลใน struct ไม่ใช่เขียนทับมัน หากเราต้องการเปลี่ยนอินสแตนซ์ที่เราเรียกเมธอดบนนั้นเป็นส่วนหนึ่งของสิ่งที่เมธอดทำ เราจะใช้ `&mut self` เป็นพารามิเตอร์ตัวแรก การมีเมธอดที่รับความเป็นเจ้าของอินสแตนซ์โดยใช้เพียง `self` เป็นพารามิเตอร์ตัวแรกนั้นหาได้ยาก เทคนิคนี้มักใช้เมื่อเมธอดแปลง `self` ให้เป็นสิ่งอื่น และคุณต้องการป้องกันไม่ให้ผู้เรียกใช้ต้นฉบับของอินสแตนซ์หลังจากการแปลง

เหตุผลหลักในการใช้เมธอดแทนฟังก์ชัน นอกเหนือจากการมีวากยสัมพันธ์ของเมธอดและไม่ต้องระบุชนิดของ `self` ซ้ำในทุกซิกเนเจอร์ของเมธอด คือการจัดระเบียบ เราได้รวบรวมทุกสิ่งที่เราทำได้กับอินสแตนซ์ของชนิดข้อมูลไว้ในบล็อก `impl` เดียว แทนที่จะทำให้ผู้ใช้โค้ดของเราในอนาคตต้องไปค้นหาความสามารถของ `Rectangle` ในที่ต่างๆ ทั่วไลบรารีที่เรามอบให้

> ### ตัวดำเนินการ `->` อยู่ที่ไหน?
>
> ใน C และ C++ มีการใช้ตัวดำเนินการ (operator) สองตัวที่แตกต่างกันสำหรับการเรียกเมธอด: คุณใช้ `.` หากคุณกำลังเรียกเมธอดบนออบเจกต์โดยตรง และใช้ `->` หากคุณกำลังเรียกเมธอดบนพอยน์เตอร์ (pointer) ที่ชี้ไปยังออบเจกต์และจำเป็นต้องดีเรเฟอเรนซ์ (dereference) พอยน์เตอร์นั้นก่อน กล่าวอีกนัยหนึ่ง หาก `object` เป็นพอยน์เตอร์ `object->something()` จะคล้ายคลึงกับ `(*object).something()`
>
> Rust ไม่มีสิ่งที่เทียบเท่ากับตัวดำเนินการ `->` แต่ Rust มีฟีเจอร์ที่เรียกว่า _การอ้างอิงและดีเรเฟอเรนซ์อัตโนมัติ_ (automatic referencing and dereferencing) การเรียกเมธอดเป็นหนึ่งในไม่กี่จุดใน Rust ที่มีพฤติกรรมนี้
>
> มันทำงานดังนี้: เมื่อคุณเรียกเมธอดด้วย `object.something()` Rust จะเติม `&`, `&mut` หรือ `*` เข้าไปโดยอัตโนมัติ เพื่อให้ `object` ตรงกับซิกเนเจอร์ของเมธอด กล่าวอีกนัยหนึ่ง สองบรรทัดต่อไปนี้เทียบเท่ากัน:
>
> <!-- CAN'T EXTRACT SEE BUG https://github.com/rust-lang/mdBook/issues/1127 -->
>
> ```rust
> # #[derive(Debug,Copy,Clone)]
> # struct Point {
> #     x: f64,
> #     y: f64,
> # }
> #
> # impl Point {
> #    fn distance(&self, other: &Point) -> f64 {
> #        let x_squared = f64::powi(other.x - self.x, 2);
> #        let y_squared = f64::powi(other.y - self.y, 2);
> #
> #        f64::sqrt(x_squared + y_squared)
> #    }
> # }
> # let p1 = Point { x: 0.0, y: 0.0 };
> # let p2 = Point { x: 5.0, y: 6.5 };
> p1.distance(&p2);
> (&p1).distance(&p2);
> ```
>
> แบบแรกดูสะอาดตากว่ามาก พฤติกรรมการอ้างอิงอัตโนมัตินี้ทำงานได้เพราะเมธอดมีรีซีฟเวอร์ (receiver) ที่ชัดเจน นั่นคือชนิดของ `self` เมื่อพิจารณารีซีฟเวอร์และชื่อของเมธอด Rust ก็สามารถระบุได้อย่างแน่นอนว่าเมธอดนั้นกำลังอ่านค่า (`&self`) เปลี่ยนแปลงค่า (`&mut self`) หรือบริโภคค่า (`self`) การที่ Rust ทำให้การยืมเป็นไปโดยปริยายสำหรับรีซีฟเวอร์ของเมธอดเป็นส่วนสำคัญที่ทำให้ความเป็นเจ้าของใช้งานได้สะดวกในทางปฏิบัติ

### ฟังก์ชันที่เชื่อมโยงกับชนิดข้อมูล

ฟังก์ชันทั้งหมดที่นิยามภายในบล็อก `impl` เรียกว่า _ฟังก์ชันที่เชื่อมโยงกับชนิดข้อมูล_ (associated function) เพราะมันถูกเชื่อมโยงกับชนิดข้อมูลที่ตั้งชื่อตามหลัง `impl` เราสามารถนิยามฟังก์ชันที่เชื่อมโยงกับชนิดข้อมูลซึ่งไม่มี `self` เป็นพารามิเตอร์ตัวแรกได้ (จึงไม่ใช่เมธอด) เพราะมันไม่จำเป็นต้องใช้อินสแตนซ์ของชนิดข้อมูลนั้นในการทำงาน เราเคยใช้ฟังก์ชันแบบนี้มาแล้วหนึ่งตัว นั่นคือฟังก์ชัน `String::from` ที่นิยามบนชนิด `String`

ฟังก์ชันที่เชื่อมโยงกับชนิดข้อมูลซึ่งไม่ใช่เมธอดมักใช้เป็นคอนสตรัคเตอร์ (constructor) ที่จะคืนค่าอินสแตนซ์ใหม่ของ struct ฟังก์ชันเหล่านี้มักถูกตั้งชื่อว่า `new` แต่ `new` ไม่ใช่ชื่อพิเศษและไม่ได้ถูกสร้างมาพร้อมกับภาษา ตัวอย่างเช่น เราอาจเลือกจัดเตรียมฟังก์ชันที่เชื่อมโยงกับชนิดข้อมูลชื่อ `square` ที่มีพารามิเตอร์มิติหนึ่งตัว แล้วใช้ค่านั้นเป็นทั้งความกว้างและความสูง ทำให้สร้าง `Rectangle` ที่เป็นรูปสี่เหลี่ยมจัตุรัสได้ง่ายขึ้น แทนที่จะต้องระบุค่าเดิมซ้ำสองครั้ง:

ในการเรียกฟังก์ชันที่เชื่อมโยงกับชนิดข้อมูลนี้ เราใช้ไวยากรณ์ `::` กับชื่อของ struct โดย `let sq = Rectangle::square(3);` เป็นตัวอย่างหนึ่ง ฟังก์ชันนี้ถูกจัดอยู่ในเนมสเปซ (namespace) ของ struct: ไวยากรณ์ `::` ถูกใช้ทั้งกับฟังก์ชันที่เชื่อมโยงกับชนิดข้อมูลและเนมสเปซที่สร้างขึ้นโดยมอดูล (module) เราจะพูดคุยเรื่องมอดูลใน[บทที่ 7][modules]<!-- ignore -->

## สรุป

struct ช่วยให้คุณสร้างชนิดข้อมูลกำหนดเองที่มีความหมายสำหรับโดเมนของคุณ ด้วยการใช้ struct คุณสามารถเชื่อมชิ้นส่วนข้อมูลที่เกี่ยวข้องกันไว้ด้วยกันและตั้งชื่อแต่ละชิ้นเพื่อให้โค้ดของคุณชัดเจน ในบล็อก `impl` คุณสามารถนิยามฟังก์ชันที่เชื่อมโยงกับชนิดข้อมูลของคุณ และเมธอดเป็นฟังก์ชันที่เชื่อมโยงกับชนิดข้อมูลประเภทหนึ่งที่ช่วยให้คุณระบุพฤติกรรมที่อินสแตนซ์ของ struct ของคุณมีได้

แต่ struct ไม่ใช่วิธีเดียวที่คุณจะสร้างชนิดข้อมูลกำหนดเองได้: มาหันไปดูฟีเจอร์ enum ของ Rust เพื่อเพิ่มเครื่องมืออีกชิ้นให้กับกล่องเครื่องมือของคุณกัน
