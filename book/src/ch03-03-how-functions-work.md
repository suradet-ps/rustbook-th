## ฟังก์ชัน

ฟังก์ชัน (function) เป็นส่วนประกอบพื้นฐานที่พบได้ทั่วไปในโค้ด Rust คุณได้เห็นหนึ่งในฟังก์ชันที่สำคัญที่สุดของภาษาไปแล้ว นั่นคือฟังก์ชัน `main` ซึ่งเป็นจุดเริ่มต้นการทำงานของโปรแกรมจำนวนมาก และคุณยังได้เห็นคีย์เวิร์ด `fn` ที่ใช้สำหรับประกาศฟังก์ชันใหม่ด้วย

โค้ด Rust ใช้สไตล์แบบ _snake case_ เป็นธรรมเนียมปฏิบัติในการตั้งชื่อฟังก์ชันและตัวแปร โดยตัวอักษรทั้งหมดจะเป็นตัวพิมพ์เล็กและคั่นคำด้วยขีดล่าง (underscore) ตัวอย่างโปรแกรมที่มีการนิยามฟังก์ชันมีดังนี้:

<span class="filename">ชื่อไฟล์: src/main.rs</span>

```rust
{{#rustdoc_include ../listings/ch03-common-programming-concepts/no-listing-16-functions/src/main.rs}}
```

เรานิยามฟังก์ชันใน Rust โดยขึ้นต้นด้วย `fn` ตามด้วยชื่อฟังก์ชันและคู่วงเล็บเปิดปิด ส่วนวงเล็บปีกกาจะบอกให้คอมไพเลอร์ทราบถึงขอบเขตเริ่มต้นและสิ้นสุดของเนื้อหาฟังก์ชัน (body)

เราสามารถเรียกใช้ฟังก์ชันใดก็ได้ที่นิยามไว้ โดยระบุชื่อฟังก์ชันตามด้วยคู่วงเล็บเปิดปิด เนื่องจาก `another_function` ถูกนิยามไว้ในโปรแกรม เราจึงสามารถเรียกใช้มันจากภายในฟังก์ชัน `main` ได้ โปรดสังเกตว่าเรานิยาม `another_function` ไว้ _ต่อจาก_ ฟังก์ชัน `main` ในซอร์สโค้ด แต่จริงๆ แล้วเราจะนิยามไว้ก่อนหน้าฟังก์ชัน `main` ก็ได้เช่นกัน Rust ไม่สนใจว่าคุณจะเขียนนิยามฟังก์ชันไว้ที่ใด ขอเพียงแค่นิยามไว้ภายในขอบเขต (scope) ที่โค้ดผู้เรียกสามารถมองเห็นได้ก็พอ

ลองสร้างโปรเจกต์แบบไบนารีใหม่ขึ้นมาชื่อ _functions_ เพื่อทดลองใช้งานฟังก์ชันเพิ่มเติม นำโค้ดตัวอย่างของ `another_function` ใส่ลงใน _src/main.rs_ แล้วลองรันดู จะได้ผลลัพธ์ดังนี้:

```console
{{#include ../listings/ch03-common-programming-concepts/no-listing-16-functions/output.txt}}
```

คำสั่งต่างๆ จะทำงานตามลำดับที่ปรากฏในฟังก์ชัน `main` เริ่มจากพิมพ์ข้อความ “Hello, world!” ก่อน จากนั้นจึงเรียกใช้ `another_function` แล้วพิมพ์ข้อความของฟังก์ชันนั้นตามมา

### พารามิเตอร์

เราสามารถนิยามฟังก์ชันให้รับ _พารามิเตอร์_ (parameter) ได้ ซึ่งพารามิเตอร์ก็คือตัวแปรพิเศษที่เป็นส่วนหนึ่งของลายเซ็นฟังก์ชัน (function signature) เมื่อฟังก์ชันมีพารามิเตอร์ คุณจะสามารถส่งค่าจริงไปให้พารามิเตอร์เหล่านั้นได้ ซึ่งในทางเทคนิค ค่าจริงที่ส่งเข้าไปจะเรียกว่า _อาร์กิวเมนต์_ (argument) อย่างไรก็ดี ในการสื่อสารทั่วไป ผู้คนมักใช้คำว่า _พารามิเตอร์_ และ _อาร์กิวเมนต์_ สลับกัน ไม่ว่าจะหมายถึงตัวแปรที่ระบุในการนิยามฟังก์ชัน หรือค่าจริงที่ส่งเข้าไปตอนเรียกใช้ฟังก์ชันก็ตาม

ใน `another_function` เวอร์ชันนี้ เราได้เพิ่มพารามิเตอร์เข้าไปหนึ่งตัว:

ในลายเซ็นของฟังก์ชัน คุณ _จำเป็นต้อง_ ประกาศชนิดข้อมูลของพารามิเตอร์แต่ละตัวเสมอ นี่เป็นการตัดสินใจออกแบบโดยตั้งใจของ Rust การบังคับให้ระบุชนิดข้อมูลในนิยามฟังก์ชัน ส่งผลให้คอมไพเลอร์แทบไม่จำเป็นต้องให้คุณไประบุชนิดข้อมูลซ้ำในส่วนอื่นๆ ของโค้ดเพื่ออนุมานว่าคุณหมายถึงชนิดข้อมูลใด นอกจากนี้ คอมไพเลอร์ยังสามารถแสดงข้อความแจ้งเตือนข้อผิดพลาดที่เป็นประโยชน์ยิ่งขึ้นได้ หากทราบล่วงหน้าว่าฟังก์ชันนั้นคาดหวังชนิดข้อมูลใด

### สเตตเมนต์และนิพจน์

เนื้อหาของฟังก์ชันประกอบขึ้นจากชุดของสเตตเมนต์ (statement) ซึ่งอาจปิดท้ายด้วยนิพจน์ (expression) ได้ จนถึงตอนนี้ ฟังก์ชันที่เราเขียนกันไปยังไม่มีนิพจน์ปิดท้าย แต่คุณได้เห็นนิพจน์เป็นส่วนหนึ่งของสเตตเมนต์มาบ้างแล้ว เนื่องจาก Rust เป็นภาษาที่ทำงานบนพื้นฐานของนิพจน์ (expression-based language) ความแตกต่างระหว่างสองสิ่งนี้จึงเป็นเรื่องสำคัญที่ต้องทำความเข้าใจ ภาษาโปรแกรมอื่นๆ มักไม่มีความแตกต่างในลักษณะนี้ ดังนั้นเรามาดูกันว่าสเตตเมนต์และนิพจน์คืออะไร และความแตกต่างของพวกมันส่งผลต่อเนื้อหาของฟังก์ชันอย่างไร

- _สเตตเมนต์ (Statement)_ คือชุดคำสั่งที่ดำเนินการบางอย่างและไม่มีการคืนค่า
- _นิพจน์ (Expression)_ คือส่วนที่ประเมินผลลัพธ์ออกมาเป็นค่าใดค่าหนึ่ง

มาดูตัวอย่างกัน

ในความเป็นจริง เราได้ใช้ทั้งสเตตเมนต์และนิพจน์กันไปแล้ว การสร้างตัวแปรและกำหนดค่าให้มันด้วยคีย์เวิร์ด `let` ถือเป็นสเตตเมนต์ ในลิสติ้ง 3-1 คำสั่ง `let y = 6;` คือสเตตเมนต์

สเตตเมนต์ `let y = 6` ไม่มีการคืนค่า จึงไม่มีค่าใดๆ ที่จะนำไปผูกเข้ากับ `x` ได้ ซึ่งจุดนี้แตกต่างจากภาษาอื่นอย่างเช่น C และ Ruby ที่การกำหนดค่าจะคืนค่าของการกำหนดนั้นกลับมาด้วย ทำให้ในภาษาเหล่านั้นคุณสามารถเขียน `x = y = 6` เพื่อกำหนดให้ทั้ง `x` และ `y` มีค่าเป็น `6` ได้ แต่สำหรับใน Rust คุณไม่สามารถทำเช่นนั้นได้

สำหรับนิพจน์ (expression) นั้นจะประเมินผลลัพธ์ออกมาเป็นค่าหนึ่งเสมอ และโค้ดส่วนใหญ่ที่คุณจะเขียนใน Rust ก็คือนิพจน์นี่เอง ลองพิจารณาการคำนวณทางคณิตศาสตร์อย่าง `5 + 6` ซึ่งเป็นนิพจน์ที่ประเมินผลได้เป็น `11` นอกจากนี้นิพจน์ยังสามารถเป็นส่วนประกอบย่อยของสเตตเมนต์ได้อีกด้วย เช่น ในลิสติ้ง 3-1 เลข `6` ในสเตตเมนต์ `let y = 6;` ก็คือนิพจน์ที่ประเมินผลได้ค่า `6` หรือแม้แต่การเรียกใช้ฟังก์ชัน การเรียกใช้มาโคร รวมถึงบล็อกขอบเขตใหม่ที่สร้างขึ้นด้วยวงเล็บปีกกา ต่างก็ล้วนเป็นนิพจน์ทั้งสิ้น ตัวอย่างเช่น:

```rust
{{#rustdoc_include ../listings/ch03-common-programming-concepts/no-listing-20-blocks-are-expressions/src/main.rs}}
```

นิพจน์ส่วนนี้:

```rust,ignore
{
    let x = 3;
    x + 1
}
```

คือบล็อกคำสั่งซึ่งในกรณีนี้จะประเมินผลลัพธ์ออกมาได้เป็น `4` จากนั้นค่านั้นจะถูกผูกเข้ากับตัวแปร `y` โดยสเตตเมนต์ `let` โปรดสังเกตบรรทัด `x + 1` ซึ่งไม่มีเครื่องหมายอัฒภาค (semicolon) ต่อท้าย ต่างจากบรรทัดส่วนใหญ่ที่คุณเคยเห็นมา นิพจน์จะไม่มีเครื่องหมายอัฒภาคปิดท้าย หากคุณใส่อัฒภาคต่อท้ายนิพจน์ มันจะกลายสภาพเป็นสเตตเมนต์ทันที และจะไม่มีการคืนค่าใดๆ ออกมาอีก ขอให้จำจุดนี้ไว้ให้ดีในระหว่างที่เราจะไปศึกษาเรื่องค่าคืนกลับของฟังก์ชันและนิพจน์กันต่อ

### ฟังก์ชันที่มีการคืนค่า
