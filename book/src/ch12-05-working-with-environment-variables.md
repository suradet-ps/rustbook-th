## การใช้งานตัวแปรสภาพแวดล้อม

เราจะปรับปรุงไบนารี `minigrep` ด้วยการเพิ่มฟีเจอร์พิเศษ: ตัวเลือกสำหรับการค้นหาแบบไม่คำนึงถึงตัวพิมพ์เล็ก-ใหญ่ (case-insensitive) ที่ผู้ใช้เปิดได้ผ่านตัวแปรสภาพแวดล้อม (environment variable) เราอาจทำให้ฟีเจอร์นี้เป็นตัวเลือกบรรทัดคำสั่ง (command line) และกำหนดให้ผู้ใช้ป้อนมันทุกครั้งที่ต้องการให้มีผล แต่การทำให้มันเป็นตัวแปรสภาพแวดล้อมแทนจะช่วยให้ผู้ใช้ของเราตั้งตัวแปรสภาพแวดล้อมครั้งเดียว แล้วการค้นหาทั้งหมดของพวกเขาจะไม่คำนึงถึงตัวพิมพ์เล็ก-ใหญ่ในเซสชันเทอร์มินัลนั้น

### การเขียนเทสต์ที่ล้มเหลวสำหรับการค้นหาแบบไม่คำนึงถึงตัวพิมพ์เล็ก-ใหญ่

ก่อนอื่นเราเพิ่มฟังก์ชันใหม่ `search_case_insensitive` ให้ไลบรารี `minigrep` ซึ่งจะถูกเรียกเมื่อตัวแปรสภาพแวดล้อมมีค่า เราจะทำตามกระบวนการ TDD ต่อไป ขั้นตอนแรกจึงเป็นการเขียนเทสต์ (test) ที่ล้มเหลวอีกครั้ง เราจะเพิ่มเทสต์ใหม่สำหรับฟังก์ชัน `search_case_insensitive` ใหม่ และเปลี่ยนชื่อเทสต์เก่าของเราจาก `one_result` เป็น `case_sensitive` เพื่อให้เห็นความแตกต่างระหว่างเทสต์ทั้งสองชัดเจนขึ้น ดังที่แสดงในลิสติ้ง 12-20

โปรดสังเกตว่าเราได้แก้ไข `contents` ของเทสต์เก่าด้วย เราได้เพิ่มบรรทัดใหม่ที่มีข้อความ `"Duct tape."` โดยใช้ _D_ ตัวพิมพ์ใหญ่ ซึ่งไม่ควรตรงกับ query `"duct"` เมื่อเราค้นหาแบบคำนึงถึงตัวพิมพ์เล็ก-ใหญ่ การเปลี่ยนเทสต์เก่าเช่นนี้ช่วยให้แน่ใจว่าเราจะไม่เผลอทำให้ฟังก์ชันการทำงานการค้นหาแบบคำนึงถึงตัวพิมพ์เล็ก-ใหญ่ที่เราอิมพลีเมนต์ไว้แล้วเสียหาย เทสต์นี้ควรผ่านในตอนนี้และควรผ่านต่อไปขณะที่เราทำการค้นหาแบบไม่คำนึงถึงตัวพิมพ์เล็ก-ใหญ่

เทสต์ใหม่สำหรับการค้นหาแบบไม่คำนึงถึงตัวพิมพ์เล็ก-ใหญ่ใช้ `"rUsT"` เป็น query ในฟังก์ชัน `search_case_insensitive` ที่เรากำลังจะเพิ่ม query `"rUsT"` ควรตรงกับบรรทัดที่บรรจุ `"Rust:"` ที่มี _R_ ตัวพิมพ์ใหญ่ และตรงกับบรรทัด `"Trust me."` แม้ว่าทั้งสองจะใช้ตัวพิมพ์ต่างจาก query ก็ตาม นี่คือเทสต์ที่ล้มเหลวของเรา และมันจะคอมไพล์ไม่ผ่านเพราะเรายังไม่ได้นิยามฟังก์ชัน `search_case_insensitive` เชิญเพิ่มการอิมพลีเมนต์โครงร่างที่คืนเวกเตอร์ว่างเสมอ คล้ายกับวิธีที่เราทำกับฟังก์ชัน `search` ในลิสติ้ง 12-16 เพื่อดูว่าเทสต์คอมไพล์ผ่านและล้มเหลว

### การอิมพลีเมนต์ฟังก์ชัน `search_case_insensitive`

ฟังก์ชัน `search_case_insensitive` ดังที่แสดงในลิสติ้ง 12-21 จะเกือบเหมือนกับฟังก์ชัน `search` ความแตกต่างเพียงอย่างเดียวคือเราจะแปลง `query` และแต่ละ `line` เป็นตัวพิมพ์เล็ก เพื่อให้ไม่ว่าอาร์กิวเมนต์ (argument) อินพุตจะเป็นตัวพิมพ์ใด มันจะเป็นตัวพิมพ์เดียวกันเมื่อเราตรวจสอบว่าบรรทัดนั้นบรรจุ query หรือไม่

ก่อนอื่น เราแปลงสตริง `query` เป็นตัวพิมพ์เล็กและเก็บมันไว้ในตัวแปรใหม่ชื่อเดิม ซึ่งบังเงา query ต้นฉบับ การเรียก `to_lowercase` บน query เป็นสิ่งจำเป็น เพื่อว่าไม่ว่า query ของผู้ใช้จะเป็น `"rust"`, `"RUST"`, `"Rust"` หรือ `"rUsT"` เราจะถือว่า query เป็น `"rust"` และไม่คำนึงถึงตัวพิมพ์ แม้ `to_lowercase` จะจัดการ Unicode พื้นฐานได้ แต่มันจะไม่แม่นยำ 100 เปอร์เซ็นต์ หากเรากำลังเขียนแอปพลิเคชันจริง เราคงอยากทำงานเพิ่มเติมตรงนี้ แต่หัวข้อนี้ว่าด้วยตัวแปรสภาพแวดล้อม ไม่ใช่ Unicode เราจึงปล่อยไว้แค่นี้ก่อน

โปรดสังเกตว่าตอนนี้ `query` เป็น `String` ไม่ใช่สตริงสไลซ์ เพราะการเรียก `to_lowercase` สร้างข้อมูลใหม่แทนที่จะอ้างถึงข้อมูลที่มีอยู่ ตัวอย่างเช่น สมมติว่า query คือ `"rUsT"`: สตริงสไลซ์นั้นไม่มี `u` หรือ `t` ตัวพิมพ์เล็กให้เราใช้ เราจึงต้องจัดสรร `String` ใหม่ที่บรรจุ `"rust"` เมื่อเราส่ง `query` เป็นอาร์กิวเมนต์ให้เมธอด `contains` ตอนนี้ เราต้องเพิ่มเครื่องหมายแอมเพอร์แซนด์ เพราะซิกเนเจอร์ของ `contains` ถูกนิยามให้รับสตริงสไลซ์

ต่อไป เราเพิ่มการเรียก `to_lowercase` บนแต่ละ `line` เพื่อแปลงอักขระทั้งหมดเป็นตัวพิมพ์เล็ก ตอนนี้เราได้แปลง `line` และ `query` เป็นตัวพิมพ์เล็กแล้ว เราจะพบรายการที่ตรงกันไม่ว่า query จะเป็นตัวพิมพ์ใดก็ตาม

ในที่นี้ เราสร้างตัวแปรใหม่ชื่อ `ignore_case` เพื่อกำหนดค่าของมัน เราเรียกฟังก์ชัน `env::var` และส่งชื่อของตัวแปรสภาพแวดล้อม `IGNORE_CASE` ให้มัน ฟังก์ชัน `env::var` คืนค่า `Result` ที่จะเป็นวาเรียนต์ `Ok` ที่สำเร็จและบรรจุค่าของตัวแปรสภาพแวดล้อม หากตัวแปรสภาพแวดล้อมถูกตั้งค่าเป็นค่าใดๆ มันจะคืนวาเรียนต์ `Err` หากตัวแปรสภาพแวดล้อมไม่ได้ถูกตั้งค่าไว้

เราใช้เมธอด `is_ok` บน `Result` เพื่อตรวจสอบว่าตัวแปรสภาพแวดล้อมถูกตั้งค่าไว้หรือไม่ ซึ่งหมายความว่าโปรแกรมควรค้นหาแบบไม่คำนึงถึงตัวพิมพ์เล็ก-ใหญ่ หากตัวแปรสภาพแวดล้อม `IGNORE_CASE` ไม่ได้ถูกตั้งค่าเป็นอะไรเลย `is_ok` จะคืนค่า `false` และโปรแกรมจะค้นหาแบบคำนึงถึงตัวพิมพ์เล็ก-ใหญ่ เราไม่สนใจ_ค่า_ของตัวแปรสภาพแวดล้อม สนใจเพียงว่ามันถูกตั้งค่าหรือไม่เท่านั้น เราจึงตรวจสอบ `is_ok` แทนที่จะใช้ `unwrap`, `expect` หรือเมธอดอื่นๆ ที่เราเคยเห็นบน `Result`

เราส่งค่าในตัวแปร `ignore_case` ให้อินสแตนซ์ `Config` เพื่อให้ฟังก์ชัน `run` อ่านค่านั้นและตัดสินใจว่าจะเรียก `search_case_insensitive` หรือ `search` ตามที่เราได้อิมพลีเมนต์ในลิสติ้ง 12-22
