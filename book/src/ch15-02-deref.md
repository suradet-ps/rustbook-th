## ปฏิบัติกับสมาร์ตพอยน์เตอร์เหมือนเรเฟอเรนซ์ทั่วไป

การอิมพลีเมนต์เทรต (trait) `Deref` อนุญาตให้คุณปรับแต่งพฤติกรรมของ_ตัวดำเนินการดีเรเฟอเรนซ์_ (dereference operator) `*` (อย่าสับสนกับตัวดำเนินการคูณหรือตัวดำเนินการ glob) โดยการอิมพลีเมนต์ `Deref` ในลักษณะที่ทำให้สมาร์ตพอยน์เตอร์ (smart pointer) สามารถถูกปฏิบัติเหมือนเรเฟอเรนซ์ (reference) ทั่วไปได้ คุณจะเขียนโค้ดที่ทำงานกับเรเฟอเรนซ์และใช้โค้ดนั้นกับสมาร์ตพอยน์เตอร์ได้ด้วย

ก่อนอื่น มาดูว่าตัวดำเนินการดีเรเฟอเรนซ์ทำงานกับเรเฟอเรนซ์ทั่วไปอย่างไร จากนั้น เราจะลองนิยามชนิดข้อมูลที่กำหนดเองซึ่งทำตัวเหมือน `Box<T>` และดูว่าทำไมตัวดำเนินการดีเรเฟอเรนซ์จึงไม่ทำงานเหมือนกับเรเฟอเรนซ์บนชนิดข้อมูลที่เรานิยามขึ้นใหม่ของเรา จากนั้น เราจะสำรวจว่าการอิมพลีเมนต์เทรต `Deref` ทำให้สมาร์ตพอยน์เตอร์ทำงานในลักษณะคล้ายเรเฟอเรนซ์ได้อย่างไร จากนั้น เราจะดูฟีเจอร์การบังคับดีเรฟ (deref coercion) ของ Rust และวิธีที่มันช่วยให้เราทำงานกับทั้งเรเฟอเรนซ์หรือสมาร์ตพอยน์เตอร์ได้

### การอิมพลีเมนต์เทรต `Deref`

```rust
{{#rustdoc_include ../listings/ch15-smart-pointers/listing-15-10/src/main.rs:here}}
```

วากยสัมพันธ์ `type Target = T;` นิยามชนิดที่เชื่อมโยง (associated type) สำหรับเทรต `Deref` ใช้ ชนิดที่เชื่อมโยงเป็นวิธีที่ต่างออกไปเล็กน้อยในการประกาศพารามิเตอร์เจเนอริก แต่คุณยังไม่ต้องกังวลเกี่ยวกับมันตอนนี้ เราจะครอบคลุมมันโดยละเอียดมากขึ้นในบทที่ 20

เราเติมบอดี้ของเมธอด `deref` ด้วย `&self.0` เพื่อให้ `deref` คืนเรเฟอเรนซ์ไปยังค่าที่เราต้องการเข้าถึงด้วยตัวดำเนินการ `*` ย้อนนึกถึง[“การสร้างชนิดข้อมูลที่แตกต่างกันด้วยทูเพิลสตรัค”][tuple-structs]<!-- ignore --> ในบทที่ 5 ว่า `.0` เข้าถึงค่าแรกในทูเพิลสตรัค ฟังก์ชัน `main` ในลิสติ้ง 15-9 ที่เรียก `*` บนค่า `MyBox<T>` ตอนนี้คอมไพล์ผ่านแล้ว และแอสเซอร์ชันต่างๆ ก็ผ่านด้วย!

หากไม่มีเทรต `Deref` คอมไพเลอร์จะดีเรเฟอเรนซ์ได้เฉพาะเรเฟอเรนซ์ `&` เท่านั้น เมธอด `deref` มอบความสามารถให้คอมไพเลอร์รับค่าของชนิดใดก็ได้ที่อิมพลีเมนต์ `Deref` และเรียกเมธอด `deref` เพื่อรับเรเฟอเรนซ์ที่มันรู้วิธีดีเรเฟอเรนซ์

เมื่อเราใส่ `*y` ในลิสติ้ง 15-9 เบื้องหลังแล้ว Rust รันโค้ดนี้จริงๆ:

```rust,ignore
*(y.deref())
```

Rust แทนที่ตัวดำเนินการ `*` ด้วยการเรียกเมธอด `deref` แล้วตามด้วยการดีเรเฟอเรนซ์ธรรมดา เพื่อให้เราไม่ต้องคิดว่าเราจำเป็นต้องเรียกเมธอด `deref` หรือไม่ ฟีเจอร์ของ Rust นี้ช่วยให้เราเขียนโค้ดที่ทำงานเหมือนกันไม่ว่าเราจะมีเรเฟอเรนซ์ทั่วไปหรือชนิดข้อมูลที่อิมพลีเมนต์ `Deref`

เหตุผลที่เมธอด `deref` คืนเรเฟอเรนซ์ไปยังค่า และเหตุผลที่การดีเรเฟอเรนซ์ธรรมดานอกวงเล็บใน `*(y.deref())` ยังคงจำเป็นนั้น เกี่ยวข้องกับระบบความเป็นเจ้าของ (ownership) หากเมธอด `deref` คืนค่าโดยตรงแทนที่จะเป็นเรเฟอเรนซ์ไปยังค่า ค่านั้นจะถูกย้ายออกจาก `self` เราไม่ต้องการรับความเป็นเจ้าของค่าภายใน `MyBox<T>` ในกรณีนี้หรือในกรณีส่วนใหญ่ที่เราใช้ตัวดำเนินการดีเรเฟอเรนซ์

โปรดสังเกตว่าตัวดำเนินการ `*` ถูกแทนที่ด้วยการเรียกเมธอด `deref` แล้วตามด้วยการเรียกตัวดำเนินการ `*` เพียงครั้งเดียว ทุกครั้งที่เราใช้ `*` ในโค้ดของเรา เพราะการแทนที่ตัวดำเนินการ `*` ไม่เรียกซ้ำอย่างไม่สิ้นสุด เราจึงได้ข้อมูลชนิด `i32` ซึ่งตรงกับ `5` ใน `assert_eq!` ในลิสติ้ง 15-9

### การใช้การบังคับดีเรฟในฟังก์ชันและเมธอด

_การบังคับดีเรฟ_ (deref coercion) แปลงเรเฟอเรนซ์ไปยังชนิดข้อมูลที่อิมพลีเมนต์เทรต `Deref` ให้เป็นเรเฟอเรนซ์ไปยังอีกชนิดข้อมูลหนึ่ง ตัวอย่างเช่น การบังคับดีเรฟสามารถแปลง `&String` เป็น `&str` ได้เพราะ `String` อิมพลีเมนต์เทรต `Deref` ในลักษณะที่คืน `&str` การบังคับดีเรฟเป็นความสะดวกที่ Rust ทำกับอาร์กิวเมนต์ของฟังก์ชันและเมธอด และมันทำงานเฉพาะกับชนิดข้อมูลที่อิมพลีเมนต์เทรต `Deref` เท่านั้น มันเกิดขึ้นโดยอัตโนมัติเมื่อเราส่งเรเฟอเรนซ์ไปยังค่าของชนิดข้อมูลหนึ่งเป็นอาร์กิวเมนต์ให้กับฟังก์ชันหรือเมธอดที่ไม่ตรงกับชนิดของพารามิเตอร์ในนิยามของฟังก์ชันหรือเมธอดนั้น ลำดับการเรียกเมธอด `deref` จะแปลงชนิดข้อมูลที่เรามอบให้เป็นชนิดข้อมูลที่พารามิเตอร์ต้องการ

การบังคับดีเรฟถูกเพิ่มเข้าไปใน Rust เพื่อให้นักเขียนโปรแกรมที่เขียนการเรียกฟังก์ชันและเมธอดไม่จำเป็นต้องเพิ่มเรเฟอเรนซ์และการดีเรเฟอเรนซ์แบบชัดแจ้งด้วย `&` และ `*` มากเท่าเดิม ฟีเจอร์การบังคับดีเรฟยังช่วยให้เราเขียนโค้ดที่ทำงานได้กับทั้งเรเฟอเรนซ์หรือสมาร์ตพอยน์เตอร์ได้มากขึ้น

เพื่อดูการบังคับดีเรฟในภาคปฏิบัติ เราใช้ชนิด `MyBox<T>` ที่เรานิยามในลิสติ้ง 15-8 รวมถึงการอิมพลีเมนต์ `Deref` ที่เราเพิ่มในลิสติ้ง 15-10 ลิสติ้ง 15-11 แสดงนิยามของฟังก์ชันที่มีพารามิเตอร์เป็นสตริงสไลซ์ (string slice)

<a id="how-deref-coercion-interacts-with-mutability"></a>

### การจัดการการบังคับดีเรฟกับเรเฟอเรนซ์แบบเปลี่ยนแปลงได้

คล้ายกับวิธีที่คุณใช้เทรต `Deref` เพื่อโอเวอร์ไรด์ตัวดำเนินการ `*` บนเรเฟอเรนซ์แบบเปลี่ยนแปลงไม่ได้ (immutable) คุณสามารถใช้เทรต `DerefMut` เพื่อโอเวอร์ไรด์ตัวดำเนินการ `*` บนเรเฟอเรนซ์แบบเปลี่ยนแปลงได้ (mutable reference) ได้

Rust ทำการบังคับดีเรฟเมื่อมันพบชนิดข้อมูลและการอิมพลีเมนต์เทรตในสามกรณี:

1. จาก `&T` ไปยัง `&U` เมื่อ `T: Deref<Target=U>`
2. จาก `&mut T` ไปยัง `&mut U` เมื่อ `T: DerefMut<Target=U>`
3. จาก `&mut T` ไปยัง `&U` เมื่อ `T: Deref<Target=U>`

สองกรณีแรกเหมือนกัน ยกเว้นว่ากรณีที่สองใช้ความสามารถในการเปลี่ยนแปลงค่า (mutability) กรณีแรกกล่าวว่าหากคุณมี `&T` และ `T` อิมพลีเมนต์ `Deref` ไปยังชนิด `U` บางชนิด คุณจะได้ `&U` อย่างโปร่งใส กรณีที่สองกล่าวว่าการบังคับดีเรฟแบบเดียวกันเกิดขึ้นกับเรเฟอเรนซ์แบบเปลี่ยนแปลงได้

กรณีที่สามซับซ้อนกว่า: Rust จะบังคับเรเฟอเรนซ์แบบเปลี่ยนแปลงได้ให้เป็นเรเฟอเรนซ์แบบเปลี่ยนแปลงไม่ได้ด้วย แต่การย้อนกลับ_ไม่_สามารถทำได้: เรเฟอเรนซ์แบบเปลี่ยนแปลงไม่ได้จะไม่มีวันถูกบังคับให้เป็นเรเฟอเรนซ์แบบเปลี่ยนแปลงได้ เพราะกฎการยืม หากคุณมีเรเฟอเรนซ์แบบเปลี่ยนแปลงได้ เรเฟอเรนซ์แบบเปลี่ยนแปลงได้นั้นต้องเป็นเรเฟอเรนซ์เดียวไปยังข้อมูลนั้น (ไม่เช่นนั้นโปรแกรมจะไม่คอมไพล์) การแปลงเรเฟอเรนซ์แบบเปลี่ยนแปลงได้หนึ่งตัวเป็นเรเฟอเรนซ์แบบเปลี่ยนแปลงไม่ได้หนึ่งตัวจะไม่ละเมิดกฎการยืม การแปลงเรเฟอเรนซ์แบบเปลี่ยนแปลงไม่ได้เป็นเรเฟอเรนซ์แบบเปลี่ยนแปลงได้จะต้องอาศัยว่าเรเฟอเรนซ์แบบเปลี่ยนแปลงไม่ได้ตั้งต้นเป็นเรเฟอเรนซ์แบบเปลี่ยนแปลงไม่ได้เพียงตัวเดียวไปยังข้อมูลนั้น แต่กฎการยืมไม่ได้รับประกันเช่นนั้น ดังนั้น Rust จึงไม่สามารถสันนิษฐานได้ว่าการแปลงเรเฟอเรนซ์แบบเปลี่ยนแปลงไม่ได้เป็นเรเฟอเรนซ์แบบเปลี่ยนแปลงได้นั้นเป็นไปได้
