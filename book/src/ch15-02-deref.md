## ปฏิบัติกับสมาร์ตพอยน์เตอร์เหมือนเรเฟอเรนซ์ทั่วไป

การอิมพลีเมนต์เทรต `Deref` ช่วยให้คุณสามารถปรับแต่งพฤติกรรมของ_ตัวดำเนินการดีเรเฟอเรนซ์ (dereference operator)_ `*` ได้ (อย่าสับสนกับตัวดำเนินการคูณหรือตัวดำเนินการ glob) การอิมพลีเมนต์ `Deref` ในลักษณะที่ทำให้สมาร์ตพอยน์เตอร์ (smart pointer) ถูกปฏิบัติเสมือนเป็นเรเฟอเรนซ์ (reference) ทั่วไป จะช่วยให้คุณเขียนโค้ดที่ทำงานร่วมกับเรเฟอเรนซ์ และนำโค้ดนั้นไปใช้งานกับสมาร์ตพอยน์เตอร์ได้ด้วยเช่นกัน

ก่อนอื่น เราจะมาดูกันว่าตัวดำเนินการดีเรเฟอเรนซ์ทำงานกับเรเฟอเรนซ์ทั่วไปอย่างไร จากนั้น เราจะลองนิยามชนิดข้อมูลแบบกำหนดเองที่ทำงานคล้าย `Box<T>` แล้วดูว่าเหตุใดตัวดำเนินการดีเรเฟอเรนซ์จึงยังไม่ทำงานเสมือนเรเฟอเรนซ์บนชนิดข้อมูลที่เพิ่งสร้างขึ้นใหม่นี้ ถัดมา เราจะไปสำรวจว่าการอิมพลีเมนต์เทรต `Deref` ช่วยให้สมาร์ตพอยน์เตอร์ทำงานคล้ายเรเฟอเรนซ์ได้อย่างไร และท้ายที่สุด เราจะศึกษาฟีเจอร์การแปลงชนิดข้อมูลด้วยการดีเรฟ หรือ _การบังคับดีเรฟ (deref coercion)_ ของ Rust พร้อมดูว่ามันช่วยให้เราทำงานร่วมกับทั้งเรเฟอเรนซ์หรือสมาร์ตพอยน์เตอร์ได้อย่างไร

### การนิยามสมาร์ตพอยน์เตอร์ของเราเอง

มาลองสร้างชนิดข้อมูลแบบห่อหุ้ม (wrapper type) ที่คล้ายคลึงกับชนิดข้อมูล `Box<T>` ในไลบรารีมาตรฐาน เพื่อสัมผัสด้วยตนเองว่าชนิดข้อมูลสมาร์ตพอยน์เตอร์มีพฤติกรรมแตกต่างจากเรเฟอเรนซ์ตามค่าเริ่มต้นอย่างไร จากนั้นเราจะดูวิธีเพิ่มความสามารถในการใช้งานตัวดำเนินการดีเรเฟอเรนซ์เข้าไป

> หมายเหตุ: มีความแตกต่างสำคัญประการหนึ่งระหว่างชนิดข้อมูล `MyBox<T>` ที่เรากำลังจะสร้างขึ้น กับ `Box<T>` ของจริง นั่นคือ เวอร์ชันของเราจะไม่เก็บข้อมูลไว้บนฮีป เนื่องจากเรามุ่งเน้นตัวอย่างนี้ไปที่เรื่อง `Deref` ดังนั้นสถานที่ที่เก็บข้อมูลจริงจึงมีความสำคัญน้อยกว่าพฤติกรรมที่เสมือนพอยน์เตอร์

### การอิมพลีเมนต์เทรต `Deref`

ดังที่ได้พูดคุยกันใน [“การอิมพลีเมนต์เทรตบนชนิดข้อมูล”][impl-trait]<!-- ignore --> ในบทที่ 10 ในการอิมพลีเมนต์เทรต เราจำเป็นต้องจัดเตรียมโค้ดการทำงานสำหรับเมธอดที่เทรตนั้นกำหนดไว้ โดยเทรต `Deref` ที่ไลบรารีมาตรฐานจัดเตรียมไว้ให้นั้น กำหนดให้เราต้องอิมพลีเมนต์เมธอดหนึ่งตัวชื่อ `deref` ซึ่งจะทำการยืม `self` และคืนค่าเป็นเรเฟอเรนซ์ที่ชี้ไปยังข้อมูลภายใน ลิสติ้ง 15-10 แสดงการอิมพลีเมนต์ `Deref` เพื่อนำไปเพิ่มเข้ากับนิยามของ `MyBox<T>`

```rust
{{#rustdoc_include ../listings/ch15-smart-pointers/listing-15-10/src/main.rs:here}}
```

ไวยากรณ์ `type Target = T;` เป็นการนิยามชนิดข้อมูลที่เกี่ยวข้อง (associated type) ให้เทรต `Deref` นำไปใช้งาน โดยชนิดข้อมูลที่เกี่ยวข้องเป็นอีกวิธีหนึ่งในการประกาศพารามิเตอร์เจเนอริก ซึ่งคุณยังไม่ต้องกังวลกับมันในตอนนี้ เพราะเราจะไปเจาะลึกรายละเอียดกันในบทที่ 20

เราเขียนเนื้อหาภายในเมธอด `deref` ด้วย `&self.0` เพื่อให้ `deref` คืนเรเฟอเรนซ์ที่ชี้ไปยังค่าที่เราต้องการเข้าถึงด้วยตัวดำเนินการ `*` (จำได้ไหมว่าจากหัวข้อ [“การสร้างชนิดข้อมูลที่แตกต่างกันด้วยทูเพิล struct”][tuple-structs]<!-- ignore --> ในบทที่ 5 การใช้ `.0` เป็นการเข้าถึงค่าตัวแรกในทูเพิลสตรัค) เมื่อเพิ่มโค้ดนี้แล้ว ฟังก์ชัน `main` ในลิสติ้ง 15-9 ที่เรียกใช้ `*` บนค่า `MyBox<T>` ก็จะคอมไพล์ผ่าน และการยืนยันเงื่อนไขทั้งหมดก็ทำงานได้อย่างถูกต้อง!

หากไม่มีเทรต `Deref` คอมไพเลอร์จะสามารถดีเรเฟอเรนซ์ได้เฉพาะเรเฟอเรนซ์ `&` เท่านั้น แต่เมธอด `deref` ได้มอบความสามารถให้คอมไพเลอร์สามารถรับค่าของชนิดข้อมูลใด ๆ ที่อิมพลีเมนต์ `Deref` แล้วเรียกเมธอด `deref` เพื่อแปลงให้กลายเป็นเรเฟอเรนซ์ที่คอมไพเลอร์รู้วิธีดีเรเฟอเรนซ์ได้

เมื่อเราเขียน `*y` ในลิสติ้ง 15-9 แท้จริงแล้วเบื้องหลัง Rust ได้รันโค้ดต่อไปนี้:

```rust,ignore
*(y.deref())
```

Rust จะแทนที่ตัวดำเนินการ `*` ด้วยการเรียกเมธอด `deref` แล้วตามด้วยการดีเรเฟอเรนซ์แบบธรรมดาหนึ่งครั้ง ทำให้เราไม่จำเป็นต้องมาคอยพะวงว่าเมื่อใดจะต้องเรียกใช้เมธอด `deref` ด้วยตนเอง ฟีเจอร์นี้ของ Rust ช่วยให้เราสามารถเขียนโค้ดที่ทำงานได้เหมือนกันทุกประการ ไม่ว่าเราจะส่งเรเฟอเรนซ์ธรรมดา หรือส่งชนิดข้อมูลที่อิมพลีเมนต์ `Deref` มาให้ก็ตาม

เหตุผลที่เมธอด `deref` ต้องคืนค่าเป็นเรเฟอเรนซ์ที่ชี้ไปยังค่า และเหตุใดการดีเรเฟอเรนซ์แบบธรรมดานอกวงเล็บใน `*(y.deref())` จึงยังคงจำเป็นอยู่นั้น เกี่ยวข้องกับระบบความเป็นเจ้าของ (ownership) เพราะหากเมธอด `deref` คืนค่านั้นออกมาโดยตรงแทนที่จะเป็นเรเฟอเรนซ์ ค่านั้นก็จะถูกย้ายออกจาก `self` แต่เราไม่ได้ต้องการเข้ายึดครองสิทธิ์ความเป็นเจ้าของค่าที่อยู่ภายใน `MyBox<T>` ในกรณีนี้ หรือในกรณีส่วนใหญ่ที่เราใช้ตัวดำเนินการดีเรเฟอเรนซ์

โปรดสังเกตว่า ทุกครั้งที่เราใช้ `*` ในโค้ด ตัวดำเนินการ `*` จะถูกแทนที่ด้วยการเรียกเมธอด `deref` ตามด้วยการใช้ตัวดำเนินการ `*` อีกเพียงหนึ่งครั้งเท่านั้น และเนื่องจากการแทนที่ตัวดำเนินการ `*` นี้ไม่ได้เกิดการเรียกซ้ำอย่างไม่สิ้นสุด เราจึงได้ข้อมูลชนิด `i32` ซึ่งตรงกับค่า `5` ในคำสั่ง `assert_eq!` ของลิสติ้ง 15-9 ในที่สุด

### การใช้การบังคับดีเรฟในฟังก์ชันและเมธอด

_การบังคับดีเรฟ (deref coercion)_ คือการแปลงเรเฟอเรนซ์ของชนิดข้อมูลที่อิมพลีเมนต์เทรต `Deref` ให้กลายเป็นเรเฟอเรนซ์ของอีกชนิดข้อมูลหนึ่ง ตัวอย่างเช่น การบังคับดีเรฟสามารถแปลง `&String` ให้เป็น `&str` ได้ เนื่องจาก `String` ได้อิมพลีเมนต์เทรต `Deref` ในรูปแบบที่คืนค่าเป็น `&str` การบังคับดีเรฟเป็นคุณสมบัติอำนวยความสะดวกที่ Rust จัดการให้อัตโนมัติกับอาร์กิวเมนต์ที่ส่งให้กับฟังก์ชันและเมธอด และจะทำงานเฉพาะกับชนิดข้อมูลที่อิมพลีเมนต์เทรต `Deref` เท่านั้น โดยจะเกิดขึ้นโดยอัตโนมัติเมื่อเราส่งเรเฟอเรนซ์ของชนิดข้อมูลหนึ่งเป็นอาร์กิวเมนต์ให้กับฟังก์ชันหรือเมธอด แต่ชนิดของมันไม่ตรงกับชนิดของพารามิเตอร์ที่นิยามไว้ ซึ่งชุดการเรียกเมธอด `deref` อย่างต่อเนื่องจะช่วยแปลงชนิดข้อมูลที่เราส่งเข้าไปให้ตรงกับชนิดข้อมูลที่พารามิเตอร์ต้องการ

ฟีเจอร์การบังคับดีเรฟถูกเพิ่มเข้ามาใน Rust เพื่อให้นักพัฒนาที่เขียนโค้ดเรียกใช้ฟังก์ชันและเมธอดไม่ต้องมาคอยใส่การอ้างอิงและการดีเรเฟอเรนซ์ด้วย `&` และ `*` อย่างโจ่งแจ้งมากเกินไป นอกจากนี้ ฟีเจอร์ดังกล่าวยังช่วยให้เราเขียนโค้ดที่สามารถนำไปประยุกต์ใช้ได้ทั้งกับเรเฟอเรนซ์และสมาร์ตพอยน์เตอร์ได้มากยิ่งขึ้น

เพื่อให้เห็นภาพการบังคับดีเรฟในการใช้งานจริง เราจะนำชนิดข้อมูล `MyBox<T>` ที่เรานิยามไว้ในลิสติ้ง 15-8 ร่วมกับการอิมพลีเมนต์ `Deref` ในลิสติ้ง 15-10 มาใช้งาน โดยลิสติ้ง 15-11 แสดงนิยามของฟังก์ชันที่มีพารามิเตอร์เป็นสตริงสไลซ์ (string slice)

<a id="how-deref-coercion-interacts-with-mutability"></a>

### การจัดการการบังคับดีเรฟกับเรเฟอเรนซ์แบบเปลี่ยนแปลงได้

ในทำนองเดียวกับที่คุณใช้เทรต `Deref` เพื่อเขียนทับพฤติกรรม (override) ของตัวดำเนินการ `*` บนเรเฟอเรนซ์แบบแก้ไขไม่ได้ (immutable reference) คุณก็สามารถใช้เทรต `DerefMut` เพื่อเขียนทับพฤติกรรมของตัวดำเนินการ `*` บนเรเฟอเรนซ์แบบแก้ไขได้ (mutable reference) ได้เช่นกัน

Rust จะดำเนินการบังคับดีเรฟเมื่อพบชนิดข้อมูลและการอิมพลีเมนต์เทรตใน 3 กรณีต่อไปนี้:

1. จาก `&T` ไปยัง `&U` เมื่อ `T: Deref<Target=U>`
2. จาก `&mut T` ไปยัง `&mut U` เมื่อ `T: DerefMut<Target=U>`
3. จาก `&mut T` ไปยัง `&U` เมื่อ `T: Deref<Target=U>`

สองกรณีแรกนั้นเหมือนกันทุกประการ เว้นแต่กรณีที่สองจะจัดการกับความสามารถในการเปลี่ยนแปลงค่า (mutability) โดยกรณีแรกระบุว่า หากคุณมี `&T` และ `T` อิมพลีเมนต์ `Deref` ไปยังชนิดข้อมูล `U` คุณจะสามารถแปลงไปเป็น `&U` ได้อย่างโปร่งใส และกรณีที่สองก็ระบุว่าการบังคับดีเรฟแบบเดียวกันนี้จะเกิดขึ้นกับเรเฟอเรนซ์แบบเปลี่ยนแปลงได้เช่นกัน

ส่วนกรณีที่สามจะมีความซับซ้อนยิ่งขึ้น: กล่าวคือ Rust สามารถแปลงเรเฟอเรนซ์แบบเปลี่ยนแปลงได้ให้กลายเป็นเรเฟอเรนซ์แบบเปลี่ยนแปลงไม่ได้ได้ แต่ในทางกลับกันจะ_ไม่_สามารถทำได้ นั่นคือ เรเฟอเรนซ์แบบเปลี่ยนแปลงไม่ได้จะไม่มีวันถูกบังคับให้เป็นเรเฟอเรนซ์แบบเปลี่ยนแปลงได้เด็ดขาด ทั้งนี้เป็นไปตามกฎการยืม (borrowing rules) เพราะหากคุณมีเรเฟอเรนซ์แบบเปลี่ยนแปลงได้ เรเฟอเรนซ์นั้นจะต้องเป็นการอ้างอิงเพียงหนึ่งเดียวไปยังข้อมูลชิ้นนั้น (มิฉะนั้นโปรแกรมจะคอมไพล์ไม่ผ่าน) ดังนั้นการแปลงเรเฟอเรนซ์แบบเปลี่ยนแปลงได้หนึ่งตัวให้กลายเป็นเรเฟอเรนซ์แบบเปลี่ยนแปลงไม่ได้หนึ่งตัวจึงไม่มีทางละเมิดกฎการยืม ในขณะที่การแปลงเรเฟอเรนซ์แบบเปลี่ยนแปลงไม่ได้ให้กลายเป็นเรเฟอเรนซ์แบบเปลี่ยนแปลงได้นั้น จะต้องมั่นใจก่อนว่าเรเฟอเรนซ์แบบเปลี่ยนแปลงไม่ได้ตัวแรกเป็นเรเฟอเรนซ์เพียงตัวเดียวที่มีอยู่จริง ๆ ซึ่งกฎการยืมไม่ได้รับประกันเช่นนั้น Rust จึงไม่สามารถสันนิษฐานได้ว่าการแปลงเรเฟอเรนซ์แบบเปลี่ยนแปลงไม่ได้ให้เป็นเรเฟอเรนซ์แบบเปลี่ยนแปลงได้นั้นจะปลอดภัยและเป็นไปได้
