# การเขียนเทสต์อัตโนมัติ

ในเรียงความปี 1972 ของเขา “The Humble Programmer” Edsger W. Dijkstra กล่าวว่า “การทดสอบโปรแกรม (program testing) อาจเป็นวิธีที่ได้ผลดีมากในการแสดงว่ามีบั๊กอยู่ แต่ก็ไร้ความหวังอย่างสิ้นเชิงในการแสดงว่ามันไม่มี” นั่นไม่ได้หมายความว่าเราไม่ควรพยายามทดสอบให้มากที่สุดเท่าที่จะทำได้!

_ความถูกต้อง_ (correctness) ในโปรแกรมของเราคือขอบเขตที่โค้ดของเราทำในสิ่งที่เราตั้งใจให้มันทำ Rust ถูกออกแบบโดยให้ความสำคัญอย่างสูงกับความถูกต้องของโปรแกรม แต่ความถูกต้องนั้นซับซ้อนและพิสูจน์ได้ไม่ง่าย ระบบชนิดข้อมูลของ Rust แบ่งเบาภาระนี้ไปส่วนใหญ่ แต่ระบบชนิดข้อมูลก็ไม่สามารถจับได้ทุกอย่าง ด้วยเหตุนี้ Rust จึงมีการรองรับการเขียนเทสต์ซอฟต์แวร์อัตโนมัติ

สมมติว่าเราเขียนฟังก์ชัน `add_two` ที่บวก 2 เข้ากับตัวเลขใดก็ตามที่ส่งให้มัน ซิกเนเจอร์ของฟังก์ชันนี้รับจำนวนเต็มเป็นพารามิเตอร์และคืนจำนวนเต็มเป็นผลลัพธ์ เมื่อเราอิมพลีเมนต์และคอมไพล์ฟังก์ชันนั้น Rust จะทำการตรวจสอบชนิดข้อมูลและการตรวจสอบการยืมทั้งหมดที่คุณได้เรียนรู้มาจนถึงตอนนี้ เพื่อให้แน่ใจว่า ตัวอย่างเช่น เราไม่ได้ส่งค่า `String` หรือเรเฟอเรนซ์ที่ไม่ถูกต้องเข้าไปในฟังก์ชันนี้ แต่ Rust _ไม่สามารถ_ ตรวจสอบได้ว่าฟังก์ชันนี้จะทำในสิ่งที่เราตั้งใจไว้อย่างแม่นยำ นั่นคือคืนพารามิเตอร์บวก 2 ไม่ใช่พารามิเตอร์บวก 10 หรือพารามิเตอร์ลบ 50! ตรงนี้เองที่เทสต์เข้ามามีบทบาท

เราสามารถเขียนเทสต์ที่ยืนยัน ตัวอย่างเช่นว่า เมื่อเราส่ง `3` ให้ฟังก์ชัน `add_two` ค่าที่คืนกลับมาคือ `5` เราสามารถรันเทสต์เหล่านี้ทุกครั้งที่เราแก้ไขโค้ดของเรา เพื่อให้แน่ใจว่าพฤติกรรมที่ถูกต้องซึ่งมีอยู่เดิมไม่เปลี่ยนแปลงไป

การทดสอบเป็นทักษะที่ซับซ้อน แม้ว่าเราไม่สามารถครอบคลุมรายละเอียดทุกอย่างเกี่ยวกับการเขียนเทสต์ที่ดีได้ในบทเดียว แต่ในบทนี้เราจะพูดคุยถึงกลไกของเครื่องมือทดสอบของ Rust เราจะพูดถึงแอนโนเทชัน (annotation) และมาโครที่คุณใช้ได้เมื่อเขียนเทสต์ พฤติกรรมเริ่มต้นและตัวเลือกที่มีให้สำหรับการรันเทสต์ และวิธีจัดระเบียบเทสต์ออกเป็นการทดสอบระดับยูนิต (unit test) และการทดสอบแบบอินทิเกรชัน (integration test)
