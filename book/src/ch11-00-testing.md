# การเขียนเทสต์อัตโนมัติ

ในเรียงความปี 1972 หัวข้อ “The Humble Programmer” ของเขา Edsger W. Dijkstra ได้กล่าวไว้ว่า “การทดสอบโปรแกรม (program testing) เป็นวิธีที่มีประสิทธิภาพอย่างยิ่งในการแสดงให้เห็นว่ามีบั๊กอยู่ แต่กลับไม่อาจพิสูจน์ได้เลยว่าโปรแกรมนั้นปลอดบั๊กอย่างแท้จริง” กระนั้น ก็ไม่ได้หมายความว่าเราไม่ควรพยายามทดสอบโค้ดให้มากที่สุดเท่าที่จะทำได้!

_ความถูกต้อง_ (correctness) ของโปรแกรม หมายถึงระดับที่โค้ดของเราสามารถทำงานได้ตรงตามสิ่งที่เราตั้งใจให้ทำอย่างแท้จริง ภาษา Rust ได้รับการออกแบบโดยให้ความสำคัญอย่างยิ่งยวดกับความถูกต้องของโปรแกรม แต่ความถูกต้องเป็นเรื่องซับซ้อนและพิสูจน์ได้ไม่ง่ายนัก แม้ว่าระบบชนิดข้อมูลของ Rust จะช่วยแบกรับภาระส่วนใหญ่ตรงนี้ไป แต่ระบบชนิดข้อมูลก็ไม่สามารถดักจับข้อผิดพลาดเชิงตรรกะได้ทั้งหมด ด้วยเหตุนี้ Rust จึงมีเครื่องมือสนับสนุนการเขียนชุดทดสอบซอฟต์แวร์แบบอัตโนมัติมาให้ในตัว

สมมติว่าเราเขียนฟังก์ชัน `add_two` เพื่อนำ 2 ไปบวกเข้ากับตัวเลขใดๆ ก็ตามที่ส่งเข้ามา ซิกเนเจอร์ของฟังก์ชันนี้จะรับเลขจำนวนเต็มเป็นพารามิเตอร์และส่งคืนผลลัพธ์เป็นเลขจำนวนเต็ม เมื่อเราอิมพลีเมนต์และคอมไพล์ฟังก์ชันดังกล่าว Rust จะทำการตรวจสอบชนิดข้อมูล (type checking) และตรวจสอบการยืม (borrow checking) ทั้งหมดตามที่คุณได้เรียนรู้มาจนถึงตอนนี้ เพื่อให้แน่ใจว่า เช่น เราไม่ได้ส่งค่า `String` หรือเรเฟอเรนซ์ที่ไม่ถูกต้องเข้าไปในฟังก์ชัน แต่ Rust _ไม่สามารถ_ ตรวจสอบได้ว่าฟังก์ชันนี้ทำงานได้ตรงตามเจตนาของเราอย่างแม่นยำหรือไม่ ซึ่งในที่นี้คือการส่งคืนค่าพารามิเตอร์บวก 2 ไม่ใช่พารามิเตอร์บวก 10 หรือพารามิเตอร์ลบ 50! และนี่คือจุดที่การทดสอบ (test) เข้ามามีบทบาทสำคัญ

เราสามารถเขียนเทสต์เพื่อยืนยันว่า เช่น เมื่อเราส่งค่า `3` ให้กับฟังก์ชัน `add_two` ค่าที่ได้กลับคืนมาจะต้องเป็น `5` เสมอ และเราสามารถรันชุดทดสอบเหล่านี้ได้ทุกครั้งที่มีการแก้ไขโค้ด เพื่อให้มั่นใจได้ว่าพฤติกรรมที่ถูกต้องซึ่งมีอยู่เดิมจะไม่ผิดเพี้ยนไป

การทดสอบซอฟต์แวร์เป็นทักษะที่มีความลึกซึ้งและซับซ้อน แม้ว่าเราไม่อาจครอบคลุมรายละเอียดทุกแง่มุมของการเขียนเทสต์ที่ดีได้ภายในบทเดียว แต่ในบทนี้เราจะมาเจาะลึกกลไกและเครื่องมืออำนวยความสะดวกด้านการทดสอบของ Rust เราจะพูดถึงแอตทริบิวต์กำกับ (annotations) และมาโครที่คุณสามารถนำมาใช้ในการเขียนเทสต์ พฤติกรรมเริ่มต้นและตัวเลือกต่างๆ สำหรับการสั่งรันเทสต์ รวมถึงวิธีจัดระเบียบโครงสร้างของชุดทดสอบออกเป็นยูนิตเทสต์ (unit test) และอินทิเกรชันเทสต์ (integration test)
