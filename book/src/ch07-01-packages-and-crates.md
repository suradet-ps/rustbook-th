## แพ็กเกจและเครต

ส่วนประกอบแรกของระบบมอดูลที่เราจะมาเรียนรู้กันคือ แพ็กเกจ (packages) และเครต (crates)

_เครต (crate)_ คือหน่วยโค้ดที่เล็กที่สุดที่คอมไพเลอร์ Rust จะหยิบขึ้นมาประมวลผลในคราวเดียว แม้ว่าคุณจะสั่งรัน `rustc` โดยตรงแทนที่จะใช้ `cargo` และส่งไฟล์ซอร์สโค้ดไปเพียงไฟล์เดียว (เหมือนที่เราเคยทำในหัวข้อ [“พื้นฐานของโปรแกรม Rust”][basics]<!-- ignore --> ในบทที่ 1) ตัวคอมไพเลอร์ก็ยังถือว่าไฟล์เดี่ยวนั้นคือเครตหนึ่งตัว โดยเครตสามารถบรรจุมอดูล (modules) ต่างๆ ไว้ภายในได้ และมอดูลเหล่านั้นก็อาจถูกแยกไปนิยามไว้ในไฟล์อื่นๆ ที่จะถูกคอมไพล์รวมเข้ากับตัวเครต ดังที่เราจะได้เห็นกันในหัวข้อต่อๆ ไป

เครตสามารถแบ่งออกเป็น 2 รูปแบบ ได้แก่: เครตไบนารี (binary crate) หรือเครตไลบรารี (library crate)
_เครตไบนารี_ คือโปรแกรมที่คุณสามารถคอมไพล์ออกมาเป็นไฟล์รันได้ (executable binary) เพื่อนำไปสั่งรัน เช่น โปรแกรมบรรทัดคำสั่ง (CLI) หรือโปรแกรมเซิร์ฟเวอร์ โดยเครตไบนารีแต่ละตัวจะต้องมีฟังก์ชันชื่อ `main` เสมอ เพื่อกำหนดจุดเริ่มต้นการทำงานเมื่อไฟล์รันได้เริ่มทำงาน ซึ่งเครตทั้งหมดที่เราได้สร้างขึ้นมาจนถึงจุดนี้ล้วนเป็นเครตไบนารีทั้งสิ้น

ในทางกลับกัน _เครตไลบรารี_ จะไม่มีฟังก์ชัน `main` และไม่สามารถคอมไพล์ออกมาเป็นไฟล์รันได้โดยตรง แต่จะถูกสร้างขึ้นเพื่อนิยามฟังก์ชันการทำงานต่างๆ โดยมีเป้าหมายเพื่อนำไปแบ่งปันและเรียกใช้งานร่วมกับโปรเจกต์อื่นๆ ตัวอย่างเช่น เครต `rand` ที่เรานำมาใช้ใน [บทที่ 2][rand]<!-- ignore --> ซึ่งทำหน้าที่ช่วยสุ่มตัวเลข โดยส่วนใหญ่แล้ว เมื่อชาว Rustacean พูดคำว่า “เครต” มักจะหมายถึงเครตไลบรารี และมักใช้คำว่า “เครต” ในความหมายเดียวกับคำว่า “ไลบรารี” ในการเขียนโปรแกรมทั่วไป

_รากของเครต (crate root)_ คือไฟล์ซอร์สโค้ดตั้งต้นที่คอมไพเลอร์ Rust จะเริ่มอ่านเป็นจุดแรก และทำหน้าที่เป็นมอดูลราก (root module) ของเครตของคุณ (เราจะอธิบายเรื่องมอดูลอย่างละเอียดในหัวข้อ [“ควบคุมสโคปและความเป็นส่วนตัวด้วยมอดูล”][modules]<!-- ignore -->)

_แพ็กเกจ (package)_ คือชุดของเครตตั้งแต่หนึ่งตัวขึ้นไปที่รวมกลุ่มกันเพื่อส่งมอบชุดฟังก์ชันการทำงานบางอย่าง โดยแพ็กเกจจะประกอบด้วยไฟล์ _Cargo.toml_ ซึ่งทำหน้าที่อธิบายวิธีการบิลด์เครตเหล่านั้น ในความเป็นจริงแล้ว ตัว Cargo เองก็เป็นแพ็กเกจหนึ่งที่บรรจุเครตไบนารีสำหรับเครื่องมือบรรทัดคำสั่งที่คุณใช้สั่งบิลด์โค้ด และในแพ็กเกจ Cargo ก็ยังมีเครตไลบรารีที่เครตไบนารีตัวนั้นต้องพึ่งพาอยู่อีกด้วย ซึ่งโปรเจกต์อื่นๆ ก็สามารถเรียกใช้เครตไลบรารีของ Cargo เพื่อนำตรรกะการทำงานแบบเดียวกับที่เครื่องมือ Cargo ใช้ไปต่อยอดได้เช่นกัน

แพ็กเกจหนึ่งแพ็กเกจสามารถมีเครตไบนารีกี่ตัวก็ได้ตามต้องการ แต่จะมีเครตไลบรารีได้มากที่สุดเพียง 1 ตัวเท่านั้น และทุกแพ็กเกจจะต้องมีเครตอย่างน้อย 1 ตัวเสมอ ไม่ว่าจะเป็นเครตไลบรารีหรือเครตไบนารีก็ตาม

ลองมาดูสิ่งที่จะเกิดขึ้นเมื่อเราสร้างแพ็กเกจใหม่ขึ้นมา เริ่มแรก ให้เราป้อนคำสั่ง `cargo new my-project`:

```console
$ cargo new my-project
     Created binary (application) `my-project` package
$ ls my-project
Cargo.toml
src
$ ls my-project/src
main.rs
```

หลังจากเรารันคำสั่ง `cargo new my-project` แล้ว เราลองใช้คำสั่ง `ls` เพื่อดูสิ่งที่ Cargo สร้างขึ้นมาให้ ในไดเรกทอรี _my-project_ จะมีไฟล์ _Cargo.toml_ ซึ่งแสดงถึงการเป็นแพ็กเกจ นอกจากนี้ยังมีไดเรกทอรี _src_ ที่บรรจุไฟล์ _main.rs_ อยู่ภายใน หากคุณลองเปิดไฟล์ _Cargo.toml_ ในโปรแกรมแก้ไขข้อความ คุณจะสังเกตเห็นว่าไม่มีส่วนใดเลยที่กล่าวถึงไฟล์ _src/main.rs_ นั่นเป็นเพราะ Cargo มีข้อตกลงร่วมกัน (convention) ว่าไฟล์ _src/main.rs_ คือรากของเครต (crate root) สำหรับเครตไบนารีที่มีชื่อเดียวกับชื่อแพ็กเกจ และในทำนองเดียวกัน Cargo ก็รับรู้อยู่แล้วว่า หากภายในไดเรกทอรีของแพ็กเกจมีไฟล์ _src/lib.rs_ อยู่ แพ็กเกจนั้นก็จะมีเครตไลบรารีที่มีชื่อเดียวกับแพ็กเกจ โดยมีไฟล์ _src/lib.rs_ ทำหน้าที่เป็นรากของเครต โดย Cargo จะเป็นผู้ส่งไฟล์รากของเครตเหล่านี้ไปให้ `rustc` ทำการบิลด์เป็นไลบรารีหรือไบนารีต่อไป

ในตัวอย่างนี้ เรามีแพ็กเกจที่บรรจุเพียงแค่ไฟล์ _src/main.rs_ ซึ่งหมายความว่ามันมีเพียงเครตไบนารีชื่อ `my-project` ตัวเดียวเท่านั้น แต่หากแพ็กเกจใดมีทั้งไฟล์ _src/main.rs_ และ _src/lib.rs_ แพ็กเกจนั้นก็จะมีเครต 2 ตัว คือเครตไบนารีและเครตไลบรารี ซึ่งทั้งสองจะมีชื่อเดียวกับชื่อแพ็กเกจ นอกจากนี้ แพ็กเกจยังสามารถมีเครตไบนารีได้หลายตัว โดยการนำไฟล์ซอร์สโค้ดไปวางไว้ในไดเรกทอรี _src/bin_ ซึ่งไฟล์แต่ละไฟล์ที่อยู่ในนั้นจะกลายเป็นเครตไบนารีแยกต่างหากแต่ละตัวทันที
