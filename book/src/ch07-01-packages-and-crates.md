## แพ็กเกจและเครต

ส่วนแรกของระบบมอดูลที่เราจะครอบคลุมคือแพ็กเกจ (package) และเครต (crate)

_เครต_ คือโค้ดจำนวนน้อยที่สุดที่คอมไพเลอร์ Rust พิจารณาในแต่ละครั้ง แม้ว่าคุณจะรัน `rustc` แทน `cargo` และส่งไฟล์ซอร์สโค้ดไฟล์เดียว (อย่างที่เราเคยทำใน[“พื้นฐานของโปรแกรม Rust”][basics]<!-- ignore --> ในบทที่ 1) คอมไพเลอร์ก็ยังถือว่าไฟล์นั้นเป็นเครตหนึ่งตัว เครตสามารถบรรจุมอดูล (module) ได้ และมอดูลเหล่านั้นอาจถูกนิยามไว้ในไฟล์อื่นที่ถูกคอมไพล์ไปพร้อมกับเครต ดังที่เราจะเห็นในหัวข้อต่อๆ ไป

เครตสามารถมาในรูปแบบใดรูปแบบหนึ่งจากสองแบบ: เครตไบนารี (binary crate) หรือเครตไลบรารี (library crate) _เครตไบนารี_ เป็นโปรแกรมที่คุณคอมไพล์เป็นไฟล์รันได้ (executable) แล้วนำไปรันได้ เช่นโปรแกรมบรรทัดคำสั่ง (command line) หรือเซิร์ฟเวอร์ แต่ละเครตต้องมีฟังก์ชันชื่อ `main` ที่นิยามว่าเกิดอะไรขึ้นเมื่อไฟล์รันได้นั้นทำงาน เครตทั้งหมดที่เราสร้างมาจนถึงตอนนี้เป็นเครตไบนารี

_เครตไลบรารี_ ไม่มีฟังก์ชัน `main` และไม่คอมไพล์เป็นไฟล์รันได้ แต่จะนิยามฟังก์ชันการทำงานที่ตั้งใจไว้ให้แชร์กับหลายโปรเจกต์ ตัวอย่างเช่น เครต `rand` ที่เราใช้ใน[บทที่ 2][rand]<!-- ignore --> ให้ฟังก์ชันการทำงานที่สร้างตัวเลขสุ่ม โดยส่วนใหญ่แล้ว เมื่อชาว Rustacean พูดว่า “เครต” พวกเขาหมายถึงเครตไลบรารี และใช้คำว่า “เครต” สลับกับแนวคิดการเขียนโปรแกรมทั่วไปอย่าง “ไลบรารี” ได้

_รากของเครต_ (crate root) คือไฟล์ซอร์สที่คอมไพเลอร์ Rust เริ่มต้นจากมันและประกอบขึ้นเป็นมอดูลรากของเครตของคุณ (เราจะอธิบายมอดูลโดยละเอียดใน[“ควบคุมสโคปและความเป็นส่วนตัวด้วยมอดูล”][modules]<!-- ignore -->)

_แพ็กเกจ_ คือกลุ่มของเครตตั้งแต่หนึ่งตัวขึ้นไปที่ให้ชุดฟังก์ชันการทำงานหนึ่งชุด แพ็กเกจประกอบด้วยไฟล์ _Cargo.toml_ ที่อธิบายวิธีบิลด์เครตเหล่านั้น จริงๆ แล้ว Cargo เป็นแพ็กเกจที่บรรจุเครตไบนารีสำหรับเครื่องมือบรรทัดคำสั่งที่คุณใช้บิลด์โค้ดของคุณ แพ็กเกจ Cargo ยังบรรจุเครตไลบรารีที่เครตไบนารีนั้นพึ่งพาด้วย โปรเจกต์อื่นสามารถพึ่งพาเครตไลบรารี Cargo เพื่อใช้ตรรกะเดียวกับที่เครื่องมือบรรทัดคำสั่ง Cargo ใช้ได้

แพ็กเกจหนึ่งๆ บรรจุเครตไบนารีได้มากเท่าที่คุณต้องการ แต่มีเครตไลบรารีได้อย่างมากเพียงหนึ่งตัว แพ็กเกจต้องบรรจุเครตอย่างน้อยหนึ่งตัว ไม่ว่าจะเป็นเครตไลบรารีหรือเครตไบนารี

มาดูกันว่าเกิดอะไรขึ้นเมื่อเราสร้างแพ็กเกจ ก่อนอื่น เราป้อนคำสั่ง `cargo new my-project`:

```console
$ cargo new my-project
     Created binary (application) `my-project` package
$ ls my-project
Cargo.toml
src
$ ls my-project/src
main.rs
```

หลังจากเรารัน `cargo new my-project` เราใช้ `ls` ดูว่า Cargo สร้างอะไรขึ้นมา ในไดเรกทอรี _my-project_ มีไฟล์ _Cargo.toml_ ซึ่งทำให้เราได้แพ็กเกจหนึ่งอัน และยังมีไดเรกทอรี _src_ ที่บรรจุ _main.rs_ เปิด _Cargo.toml_ ในโปรแกรมแก้ไขข้อความของคุณแล้วสังเกตว่าไม่มีการกล่าวถึง _src/main.rs_ เลย Cargo ใช้ธรรมเนียมปฏิบัติว่า _src/main.rs_ คือรากของเครตสำหรับเครตไบนารีที่มีชื่อเดียวกับแพ็กเกจ ในทำนองเดียวกัน Cargo รู้ว่าหากไดเรกทอรีของแพ็กเกจมี _src/lib.rs_ แพ็กเกจนั้นก็มีเครตไลบรารีที่มีชื่อเดียวกับแพ็กเกจ และ _src/lib.rs_ คือรากของเครตของเครตไลบรารีนั้น Cargo ส่งไฟล์รากของเครตเหล่านั้นให้ `rustc` เพื่อบิลด์ไลบรารีหรือไบนารี

ในที่นี้ เรามีแพ็กเกจที่บรรจุเพียง _src/main.rs_ ซึ่งหมายความว่ามันบรรจุเพียงเครตไบนารีชื่อ `my-project` หากแพ็กเกจบรรจุทั้ง _src/main.rs_ และ _src/lib.rs_ มันจะมีสองเครต คือไบนารีและไลบรารี ทั้งคู่มีชื่อเดียวกับแพ็กเกจ แพ็กเกจสามารถมีเครตไบนารีหลายตัวได้โดยวางไฟล์ไว้ในไดเรกทอรี _src/bin_: แต่ละไฟล์จะเป็นเครตไบนารีแยกกัน
