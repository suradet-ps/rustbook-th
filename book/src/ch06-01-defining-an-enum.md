## การนิยาม enum

ในขณะที่ struct ให้วิธีจัดกลุ่มฟิลด์ (field) และข้อมูลที่เกี่ยวข้องกันเข้าด้วยกัน เช่น `Rectangle` ที่มี `width` และ `height` ของมัน enum ให้วิธีบอกว่าค่าๆ หนึ่งเป็นหนึ่งในชุดค่าที่เป็นไปได้ ตัวอย่างเช่น เราอาจต้องการบอกว่า `Rectangle` เป็นหนึ่งในชุดรูปร่างที่เป็นไปได้ซึ่งรวมถึง `Circle` และ `Triangle` ด้วย เพื่อทำเช่นนี้ Rust อนุญาตให้เราเข้ารหัสความเป็นไปได้เหล่านี้เป็น enum ได้

มาดูสถานการณ์หนึ่งที่เราอาจต้องการแสดงออกในโค้ดกัน และดูว่าเหตุใด enum จึงมีประโยชน์และเหมาะสมกว่า struct ในกรณีนี้ สมมติว่าเราต้องทำงานกับที่อยู่ IP ปัจจุบัน มีมาตรฐานหลักสองแบบที่ใช้สำหรับที่อยู่ IP ได้แก่ เวอร์ชันสี่และเวอร์ชันหก เนื่องจากสิ่งเหล่านี้เป็นความเป็นไปได้เพียงอย่างเดียวสำหรับที่อยู่ IP ที่โปรแกรมของเราจะพบเจอ เราจึงสามารถ_แจกแจง_วาเรียนต์ (variant) ที่เป็นไปได้ทั้งหมด ซึ่งเป็นที่มาของชื่อ enumeration นั่นเอง

ที่อยู่ IP ใดๆ สามารถเป็นที่อยู่เวอร์ชันสี่หรือเวอร์ชันหกได้ แต่มิใช่ทั้งสองอย่างในเวลาเดียวกัน คุณสมบัตินี้ของที่อยู่ IP ทำให้โครงสร้างข้อมูลแบบ enum เหมาะสม เพราะค่า enum หนึ่งค่าสามารถเป็นได้เพียงหนึ่งในวาเรียนต์ของมันเท่านั้น ที่อยู่ทั้งเวอร์ชันสี่และเวอร์ชันหกก็ยังคงเป็นที่อยู่ IP โดยพื้นฐาน ดังนั้นจึงควรถูกปฏิบัติเป็นชนิดเดียวกันเมื่อโค้ดกำลังจัดการกับสถานการณ์ที่ใช้ได้กับที่อยู่ IP ทุกชนิด

เราสามารถแสดงแนวคิดนี้ในโค้ดได้โดยนิยามการแจกแจง `IpAddrKind` และระบุชนิดที่เป็นไปได้ที่ที่อยู่ IP สามารถเป็นได้ นั่นคือ `V4` และ `V6` สิ่งเหล่านี้คือวาเรียนต์ของ enum:


ในที่นี้ เราได้นิยาม struct `IpAddr` ที่มีสองฟิลด์ ได้แก่ ฟิลด์ `kind` ที่มีชนิดเป็น `IpAddrKind` (enum ที่เรานิยามไว้ก่อนหน้านี้) และฟิลด์ `address` ที่มีชนิดเป็น `String` เรามีอินสแตนซ์สองตัวของ struct นี้ ตัวแรกคือ `home` และมีค่า `IpAddrKind::V4` เป็น `kind` ของมันพร้อมข้อมูลที่อยู่ที่เชื่อมโยงคือ `127.0.0.1` อินสแตนซ์ตัวที่สองคือ `loopback` มันมีวาเรียนต์อีกตัวของ `IpAddrKind` เป็นค่า `kind` ของมัน นั่นคือ `V6` และมีที่อยู่ `::1` เชื่อมโยงอยู่กับมัน เราได้ใช้ struct เพื่อรวมค่า `kind` และ `address` เข้าด้วยกัน ดังนั้นตอนนี้วาเรียนต์จึงเชื่อมโยงกับค่าแล้ว

อย่างไรก็ตาม การแสดงแนวคิดเดียวกันโดยใช้เพียง enum นั้นกระชับกว่า แทนที่จะเป็น enum ซ้อนอยู่ใน struct เราสามารถใส่ข้อมูลลงในแต่ละวาเรียนต์ของ enum ได้โดยตรง นิยามใหม่ของ enum `IpAddr` นี้บอกว่าทั้งวาเรียนต์ `V4` และ `V6` จะมีค่า `String` ที่เชื่อมโยงอยู่:

```rust
{{#rustdoc_include ../listings/ch06-enums-and-pattern-matching/no-listing-02-enum-with-data/src/main.rs:here}}
```

เราแนบข้อมูลเข้ากับแต่ละวาเรียนต์ของ enum โดยตรง จึงไม่จำเป็นต้องมี struct เพิ่มเติม ในที่นี้ยังเห็นรายละเอียดอีกอย่างของการทำงานของ enum ได้ง่ายขึ้นด้วย: ชื่อของแต่ละวาเรียนต์ enum ที่เรานิยามก็กลายเป็นฟังก์ชันที่สร้างอินสแตนซ์ของ enum นั้นด้วย นั่นคือ `IpAddr::V4()` เป็นการเรียกฟังก์ชันที่รับอาร์กิวเมนต์ (argument) ชนิด `String` และคืนอินสแตนซ์ของชนิด `IpAddr` เราจะได้ฟังก์ชันตัวสร้างนี้มานิยามให้โดยอัตโนมัติอันเป็นผลมาจากการนิยาม enum

การใช้ enum แทน struct ยังมีข้อได้เปรียบอีกอย่างหนึ่ง: แต่ละวาเรียนต์สามารถมีชนิดและปริมาณข้อมูลที่เชื่อมโยงที่แตกต่างกันได้ ที่อยู่ IP เวอร์ชันสี่จะมีองค์ประกอบตัวเลขสี่ตัวที่มีค่าระหว่าง 0 ถึง 255 เสมอ หากเราต้องการจัดเก็บที่อยู่ `V4` เป็นค่า `u8` สี่ค่า แต่ยังคงแสดงที่อยู่ `V6` เป็นค่า `String` หนึ่งค่า เราจะทำไม่ได้หากใช้ struct แต่ enum จัดการกรณีนี้ได้อย่างง่ายดาย:

```rust
{{#rustdoc_include ../listings/ch06-enums-and-pattern-matching/no-listing-03-variants-with-different-data/src/main.rs:here}}
```

เราได้แสดงวิธีที่แตกต่างกันหลายวิธีในการนิยามโครงสร้างข้อมูลเพื่อจัดเก็บที่อยู่ IP เวอร์ชันสี่และเวอร์ชันหก อย่างไรก็ตาม ปรากฏว่าความต้องการจัดเก็บที่อยู่ IP และเข้ารหัสว่ามันเป็นชนิดใดนั้นพบได้บ่อยมากจนกระทั่ง[ไลบรารีมาตรฐานมีนิยามที่เราใช้งานได้!][IpAddr]<!-- ignore --> มาดูกันว่าไลบรารีมาตรฐานนิยาม `IpAddr` อย่างไร มันมี enum และวาเรียนต์ตรงตามที่เรานิยามและใช้งาน แต่ฝังข้อมูลที่อยู่ไว้ภายในวาเรียนต์ในรูปแบบของ struct สองตัวที่แตกต่างกัน ซึ่งนิยามแตกต่างกันสำหรับแต่ละวาเรียนต์:

```rust
struct Ipv4Addr {
    // --snip--
}

struct Ipv6Addr {
    // --snip--
}

enum IpAddr {
    V4(Ipv4Addr),
    V6(Ipv6Addr),
}
```

โค้ดนี้แสดงให้เห็นว่าคุณสามารถใส่ข้อมูลชนิดใดก็ได้ไว้ในวาเรียนต์ของ enum เช่น สตริง ชนิดตัวเลข หรือ struct คุณยังสามารถใส่ enum อีกตัวเข้าไปได้ด้วย! อีกทั้งชนิดข้อมูลในไลบรารีมาตรฐานก็มักไม่ได้ซับซ้อนกว่าสิ่งที่คุณคิดขึ้นมาได้มากนัก

โปรดสังเกตว่าแม้ไลบรารีมาตรฐานจะมีนิยามของ `IpAddr` เราก็ยังสร้างและใช้นิยามของเราเองได้โดยไม่ขัดแย้งกัน เพราะเรายังไม่ได้นำนิยามของไลบรารีมาตรฐานเข้ามาในสโคป (scope) ของเรา เราจะพูดคุยเพิ่มเติมเกี่ยวกับการนำชนิดข้อมูลเข้าสู่สโคปในบทที่ 7

enum นี้มีสี่วาเรียนต์ที่มีชนิดต่างกัน:

- `Quit`: ไม่มีข้อมูลใดๆ เชื่อมโยงอยู่กับมันเลย
- `Move`: มีฟิลด์ที่มีชื่อเหมือนที่ struct มี
- `Write`: มี `String` หนึ่งค่า
- `ChangeColor`: มีค่า `i32` สามค่า

การนิยาม enum ที่มีวาเรียนต์อย่างเช่นในลิสติ้ง 6-2 นั้นคล้ายกับการนิยาม struct ชนิดต่างๆ กัน ยกเว้นว่า enum ไม่ได้ใช้คำสงวน (keyword) `struct` และวาเรียนต์ทั้งหมดถูกรวบไว้ด้วยกันภายใต้ชนิด `Message` struct ต่อไปนี้สามารถเก็บข้อมูลชุดเดียวกับที่วาเรียนต์ของ enum ข้างต้นเก็บได้:

```rust

```

แต่หากเราใช้ struct ต่างๆ กัน ซึ่งแต่ละตัวมีชนิดของตัวเอง เราจะนิยามฟังก์ชันที่รับข้อความชนิดใดก็ได้เหล่านี้ได้ไม่ง่ายเท่ากับการใช้ enum `Message` ที่นิยามในลิสติ้ง 6-2 ซึ่งเป็นชนิดเดียว

### enum `Option`

หัวข้อนี้สำรวจกรณีศึกษาของ `Option` ซึ่งเป็น enum อีกตัวที่นิยามโดยไลบรารีมาตรฐาน ชนิด `Option` เข้ารหัสสถานการณ์ที่พบได้บ่อยมากซึ่งค่าหนึ่งอาจเป็นอะไรบางอย่าง หรืออาจไม่ใช่อะไรเลย

ตัวอย่างเช่น หากคุณขอรายการแรกในลิสต์ที่ไม่ว่างเปล่า คุณจะได้ค่ามา หากคุณขอรายการแรกในลิสต์ที่ว่างเปล่า คุณจะไม่ได้อะไรเลย การแสดงแนวคิดนี้ในแง่ของระบบชนิดข้อมูลหมายความว่าคอมไพเลอร์สามารถตรวจสอบได้ว่าคุณได้จัดการทุกกรณีที่คุณควรจัดการแล้วหรือไม่ ฟังก์ชันการทำงานนี้สามารถป้องกันบั๊กที่พบได้บ่อยมากในภาษาโปรแกรมอื่น

การออกแบบภาษาโปรแกรมมักถูกมองในแง่ของคุณลักษณะที่คุณรวมไว้ แต่คุณลักษณะที่คุณตัดออกก็สำคัญเช่นกัน Rust ไม่มีคุณลักษณะ null ที่ภาษาโปรแกรมอื่นหลายภาษามี _Null_ คือค่าที่หมายความว่าไม่มีค่าอยู่ตรงนั้น ในภาษาที่มี null ตัวแปรสามารถอยู่ในสถานะใดสถานะหนึ่งในสองสถานะได้เสมอ: null หรือไม่ใช่ null

ในการนำเสนอของเขาในปี 2009 เรื่อง “Null References: The Billion Dollar Mistake” Tony Hoare ผู้ประดิษฐ์ null กล่าวไว้ดังนี้:

> ผมเรียกมันว่าความผิดพลาดพันล้านดอลลาร์ของผม ในตอนนั้น ผมกำลังออกแบบระบบชนิดข้อมูลที่ครอบคลุมสำหรับเรเฟอเรนซ์เป็นครั้งแรกในภาษาเชิงวัตถุ
> เป้าหมายของผมคือทำให้แน่ใจว่าการใช้เรเฟอเรนซ์ทั้งหมดจะปลอดภัยอย่างสมบูรณ์ โดยมีการตรวจสอบที่ทำโดยอัตโนมัติจากคอมไพเลอร์
> แต่ผมก็ต้านทานสิ่งล่อใจที่จะใส่เรเฟอเรนซ์ null เข้าไปไม่ไหว เพราะมันอิมพลีเมนต์ง่ายมาก
> สิ่งนี้นำไปสู่ข้อผิดพลาด ช่องโหว่ และระบบล่มมากมายนับไม่ถ้วน ซึ่งคงก่อความเจ็บปวดและความเสียหายมูลค่าหนึ่งพันล้านดอลลาร์ในช่วงสี่สิบปีที่ผ่านมา

ปัญหาของค่า null คือ หากคุณพยายามใช้ค่า null เสมือนเป็นค่าไม่ใช่ null คุณจะได้รับข้อผิดพลาดบางอย่าง เนื่องจากคุณสมบัติเป็น null หรือไม่ใช่ null นี้แผ่ขยายไปทั่ว การเกิดข้อผิดพลาดแบบนี้จึงเป็นเรื่องง่ายมาก

อย่างไรก็ตาม แนวคิดที่ null พยายามจะแสดงออกมานั้นยังมีประโยชน์อยู่ นั่นคือ null เป็นค่าที่ไม่ถูกต้องหรือไม่มีอยู่ด้วยเหตุผลบางอย่างในขณะนั้น

ปัญหาไม่ใช่ที่แนวคิดจริงๆ แต่เป็นที่การอิมพลีเมนต์ (implementation) โดยเฉพาะ ด้วยเหตุนี้ Rust จึงไม่มี null แต่มี enum ที่สามารถเข้ารหัสแนวคิดของค่าที่มีอยู่หรือไม่มีอยู่ได้ enum นี้คือ `Option<T>` และมันถูก[นิยามโดยไลบรารีมาตรฐาน][option]<!-- ignore --> ดังนี้:

```rust
enum Option<T> {
    None,
    Some(T),
}
```

enum `Option<T>` มีประโยชน์มากจนกระทั่งถูกรวมไว้ในพรีลูด (prelude) ด้วย คุณไม่จำเป็นต้องนำมันเข้าสู่สโคปอย่างชัดแจ้ง วาเรียนต์ของมันก็ถูกรวมไว้ในพรีลูดเช่นกัน: คุณสามารถใช้ `Some` และ `None` ได้โดยตรงโดยไม่ต้องมีคำนำหน้า `Option::` enum `Option<T>` ก็ยังคงเป็น enum ธรรมดา และ `Some(T)` กับ `None` ก็ยังเป็นวาเรียนต์ของชนิด `Option<T>`

วากยสัมพันธ์ (syntax) `<T>` เป็นฟีเจอร์ของ Rust ที่เรายังไม่ได้พูดถึง มันคือพารามิเตอร์ชนิดข้อมูลแบบเจเนอริก (generic type parameter) และเราจะครอบคลุมเจเนอริกโดยละเอียดมากขึ้นในบทที่ 10 สำหรับตอนนี้ สิ่งที่คุณจำเป็นต้องรู้ก็คือ `<T>` หมายความว่าวาเรียนต์ `Some` ของ enum `Option` สามารถเก็บข้อมูลหนึ่งชิ้นที่มีชนิดใดก็ได้ และแต่ละชนิดที่เป็นรูปธรรมที่ถูกใช้แทน `T` ทำให้ชนิด `Option<T>` โดยรวมกลายเป็นชนิดที่แตกต่างกัน นี่คือตัวอย่างการใช้ค่า `Option` เพื่อเก็บชนิดตัวเลขและชนิดอักขระ:

ชนิดของ `some_number` คือ `Option<i32>` ชนิดของ `some_char` คือ `Option<char>` ซึ่งเป็นชนิดที่แตกต่างกัน Rust สามารถอนุมานชนิดเหล่านี้ได้เพราะเราได้ระบุค่าภายในวาเรียนต์ `Some` สำหรับ `absent_number` นั้น Rust ต้องการให้เราระบุชนิด `Option` โดยรวม: คอมไพเลอร์ (compiler) ไม่สามารถอนุมานชนิดที่วาเรียนต์ `Some` ที่สอดคล้องกันจะเก็บได้จากการดูเฉพาะค่า `None` เท่านั้น ในที่นี้ เราบอก Rust ว่าเราต้องการให้ `absent_number` มีชนิดเป็น `Option<i32>`

เมื่อเรามีค่า `Some` เรารู้ว่ามีค่าอยู่ และค่านั้นถูกเก็บไว้ภายใน `Some` เมื่อเรามีค่า `None` ในแง่หนึ่งมันหมายความเช่นเดียวกับ null: เราไม่มีค่าที่ถูกต้อง แล้วทำไมการมี `Option<T>` จึงดีกว่าการมี null?

พูดสั้นๆ ก็คือ เพราะ `Option<T>` และ `T` (โดยที่ `T` สามารถเป็นชนิดใดก็ได้) เป็นชนิดที่แตกต่างกัน คอมไพเลอร์จะไม่ยอมให้เราใช้ค่า `Option<T>` ราวกับว่ามันเป็นค่าที่ถูกต้องแน่นอน ตัวอย่างเช่น โค้ดนี้จะไม่คอมไพล์ เพราะมันพยายามบวก `i8` เข้ากับ `Option<i8>`:

เข้มข้นจริงๆ! โดยแท้จริงแล้ว ข้อความแสดงข้อผิดพลาดนี้หมายความว่า Rust ไม่เข้าใจวิธีบวก `i8` กับ `Option<i8>` เพราะมันเป็นชนิดที่แตกต่างกัน เมื่อเรามีค่าที่มีชนิดอย่าง `i8` ใน Rust คอมไพเลอร์จะทำให้แน่ใจว่าเรามีค่าที่ถูกต้องเสมอ เราสามารถดำเนินการต่อได้อย่างมั่นใจโดยไม่ต้องตรวจสอบ null ก่อนใช้ค่านั้น เฉพาะเมื่อเรามี `Option<i8>` (หรือชนิดของค่าอะไรก็ตามที่เรากำลังทำงานด้วย) เท่านั้นที่เราต้องกังวลเกี่ยวกับการอาจไม่มีค่า และคอมไพเลอร์จะทำให้แน่ใจว่าเราจัดการกรณีนั้นก่อนใช้ค่า

กล่าวอีกนัยหนึ่ง คุณต้องแปลง `Option<T>` เป็น `T` ก่อนที่คุณจะดำเนินการแบบ `T` กับมันได้ โดยทั่วไปแล้ว สิ่งนี้ช่วยจับปัญหาที่พบบ่อยที่สุดอย่างหนึ่งของ null นั่นคือการสมมติว่าอะไรบางอย่างไม่ใช่ null เมื่อมันเป็น null จริงๆ

การขจัดความเสี่ยงจากการสมมติค่าไม่ใช่ null อย่างผิดพลาดช่วยให้คุณมั่นใจในโค้ดของคุณมากขึ้น การจะมีค่าที่อาจเป็น null ได้นั้น คุณต้องเลือกเปิดใช้งานอย่างชัดแจ้งโดยทำให้ชนิดของค่านั้นเป็น `Option<T>` จากนั้น เมื่อคุณใช้ค่านั้น คุณจำเป็นต้องจัดการกรณีที่ค่าเป็น null อย่างชัดแจ้ง ทุกที่ที่ค่าหนึ่งมีชนิดที่ไม่ใช่ `Option<T>` คุณ_สามารถ_สมมติได้อย่างปลอดภัยว่าค่านั้นไม่ใช่ null นี่เป็นการตัดสินใจออกแบบโดยเจตนาของ Rust เพื่อจำกัดการแผ่ขยายของ null และเพิ่มความปลอดภัยของโค้ด Rust

แล้วคุณจะดึงค่า `T` ออกจากวาเรียนต์ `Some` ได้อย่างไรเมื่อคุณมีค่าที่มีชนิด `Option<T>` เพื่อให้คุณใช้ค่านั้นได้? enum `Option<T>` มีเมธอดจำนวนมากที่มีประโยชน์ในหลากหลายสถานการณ์ คุณสามารถดูได้ใน[เอกสารประกอบของมัน][docs]<!-- ignore --> การทำความคุ้นเคยกับเมธอดบน `Option<T>` จะมีประโยชน์อย่างยิ่งในการเดินทางกับ Rust ของคุณ

โดยทั่วไปแล้ว การจะใช้ค่า `Option<T>` คุณต้องการโค้ดที่จะจัดการกับแต่ละวาเรียนต์ คุณต้องการโค้ดบางส่วนที่จะรันเฉพาะเมื่อคุณมีค่า `Some(T)` และโค้ดนี้ได้รับอนุญาตให้ใช้ `T` ที่อยู่ข้างในได้ คุณต้องการโค้ดอีกส่วนหนึ่งให้รันเฉพาะเมื่อคุณมีค่า `None` และโค้ดนั้นไม่มีค่า `T` ให้ใช้งาน เอ็กซ์เพรสชัน `match` เป็นโครงสร้างการควบคุมโฟลว์ที่ทำเช่นนี้ได้พอดีเมื่อใช้กับ enum: มันจะรันโค้ดที่แตกต่างกันโดยขึ้นอยู่กับว่ามันมีวาเรียนต์ใดของ enum และโค้ดนั้นสามารถใช้ข้อมูลภายในค่าที่จับคู่ได้
