## เทรตขั้นสูง

เราได้แนะนำให้รู้จักกับเทรต (trait) เป็นครั้งแรกในหัวข้อ[“นิยามพฤติกรรมร่วมด้วยเทรต”][traits]<!-- ignore --> ในบทที่ 10 แต่ในตอนนั้นเรายังไม่ได้ลงลึกถึงรายละเอียดขั้นสูง เมื่อตอนนี้คุณมีความเข้าใจเกี่ยวกับ Rust มากขึ้นแล้ว เราจึงพร้อมที่จะมาเจาะลึกในรายละเอียดปลีกย่อยกัน

### การนิยามเทรตด้วยชนิดข้อมูลที่เชื่อมโยง

_ชนิดข้อมูลที่เชื่อมโยง (associated types)_ ทำหน้าที่เชื่อมตัวแทนชนิดข้อมูล (type placeholder) เข้ากับเทรต เพื่อให้นิยามเมธอดของเทรตสามารถนำชนิดข้อมูลตัวแทนเหล่านี้ไปใช้ในซิกเนเจอร์ได้ โดยผู้ที่อิมพลีเมนต์เทรตจะเป็นผู้ระบุชนิดข้อมูลที่เป็นรูปธรรม (concrete type) ที่จะนำมาใช้งานแทนตัวแทนชนิดข้อมูลสำหรับการอิมพลีเมนต์นั้น ๆ ด้วยวิธีนี้ เราจึงสามารถนิยามเทรตที่ใช้ชนิดข้อมูลบางอย่างได้ โดยไม่จำเป็นต้องรู้ล่วงหน้าว่าชนิดข้อมูลจริง ๆ คืออะไร จนกระทั่งถึงเวลาที่เทรตนั้นถูกนำไปอิมพลีเมนต์

เราได้เกริ่นไว้ว่าฟีเจอร์ขั้นสูงส่วนใหญ่ในบทนี้มักไม่ค่อยได้ใช้งานบ่อยนัก แต่ชนิดข้อมูลที่เชื่อมโยงจะอยู่ตรงกึ่งกลาง กล่าวคือ มีการใช้งานน้อยกว่าฟีเจอร์ทั่วไปที่อธิบายไว้ในส่วนอื่น ๆ ของหนังสือ แต่ก็ยังพบบ่อยกว่าฟีเจอร์ขั้นสูงตัวอื่น ๆ ที่กล่าวถึงในบทนี้

ตัวอย่างหนึ่งของเทรตที่มีชนิดข้อมูลที่เชื่อมโยงคือเทรต `Iterator` ในไลบรารีมาตรฐาน ชนิดข้อมูลที่เชื่อมโยงนี้มีชื่อว่า `Item` ซึ่งทำหน้าที่เป็นตัวแทนของชนิดข้อมูลของค่าที่ชนิดข้อมูลผู้อิมพลีเมนต์เทรต `Iterator` กำลังวนซ้ำอยู่ นิยามของเทรต `Iterator` มีลักษณะดังที่แสดงในลิสติ้ง 20-13

ความแตกต่างคือ เมื่อใช้เจเนอริกดังในลิสติ้ง 20-14 เราจะต้องระบุชนิดข้อมูลในการอิมพลีเมนต์แต่ละครั้ง และเนื่องจากเราสามารถอิมพลีเมนต์ `Iterator<String> for Counter` หรือชนิดข้อมูลอื่นใดก็ได้ เราจึงอาจมีโค้ดการอิมพลีเมนต์ `Iterator` ให้กับ `Counter` ได้หลายแบบ กล่าวคือ เมื่อเทรตมีพารามิเตอร์เจเนอริก เทรตนั้นจะสามารถอิมพลีเมนต์ให้กับชนิดข้อมูลหนึ่ง ๆ ได้หลายครั้ง โดยเปลี่ยนชนิดข้อมูลที่เป็นรูปธรรมของพารามิเตอร์เจเนอริกในแต่ละครั้ง ส่งผลให้เวลาที่เราเรียกใช้เมธอด `next` บน `Counter` เราจะต้องระบุชนิดข้อมูลกำกับไว้ด้วยเสมอ เพื่อบอกว่าเราต้องการเรียกใช้การอิมพลีเมนต์ของ `Iterator` ตัวใด

แต่สำหรับชนิดข้อมูลที่เชื่อมโยง เราไม่จำเป็นต้องระบุชนิดข้อมูลกำกับซ้ำ ๆ เพราะเราสามารถอิมพลีเมนต์เทรตบนชนิดข้อมูลหนึ่งได้เพียงครั้งเดียวเท่านั้น ในลิสติ้ง 20-13 ที่ใช้นิยามแบบชนิดข้อมูลที่เชื่อมโยง เราเลือกได้ว่าชนิดข้อมูลของ `Item` จะเป็นอะไรเพียงครั้งเดียว เนื่องจากมีบล็อก `impl Iterator for Counter` ได้เพียงบล็อกเดียวเท่านั้น เราจึงไม่จำเป็นต้องระบุว่าต้องการอิเทอเรเตอร์ (iterator) ของค่า `u32` ทุกครั้งที่เรียกใช้ `next` บน `Counter`

นอกจากนี้ ชนิดข้อมูลที่เชื่อมโยงยังกลายเป็นส่วนหนึ่งของข้อตกลง (contract) ของเทรตด้วย กล่าวคือ ผู้อิมพลีเมนต์เทรตจะต้องเตรียมชนิดข้อมูลจริงมาแทนที่ตัวแทนของชนิดข้อมูลที่เชื่อมโยงเสมอ โดยชนิดข้อมูลที่เชื่อมโยงมักจะมีชื่อที่สื่อถึงการนำไปใช้งาน และการอธิบายรายละเอียดของชนิดข้อมูลที่เชื่อมโยงไว้ในเอกสาร API ก็ถือเป็นแนวทางปฏิบัติที่ดี

### การใช้พารามิเตอร์ชนิดข้อมูลเริ่มต้นและการโอเวอร์โหลดตัวดำเนินการ

เมื่อเราใช้พารามิเตอร์ชนิดข้อมูลเจเนอริก เราสามารถกำหนดชนิดข้อมูลที่เป็นรูปธรรมเริ่มต้น (default concrete type) ให้กับชนิดข้อมูลเจเนอริกนั้นได้ ซึ่งจะช่วยให้ผู้ที่อิมพลีเมนต์เทรตไม่จำเป็นต้องระบุชนิดข้อมูลที่เป็นรูปธรรม หากค่าเริ่มต้นนั้นสามารถใช้งานได้อยู่แล้ว คุณสามารถกำหนดชนิดข้อมูลเริ่มต้นเมื่อประกาศชนิดข้อมูลเจเนอริกด้วยไวยากรณ์ `<PlaceholderType=ConcreteType>`

ตัวอย่างสถานการณ์ที่เห็นประโยชน์ของเทคนิคนี้ได้อย่างชัดเจนคือ _การโอเวอร์โหลดตัวดำเนินการ (operator overloading)_ ซึ่งคุณสามารถปรับแต่งพฤติกรรมการทำงานของตัวดำเนินการ (เช่น `+`) ในสถานการณ์เฉพาะเจาะจงได้

Rust ไม่อนุญาตให้คุณสร้างตัวดำเนินการขึ้นมาเอง หรือโอเวอร์โหลดตัวดำเนินการใด ๆ ได้ตามใจชอบ แต่คุณสามารถโอเวอร์โหลดการดำเนินการและเทรตที่เกี่ยวข้องซึ่งระบุไว้ใน `std::ops` ได้ โดยการอิมพลีเมนต์เทรตที่เชื่อมโยงกับตัวดำเนินการนั้น ๆ ตัวอย่างเช่น ในลิสติ้ง 20-15 เราโอเวอร์โหลดตัวดำเนินการ `+` เพื่อนำอินสแตนซ์ของ `Point` สองตัวมาบวกเข้าด้วยกัน ซึ่งทำได้โดยการอิมพลีเมนต์เทรต `Add` ให้กับ struct `Point`

เมธอด `add` นำค่า `x` ของอินสแตนซ์ `Point` ทั้งสองตัวมาบวกกัน และนำค่า `y` ของอินสแตนซ์ `Point` ทั้งสองตัวมาบวกกัน เพื่อสร้างเป็น `Point` ตัวใหม่ขึ้นมา เทรต `Add` มีชนิดข้อมูลที่เชื่อมโยงชื่อ `Output` ซึ่งทำหน้าที่กำหนดชนิดข้อมูลที่จะถูกส่งกลับคืนมาจากเมธอด `add`

ชนิดข้อมูลเจเนอริกเริ่มต้นในโค้ดนี้อยู่ภายในเทรต `Add` โดยมีนิยามดังต่อไปนี้:

```rust
trait Add<Rhs=Self> {
    type Output;

    fn add(self, rhs: Rhs) -> Self::Output;
}
```

โค้ดนี้น่าจะดูคุ้นเคยเป็นส่วนใหญ่: เป็นเทรตที่มีหนึ่งเมธอดและหนึ่งชนิดข้อมูลที่เชื่อมโยง ส่วนใหม่ที่เพิ่มเข้ามาคือ `Rhs=Self`: ไวยากรณ์นี้เรียกว่า _พารามิเตอร์ชนิดข้อมูลเริ่มต้น (default type parameters)_ โดยพารามิเตอร์ชนิดข้อมูลเจเนอริก `Rhs` (ย่อมาจาก “right-hand side” หรือด้านขวามือ) เป็นตัวกำหนดชนิดข้อมูลของพารามิเตอร์ `rhs` ในเมธอด `add` หากเราไม่ได้ระบุชนิดข้อมูลที่เป็นรูปธรรมให้กับ `Rhs` เมื่อเราอิมพลีเมนต์เทรต `Add` ชนิดข้อมูลของ `Rhs` จะใช้ค่าเริ่มต้นเป็น `Self` ซึ่งก็คือชนิดข้อมูลที่เรากำลังอิมพลีเมนต์เทรต `Add` ให้นั่นเอง

ตอนที่เราอิมพลีเมนต์ `Add` ให้กับ `Point` เราใช้ค่าเริ่มต้นของ `Rhs` เพราะเราต้องการนำอินสแตนซ์ของ `Point` สองตัวมาบวกกัน คราวนี้มาดูตัวอย่างการอิมพลีเมนต์เทรต `Add` ในกรณีที่เราต้องการปรับแต่งชนิดข้อมูลของ `Rhs` แทนที่จะใช้ค่าเริ่มต้นกันบ้าง

สมมติว่าเรามี struct สองตัวคือ `Millimeters` และ `Meters` ซึ่งเก็บค่าในหน่วยวัดที่แตกต่างกัน การนำชนิดข้อมูลที่มีอยู่แล้วมาห่อหุ้มไว้ในอีก struct หนึ่งแบบบาง ๆ นี้เป็นที่รู้จักกันในชื่อ _รูปแบบนิวไทป์ (newtype pattern)_ ซึ่งเราจะอธิบายอย่างละเอียดในหัวข้อ[“การอิมพลีเมนต์เทรตภายนอกด้วยแพตเทิร์นนิวไทป์”][newtype]<!-- ignore --> เราต้องการนำค่าในหน่วยมิลลิเมตรมาบวกกับค่าในหน่วยเมตร และให้โค้ดการอิมพลีเมนต์ `Add` ทำการแปลงหน่วยให้ถูกต้อง เราสามารถอิมพลีเมนต์ `Add` ให้กับ `Millimeters` โดยกำหนดให้ `Meters` เป็น `Rhs` ได้ ดังที่แสดงในลิสติ้ง 20-16

ในการบวกค่าระหว่าง `Millimeters` กับ `Meters` เราระบุเป็น `impl Add<Meters>` เพื่อกำหนดค่าให้กับพารามิเตอร์ชนิดข้อมูล `Rhs` แทนที่จะใช้ค่าเริ่มต้นซึ่งเป็น `Self`

คุณจะได้ใช้งานพารามิเตอร์ชนิดข้อมูลเริ่มต้นใน 2 วัตถุประสงค์หลัก ได้แก่:

1. เพื่อต่อขยายชนิดข้อมูลโดยไม่ส่งผลกระทบให้โค้ดเดิมเสียหาย (non-breaking extension)
2. เพื่อเปิดโอกาสให้ปรับแต่งได้ในกรณีเฉพาะที่ผู้ใช้ส่วนใหญ่ไม่จำเป็นต้องใช้

เทรต `Add` ในไลบรารีมาตรฐานเป็นตัวอย่างที่ดีของวัตถุประสงค์ข้อที่สอง: โดยทั่วไปแล้ว คุณมักจะบวกข้อมูลที่มีชนิดเดียวกัน แต่เทรต `Add` ก็เปิดความสามารถให้ปรับแต่งได้มากกว่านั้น การใช้พารามิเตอร์ชนิดข้อมูลเริ่มต้นในนิยามของเทรต `Add` ทำให้คุณไม่จำเป็นต้องระบุพารามิเตอร์เสริมในกรณีใช้งานทั่วไป ช่วยลดโค้ดส่วนเกินที่ซ้ำซ้อน (boilerplate) และทำให้เรียกใช้งานเทรตได้สะดวกยิ่งขึ้น

ส่วนวัตถุประสงค์ข้อแรกมีลักษณะคล้ายกันแต่เป็นมุมกลับ: หากคุณต้องการเพิ่มพารามิเตอร์ชนิดข้อมูลให้กับเทรตเดิมที่มีอยู่แล้ว คุณสามารถกำหนดค่าเริ่มต้นให้กับพารามิเตอร์นั้น เพื่อให้สามารถขยายฟังก์ชันการทำงานของเทรตได้โดยไม่ทำให้โค้ดที่อิมพลีเมนต์เทรตเดิมไว้พังทลายลง

### การใช้ซูเปอร์เทรต

ในบางครั้งคุณอาจเขียนนิยามเทรตที่ต้องพึ่งพาเทรตอื่น: เพื่อให้ชนิดข้อมูลหนึ่งสามารถอิมพลีเมนต์เทรตแรกได้ คุณต้องการกำหนดให้ชนิดข้อมูลนั้นต้องอิมพลีเมนต์เทรตที่สองด้วยเช่นกัน เหตุผลที่ทำเช่นนี้เพื่อให้โค้ดนิยามเทรตของคุณสามารถดึงรายการที่เชื่อมโยงของเทรตที่สองมาใช้งานได้ โดยเทรตที่เทรตของคุณพึ่งพาอยู่นั้นจะเรียกว่า _ซูเปอร์เทรต (supertrait)_

ตัวอย่างเช่น สมมติว่าเราต้องการสร้างเทรต `OutlinePrint` ที่มีเมธอด `outline_print` ซึ่งจะพิมพ์ค่าที่กำหนดโดยจัดรูปแบบให้อยู่ภายในกรอบเครื่องหมายดอกจัน กล่าวคือ หากมี struct `Point` ที่อิมพลีเมนต์เทรต `Display` ของไลบรารีมาตรฐานเพื่อให้ผลลัพธ์เป็น `(x, y)` เมื่อเราเรียก `outline_print` บนอินสแตนซ์ `Point` ที่มีค่า `x` เป็น `1` และ `y` เป็น `3` ควรจะพิมพ์ผลลัพธ์ออกมาดังนี้:

```text
**********
*        *
* (1, 3) *
*        *
**********
```

ในการอิมพลีเมนต์เมธอด `outline_print` เราจำเป็นต้องอาศัยฟังก์ชันการทำงานของเทรต `Display` ดังนั้น เราจึงต้องระบุว่าเทรต `OutlinePrint` จะใช้งานได้เฉพาะกับชนิดข้อมูลที่อิมพลีเมนต์ `Display` ร่วมด้วยเท่านั้น เพื่อให้มีฟังก์ชันที่ `OutlinePrint` ต้องการใช้งาน เราสามารถกำหนดเช่นนั้นได้ในนิยามเทรตด้วยการระบุ `OutlinePrint: Display` ซึ่งเทคนิคนี้คล้ายกับการเพิ่มข้อกำหนดเทรต (trait bound) ให้กับตัวเทรต ลิสติ้ง 20-23 แสดงการอิมพลีเมนต์เทรต `OutlinePrint`

### การอิมพลีเมนต์เทรตภายนอกด้วยแพตเทิร์นนิวไทป์

ในหัวข้อ[“การอิมพลีเมนต์เทรตบนชนิดข้อมูล”][implementing-a-trait-on-a-type]<!--
ignore --> ในบทที่ 10 เราได้กล่าวถึงกฎเด็กกำพร้า (orphan rule) ซึ่งระบุว่าเราจะได้รับอนุญาตให้อิมพลีเมนต์เทรตบนชนิดข้อมูลได้ ก็ต่อเมื่อเทรตหรือชนิดข้อมูลนั้นอย่างใดอย่างหนึ่ง หรือทั้งสองอย่าง เป็นของเครตเราเองเท่านั้น เราสามารถหลีกเลี่ยงข้อจำกัดนี้ได้โดยใช้รูปแบบนิวไทป์ (newtype pattern) ซึ่งเกี่ยวข้องกับการสร้างชนิดข้อมูลใหม่ด้วยทูเพิล struct (เราได้อธิบายทูเพิล struct ไว้ในหัวข้อ[“การสร้างชนิดข้อมูลที่แตกต่างกันด้วยทูเพิล struct”][tuple-structs]<!-- ignore --> ในบทที่ 5) โดยทูเพิล struct นี้จะมีเพียงฟิลด์เดียว ทำหน้าที่เป็นตัวห่อหุ้มแบบบาง ๆ ครอบชนิดข้อมูลที่เราต้องการอิมพลีเมนต์เทรตให้ และเนื่องจากชนิดข้อมูลตัวห่อหุ้มนี้เป็นของเครตเราเอง เราจึงสามารถอิมพลีเมนต์เทรตให้กับตัวห่อหุ้มนี้ได้ คำว่า _นิวไทป์ (newtype)_ มีที่มาจากภาษาการเขียนโปรแกรม Haskell การใช้รูปแบบนี้ไม่มีต้นทุนด้านประสิทธิภาพในตอนรันไทม์แต่อย่างใด เนื่องจากชนิดข้อมูลตัวห่อหุ้มจะถูกตัดทอนออกไปในขั้นตอนการคอมไพล์

ตัวอย่างเช่น สมมติว่าเราต้องการอิมพลีเมนต์ `Display` ให้กับ `Vec<T>` ซึ่งกฎออร์แฟนจะไม่อนุญาตให้เราทำได้โดยตรง เนื่องจากทั้งเทรต `Display` และชนิดข้อมูล `Vec<T>` ต่างก็ถูกนิยามไว้นอกเครตของเรา เราจึงสามารถสร้าง struct `Wrapper` ขึ้นมาเพื่อเก็บอินสแตนซ์ของ `Vec<T>` จากนั้นเราก็สามารถอิมพลีเมนต์ `Display` ให้กับ `Wrapper` และนำค่า `Vec<T>` ภายในไปใช้งานได้ ดังที่แสดงในลิสติ้ง 20-24

ข้อเสียของการใช้เทคนิคนี้คือ `Wrapper` เป็นชนิดข้อมูลใหม่ จึงไม่มีเมธอดเดิมของค่าที่มันห่อหุ้มอยู่ หากต้องการให้ทำงานได้เหมือนเดิม เราจะต้องอิมพลีเมนต์เมธอดทั้งหมดของ `Vec<T>` ให้กับ `Wrapper` โดยตรง เพื่อให้เมธอดเหล่านั้นส่งต่อการทำงานไปยัง `self.0` ซึ่งจะช่วยให้เราปฏิบัติต่อ `Wrapper` เสมือนเป็น `Vec<T>` ได้อย่างสมบูรณ์ หรือหากต้องการให้ชนิดข้อมูลใหม่มีครบทุกเมธอดที่ชนิดข้อมูลภายในมี การอิมพลีเมนต์เทรต `Deref` ให้กับ `Wrapper` เพื่อคืนชนิดข้อมูลภายในก็เป็นอีกหนึ่งทางออก (เราได้อธิบายการอิมพลีเมนต์เทรต `Deref` ไว้ในหัวข้อ[“ปฏิบัติกับสมาร์ตพอยน์เตอร์เหมือนเรเฟอเรนซ์ทั่วไป”][smart-pointer-deref]<!-- ignore --> ในบทที่ 15) แต่หากเราไม่ต้องการให้ชนิดข้อมูล `Wrapper` มีเมธอดทุกตัวเหมือนชนิดข้อมูลภายใน—ตัวอย่างเช่น เพื่อจำกัดพฤติกรรมของชนิดข้อมูล `Wrapper` ไม่ให้ทำบางอย่างได้—เราก็เพียงแค่อิมพลีเมนต์เฉพาะเมธอดที่เราต้องการใช้งานจริง ๆ ด้วยตนเอง

รูปแบบนิวไทป์นี้ยังมีประโยชน์อย่างมากแม้ในกรณีที่ไม่เกี่ยวข้องกับเทรตเลยก็ตาม ตอนนี้ขอให้เราสลับความสนใจไปสำรวจแนวทางขั้นสูงในการทำงานร่วมกับระบบชนิดข้อมูลของ Rust กันต่อ
