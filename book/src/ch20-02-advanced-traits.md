### การนิยามเทรตด้วยชนิดข้อมูลที่เชื่อมโยง

_ชนิดข้อมูลที่เชื่อมโยง_ (associated type) เชื่อมต่อตัวแทนชนิดข้อมูลเข้ากับเทรต โดยที่นิยามเมธอดของเทรตสามารถใช้ชนิดข้อมูลตัวแทนเหล่านี้ในซิกเนเจอร์ของมันได้ ผู้อิมพลีเมนต์เทรตจะระบุชนิดข้อมูลที่เป็นรูปธรรมที่จะใช้แทนตัวแทนชนิดข้อมูลสำหรับการอิมพลีเมนต์นั้นๆ ด้วยวิธีนี้ เราจึงสามารถนิยามเทรตที่ใช้ชนิดข้อมูลบางชนิดโดยไม่ต้องรู้ว่าชนิดข้อมูลเหล่านั้นคืออะไรกันแน่ จนกว่าเทรตจะถูกอิมพลีเมนต์

เราได้อธิบายฟีเจอร์ขั้นสูงส่วนใหญ่ในบทนี้ว่าแทบไม่ค่อยจำเป็นต้องใช้ ชนิดข้อมูลที่เชื่อมโยงอยู่ตรงกลางๆ: มันถูกใช้ไม่บ่อยนักเมื่อเทียบกับฟีเจอร์ที่อธิบายไว้ในส่วนอื่นของหนังสือ แต่ถูกใช้บ่อยกว่าฟีเจอร์อื่นๆ หลายตัวที่พูดคุยกันในบทนี้

ตัวอย่างหนึ่งของเทรตที่มีชนิดข้อมูลที่เชื่อมโยงคือเทรต `Iterator` ที่ไลบรารีมาตรฐานจัดเตรียมไว้ ชนิดข้อมูลที่เชื่อมโยงนี้มีชื่อว่า `Item` และทำหน้าที่เป็นตัวแทนของชนิดข้อมูลของค่าที่ชนิดข้อมูลซึ่งอิมพลีเมนต์เทรต `Iterator` กำลังวนซ้ำ นิยามของเทรต `Iterator` เป็นดังที่แสดงในลิสติ้ง 20-13

สำหรับชนิดข้อมูลที่เชื่อมโยง เราไม่จำเป็นต้องระบุชนิดข้อมูล เพราะเราอิมพลีเมนต์เทรตบนชนิดข้อมูลหนึ่งได้เพียงครั้งเดียว ในลิสติ้ง 20-13 ที่มีนิยามซึ่งใช้ชนิดข้อมูลที่เชื่อมโยง เราเลือกได้ว่าชนิดของ `Item` จะเป็นอะไรเพียงครั้งเดียว เพราะมี `impl Iterator for Counter` ได้เพียงหนึ่งเดียวเท่านั้น เราไม่จำเป็นต้องระบุว่าเราต้องการอิเทอเรเตอร์ (iterator) ของค่า `u32` ทุกครั้งที่เราเรียก `next` บน `Counter`

ชนิดข้อมูลที่เชื่อมโยงยังกลายเป็นส่วนหนึ่งของสัญญาของเทรตด้วย: ผู้อิมพลีเมนต์เทรตต้องจัดเตรียมชนิดข้อมูลมาแทนที่ตัวแทนของชนิดข้อมูลที่เชื่อมโยง ชนิดข้อมูลที่เชื่อมโยงมักมีชื่อที่อธิบายว่าชนิดข้อมูลนั้นจะถูกใช้อย่างไร และการจัดทำเอกสารของชนิดข้อมูลที่เชื่อมโยงในเอกสาร API ก็เป็นแนวปฏิบัติที่ดี

### การใช้พารามิเตอร์ชนิดข้อมูลเริ่มต้นและการโอเวอร์โหลดตัวดำเนินการ

เมื่อเราใช้พารามิเตอร์ชนิดข้อมูลเจเนอริก เราสามารถระบุชนิดข้อมูลที่เป็นรูปธรรมเริ่มต้นให้กับชนิดข้อมูลเจเนอริกได้ สิ่งนี้ช่วยลดความจำเป็นที่ผู้อิมพลีเมนต์เทรตจะต้องระบุชนิดข้อมูลที่เป็นรูปธรรมหากชนิดข้อมูลเริ่มต้นใช้ได้ คุณระบุชนิดข้อมูลเริ่มต้นเมื่อประกาศชนิดข้อมูลเจเนอริกด้วยวากยสัมพันธ์ `<PlaceholderType=ConcreteType>`

ตัวอย่างที่ดีของสถานการณ์ที่เทคนิคนี้มีประโยชน์คือ_การโอเวอร์โหลดตัวดำเนินการ_ (operator overloading) ซึ่งคุณปรับแต่งพฤติกรรมของตัวดำเนินการ (เช่น `+`) ในสถานการณ์เฉพาะ

Rust ไม่อนุญาตให้คุณสร้างตัวดำเนินการของคุณเองหรือโอเวอร์โหลดตัวดำเนินการใดก็ได้ตามอำเภอใจ แต่คุณสามารถโอเวอร์โหลดการดำเนินการและเทรตที่สอดคล้องกันซึ่งระบุไว้ใน `std::ops` ได้โดยการอิมพลีเมนต์เทรตที่เชื่อมโยงกับตัวดำเนินการนั้น ตัวอย่างเช่น ในลิสติ้ง 20-15 เราโอเวอร์โหลดตัวดำเนินการ `+` เพื่อบวกอินสแตนซ์ `Point` สองตัวเข้าด้วยกัน เราทำเช่นนี้โดยอิมพลีเมนต์เทรต `Add` บน struct `Point`

เมธอด `add` บวกค่า `x` ของอินสแตนซ์ `Point` สองตัวและค่า `y` ของอินสแตนซ์ `Point` สองตัวเพื่อสร้าง `Point` ใหม่ เทรต `Add` มีชนิดข้อมูลที่เชื่อมโยงชื่อ `Output` ที่กำหนดชนิดข้อมูลที่ถูกคืนกลับจากเมธอด `add`

ชนิดข้อมูลเจเนอริกเริ่มต้นในโค้ดนี้อยู่ภายในเทรต `Add` นี่คือนิยามของมัน:

```rust
trait Add<Rhs=Self> {
    type Output;

    fn add(self, rhs: Rhs) -> Self::Output;
}
```

โค้ดนี้ควรดูคุ้นเคยโดยทั่วไป: เทรตที่มีเมธอดหนึ่งตัวและชนิดข้อมูลที่เชื่อมโยงหนึ่งตัว ส่วนใหม่คือ `Rhs=Self`: วากยสัมพันธ์นี้เรียกว่า_พารามิเตอร์ชนิดข้อมูลเริ่มต้น_ (default type parameter) พารามิเตอร์ชนิดข้อมูลเจเนอริก `Rhs` (ย่อมาจาก “right-hand side” หรือด้านขวา) กำหนดชนิดข้อมูลของพารามิเตอร์ `rhs` ในเมธอด `add` หากเราไม่ระบุชนิดข้อมูลที่เป็นรูปธรรมสำหรับ `Rhs` เมื่อเราอิมพลีเมนต์เทรต `Add` ชนิดของ `Rhs` จะมีค่าเริ่มต้นเป็น `Self` ซึ่งจะเป็นชนิดข้อมูลที่เรากำลังอิมพลีเมนต์ `Add` บนมัน

เมื่อเราอิมพลีเมนต์ `Add` สำหรับ `Point` เราใช้ค่าเริ่มต้นของ `Rhs` เพราะเราต้องการบวกอินสแตนซ์ `Point` สองตัว มาดูตัวอย่างการอิมพลีเมนต์เทรต `Add` ที่เราต้องการปรับแต่งชนิด `Rhs` แทนที่จะใช้ค่าเริ่มต้นกัน

เรามี struct สองตัวคือ `Millimeters` และ `Meters` ที่บรรจุค่าในหน่วยที่ต่างกัน การห่อชนิดข้อมูลที่มีอยู่แล้วไว้ใน struct อื่นแบบบางๆ นี้รู้จักกันในชื่อ_แพตเทิร์นนิวไทป์_ (newtype pattern) ซึ่งเราอธิบายไว้โดยละเอียดมากขึ้นในหัวข้อ[“การอิมพลีเมนต์เทรตภายนอกด้วยแพตเทิร์นนิวไทป์”][newtype]<!-- ignore --> เราต้องการบวกค่าในหน่วยมิลลิเมตรกับค่าในหน่วยเมตร และให้การอิมพลีเมนต์ `Add` ทำการแปลงหน่วยอย่างถูกต้อง เราสามารถอิมพลีเมนต์ `Add` สำหรับ `Millimeters` โดยมี `Meters` เป็น `Rhs` ดังที่แสดงในลิสติ้ง 20-16

คุณจะใช้พารามิเตอร์ชนิดข้อมูลเริ่มต้นในสองวิธีหลักๆ:

1. เพื่อขยายชนิดข้อมูลโดยไม่ทำให้โค้ดที่มีอยู่เดิมพัง
2. เพื่อเปิดให้ปรับแต่งได้ในกรณีเฉพาะที่ผู้ใช้ส่วนใหญ่ไม่จำเป็นต้องใช้

เทรต `Add` ของไลบรารีมาตรฐานเป็นตัวอย่างของจุดประสงค์ข้อที่สอง: โดยปกติแล้ว คุณจะบวกสองชนิดข้อมูลที่เหมือนกัน แต่เทรต `Add` ให้ความสามารถในการปรับแต่งเกินกว่านั้น การใช้พารามิเตอร์ชนิดข้อมูลเริ่มต้นในนิยามของเทรต `Add` หมายความว่าคุณไม่ต้องระบุพารามิเตอร์เพิ่มเติมในกรณีส่วนใหญ่ พูดอีกนัยหนึ่ง ไม่จำเป็นต้องมีโค้ดอิมพลีเมนต์ที่ซ้ำซาก ทำให้เทรตนี้ใช้งานได้ง่ายขึ้น

จุดประสงค์ข้อแรกคล้ายกับข้อที่สองแต่กลับกัน: หากคุณต้องการเพิ่มพารามิเตอร์ชนิดข้อมูลให้กับเทรตที่มีอยู่เดิม คุณสามารถให้ค่าเริ่มต้นกับมันเพื่อให้ขยายฟังก์ชันการทำงานของเทรตได้โดยไม่ทำให้โค้ดการอิมพลีเมนต์ที่มีอยู่เดิมพัง

### การแยกแยะระหว่างเมธอดที่ชื่อเหมือนกัน

ไม่มีอะไรใน Rust ห้ามเทรตหนึ่งมีเมธอดที่ชื่อซ้ำกับเมธอดของเทรตอื่น และ Rust ก็ไม่ได้ห้ามคุณอิมพลีเมนต์ทั้งสองเทรตบนชนิดข้อมูลเดียวเช่นกัน นอกจากนี้ยังเป็นไปได้ที่จะอิมพลีเมนต์เมธอดบนชนิดข้อมูลโดยตรงด้วยชื่อเดียวกับเมธอดจากเทรต

เมื่อเรียกเมธอดที่ชื่อเหมือนกัน คุณจะต้องบอก Rust ว่าคุณต้องการใช้ตัวใด พิจารณาโค้ดในลิสติ้ง 20-17 ที่เราได้นิยามเทรตสองตัวคือ `Pilot` และ `Wizard` ซึ่งทั้งคู่มีเมธอดชื่อ `fly` จากนั้นเราอิมพลีเมนต์ทั้งสองเทรตบนชนิดข้อมูล `Human` ที่มีเมธอดชื่อ `fly` อิมพลีเมนต์อยู่แล้วบนมันโดยตรง เมธอด `fly` แต่ละตัวทำสิ่งแตกต่างกัน

### การใช้ซูเปอร์เทรต

บางครั้งคุณอาจเขียนนิยามเทรตที่ขึ้นอยู่กับเทรตอื่น: เพื่อให้ชนิดข้อมูลหนึ่งอิมพลีเมนต์เทรตแรก คุณต้องการกำหนดให้ชนิดข้อมูลนั้นอิมพลีเมนต์เทรตที่สองด้วย คุณจะทำเช่นนี้เพื่อให้นิยามเทรตของคุณสามารถใช้รายการที่เชื่อมโยงของเทรตที่สองได้ เทรตที่นิยามเทรตของคุณพึ่งพาอยู่นี้เรียกว่า_ซูเปอร์เทรต_ (supertrait) ของเทรตคุณ

ตัวอย่างเช่น สมมติว่าเราต้องการสร้างเทรต `OutlinePrint` ที่มีเมธอด `outline_print` ซึ่งจะพิมพ์ค่าที่ให้มาโดยจัดรูปแบบให้มีกรอบเป็นเครื่องหมายดอกจัน นั่นคือ เมื่อให้ struct `Point` ที่อิมพลีเมนต์เทรต `Display` ของไลบรารีมาตรฐานซึ่งให้ผลลัพธ์เป็น `(x, y)` เมื่อเราเรียก `outline_print` บนอินสแตนซ์ `Point` ที่มี `1` เป็น `x` และ `3` เป็น `y` มันควรพิมพ์ผลลัพธ์ต่อไปนี้:

```text
**********
*        *
* (1, 3) *
*        *
**********
```

ในการอิมพลีเมนต์เมธอด `outline_print` เราต้องการใช้ฟังก์ชันการทำงานของเทรต `Display` ดังนั้น เราจึงต้องระบุว่าเทรต `OutlinePrint` จะทำงานเฉพาะกับชนิดข้อมูลที่อิมพลีเมนต์ `Display` ด้วยและจัดเตรียมฟังก์ชันการทำงานที่ `OutlinePrint` ต้องการ เราทำเช่นนั้นได้ในนิยามเทรตโดยระบุ `OutlinePrint: Display` เทคนิคนี้คล้ายกับการเพิ่มบาวด์ของเทรต (trait bound) ให้กับเทรต ลิสติ้ง 20-23 แสดงการอิมพลีเมนต์เทรต `OutlinePrint`

ignore --> ในบทที่ 10 เราได้กล่าวถึงกฎออร์แฟน (orphan rule) ที่ระบุว่าเราอิมพลีเมนต์เทรตบนชนิดข้อมูลได้ก็ต่อเมื่อเทรตหรือชนิดข้อมูลอย่างใดอย่างหนึ่ง หรือทั้งคู่ เป็นของเครตของเราเอง เป็นไปได้ที่จะหลีกเลี่ยงข้อจำกัดนี้โดยใช้แพตเทิร์นนิวไทป์ ซึ่งเกี่ยวข้องกับการสร้างชนิดข้อมูลใหม่ในทูเพิล struct (เราได้ครอบคลุมทูเพิล struct ไว้ในหัวข้อ[“การสร้างชนิดข้อมูลที่แตกต่างกันด้วยทูเพิล struct”][tuple-structs]<!-- ignore --> ในบทที่ 5) ทูเพิล struct นี้จะมีฟิลด์หนึ่งฟิลด์และเป็นตัวห่อแบบบางๆ ครอบชนิดข้อมูลที่เราต้องการอิมพลีเมนต์เทรตให้ จากนั้น ชนิดข้อมูลตัวห่อก็เป็นของเครตของเรา และเราสามารถอิมพลีเมนต์เทรตบนตัวห่อได้ _นิวไทป์_ (newtype) เป็นคำที่มาจากภาษาการเขียนโปรแกรม Haskell ไม่มีค่าปรับด้านประสิทธิภาพตอนรันไทม์สำหรับการใช้แพตเทิร์นนี้ และชนิดข้อมูลตัวห่อจะถูกตัดออกไปตอนคอมไพล์

ตัวอย่างเช่น สมมติว่าเราต้องการอิมพลีเมนต์ `Display` บน `Vec<T>` ซึ่งกฎออร์แฟนห้ามเราทำโดยตรงเพราะเทรต `Display` และชนิดข้อมูล `Vec<T>` ถูกนิยามไว้นอกเครตของเรา เราสามารถสร้าง struct `Wrapper` ที่บรรจุอินสแตนซ์ของ `Vec<T>` ได้ จากนั้นเราสามารถอิมพลีเมนต์ `Display` บน `Wrapper` และใช้ค่า `Vec<T>` ได้ ดังที่แสดงในลิสติ้ง 20-24

การอิมพลีเมนต์ `Display` ใช้ `self.0` เพื่อเข้าถึง `Vec<T>` ที่อยู่ภายใน เพราะ `Wrapper` เป็นทูเพิล struct และ `Vec<T>` เป็นรายการที่ดัชนี 0 ในทูเพิล จากนั้น เราสามารถใช้ฟังก์ชันการทำงานของเทรต `Display` บน `Wrapper` ได้

ข้อเสียของการใช้เทคนิคนี้คือ `Wrapper` เป็นชนิดข้อมูลใหม่ มันจึงไม่มีเมธอดของค่าที่มันบรรจุอยู่ เราจะต้องอิมพลีเมนต์เมธอดทั้งหมดของ `Vec<T>` บน `Wrapper` โดยตรง เพื่อให้เมธอดเหล่านั้นส่งต่อไปยัง `self.0` ซึ่งจะช่วยให้เราปฏิบัติกับ `Wrapper` เหมือนกับ `Vec<T>` ได้อย่างแม่นยำ หากเราต้องการให้ชนิดข้อมูลใหม่มีทุกเมธอดที่ชนิดข้อมูลภายในมี การอิมพลีเมนต์เทรต `Deref` บน `Wrapper` เพื่อคืนชนิดข้อมูลภายในจะเป็นทางออกหนึ่ง (เราได้พูดคุยถึงการอิมพลีเมนต์เทรต `Deref` ไว้ในหัวข้อ[“ปฏิบัติกับสมาร์ตพอยน์เตอร์เหมือนเรเฟอเรนซ์ทั่วไป”][smart-pointer-deref]<!-- ignore --> ในบทที่ 15) หากเราไม่ต้องการให้ชนิดข้อมูล `Wrapper` มีทุกเมธอดของชนิดข้อมูลภายใน ตัวอย่างเช่น เพื่อจำกัดพฤติกรรมของชนิดข้อมูล `Wrapper` เราก็จะต้องอิมพลีเมนต์เฉพาะเมธอดที่เราต้องการจริงๆ ด้วยตัวเอง

แพตเทิร์นนิวไทป์นี้ยังมีประโยชน์แม้ในกรณีที่ไม่เกี่ยวข้องกับเทรตเลย มาสลับความสนใจและดูวิธีขั้นสูงบางประการในการโต้ตอบกับระบบชนิดข้อมูลของ Rust กัน
