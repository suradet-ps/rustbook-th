## ชนิดข้อมูล

ทุกค่าใน Rust มี_ชนิดข้อมูล_ (data type) ของมันเอง ซึ่งบอก Rust ว่าข้อมูลชนิดใดกำลังถูกระบุ เพื่อให้มันรู้วิธีจัดการกับข้อมูลนั้น เราจะดูกลุ่มย่อยของชนิดข้อมูลสองกลุ่ม ได้แก่ สเกลาร์ (scalar) และคอมพาวด์ (compound)

โปรดจำไว้ว่า Rust เป็นภาษาแบบ_กำหนดชนิดสแตติก_ (statically typed) ซึ่งหมายความว่ามันต้องรู้ชนิดของตัวแปรทั้งหมดตอนคอมไพล์ ปกติแล้วคอมไพเลอร์สามารถอนุมานได้ว่าเราต้องการใช้ชนิดใดจากค่าและวิธีที่เราใช้งานมัน ในกรณีที่สามารถเป็นได้หลายชนิด เช่นเมื่อเราแปลง `String` เป็นชนิดตัวเลขโดยใช้ `parse` ในหัวข้อ[“การเปรียบเทียบคำทายกับตัวเลขลับ”][comparing-the-guess-to-the-secret-number]<!-- ignore --> ในบทที่ 2 เราต้องเพิ่มการระบุชนิดข้อมูล ดังนี้:

```rust
let guess: u32 = "42".parse().expect("Not a number!");
```

หากเราไม่เพิ่มการระบุชนิดข้อมูล `: u32` ที่แสดงในโค้ดข้างต้น Rust จะแสดงข้อผิดพลาดต่อไปนี้ ซึ่งหมายความว่าคอมไพเลอร์ต้องการข้อมูลเพิ่มเติมจากเราเพื่อรู้ว่าเราต้องการใช้ชนิดใด:

```console
{{#include ../listings/ch03-common-programming-concepts/output-only-01-no-type-annotations/output.txt}}
```

คุณจะเห็นการระบุชนิดข้อมูลที่แตกต่างกันสำหรับชนิดข้อมูลอื่นๆ

### ชนิดสเกลาร์

ชนิด_สเกลาร์_ (scalar) แทนค่าเพียงค่าเดียว Rust มีชนิดสเกลาร์หลักสี่ชนิด ได้แก่ จำนวนเต็ม (integer) จำนวนทศนิยม (floating-point number) บูลีน (boolean) และอักขระ (character) คุณอาจคุ้นเคยกับสิ่งเหล่านี้จากภาษาโปรแกรมอื่นๆ มาดูกันว่ามันทำงานอย่างไรใน Rust

#### ชนิดจำนวนเต็ม

_จำนวนเต็ม_ (integer) คือตัวเลขที่ไม่มีส่วนเศษส่วน เราใช้ชนิดจำนวนเต็มหนึ่งชนิดในบทที่ 2 คือชนิด `u32` การประกาศชนิดนี้บ่งชี้ว่าค่าที่เชื่อมโยงกับมันควรเป็นจำนวนเต็มแบบไม่มีเครื่องหมาย (unsigned integer) ที่ใช้พื้นที่ 32 บิต โดยชนิดจำนวนเต็มแบบมีเครื่องหมาย (signed integer) จะขึ้นต้นด้วย `i` แทน `u` ตารางที่ 3-1 แสดงชนิดจำนวนเต็มที่มีมาให้ในตัวใน Rust เราสามารถใช้ชนิดย่อยใดก็ได้จากเหล่านี้เพื่อประกาศชนิดของค่าจำนวนเต็ม

<span class="caption">ตารางที่ 3-1: ชนิดจำนวนเต็มใน Rust</span>

| ความยาว                | มีเครื่องหมาย | ไม่มีเครื่องหมาย |
| ---------------------- | ------------- | ---------------- |
| 8 บิต                  | `i8`          | `u8`             |
| 16 บิต                 | `i16`         | `u16`            |
| 32 บิต                 | `i32`         | `u32`            |
| 64 บิต                 | `i64`         | `u64`            |
| 128 บิต                | `i128`        | `u128`           |
| ขึ้นอยู่กับสถาปัตยกรรม | `isize`       | `usize`          |

แต่ละชนิดย่อยสามารถเป็นได้ทั้งแบบมีเครื่องหมายหรือไม่มีเครื่องหมาย และมีขนาดที่ชัดเจน _แบบมีเครื่องหมาย_ (signed) และ_แบบไม่มีเครื่องหมาย_ (unsigned) หมายถึงว่าตัวเลขนั้นเป็นค่าลบได้หรือไม่ หรือพูดอีกนัยหนึ่ง คือตัวเลขนั้นจำเป็นต้องมีเครื่องหมายกำกับ (signed) หรือจะเป็นค่าบวกเสมอจึงสามารถแสดงได้โดยไม่มีเครื่องหมาย (unsigned) มันเหมือนกับการเขียนตัวเลขบนกระดาษ เมื่อเครื่องหมายมีความสำคัญ ตัวเลขจะถูกเขียนพร้อมเครื่องหมายบวกหรือลบ แต่เมื่อปลอดภัยที่จะสมมติว่าตัวเลขเป็นค่าบวก มันจะถูกเขียนโดยไม่มีเครื่องหมาย ตัวเลขแบบมีเครื่องหมายถูกจัดเก็บโดยใช้รูปแบบ[two's complement][twos-complement]<!-- ignore -->

แต่ละชนิดย่อยแบบมีเครื่องหมายสามารถเก็บตัวเลขตั้งแต่ −(2<sup>n − 1</sup>) ถึง 2<sup>n − 1</sup> − 1 โดยรวมขอบเขตทั้งสองข้างไว้ด้วย โดย _n_ คือจำนวนบิตที่ชนิดย่อยนั้นใช้ ดังนั้น `i8` จึงเก็บตัวเลขตั้งแต่ −(2<sup>7</sup>) ถึง 2<sup>7</sup> − 1 ซึ่งเท่ากับ −128 ถึง 127 ชนิดย่อยแบบไม่มีเครื่องหมายสามารถเก็บตัวเลขตั้งแต่ 0 ถึง 2<sup>n</sup> − 1 ดังนั้น `u8` จึงเก็บตัวเลขตั้งแต่ 0 ถึง 2<sup>8</sup> − 1 ซึ่งเท่ากับ 0 ถึง 255

นอกจากนี้ ชนิด `isize` และ `usize` ยังขึ้นอยู่กับสถาปัตยกรรมของคอมพิวเตอร์ที่โปรแกรมของคุณรันอยู่ ถ้าเป็นสถาปัตยกรรม 64 บิต จะเป็น 64 บิต และถ้าเป็นสถาปัตยกรรม 32 บิต จะเป็น 32 บิต

คุณสามารถเขียนลิเทอรัลจำนวนเต็มได้ในรูปแบบใดก็ได้ที่แสดงในตารางที่ 3-2 โปรดสังเกตว่าลิเทอรัลตัวเลขที่สามารถเป็นชนิดตัวเลขได้หลายชนิดนั้นอนุญาตให้มีคำต่อท้ายชนิด เช่น `57u8` เพื่อระบุชนิดได้ ลิเทอรัลตัวเลขยังสามารถใช้ `_` เป็นตัวคั่นเพื่อให้อ่านตัวเลขได้ง่ายขึ้น เช่น `1_000` ซึ่งจะมีค่าเดียวกันกับถ้าคุณระบุ `1000`

<span class="caption">ตารางที่ 3-2: ลิเทอรัลจำนวนเต็มใน Rust</span>

| ลิเทอรัลตัวเลข    | ตัวอย่าง      |
| ------------------ | ------------- |
| ทศนิยม             | `98_222`      |
| เลขฐานสิบหก        | `0xff`        |
| เลขฐานแปด          | `0o77`        |
| เลขฐานสอง          | `0b1111_0000` |
| ไบต์ (เฉพาะ `u8`)  | `b'A'`        |

แล้วคุณจะรู้ได้อย่างไรว่าควรใช้จำนวนเต็มชนิดใด? หากคุณไม่แน่ใจ ค่าเริ่มต้นของ Rust โดยทั่วไปเป็นจุดเริ่มต้นที่ดี ชนิดจำนวนเต็มมีค่าเริ่มต้นเป็น `i32` สถานการณ์หลักที่คุณจะใช้ `isize` หรือ `usize` คือเมื่อทำการจัดดัชนี (index) คอลเลกชันบางประเภท

> ##### การล้นของจำนวนเต็ม
>
> สมมติว่าคุณมีตัวแปรชนิด `u8` ที่เก็บค่าได้ระหว่าง 0 ถึง 255 หากคุณพยายามเปลี่ยนตัวแปรให้เป็นค่านอกช่วงนั้น เช่น 256 จะเกิด_การล้นของจำนวนเต็ม_ (integer overflow) ซึ่งอาจให้ผลลัพธ์เป็นพฤติกรรมใดพฤติกรรมหนึ่งจากสองแบบ เมื่อคุณคอมไพล์ในโหมดดีบัก Rust จะรวมการตรวจสอบการล้นของจำนวนเต็มที่ทำให้โปรแกรมของคุณ_แพนิก_ (panic) ตอนรันไทม์หากเกิดพฤติกรรมนี้ขึ้น Rust ใช้คำว่า_การแพนิก_ (panicking) เมื่อโปรแกรมออกจากการทำงานพร้อมข้อผิดพลาด เราจะพูดถึงการแพนิกโดยละเอียดมากขึ้นในหัวข้อ[“ข้อผิดพลาดที่กู้คืนไม่ได้ด้วย `panic!`”][unrecoverable-errors-with-panic]<!-- ignore --> ในบทที่ 9
>
> เมื่อคุณคอมไพล์ในโหมดรีลีสด้วยแฟล็ก `--release` Rust จะ_ไม่_รวมการตรวจสอบการล้นของจำนวนเต็มที่ทำให้เกิดการแพนิก แต่ถ้าเกิดการล้นขึ้น Rust จะทำ_การห่อแบบ two's complement_ (two's complement wrapping) พูดสั้นๆ คือ ค่าที่มากกว่าค่าสูงสุดที่ชนิดนั้นเก็บได้จะ "วนกลับ" ไปยังค่าต่ำสุดที่ชนิดนั้นเก็บได้ ในกรณีของ `u8` ค่า 256 จะกลายเป็น 0 ค่า 257 กลายเป็น 1 และอื่นๆ โปรแกรมจะไม่แพนิก แต่ตัวแปรจะมีค่าที่ไม่ใช่สิ่งที่คุณคาดหวังไว้แน่ๆ การพึ่งพาพฤติกรรมการห่อของการล้นของจำนวนเต็มถือเป็นข้อผิดพลาด
>
> เพื่อจัดการกับความเป็นไปได้ที่จะเกิดการล้นอย่างชัดแจ้ง คุณสามารถใช้กลุ่มเมธอดที่ไลบรารีมาตรฐานมีให้สำหรับชนิดตัวเลขพื้นฐานดังต่อไปนี้:
>
> - ห่อในทุกโหมดการคอมไพล์ด้วยเมธอด `wrapping_*` เช่น `wrapping_add`
> - คืนค่า `None` หากเกิดการล้นด้วยเมธอด `checked_*`
> - คืนค่าพร้อมบูลีนที่บ่งชี้ว่าเกิดการล้นหรือไม่ด้วยเมธอด `overflowing_*`
> - อิ่มตัวที่ค่าต่ำสุดหรือสูงสุดของค่าด้วยเมธอด `saturating_*`

### ชนิดคอมพาวด์

ชนิด_คอมพาวด์_ (compound) สามารถจัดกลุ่มหลายค่าไว้ในชนิดเดียวได้ Rust มีชนิดคอมพาวด์พื้นฐานสองชนิด ได้แก่ ทูเพิล (tuple) และอาร์เรย์ (array)

#### ชนิดทูเพิล

ทูเพิล (tuple) เป็นวิธีการทั่วไปในการจัดกลุ่มค่าจำนวนหนึ่งที่มีชนิดหลากหลายไว้ในชนิดคอมพาวด์เดียว ทูเพิลมีความยาวคงที่ เมื่อประกาศแล้ว มันไม่สามารถเพิ่มหรือลดขนาดได้

เราสร้างทูเพิลโดยเขียนรายการค่าที่คั่นด้วยจุลภาคไว้ในวงเล็บ แต่ละตำแหน่งในทูเพิลมีชนิดของมัน และชนิดของค่าต่างๆ ในทูเพิลไม่จำเป็นต้องเหมือนกัน เราได้เพิ่มการระบุชนิดข้อมูลแบบไม่บังคับในตัวอย่างนี้:

<span class="filename">ชื่อไฟล์: src/main.rs</span>

```rust
{{#rustdoc_include ../listings/ch03-common-programming-concepts/no-listing-10-tuples/src/main.rs}}
```

ตัวแปร `tup` ผูกกับทูเพิลทั้งอัน เพราะทูเพิลถือเป็นองค์ประกอบคอมพาวด์เดียว หากต้องการดึงค่าทีละค่าออกจากทูเพิล เราสามารถใช้การจับคู่แพตเทิร์น (pattern matching) เพื่อแยกโครงสร้างค่าทูเพิลได้ ดังนี้:

<span class="filename">ชื่อไฟล์: src/main.rs</span>

```rust
{{#rustdoc_include ../listings/ch03-common-programming-concepts/no-listing-11-destructuring-tuples/src/main.rs}}
```

โปรแกรมนี้เริ่มต้นด้วยการสร้างทูเพิลและผูกมันกับตัวแปร `tup` จากนั้นใช้แพตเทิร์นกับ `let` เพื่อนำ `tup` มาแปลงเป็นตัวแปรแยกสามตัว ได้แก่ `x`, `y` และ `z` กระบวนการนี้เรียกว่า_การแยกโครงสร้างข้อมูล_ (destructuring) เพราะมันแยกทูเพิลเดี่ยวออกเป็นสามส่วน สุดท้าย โปรแกรมพิมพ์ค่าของ `y` ซึ่งก็คือ `6.4`

นอกจากนี้เรายังสามารถเข้าถึงองค์ประกอบของทูเพิลได้โดยตรงโดยใช้จุด (`.`) ตามด้วยดัชนีของค่าที่เราต้องการเข้าถึง ตัวอย่างเช่น:

<span class="filename">ชื่อไฟล์: src/main.rs</span>

```rust
{{#rustdoc_include ../listings/ch03-common-programming-concepts/no-listing-12-tuple-indexing/src/main.rs}}
```

โปรแกรมนี้สร้างทูเพิล `x` แล้วเข้าถึงแต่ละองค์ประกอบของทูเพิลโดยใช้ดัชนีของมันตามลำดับ เช่นเดียวกับภาษาโปรแกรมส่วนใหญ่ ดัชนีแรกในทูเพิลคือ 0

ทูเพิลที่ไม่มีค่าใดๆ มีชื่อพิเศษว่า _unit_ ทั้งค่านี้และชนิดที่สอดคล้องกันเขียนเป็น `()` และแทนค่าว่างหรือชนิดที่คืนกลับแบบว่าง เอ็กซ์เพรสชันจะคืนค่า unit โดยปริยายหากไม่ได้คืนค่าอื่นใด

#### ชนิดอาร์เรย์

อีกวิธีหนึ่งในการมีคอลเลกชันของหลายค่าคือการใช้_อาร์เรย์_ (array) ต่างจากทูเพิล ทุกองค์ประกอบของอาร์เรย์ต้องมีชนิดเดียวกัน ต่างจากอาร์เรย์ในบางภาษา อาร์เรย์ใน Rust มีความยาวคงที่

เราเขียนค่าในอาร์เรย์เป็นรายการที่คั่นด้วยจุลภาคไว้ในวงเล็บเหลี่ยม:

<span class="filename">ชื่อไฟล์: src/main.rs</span>

```rust
{{#rustdoc_include ../listings/ch03-common-programming-concepts/no-listing-13-arrays/src/main.rs}}
```

อาร์เรย์มีประโยชน์เมื่อคุณต้องการให้ข้อมูลของคุณถูกจัดสรรบนสแตก (stack) เช่นเดียวกับชนิดอื่นๆ ที่เราเห็นมาจนถึงตอนนี้ แทนที่จะเป็นฮีป (heap) (เราจะพูดถึงสแตกและฮีปเพิ่มเติมใน[บทที่ 4][stack-and-heap]<!-- ignore -->) หรือเมื่อคุณต้องการรับประกันว่าคุณมีจำนวนองค์ประกอบคงที่เสมอ อย่างไรก็ตาม อาร์เรย์มีความยืดหยุ่นน้อยกว่าชนิดเวกเตอร์ (vector) เวกเตอร์เป็นชนิดคอลเลกชันที่คล้ายกันซึ่งไลบรารีมาตรฐานมีให้ ซึ่ง_อนุญาต_ให้เพิ่มหรือลดขนาดได้เพราะเนื้อหาของมันอยู่บนฮีป หากคุณไม่แน่ใจว่าจะใช้อาร์เรย์หรือเวกเตอร์ โอกาสมากที่คุณควรใช้เวกเตอร์ [บทที่ 8][vectors]<!-- ignore --> พูดถึงเวกเตอร์โดยละเอียดเพิ่มเติม

อย่างไรก็ตาม อาร์เรย์มีประโยชน์มากกว่าเมื่อคุณรู้ว่าจำนวนองค์ประกอบจะไม่จำเป็นต้องเปลี่ยนแปลง ตัวอย่างเช่น หากคุณใช้ชื่อเดือนในโปรแกรม คุณน่าจะใช้อาร์เรย์แทนเวกเตอร์ เพราะคุณรู้ว่ามันจะมี 12 องค์ประกอบเสมอ:

```rust
let months = ["January", "February", "March", "April", "May", "June", "July",
              "August", "September", "October", "November", "December"];
```

คุณเขียนชนิดของอาร์เรย์โดยใช้วงเล็บเหลี่ยมที่บรรจุชนิดของแต่ละองค์ประกอบ อัฒภาค และจำนวนองค์ประกอบในอาร์เรย์ ดังนี้:

```rust
let a: [i32; 5] = [1, 2, 3, 4, 5];
```

ในที่นี้ `i32` คือชนิดของแต่ละองค์ประกอบ หลังอัฒภาค ตัวเลข `5` บ่งชี้ว่าอาร์เรย์มีห้าองค์ประกอบ

คุณยังสามารถกำหนดค่าเริ่มต้นให้อาร์เรย์มีค่าเดียวกันในทุกองค์ประกอบได้โดยระบุค่าเริ่มต้น ตามด้วยอัฒภาค และตามด้วยความยาวของอาร์เรย์ในวงเล็บเหลี่ยม ดังที่แสดงที่นี่:

```rust
let a = [3; 5];
```

อาร์เรย์ชื่อ `a` จะมี `5` องค์ประกอบที่ถูกกำหนดค่าเริ่มต้นเป็น `3` ทั้งหมด นี่เทียบเท่ากับการเขียน `let a = [3, 3, 3, 3, 3];` แต่กระชับกว่า
