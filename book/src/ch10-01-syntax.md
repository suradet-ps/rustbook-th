## ชนิดข้อมูลเจเนอริก

เราใช้เจเนอริก (generic) เพื่อสร้างนิยามสำหรับรายการต่างๆ เช่น ซิกเนเจอร์ของฟังก์ชันหรือ struct ซึ่งเราสามารถนำไปใช้กับชนิดข้อมูลที่เป็นรูปธรรมที่แตกต่างกันได้หลายชนิด มาดูวิธีนิยามฟังก์ชัน struct enum และเมธอดโดยใช้เจเนอริกก่อน จากนั้น เราจะพูดคุยถึงว่าเจเนอริกส่งผลต่อประสิทธิภาพของโค้ดอย่างไร

### ในนิยามฟังก์ชัน

ในการกำหนดพารามิเตอร์ให้กับชนิดข้อมูลในฟังก์ชันเดียวใหม่นี้ เราจำเป็นต้องตั้งชื่อพารามิเตอร์ชนิดข้อมูล เช่นเดียวกับที่เราทำกับพารามิเตอร์ค่าของฟังก์ชัน คุณสามารถใช้ชื่อเรียก (identifier) ใดก็ได้เป็นชื่อพารามิเตอร์ชนิดข้อมูล แต่เราจะใช้ `T` เพราะตามธรรมเนียมปฏิบัติ ชื่อพารามิเตอร์ชนิดข้อมูลใน Rust นั้นสั้น มักมีเพียงตัวอักษรเดียว และธรรมเนียมการตั้งชื่อชนิดข้อมูลของ Rust คือ UpperCamelCase `T` ซึ่งย่อมาจาก _type_ เป็นตัวเลือกเริ่มต้นของโปรแกรมเมอร์ Rust ส่วนใหญ่

เมื่อเราใช้พารามิเตอร์ในบอดี้ของฟังก์ชัน เราต้องประกาศชื่อพารามิเตอร์ในซิกเนเจอร์เพื่อให้คอมไพเลอร์รู้ว่าชื่อนั้นหมายถึงอะไร ในทำนองเดียวกัน เมื่อเราใช้ชื่อพารามิเตอร์ชนิดข้อมูลในซิกเนเจอร์ของฟังก์ชัน เราต้องประกาศชื่อพารามิเตอร์ชนิดข้อมูลก่อนที่เราจะใช้มัน ในการนิยามฟังก์ชัน `largest` แบบเจเนอริก เราจะวางการประกาศชื่อชนิดข้อมูลไว้ภายในวงเล็บมุม `<>` ระหว่างชื่อฟังก์ชันกับรายการพารามิเตอร์ ดังนี้:

```rust,ignore

```

### ในนิยาม enum

เช่นเดียวกับที่เราทำกับ struct เราสามารถนิยาม enum ให้บรรจุชนิดข้อมูลเจเนอริกในวาเรียนต์ของมันได้ มาดู enum `Option<T>` ที่ไลบรารีมาตรฐานมีให้ ซึ่งเราใช้ในบทที่ 6 อีกครั้ง:

```rust
enum Option<T> {
    Some(T),
    None,
}
```

นิยามนี้น่าจะเข้าใจได้ชัดเจนขึ้นสำหรับคุณแล้ว อย่างที่คุณเห็น enum `Option<T>` เป็นเจเนอริกเหนือชนิด `T` และมีสองวาเรียนต์: `Some` ซึ่งบรรจุค่าหนึ่งค่าที่มีชนิด `T` และวาเรียนต์ `None` ที่ไม่บรรจุค่าใดเลย การใช้ enum `Option<T>` ทำให้เราสามารถแสดงแนวคิดนามธรรมของค่าที่อาจมีหรือไม่มีก็ได้ และเพราะ `Option<T>` เป็นเจเนอริก เราจึงใช้นามธรรมนี้ได้ไม่ว่าชนิดของค่าที่อาจมีหรือไม่มีนั้นจะเป็นอะไร

enum ยังสามารถใช้ชนิดเจเนอริกหลายชนิดได้เช่นกัน นิยามของ enum `Result` ที่เราใช้ในบทที่ 9 เป็นตัวอย่างหนึ่ง:

```rust
enum Result<T, E> {
    Ok(T),
    Err(E),
}
```

enum `Result` เป็นเจเนอริกเหนือสองชนิด คือ `T` และ `E` และมีสองวาเรียนต์: `Ok` ซึ่งบรรจุค่าที่มีชนิด `T` และ `Err` ซึ่งบรรจุค่าที่มีชนิด `E` นิยามนี้ทำให้สะดวกในการใช้ enum `Result` ในทุกที่ที่เรามีการดำเนินการที่อาจสำเร็จ (คืนค่าที่มีชนิด `T` บางชนิด) หรือล้มเหลว (คืนข้อผิดพลาดที่มีชนิด `E` บางชนิด) อันที่จริง นี่คือสิ่งที่เราใช้ในการเปิดไฟล์ในลิสติ้ง 9-3 โดย `T` ถูกเติมด้วยชนิด `std::fs::File` เมื่อไฟล์ถูกเปิดสำเร็จ และ `E` ถูกเติมด้วยชนิด `std::io::Error` เมื่อเกิดปัญหาในการเปิดไฟล์

เมื่อคุณตระหนักถึงสถานการณ์ในโค้ดของคุณที่มีนิยาม struct หรือ enum หลายอันที่ต่างกันเพียงชนิดของค่าที่มันบรรจุอยู่ คุณสามารถหลีกเลี่ยงความซ้ำซ้อนได้โดยใช้ชนิดเจเนอริกแทน

โปรดสังเกตว่าเราต้องประกาศ `T` ต่อจาก `impl` เพื่อให้เราสามารถใช้ `T` ระบุว่าเรากำลังอิมพลีเมนต์เมธอดบนชนิด `Point<T>` การประกาศ `T` เป็นชนิดเจเนอริกหลัง `impl` ทำให้ Rust ระบุได้ว่าชนิดในวงเล็บมุมใน `Point` นั้นเป็นชนิดเจเนอริก ไม่ใช่ชนิดที่เป็นรูปธรรม เราสามารถเลือกชื่ออื่นสำหรับพารามิเตอร์เจเนอริกตัวนี้แทนชื่อพารามิเตอร์เจเนอริกที่ประกาศในนิยาม struct ก็ได้ แต่การใช้ชื่อเดียวกันนั้นเป็นธรรมเนียมปฏิบัติ หากคุณเขียนเมธอดภายใน `impl` ที่ประกาศชนิดเจเนอริก เมธอดนั้นจะถูกนิยามบนอินสแตนซ์ใดก็ได้ของชนิดนั้น ไม่ว่าชนิดที่เป็นรูปธรรมใดจะมาแทนที่ชนิดเจเนอริกในที่สุด

เรายังสามารถระบุข้อจำกัดบนชนิดเจเนอริกเมื่อนิยามเมธอดบนชนิดนั้นได้ ตัวอย่างเช่น เราสามารถอิมพลีเมนต์เมธอดบนอินสแตนซ์ `Point<f32>` เท่านั้น แทนที่จะอิมพลีเมนต์บนอินสแตนซ์ `Point<T>` ที่มีชนิดเจเนอริกใดก็ได้ ในลิสติ้ง 10-10 เราใช้ชนิดที่เป็นรูปธรรม `f32` ซึ่งหมายความว่าเราไม่ประกาศชนิดใดๆ หลัง `impl`

พารามิเตอร์ชนิดข้อมูลแบบเจเนอริกในนิยาม struct ไม่จำเป็นต้องเหมือนกับที่คุณใช้ในซิกเนเจอร์ของเมธอดของ struct เดียวกันเสมอไป ลิสติ้ง 10-11 ใช้ชนิดเจเนอริก `X1` และ `Y1` สำหรับ struct `Point` และ `X2` กับ `Y2` สำหรับซิกเนเจอร์ของเมธอด `mixup` เพื่อให้ตัวอย่างชัดเจนยิ่งขึ้น เมธอดนี้สร้างอินสแตนซ์ `Point` ใหม่โดยใช้ค่า `x` จาก `Point` ตัว `self` (ชนิด `X1`) และค่า `y` จาก `Point` ที่ส่งเข้ามา (ชนิด `Y2`)

### ประสิทธิภาพของโค้ดที่ใช้เจเนอริก

คุณอาจสงสัยว่ามีค่าใช้จ่ายตอนรันไทม์หรือไม่เมื่อใช้พารามิเตอร์ชนิดข้อมูลแบบเจเนอริก ข่าวดีก็คือ การใช้ชนิดเจเนอริกจะไม่ทำให้โปรแกรมของคุณทำงานช้าลงไปกว่าการใช้ชนิดที่เป็นรูปธรรมเลย

Rust ทำสิ่งนี้ได้โดยการทำมอโนมอร์ไฟเซชัน (monomorphization) ของโค้ดที่ใช้เจเนอริกตอนคอมไพล์ _การมอโนมอร์ไฟเซชัน_ เป็นกระบวนการเปลี่ยนโค้ดเจเนอริกให้เป็นโค้ดเฉพาะเจาะจงโดยการเติมชนิดที่เป็นรูปธรรมที่ถูกใช้ตอนคอมไพล์ ในกระบวนการนี้ คอมไพเลอร์ทำสิ่งที่ตรงกันข้ามกับขั้นตอนที่เราใช้สร้างฟังก์ชันเจเนอริกในลิสติ้ง 10-5: คอมไพเลอร์ดูทุกจุดที่มีการเรียกโค้ดเจเนอริกและสร้างโค้ดสำหรับชนิดที่เป็นรูปธรรมที่โค้ดเจเนอริกถูกเรียกด้วย

มาดูกันว่าสิ่งนี้ทำงานอย่างไรโดยใช้ enum `Option<T>` แบบเจเนอริกของไลบรารีมาตรฐาน:

```rust
let integer = Some(5);
let float = Some(5.0);
```

เมื่อ Rust คอมไพล์โค้ดนี้ มันจะทำการมอโนมอร์ไฟเซชัน ในระหว่างกระบวนการนั้น คอมไพเลอร์จะอ่านค่าที่ถูกใช้ในอินสแตนซ์ `Option<T>` และระบุชนิด `Option<T>` ได้สองแบบ: แบบหนึ่งคือ `i32` และอีกแบบคือ `f64` ด้วยเหตุนี้ มันจึงขยายนิยามเจเนอริกของ `Option<T>` ออกเป็นสองนิยามที่เฉพาะเจาะจงกับ `i32` และ `f64` ซึ่งเป็นการแทนที่นิยามเจเนอริกด้วยนิยามเฉพาะเจาะจงเหล่านั้น

เวอร์ชันของโค้ดหลังการมอโนมอร์ไฟเซชันมีหน้าตาคล้ายกับโค้ดต่อไปนี้ (คอมไพเลอร์ใช้ชื่อที่แตกต่างจากที่เราใช้ในที่นี้เพื่อการอธิบาย):

<Listing file-name="src/main.rs">

```rust
enum Option_i32 {
    Some(i32),
    None,
}

enum Option_f64 {
    Some(f64),
    None,
}

fn main() {
    let integer = Option_i32::Some(5);
    let float = Option_f64::Some(5.0);
}
```

</Listing>

`Option<T>` แบบเจเนอริกถูกแทนที่ด้วยนิยามเฉพาะเจาะจงที่คอมไพเลอร์สร้างขึ้น เพราะ Rust คอมไพล์โค้ดเจเนอริกให้เป็นโค้ดที่ระบุชนิดในแต่ละอินสแตนซ์ เราจึงไม่มีค่าใช้จ่ายตอนรันไทม์จากการใช้เจเนอริก เมื่อโค้ดรัน มันจะทำงานเหมือนกับว่าเราทำสำเนานิยามแต่ละอันด้วยมือ กระบวนการมอโนมอร์ไฟเซชันทำให้เจเนอริกของ Rust มีประสิทธิภาพสูงมากตอนรันไทม์
