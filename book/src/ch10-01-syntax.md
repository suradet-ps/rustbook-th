## ชนิดข้อมูลเจเนอริก

เราใช้เจเนอริก (generics) เพื่อสร้างนิยามสำหรับสิ่งต่างๆ เช่น ลายเซ็นฟังก์ชัน (function signatures) หรือ struct ซึ่งช่วยให้เราสามารถนำโครงสร้างเดียวกันไปใช้งานร่วมกับประเภทข้อมูลรูปธรรมที่หลากหลายได้ มาเริ่มต้นดูวิธีการนิยามฟังก์ชัน, struct, enum และเมธอดโดยใช้เจเนอริกกันก่อน จากนั้นเราจะมาพูดคุยกันว่าเจเนอริกส่งผลต่อประสิทธิภาพของโค้ดอย่างไรบ้าง

### ในนิยามฟังก์ชัน

เมื่อนิยามฟังก์ชันที่ใช้งานเจเนอริก เราจะวางเจเนอริกไว้ในลายเซ็นของฟังก์ชัน ตรงตำแหน่งที่เรามักจะระบุประเภทข้อมูลของพารามิเตอร์และค่าส่งกลับ การทำเช่นนี้ช่วยให้โค้ดของเรามีความยืดหยุ่นสูงขึ้น สามารถรองรับการทำงานได้หลากหลายยิ่งขึ้นสำหรับผู้เรียกใช้ ขณะเดียวกันก็ช่วยป้องกันการเขียนโค้ดซ้ำซ้อนได้อย่างมีประสิทธิภาพ

เวลาที่เราใช้พารามิเตอร์ในเนื้อหาของฟังก์ชัน เราต้องประกาศชื่อพารามิเตอร์นั้นไว้ในลายเซ็นฟังก์ชันก่อนเพื่อให้คอมไพเลอร์เข้าใจว่าชื่อนั้นหมายถึงอะไร เช่นเดียวกัน เมื่อเราใช้ชื่อพารามิเตอร์ประเภทข้อมูลในลายเซ็นฟังก์ชัน เราก็ต้องประกาศชื่อพารามิเตอร์ประเภทข้อมูลนั้นไว้ก่อนที่จะนำไปใช้ ในการนิยามฟังก์ชัน `largest` ให้เป็นเจเนอริก เราจะใส่การประกาศชื่อประเภทไว้ภายในวงเล็บสามเหลี่ยม `<>` ระหว่างชื่อฟังก์ชันกับรายการพารามิเตอร์ ดังนี้:

### ในนิยาม enum

เช่นเดียวกับ struct เราสามารถนิยาม enum ให้เก็บประเภทข้อมูลแบบเจเนอริกไว้ภายในวาเรียนต์ต่างๆ ได้ มาย้อนดู enum `Option<T>` ของไลบรารีมาตรฐานที่เราเคยใช้กันในบทที่ 6 อีกครั้ง:

```rust
enum Option<T> {
    Some(T),
    None,
}
```

ถึงตอนนี้ นิยามนี้น่าจะดูเข้าใจง่ายและชัดเจนขึ้นมากสำหรับคุณแล้ว ดังที่คุณเห็น enum `Option<T>` เป็นเจเนอริกเหนือประเภท `T` และมีสองวาเรียนต์ ได้แก่: `Some` ซึ่งบรรจุค่าหนึ่งค่าประเภท `T` และวาเรียนต์ `None` ซึ่งไม่บรรจุค่าใดๆ เลย การใช้ enum `Option<T>` ช่วยให้เราสามารถถ่ายทอดแนวคิดเชิงนามธรรมของค่าที่อาจมีหรือไม่มีก็ได้ และด้วยความที่ `Option<T>` เป็นเจเนอริก เราจึงสามารถนำนามธรรมนี้ไปประยุกต์ใช้ได้กับทุกประเภทข้อมูล ไม่ว่าค่านั้นจะเป็นประเภทใดก็ตาม

นอกจากนี้ enum ยังสามารถใช้ประเภทเจเนอริกหลายตัวพร้อมกันได้ด้วย ตัวอย่างเช่น นิยามของ enum `Result` ที่เราเพิ่งใช้งานกันในบทที่ 9:

```rust
enum Result<T, E> {
    Ok(T),
    Err(E),
}
```

enum `Result` เป็นเจเนอริกเหนือสองประเภทข้อมูลคือ `T` และ `E` โดยมีสองวาเรียนต์ ได้แก่ `Ok` ซึ่งบรรจุค่าประเภท `T` และ `Err` ซึ่งบรรจุค่าประเภท `E` นิยามนี้ช่วยให้เราสามารถนำ enum `Result` ไปใช้งานได้อย่างสะดวกสบายในทุกที่ที่มีการดำเนินการซึ่งอาจสำเร็จ (ส่งคืนค่าประเภท `T`) หรืออาจล้มเหลว (ส่งคืนข้อผิดพลาดประเภท `E`) ซึ่งที่จริงนี่คือสิ่งที่เราใช้ในการเปิดไฟล์ในลิสติ้ง 9-3 โดย `T` ถูกแทนที่ด้วยประเภท `std::fs::File` เมื่อเปิดไฟล์สำเร็จ และ `E` ถูกแทนที่ด้วยประเภท `std::io::Error` เมื่อเกิดปัญหาในการเปิดไฟล์

เมื่อใดก็ตามที่คุณสังเกตเห็นว่า ในโค้ดของคุณมีนิยามของ struct หรือ enum หลายตัวที่แตกต่างกันเพียงแค่ประเภทของค่าที่บรรจุอยู่ภายใน คุณสามารถหลีกเลี่ยงการเขียนโค้ดซ้ำซ้อนได้ด้วยการหันมาใช้ประเภทเจเนอริกแทน

### ประสิทธิภาพของโค้ดที่ใช้เจเนอริก

คุณอาจกำลังสงสัยว่า การใช้พารามิเตอร์ประเภทข้อมูลแบบเจเนอริกจะมีผลต่อประสิทธิภาพการทำงานในตอนรันไทม์ (runtime cost) หรือไม่ ข่าวดีก็คือ การใช้งานประเภทเจเนอริกจะไม่ทำให้โปรแกรมของคุณทำงานช้าลงไปกว่าการเขียนด้วยประเภทรูปธรรมเลยแม้แต่น้อย

Rust สามารถทำเช่นนี้ได้โดยการใช้กระบวนการที่เรียกว่า *โมโนมอร์ไฟเซชัน (monomorphization)* กับโค้ดที่ใช้เจเนอริกตั้งแต่ตอนคอมไพล์ โดย *โมโนมอร์ไฟเซชัน* คือกระบวนการแปลงโค้ดที่เป็นเจเนอริกให้กลายเป็นโค้ดเฉพาะเจาะจง โดยการนำประเภทข้อมูลรูปธรรมที่มีการใช้งานจริงตอนคอมไพล์มาใส่แทนที่ ในขั้นตอนนี้ คอมไพเลอร์จะทำสิ่งตรงกันข้ามกับขั้นตอนที่เราเคยทำเพื่อสร้างฟังก์ชันเจเนอริกในลิสติ้ง 10-5: คอมไพเลอร์จะกวาดดูทุกจุดที่มีการเรียกใช้โค้ดเจเนอริก แล้วสร้างโค้ดชุดใหม่สำหรับประเภทรูปธรรมแต่ละประเภทที่มีการเรียกใช้ขึ้นมา

มาดูตัวอย่างการทำงานของกระบวนการนี้ผ่าน enum `Option<T>` ของไลบรารีมาตรฐานกัน:

```rust
let integer = Some(5);
let float = Some(5.0);
```

เมื่อ Rust ทำการคอมไพล์โค้ดนี้ มันจะเริ่มกระบวนการโมโนมอร์ไฟเซชัน โดยคอมไพเลอร์จะอ่านค่าที่ถูกส่งเข้าไปในอินสแตนซ์ของ `Option<T>` แล้วระบุได้ว่ามี `Option<T>` อยู่สองประเภท: ประเภทแรกคือ `i32` และอีกประเภทหนึ่งคือ `f64` จากนั้นคอมไพเลอร์จะแตกนิยามเจเนอริกของ `Option<T>` ออกเป็นสองนิยามที่เจาะจงสำหรับ `i32` และ `f64` แล้วนำนิยามเฉพาะเจาะจงเหล่านี้ไปแทนที่นิยามเจเนอริกเดิม

โค้ดหลังผ่านกระบวนการโมโนมอร์ไฟเซชันจะมีหน้าตาประมาณนี้ (คอมไพเลอร์จริงจะใช้ชื่อที่ต่างไปจากนี้เล็กน้อย แต่เราจำลองชื่อขึ้นเพื่อให้เข้าใจง่าย):

<Listing file-name="src/main.rs">

```rust
enum Option_i32 {
    Some(i32),
    None,
}

enum Option_f64 {
    Some(f64),
    None,
}

fn main() {
    let integer = Option_i32::Some(5);
    let float = Option_f64::Some(5.0);
}
```

</Listing>

ตัว `Option<T>` ที่เป็นเจเนอริกจะถูกแทนที่ด้วยนิยามเฉพาะเจาะจงที่คอมไพเลอร์สร้างขึ้น และด้วยความที่ Rust คอมไพล์โค้ดเจเนอริกให้กลายเป็นโค้ดที่ระบุประเภทชัดเจนในแต่ละอินสแตนซ์ เราจึงไม่ต้องเสียค่าใช้จ่ายด้านประสิทธิภาพใดๆ ตอนรันไทม์เลยจากการใช้เจเนอริก เมื่อโค้ดทำงาน มันจะมีประสิทธิภาพเทียบเท่ากับการที่เรามานั่งคัดลอกและเขียนนิยามของแต่ละประเภทข้อมูลด้วยตัวเองทุกประการ กระบวนการโมโนมอร์ไฟเซชันนี้เองที่ทำให้เจเนอริกของ Rust มีประสิทธิภาพสูงสุดในตอนรันไทม์
