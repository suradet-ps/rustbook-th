## ปรับแต่งการบิลด์ด้วยโปรไฟล์การรีลีส

ใน Rust _โปรไฟล์การรีลีส_ (release profile) เป็นโปรไฟล์ที่นิยามไว้ล่วงหน้าและปรับแต่งได้ โดยมีการตั้งค่าต่างๆ ที่แตกต่างกันซึ่งช่วยให้โปรแกรมเมอร์ควบคุมตัวเลือกต่างๆ สำหรับการคอมไพล์โค้ดได้มากขึ้น แต่ละโปรไฟล์ถูกตั้งค่าแยกจากกันโดยอิสระ

Cargo มีโปรไฟล์หลักสองโปรไฟล์: โปรไฟล์ `dev` ที่ Cargo ใช้เมื่อคุณรัน `cargo build` และโปรไฟล์ `release` ที่ Cargo ใช้เมื่อคุณรัน `cargo build --release` โปรไฟล์ `dev` ถูกนิยามด้วยค่าเริ่มต้นที่ดีสำหรับการพัฒนา และโปรไฟล์ `release` มีค่าเริ่มต้นที่ดีสำหรับการบิลด์รีลีส

ชื่อโปรไฟล์เหล่านี้อาจดูคุ้นเคยจากเอาต์พุตของการบิลด์ของคุณ:

<!-- manual-regeneration
anywhere, run:
cargo build
cargo build --release
and ensure output below is accurate
-->

```console
$ cargo build
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.00s
$ cargo build --release
    Finished `release` profile [optimized] target(s) in 0.32s
```

`dev` และ `release` คือโปรไฟล์ที่แตกต่างกันเหล่านี้ซึ่งถูกใช้โดยคอมไพเลอร์

Cargo มีการตั้งค่าเริ่มต้นสำหรับแต่ละโปรไฟล์ซึ่งมีผลเมื่อคุณยังไม่ได้เพิ่มส่วน `[profile.*]` ใดๆ อย่างชัดแจ้งในไฟล์ _Cargo.toml_ ของโปรเจกต์ ด้วยการเพิ่มส่วน `[profile.*]` สำหรับโปรไฟล์ใดก็ตามที่คุณต้องการปรับแต่ง คุณจะเขียนทับชุดย่อยใดๆ ของการตั้งค่าเริ่มต้นก็ได้ ตัวอย่างเช่น นี่คือค่าเริ่มต้นของการตั้งค่า `opt-level` สำหรับโปรไฟล์ `dev` และ `release`:

<span class="filename">ชื่อไฟล์: Cargo.toml</span>

```toml
[profile.dev]
opt-level = 0

[profile.release]
opt-level = 3
```

การตั้งค่า `opt-level` ควบคุมจำนวนการปรับแต่งประสิทธิภาพ (optimization) ที่ Rust จะนำไปใช้กับโค้ดของคุณ โดยมีช่วงตั้งแต่ 0 ถึง 3 การนำการปรับแต่งไปใช้มากขึ้นจะยืดเวลาการคอมไพล์ ดังนั้นหากคุณอยู่ระหว่างการพัฒนาและคอมไพล์โค้ดบ่อยครั้ง คุณจะต้องการการปรับแต่งน้อยลงเพื่อให้คอมไพล์เร็วขึ้น แม้ว่าโค้ดที่ได้จะรันช้าลงก็ตาม ด้วยเหตุนี้ `opt-level` ค่าเริ่มต้นสำหรับ `dev` จึงเป็น `0` เมื่อคุณพร้อมที่จะปล่อยโค้ดของคุณ ทางที่ดีที่สุดคือใช้เวลาคอมไพล์มากขึ้น คุณจะคอมไพล์ในโหมดรีลีสเพียงครั้งเดียว แต่คุณจะรันโปรแกรมที่คอมไพล์แล้วหลายครั้ง โหมดรีลีสจึงแลกเวลาคอมไพล์ที่ยาวนานขึ้นกับโค้ดที่รันเร็วขึ้น นั่นคือเหตุผลที่ `opt-level` ค่าเริ่มต้นสำหรับโปรไฟล์ `release` เป็น `3`

คุณสามารถเขียนทับการตั้งค่าเริ่มต้นได้โดยเพิ่มค่าที่แตกต่างออกไปสำหรับมันใน _Cargo.toml_ ตัวอย่างเช่น หากเราต้องการใช้ระดับการปรับแต่ง 1 ในโปรไฟล์การพัฒนา เราสามารถเพิ่มสองบรรทัดนี้ลงในไฟล์ _Cargo.toml_ ของโปรเจกต์ของเรา:

<span class="filename">ชื่อไฟล์: Cargo.toml</span>

```toml
[profile.dev]
opt-level = 1
```

โค้ดนี้เขียนทับการตั้งค่าเริ่มต้นของ `0` ตอนนี้เมื่อเรารัน `cargo build` Cargo จะใช้ค่าเริ่มต้นสำหรับโปรไฟล์ `dev` บวกกับการปรับแต่ง `opt-level` ของเรา เพราะเราตั้ง `opt-level` เป็น `1` Cargo จะนำการปรับแต่งไปใช้มากกว่าค่าเริ่มต้น แต่ไม่มากเท่าในบิลด์รีลีส

สำหรับรายการตัวเลือกการตั้งค่าและค่าเริ่มต้นทั้งหมดของแต่ละโปรไฟล์ โปรดดู[เอกสารของ Cargo](https://doc.rust-lang.org/cargo/reference/profiles.html)
