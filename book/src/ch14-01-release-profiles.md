## ปรับแต่งการบิลด์ด้วยโปรไฟล์การรีลีส

ในภาษา Rust _โปรไฟล์การรีลีส_ (release profiles) คือโปรไฟล์การตั้งค่าที่ถูกกำหนดไว้ล่วงหน้าและสามารถปรับแต่งได้ ซึ่งช่วยให้โปรแกรมเมอร์สามารถควบคุมตัวเลือกต่าง ๆ สำหรับการคอมไพล์โค้ดได้อย่างยืดหยุ่น โดยแต่ละโปรไฟล์จะถูกตั้งค่าแยกต่างหากเป็นอิสระจากกัน

Cargo มีโปรไฟล์หลักอยู่สองโปรไฟล์ ได้แก่: โปรไฟล์ `dev` ที่ Cargo จะเลือกใช้เมื่อคุณสั่ง `cargo build` และโปรไฟล์ `release` ที่ Cargo จะใช้เมื่อคุณสั่ง `cargo build --release` โดยโปรไฟล์ `dev` จะถูกกำหนดค่าเริ่มต้นให้เหมาะสำหรับการพัฒนาโปรแกรม ส่วนโปรไฟล์ `release` จะมีค่าเริ่มต้นที่เหมาะสมสำหรับการบิลด์เพื่อนำไปใช้งานจริง (release builds)

ชื่อของโปรไฟล์เหล่านี้อาจดูคุ้นตาจากข้อความผลลัพธ์การบิลด์ของคุณ:

<!-- manual-regeneration
anywhere, run:
cargo build
cargo build --release
and ensure output below is accurate
-->

```console
$ cargo build
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.00s
$ cargo build --release
    Finished `release` profile [optimized] target(s) in 0.32s
```

คำว่า `dev` และ `release` เหล่านี้ก็คือโปรไฟล์ที่แตกต่างกันซึ่งคอมไพเลอร์เลือกนำมาใช้นั่นเอง

Cargo มีการกำหนดค่าเริ่มต้นสำหรับแต่ละโปรไฟล์ไว้แล้ว ซึ่งจะมีผลทำงานโดยอัตโนมัติหากคุณยังไม่ได้ระบุส่วน `[profile.*]` ใด ๆ ในไฟล์ _Cargo.toml_ ของโปรเจกต์ แต่หากคุณต้องการปรับแต่งค่าของโปรไฟล์ใด คุณก็สามารถเพิ่มส่วน `[profile.*]` เพื่อเขียนทับ (override) ค่าเริ่มต้นเฉพาะบางส่วนได้ตามต้องการ ตัวอย่างเช่น นี่คือค่าเริ่มต้นของตัวเลือก `opt-level` สำหรับโปรไฟล์ `dev` และ `release`:

<span class="filename">ชื่อไฟล์: Cargo.toml</span>

```toml
[profile.dev]
opt-level = 0

[profile.release]
opt-level = 3
```

ตัวเลือก `opt-level` จะควบคุมระดับการปรับแต่งประสิทธิภาพ (optimization) ที่ Rust จะนำไปใช้กับโค้ดของคุณ โดยมีค่าตั้งแต่ระดับ 0 ถึง 3 ยิ่งระดับการปรับแต่งสูงขึ้น คอมไพเลอร์ก็จะต้องใช้เวลาในการคอมไพล์นานขึ้นตามไปด้วย ดังนั้นในระหว่างช่วงพัฒนาที่คุณต้องคอมไพล์โค้ดบ่อย ๆ คุณจึงต้องการให้คอมไพเลอร์ปรับแต่งโค้ดให้น้อยที่สุดเพื่อให้คอมไพล์ได้เร็ว แม้ว่าโค้ดที่ได้จะทำงานช้าลงก็ตาม ด้วยเหตุนี้ ค่าเริ่มต้นของ `opt-level` สำหรับโปรไฟล์ `dev` จึงเป็น `0` ในทางตรงกันข้าม เมื่อคุณพร้อมที่จะรีลีสโปรแกรมออกไปใช้งานจริง การยอมเสียเวลาคอมไพล์ให้นานขึ้นย่อมคุ้มค่ากว่า เพราะคุณจะคอมไพล์ในโหมด release เพียงครั้งเดียว แต่ผู้ใช้จะนำโปรแกรมที่คอมไพล์เสร็จแล้วไปรันใช้งานซ้ำ ๆ หลายครั้ง โหมด release จึงยอมแลกเวลาคอมไพล์ที่นานขึ้นกับประสิทธิภาพความเร็วของโปรแกรมที่ทำงานได้เร็วขึ้นอย่างยิ่ง นั่นคือเหตุผลที่ค่าเริ่มต้นของ `opt-level` ในโปรไฟล์ `release` ถูกตั้งไว้ที่ `3`

คุณสามารถเขียนทับค่าเริ่มต้นได้ง่าย ๆ เพียงแค่ระบุค่าใหม่ลงในไฟล์ _Cargo.toml_ ตัวอย่างเช่น หากเราต้องการใช้ระดับการปรับแต่งประสิทธิภาพเลเวล 1 ในโปรไฟล์สำหรับการพัฒนา เราก็สามารถเพิ่มสองบรรทัดนี้ลงในไฟล์ _Cargo.toml_ ของโปรเจกต์ได้:

<span class="filename">ชื่อไฟล์: Cargo.toml</span>

```toml
[profile.dev]
opt-level = 1
```

โค้ดส่วนนี้จะเข้าไปเขียนทับค่าเริ่มต้นเดิมซึ่งเป็น `0` และเมื่อเราสั่งรันคำสั่ง `cargo build` หลังจากนี้ Cargo จะใช้ค่าเริ่มต้นทั้งหมดของโปรไฟล์ `dev` บวกกับการปรับแต่งค่า `opt-level` ที่เรากำหนดไว้ และเนื่องจากเราตั้ง `opt-level` ไว้ที่ `1` Cargo จึงจะปรับแต่งโค้ดให้มากกว่าค่าเริ่มต้นเล็กน้อย แต่จะไม่มากเท่ากับในบิลด์รีลีส

หากต้องการดูรายการตัวเลือกการตั้งค่าทั้งหมดและค่าเริ่มต้นของแต่ละโปรไฟล์ สามารถดูเพิ่มเติมได้ที่ [เอกสารคู่มือของ Cargo](https://doc.rust-lang.org/cargo/reference/profiles.html)
