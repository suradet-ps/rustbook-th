# พื้นฐานของการเขียนโปรแกรมแบบอะซิงโครนัส: Async, Await, ฟิวเจอร์ และสตรีม

หลายๆ การดำเนินการที่เราขอให้คอมพิวเตอร์ทำอาจใช้เวลาสักพักกว่าจะเสร็จ น่าจะดีกว่าหากเราทำอย่างอื่นได้ระหว่างรอโปรเซสที่ใช้เวลานานเหล่านั้นทำงานเสร็จ คอมพิวเตอร์สมัยใหม่มีสองเทคนิคสำหรับการทำงานมากกว่าหนึ่งอย่างในเวลาเดียวกัน นั่นคือการทำงานขนาน (parallelism) และการทำงานพร้อมกัน (concurrency) อย่างไรก็ตาม ตรรกะของโปรแกรมของเราถูกเขียนขึ้นในลักษณะเส้นตรงเป็นส่วนใหญ่ เราอยากจะระบุการดำเนินการที่โปรแกรมควรทำและจุดที่ฟังก์ชันสามารถหยุดชั่วคราวแล้วให้ส่วนอื่นของโปรแกรมทำงานแทนได้ โดยไม่ต้องระบุล่วงหน้าอย่างแม่นยำว่าลำดับและลักษณะที่โค้ดแต่ละส่วนควรทำงานเป็นอย่างไร _การเขียนโปรแกรมแบบอะซิงโครนัส_ (asynchronous programming) เป็นนามธรรมที่ให้เราแสดงโค้ดของเราในแง่ของจุดที่อาจหยุดชั่วคราวและผลลัพธ์สุดท้าย ซึ่งจัดการรายละเอียดของการประสานงานให้กับเรา

บทนี้ต่อยอดจากการใช้เธรด (thread) เพื่อการทำงานขนานและการทำงานพร้อมกันในบทที่ 16 โดยแนะนำแนวทางการเขียนโค้ดรูปแบบทางเลือก ได้แก่ ฟิวเจอร์ (future) สตรีม (stream) และวากยสัมพันธ์ `async` และ `await` ของ Rust ที่ให้เราแสดงว่าการดำเนินการต่างๆ สามารถเป็นแบบอะซิงโครนัสได้อย่างไร รวมถึงเครตจากบุคคลที่สามที่อิมพลีเมนต์รันไทม์ (runtime) แบบอะซิงโครนัส ซึ่งเป็นโค้ดที่จัดการและประสานการเรียกใช้การดำเนินการแบบอะซิงโครนัส

ลองพิจารณาตัวอย่าง สมมติว่าคุณกำลังเอ็กซ์พอร์ตวิดีโอที่คุณสร้างขึ้นจากงานฉลองของครอบครัว ซึ่งเป็นการดำเนินการที่อาจใช้เวลาตั้งแต่ไม่กี่นาทีไปจนถึงหลายชั่วโมง การเอ็กซ์พอร์ตวิดีโอจะใช้พลัง CPU และ GPU มากเท่าที่ทำได้ หากคุณมีแกน CPU เพียงแกนเดียวและระบบปฏิบัติการของคุณไม่หยุดการเอ็กซ์พอร์ตนั้นจนกว่ามันจะเสร็จ นั่นคือ หากมันเรียกใช้การเอ็กซ์พอร์ตนั้น_แบบซิงโครนัส_ คุณก็จะทำอย่างอื่นบนคอมพิวเตอร์ไม่ได้เลยระหว่างที่ทาสก์ (task) นั้นทำงานอยู่ นั่นคงเป็นประสบการณ์ที่หงุดหงิดไม่น้อย โชคดีที่ระบบปฏิบัติการของคอมพิวเตอร์สามารถขัดจังหวะการเอ็กซ์พอร์ตแบบมองไม่เห็นได้บ่อยเพียงพอที่จะให้คุณทำงานอื่นไปพร้อมกันได้ และมันก็ทำเช่นนั้นจริงๆ

ทีนี้ สมมติว่าคุณกำลังดาวน์โหลดวิดีโอที่แชร์โดยคนอื่น ซึ่งก็ใช้เวลาพอสมควรเช่นกันแต่ไม่ใช้เวลา CPU มากเท่านั้น ในกรณีนี้ CPU ต้องรอให้ข้อมูลมาถึงจากเครือข่าย แม้ว่าคุณจะเริ่มอ่านข้อมูลได้เมื่อข้อมูลเริ่มมาถึง แต่อาจใช้เวลาสักพักกว่าข้อมูลทั้งหมดจะมาครบ แม้เมื่อข้อมูลมาครบแล้ว หากวิดีโอมีขนาดใหญ่โต การโหลดทั้งหมดอาจใช้เวลาอย่างน้อยหนึ่งหรือสองวินาที นั่นอาจฟังดูไม่มากนัก แต่เป็นเวลาที่นานมากสำหรับโปรเซสเซอร์สมัยใหม่ ซึ่งสามารถดำเนินการได้หลายพันล้านครั้งต่อวินาที และเช่นเดิม ระบบปฏิบัติการของคุณจะขัดจังหวะโปรแกรมของคุณแบบมองไม่เห็นเพื่อให้ CPU ทำงานอื่นระหว่างรอการเรียกเครือข่ายเสร็จสิ้น

การเอ็กซ์พอร์ตวิดีโอเป็นตัวอย่างของการดำเนินการที่_จำกัดด้วย CPU_ หรือ_จำกัดด้วยการประมวลผล_ มันถูกจำกัดด้วยความเร็วในการประมวลผลข้อมูลที่เป็นไปได้ของคอมพิวเตอร์ภายใน CPU หรือ GPU และปริมาณความเร็วนั้นที่มันสามารถทุ่มให้กับการดำเนินการได้ การดาวน์โหลดวิดีโอเป็นตัวอย่างของการดำเนินการที่_จำกัดด้วย I/O_ เพราะมันถูกจำกัดด้วยความเร็วของ_อินพุตและเอาต์พุต_ของคอมพิวเตอร์ มันทำได้เร็วเท่าที่ข้อมูลจะถูกส่งผ่านเครือข่ายได้เท่านั้น

ในทั้งสองตัวอย่างนี้ การขัดจังหวะแบบมองไม่เห็นของระบบปฏิบัติการเป็นการทำงานพร้อมกันรูปแบบหนึ่ง อย่างไรก็ตาม การทำงานพร้อมกันนั้นเกิดขึ้นเพียงในระดับของโปรแกรมทั้งหมดเท่านั้น ระบบปฏิบัติการจะขัดจังหวะโปรแกรมหนึ่งเพื่อให้โปรแกรมอื่นๆ ทำงานได้ ในหลายกรณี เนื่องจากเราเข้าใจโปรแกรมของเราในระดับที่ละเอียดกว่าที่ระบบปฏิบัติการเข้าใจมาก เราจึงมองเห็นโอกาสสำหรับการทำงานพร้อมกันที่ระบบปฏิบัติการมองไม่เห็นได้

ตัวอย่างเช่น หากเรากำลังสร้างเครื่องมือสำหรับจัดการการดาวน์โหลดไฟล์ เราควรเขียนโปรแกรมของเราให้การเริ่มดาวน์โหลดรายการหนึ่งไม่ทำให้ UI ค้าง และผู้ใช้ควรเริ่มดาวน์โหลดหลายรายการได้พร้อมกัน อย่างไรก็ตาม API ของระบบปฏิบัติการหลายตัวสำหรับการโต้ตอบกับเครือข่ายเป็นแบบ_การบล็อก_ (blocking) นั่นคือ พวกมันบล็อกความคืบหน้าของโปรแกรมจนกว่าข้อมูลที่พวกมันกำลังประมวลผลจะพร้อมอย่างสมบูรณ์

> หมายเหตุ: หากลองคิดดูแล้ว นี่คือวิธีการทำงานของฟังก์ชัน_ส่วนใหญ่_ อย่างไรก็ตาม คำว่า _การบล็อก_ มักถูกสงวนไว้สำหรับการเรียกฟังก์ชันที่โต้ตอบกับไฟล์ เครือข่าย หรือทรัพยากรอื่นๆ บนคอมพิวเตอร์ เพราะนั่นคือกรณีที่โปรแกรมแต่ละโปรแกรมจะได้ประโยชน์จากการดำเนินการนั้นเป็นแบบ_ไม่_บล็อก

เราสามารถหลีกเลี่ยงการบล็อกเธรดหลักของเราได้โดยสร้างเธรดเฉพาะสำหรับดาวน์โหลดแต่ละไฟล์ อย่างไรก็ตาม ค่าใช้จ่ายส่วนเกินของทรัพยากรระบบที่เธรดเหล่านั้นใช้จะกลายเป็นปัญหาในที่สุด จะดีกว่าหากการเรียกนั้นไม่บล็อกตั้งแต่แรก และเราสามารถนิยามทาสก์จำนวนหนึ่งที่เราต้องการให้โปรแกรมทำจนเสร็จ แล้วปล่อยให้รันไทม์เลือกว่าควรเรียกใช้พวกมันด้วยลำดับและลักษณะใดจึงจะดีที่สุด

นั่นคือสิ่งที่แอบสแตรกชัน _async_ (ย่อมาจาก _asynchronous_) ของ Rust มอบให้เราพอดี ในบทนี้ คุณจะได้เรียนรู้ทุกอย่างเกี่ยวกับ async เมื่อเราครอบคลุมหัวข้อต่อไปนี้

- วิธีใช้วากยสัมพันธ์ `async` และ `await` ของ Rust และเรียกใช้ฟังก์ชันแบบอะซิงโครนัสด้วยรันไทม์
- วิธีใช้โมเดล async เพื่อแก้ปัญหาบางส่วนที่เราพิจารณาไปแล้วในบทที่ 16
- วิธีที่มัลติเธรดและ async ให้ทางออกที่เสริมกันและกันซึ่งคุณสามารถนำมาผสมผสานกันได้ในหลายกรณี

อย่างไรก็ตาม ก่อนที่เราจะเห็นว่า async ทำงานอย่างไรในทางปฏิบัติ เราต้องขอเบี่ยงประเด็นสั้นๆ ไปพูดถึงความแตกต่างระหว่างการทำงานขนานและการทำงานพร้อมกัน

## การทำงานขนานและการทำงานพร้อมกัน

จนถึงตอนนี้ เรามองการทำงานขนานและการทำงานพร้อมกันว่าใช้แทนกันได้เป็นส่วนใหญ่ ตอนนี้เราต้องแยกแยะความแตกต่างระหว่างทั้งสองอย่างแม่นยำยิ่งขึ้น เพราะความแตกต่างจะปรากฏให้เห็นเมื่อเราเริ่มลงมือทำ

ลองพิจารณาวิธีต่างๆ ที่ทีมหนึ่งๆ จะแบ่งงานในโปรเจกต์ซอฟต์แวร์ได้ คุณอาจมอบหมายงานหลายอย่างให้สมาชิกคนเดียว มอบหมายงานอย่างละหนึ่งอย่างให้สมาชิกแต่ละคน หรือใช้วิธีผสมผสานทั้งสองแนวทาง

เมื่อบุคคลหนึ่งทำงานหลายอย่างที่แตกต่างกันก่อนที่งานใดงานหนึ่งจะเสร็จ นี่คือ_การทำงานพร้อมกัน_ วิธีหนึ่งในการอิมพลีเมนต์การทำงานพร้อมกันคล้ายกับการมีโปรเจกต์สองโปรเจกต์ที่เช็กเอาต์ไว้บนคอมพิวเตอร์ของคุณ และเมื่อคุณเบื่อหรือติดปัญหากับโปรเจกต์หนึ่ง คุณก็สลับไปทำอีกโปรเจกต์หนึ่ง คุณเป็นแค่คนคนเดียว คุณจึงทำความคืบหน้าของทั้งสองงานในเวลาเดียวกันเป๊ะๆ ไม่ได้ แต่คุณทำหลายงานพร้อมกันได้ โดยทำความคืบหน้าทีละงานด้วยการสลับไปมาระหว่างกัน (ดูรูปที่ 17-1)

ในทำนองเดียวกัน คุณอาจตระหนักว่าทาสก์หนึ่งของคุณเองนั้นขึ้นอยู่กับอีกทาสก์หนึ่งของคุณ ตอนนี้การทำงานพร้อมกันของคุณก็กลายเป็นแบบอนุกรมไปด้วย

การทำงานขนานและการทำงานพร้อมกันสามารถตัดกันได้เช่นกัน หากคุณรู้ว่าเพื่อนร่วมงานของคุณติดปัญหาจนกว่าคุณจะทำงานหนึ่งของคุณเสร็จ คุณก็คงจะทุ่มเทความพยายามทั้งหมดให้กับงานนั้นเพื่อ “ปลดบล็อก” เพื่อนร่วมงานของคุณ คุณและเพื่อนร่วมงานของคุณไม่สามารถทำงานแบบขนานได้อีกต่อไป และคุณก็ไม่สามารถทำงานของตัวเองแบบพร้อมกันได้อีกด้วย

พลวัตพื้นฐานเดียวกันนี้เกิดขึ้นกับซอฟต์แวร์และฮาร์ดแวร์ด้วย บนเครื่องที่มีแกน CPU เดียว CPU สามารถดำเนินการได้เพียงครั้งละหนึ่งอย่าง แต่ก็ยังทำงานแบบพร้อมกันได้ การใช้เครื่องมืออย่างเธรด โปรเซส และ async คอมพิวเตอร์สามารถหยุดกิจกรรมหนึ่งชั่วคราวและสลับไปทำอย่างอื่น ก่อนที่จะวนกลับไปทำกิจกรรมแรกนั้นอีกครั้ง บนเครื่องที่มีแกน CPU หลายแกน มันยังทำงานแบบขนานได้ด้วย แกนหนึ่งอาจกำลังทำงานหนึ่งอยู่ขณะที่อีกแกนหนึ่งทำงานที่ไม่เกี่ยวข้องกันเลย และการดำเนินการเหล่านั้นเกิดขึ้นในเวลาเดียวกันจริงๆ

การรันโค้ด async ใน Rust มักเกิดขึ้นแบบพร้อมกัน ขึ้นอยู่กับฮาร์ดแวร์ ระบบปฏิบัติการ และรันไทม์แบบ async ที่เราใช้ (จะพูดถึงรันไทม์แบบ async เพิ่มเติมอีกไม่นาน) การทำงานพร้อมกันนั้นอาจใช้การทำงานขนานอยู่เบื้องหลังด้วย

ตอนนี้ มาดำดิ่งไปกับวิธีการทำงานจริงๆ ของการเขียนโปรแกรมแบบ async ใน Rust กัน
