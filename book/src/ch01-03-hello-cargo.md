## Hello, Cargo!

Cargo เป็นระบบบิลด์และตัวจัดการแพ็กเกจของ Rust นักพัฒนา Rust ส่วนใหญ่ใช้เครื่องมือนี้จัดการโปรเจกต์ Rust เพราะ Cargo ทำงานหลายอย่างให้คุณ เช่น การบิลด์โค้ด การดาวน์โหลดไลบรารีที่โค้ดของคุณพึ่งพา และการบิลด์ไลบรารีเหล่านั้น (เราเรียกไลบรารีที่โค้ดของคุณต้องใช้ว่า _ดีเพนเดนซี_)

โปรแกรม Rust ที่เรียบง่ายที่สุดอย่างโปรแกรมที่เราเขียนมาแล้วไม่มีดีเพนเดนซีใดๆ หากเราสร้างโปรเจกต์ "Hello, world!" ด้วย Cargo มันจะใช้เพียงส่วนของ Cargo ที่จัดการการบิลด์โค้ดของคุณเท่านั้น เมื่อคุณเขียนโปรแกรม Rust ที่ซับซ้อนขึ้น คุณจะเพิ่มดีเพนเดนซี และหากคุณเริ่มโปรเจกต์ด้วย Cargo การเพิ่มดีเพนเดนซีจะทำได้ง่ายขึ้นมาก

เนื่องจากโปรเจกต์ Rust ส่วนใหญ่ใช้ Cargo ส่วนที่เหลือของหนังสือเล่มนี้จึงสมมติว่าคุณใช้ Cargo ด้วย Cargo จะถูกติดตั้งมาพร้อม Rust หากคุณใช้ตัวติดตั้งอย่างเป็นทางการที่กล่าวถึงในหัวข้อ["การติดตั้ง"][installation]<!-- ignore --> หากคุณติดตั้ง Rust ด้วยวิธีอื่น ให้ตรวจสอบว่ามี Cargo ติดตั้งอยู่หรือไม่โดยป้อนคำสั่งต่อไปนี้ในเทอร์มินัล:

```console
$ cargo --version
```

หากคุณเห็นหมายเลขเวอร์ชัน แสดงว่ามี! หากคุณเห็นข้อผิดพลาดอย่าง `command
not found` ให้ดูเอกสารของวิธีการติดตั้งของคุณเพื่อหาวิธีติดตั้ง Cargo แยกต่างหาก

### การสร้างโปรเจกต์ด้วย Cargo

มาสร้างโปรเจกต์ใหม่ด้วย Cargo และดูว่ามันต่างจากโปรเจกต์ "Hello, world!" เดิมของเราอย่างไร กลับไปที่ไดเรกทอรี _projects_ ของคุณ (หรือที่ไหนก็ตามที่คุณเลือกเก็บโค้ด) จากนั้นบนระบบปฏิบัติการใดก็ได้ ให้รันคำสั่งต่อไปนี้:

```console
$ cargo new hello_cargo
$ cd hello_cargo
```

คำสั่งแรกสร้างไดเรกทอรีและโปรเจกต์ใหม่ชื่อ _hello_cargo_ เราตั้งชื่อโปรเจกต์ว่า _hello_cargo_ และ Cargo จะสร้างไฟล์ของมันในไดเรกทอรีชื่อเดียวกัน

เข้าไปในไดเรกทอรี _hello_cargo_ แล้วแสดงรายการไฟล์ คุณจะเห็นว่า Cargo สร้างไฟล์สองไฟล์และไดเรกทอรีหนึ่งไดเรกทอรีให้เรา ได้แก่ ไฟล์ _Cargo.toml_ และไดเรกทอรี _src_ ที่มีไฟล์ _main.rs_ อยู่ข้างใน

Cargo ยังเริ่มต้นที่เก็บ Git ใหม่พร้อมกับไฟล์ _.gitignore_ ด้วย ไฟล์ Git จะไม่ถูกสร้างหากคุณรัน `cargo new` ภายในที่เก็บ Git ที่มีอยู่แล้ว คุณสามารถลบล้างพฤติกรรมนี้ได้ด้วย `cargo new --vcs=git`

> หมายเหตุ: Git เป็นระบบควบคุมเวอร์ชันที่นิยมใช้กันทั่วไป คุณสามารถเปลี่ยนให้ `cargo new` ใช้ระบบควบคุมเวอร์ชันอื่นหรือไม่ใช้เลยก็ได้โดยใช้แฟล็ก `--vcs` รัน `cargo new --help` เพื่อดูตัวเลือกที่มี

เปิด _Cargo.toml_ ในโปรแกรมแก้ไขข้อความที่คุณเลือก ไฟล์นี้ควรมีลักษณะคล้ายโค้ดในลิสติ้ง 1-2

<Listing number="1-2" file-name="Cargo.toml" caption="เนื้อหาของ *Cargo.toml* ที่สร้างโดย `cargo new`">

```toml
[package]
name = "hello_cargo"
version = "0.1.0"
edition = "2024"

[dependencies]
```

</Listing>

ไฟล์นี้อยู่ในรูปแบบ [_TOML_][toml]<!-- ignore --> (_Tom's Obvious, Minimal
Language_) ซึ่งเป็นรูปแบบการตั้งค่าของ Cargo

บรรทัดแรก `[package]` เป็นหัวข้อส่วนที่บ่งชี้ว่าคำสั่งถัดไปเป็นการตั้งค่าแพ็กเกจ เมื่อเราเพิ่มข้อมูลอื่นๆ ลงในไฟล์นี้ เราจะเพิ่มส่วนอื่นๆ ตามมา

สามบรรทัดถัดไปกำหนดข้อมูลการตั้งค่าที่ Cargo ต้องใช้ในการคอมไพล์โปรแกรมของคุณ ได้แก่ ชื่อ เวอร์ชัน และฉบับของ Rust ที่ใช้ เราจะพูดถึงคีย์ `edition` ใน[ภาคผนวก E][appendix-e]<!-- ignore -->

บรรทัดสุดท้าย `[dependencies]` เป็นจุดเริ่มต้นของส่วนสำหรับระบุดีเพนเดนซีของโปรเจกต์ ใน Rust เราเรียกแพ็กเกจโค้ดว่า _เครต_ โปรเจกต์นี้ไม่ต้องใช้เครตอื่น แต่ในโปรเจกต์แรกของบทที่ 2 เราจะต้องใช้ ดังนั้นเราจะกลับมาใช้ส่วน dependencies นี้ตอนนั้น

ตอนนี้ให้เปิด _src/main.rs_ แล้วดู:

<span class="filename">ชื่อไฟล์: src/main.rs</span>

```rust
fn main() {
    println!("Hello, world!");
}
```

Cargo สร้างโปรแกรม "Hello, world!" ให้คุณแล้ว เหมือนกับที่เราเขียนในลิสติ้ง 1-1! จนถึงตอนนี้ ความแตกต่างระหว่างโปรเจกต์ของเรากับโปรเจกต์ที่ Cargo สร้างคือ Cargo วางโค้ดไว้ในไดเรกทอรี _src_ และเรามีไฟล์ตั้งค่า _Cargo.toml_ อยู่ที่ไดเรกทอรีบนสุด

Cargo คาดหวังให้ไฟล์ซอร์สของคุณอยู่ในไดเรกทอรี _src_ ส่วนไดเรกทอรีโปรเจกต์ระดับบนสุดมีไว้สำหรับไฟล์ README ข้อมูลลิขสิทธิ์ ไฟล์ตั้งค่า และอื่นๆ ที่ไม่เกี่ยวข้องกับโค้ดของคุณ การใช้ Cargo ช่วยให้คุณจัดระเบียบโปรเจกต์ได้ดี ทุกอย่างมีที่ของมัน และทุกอย่างอยู่ถูกที่

หากคุณเริ่มโปรเจกต์ที่ไม่ได้ใช้ Cargo อย่างที่เราทำกับโปรเจกต์ "Hello, world!" คุณสามารถแปลงให้เป็นโปรเจกต์ที่ใช้ Cargo ได้ ย้ายโค้ดของโปรเจกต์เข้าไปในไดเรกทอรี _src_ แล้วสร้างไฟล์ _Cargo.toml_ ที่เหมาะสม วิธีง่ายๆ ในการได้ไฟล์ _Cargo.toml_ คือรัน `cargo init` ซึ่งจะสร้างให้คุณโดยอัตโนมัติ

### การบิลด์และรันโปรเจกต์ Cargo

ตอนนี้มาดูความแตกต่างเมื่อเราบิลด์และรันโปรแกรม "Hello, world!" ด้วย Cargo! จากไดเรกทอรี _hello_cargo_ ของคุณ ให้บิลด์โปรเจกต์โดยป้อนคำสั่งต่อไปนี้:

```console
$ cargo build
   Compiling hello_cargo v0.1.0 (file:///projects/hello_cargo)
    Finished dev [unoptimized + debuginfo] target(s) in 2.85 secs
```

คำสั่งนี้สร้างไฟล์ที่รันได้ใน _target/debug/hello_cargo_ (หรือ _target\debug\hello_cargo.exe_ บน Windows) แทนที่จะสร้างในไดเรกทอรีปัจจุบัน เนื่องจากการบิลด์เริ่มต้นเป็นการบิลด์แบบดีบัก Cargo จึงวางไบนารีไว้ในไดเรกทอรีชื่อ _debug_ คุณสามารถรันไฟล์ที่รันได้ด้วยคำสั่งนี้:

```console
$ ./target/debug/hello_cargo # or .\target\debug\hello_cargo.exe on Windows
Hello, world!
```

หากทุกอย่างเรียบร้อย `Hello, world!` ควรพิมพ์ออกมาที่เทอร์มินัล การรัน `cargo build` เป็นครั้งแรกยังทำให้ Cargo สร้างไฟล์ใหม่ที่ระดับบนสุดด้วย: _Cargo.lock_ ไฟล์นี้บันทึกเวอร์ชันที่แน่นอนของดีเพนเดนซีในโปรเจกต์ของคุณ โปรเจกต์นี้ไม่มีดีเพนเดนซี ไฟล์จึงค่อนข้างว่างเปล่า คุณไม่จำเป็นต้องแก้ไขไฟล์นี้ด้วยตัวเองเลย เพราะ Cargo จัดการเนื้อหาให้คุณ

เราเพิ่งบิลด์โปรเจกต์ด้วย `cargo build` และรันด้วย `./target/debug/hello_cargo` แต่เรายังใช้ `cargo run` เพื่อคอมไพล์โค้ดแล้วรันไฟล์ที่รันได้ในคำสั่งเดียวได้ด้วย:

```console
$ cargo run
    Finished dev [unoptimized + debuginfo] target(s) in 0.0 secs
     Running `target/debug/hello_cargo`
Hello, world!
```

การใช้ `cargo run` สะดวกกว่าการต้องจำไปรัน `cargo build` แล้วใช้พาธเต็มไปยังไบนารี ดังนั้นนักพัฒนาส่วนใหญ่จึงใช้ `cargo run`

สังเกตว่าคราวนี้เราไม่เห็นเอาต์พุตที่บ่งชี้ว่า Cargo กำลังคอมไพล์ `hello_cargo` Cargo รู้ว่าไฟล์ไม่ได้เปลี่ยนแปลง จึงไม่ได้บิลด์ใหม่ แต่รันไบนารีเลย หากคุณแก้ไขซอร์สโค้ด Cargo จะบิลด์โปรเจกต์ใหม่ก่อนรัน และคุณจะเห็นเอาต์พุตแบบนี้:

```console
$ cargo run
   Compiling hello_cargo v0.1.0 (file:///projects/hello_cargo)
    Finished dev [unoptimized + debuginfo] target(s) in 0.33 secs
     Running `target/debug/hello_cargo`
Hello, world!
```

Cargo ยังมีคำสั่งชื่อ `cargo check` คำสั่งนี้จะตรวจสอบโค้ดของคุณอย่างรวดเร็วเพื่อให้แน่ใจว่าคอมไพล์ผ่าน แต่ไม่สร้างไฟล์ที่รันได้:

```console
$ cargo check
   Checking hello_cargo v0.1.0 (file:///projects/hello_cargo)
    Finished dev [unoptimized + debuginfo] target(s) in 0.32 secs
```

ทำไมคุณถึงไม่อยากได้ไฟล์ที่รันได้ล่ะ? บ่อยครั้ง `cargo check` เร็วกว่า `cargo build` มาก เพราะข้ามขั้นตอนการสร้างไฟล์ที่รันได้ หากคุณตรวจสอบงานอยู่ตลอดขณะเขียนโค้ด การใช้ `cargo check` จะช่วยเร่งกระบวนการบอกคุณว่าโปรเจกต์ยังคอมไพล์ผ่านอยู่หรือไม่! ด้วยเหตุนี้ Rustacean หลายคนจึงรัน `cargo check` เป็นระยะขณะเขียนโปรแกรมเพื่อให้แน่ใจว่ามันคอมไพล์ผ่าน จากนั้นจึงรัน `cargo build` เมื่อพร้อมใช้งานไฟล์ที่รันได้

มาสรุปสิ่งที่เราเรียนรู้เกี่ยวกับ Cargo จนถึงตอนนี้:

- เราสร้างโปรเจกต์ได้ด้วย `cargo new`
- เราบิลด์โปรเจกต์ได้ด้วย `cargo build`
- เราบิลด์และรันโปรเจกต์ในขั้นตอนเดียวได้ด้วย `cargo run`
- เราบิลด์โปรเจกต์โดยไม่สร้างไบนารีเพื่อตรวจหาข้อผิดพลาดได้ด้วย `cargo check`
- แทนที่จะเก็บผลลัพธ์การบิลด์ไว้ในไดเรกทอรีเดียวกับโค้ด Cargo เก็บไว้ในไดเรกทอรี _target/debug_

ข้อดีเพิ่มเติมของการใช้ Cargo คือคำสั่งจะเหมือนกันไม่ว่าคุณจะทำงานบนระบบปฏิบัติการใด ดังนั้นจากนี้ไป เราจะไม่ให้คำแนะนำแยกสำหรับ Linux กับ macOS และ Windows อีก

### การบิลด์สำหรับการรีลีส

เมื่อโปรเจกต์ของคุณพร้อมสำหรับการเผยแพร่จริงในที่สุด คุณสามารถใช้ `cargo build
--release` เพื่อคอมไพล์พร้อมการปรับแต่งประสิทธิภาพ คำสั่งนี้จะสร้างไฟล์ที่รันได้ใน _target/release_ แทน _target/debug_ การปรับแต่งประสิทธิภาพทำให้โค้ด Rust ของคุณรันเร็วขึ้น แต่การเปิดใช้จะทำให้เวลาคอมไพล์โปรแกรมนานขึ้น นี่คือเหตุผลที่มีโปรไฟล์สองแบบ: แบบหนึ่งสำหรับการพัฒนาเมื่อคุณต้องการบิลด์ใหม่เร็วๆ และบ่อยๆ กับอีกแบบสำหรับบิลด์โปรแกรมสุดท้ายที่คุณจะมอบให้ผู้ใช้ ซึ่งจะไม่ถูกบิลด์ซ้ำบ่อยและควรรันเร็วที่สุดเท่าที่เป็นไปได้ หากคุณวัดเวลาการทำงานของโค้ด อย่าลืมรัน `cargo build --release` แล้ววัดผลด้วยไฟล์ที่รันได้ใน _target/release_

### ใช้ประโยชน์จากธรรมเนียมปฏิบัติของ Cargo

สำหรับโปรเจกต์ง่ายๆ Cargo ไม่ได้ให้ประโยชน์มากนักเมื่อเทียบกับการใช้ `rustc` เฉยๆ แต่มันจะพิสูจน์คุณค่าของตัวเองเมื่อโปรแกรมของคุณซับซ้อนขึ้น เมื่อโปรแกรมเติบโตขึ้นเป็นหลายไฟล์หรือต้องใช้ดีเพนเดนซี การให้ Cargo ประสานการบิลด์จะง่ายกว่ามาก

แม้โปรเจกต์ `hello_cargo` จะเรียบง่าย แต่ตอนนี้มันใช้เครื่องมือจริงจำนวนมากที่คุณจะใช้ตลอดอาชีพ Rust ที่เหลือของคุณ อันที่จริง ในการทำงานกับโปรเจกต์ที่มีอยู่แล้วใดๆ คุณสามารถใช้คำสั่งต่อไปนี้เพื่อดึงโค้ดด้วย Git เปลี่ยนไปที่ไดเรกทอรีของโปรเจกต์นั้น และบิลด์:

```console
$ git clone example.org/someproject
$ cd someproject
$ cargo build
```

สำหรับข้อมูลเพิ่มเติมเกี่ยวกับ Cargo ดูได้ที่[เอกสารของมัน][cargo]

- ติดตั้ง Rust เวอร์ชันเสถียรล่าสุดด้วย `rustup`
- อัปเดตเป็น Rust เวอร์ชันใหม่กว่า
- เปิดเอกสารที่ติดตั้งไว้ในเครื่อง
- เขียนและรันโปรแกรม "Hello, world!" ด้วย `rustc` โดยตรง
- สร้างและรันโปรเจกต์ใหม่ตามธรรมเนียมปฏิบัติของ Cargo

นี่เป็นเวลาที่ดีในการสร้างโปรแกรมที่จริงจังขึ้นเพื่อให้คุ้นเคยกับการอ่านและเขียนโค้ด Rust ดังนั้นในบทที่ 2 เราจะสร้างโปรแกรมเกมทายตัวเลข หากคุณอยากเริ่มด้วยการเรียนรู้ว่าแนวคิดพื้นฐานของการเขียนโปรแกรมใน Rust ทำงานอย่างไร ให้อ่านบทที่ 3 แล้วค่อยกลับมาที่บทที่ 2
