# โปรเจกต์สุดท้าย: สร้างเว็บเซิร์ฟเวอร์แบบหลายเธรด

เป็นการเดินทางอันยาวนาน แต่ในที่สุดเราก็มาถึงบทสุดท้ายของหนังสือเล่มนี้แล้ว ในบทนี้ เราจะร่วมกันสร้างโปรเจกต์ส่งท้ายอีกหนึ่งโปรเจกต์ เพื่อสาธิตแนวคิดต่าง ๆ ที่เราได้เรียนรู้ในบทท้าย ๆ รวมถึงทบทวนเนื้อหาจากบทก่อนหน้าไปพร้อมกัน

สำหรับโปรเจกต์ส่งท้ายนี้ เราจะสร้างเว็บเซิร์ฟเวอร์ (web server) ที่ตอบกลับว่า “Hello!” และแสดงผลในเว็บเบราว์เซอร์ดังรูปที่ 21-1

นี่คือแผนงานในการสร้างเว็บเซิร์ฟเวอร์ของเรา:

1. ทำความเข้าใจ TCP และ HTTP เบื้องต้น
2. รอรับการเชื่อมต่อ TCP บนซ็อกเก็ต (socket)
3. แยกวิเคราะห์คำขอ (parse HTTP requests) รูปแบบพื้นฐาน
4. สร้างการตอบกลับ (HTTP response) ที่ถูกต้องตามมาตรฐาน
5. เพิ่มประสิทธิภาพการรองรับงาน (throughput) ของเซิร์ฟเวอร์ด้วยพูลเธรด (thread pool)

ก่อนจะเริ่มต้น มีรายละเอียด 2 ข้อที่เราควรทำความเข้าใจร่วมกัน:

ประการแรก วิธีการที่เราจะใช้นี้ไม่ใช่วิธีที่ดีที่สุดในการสร้างเว็บเซิร์ฟเวอร์ด้วย Rust ในทางปฏิบัติจริง เนื่องจากชุมชนนักพัฒนาได้เผยแพร่เครต (crates) พร้อมใช้งานระดับโปรดักชันไว้มากมายบน [crates.io](https://crates.io/) ซึ่งมีเว็บเซิร์ฟเวอร์และพูลเธรดที่สมบูรณ์แบบกว่าสิ่งที่เราจะสร้างขึ้นเองมาก ทว่าเป้าหมายของเราในบทนี้คือการเรียนรู้กลไกเบื้องหลัง ไม่ใช่การเลือกทางลัด เนื่องจาก Rust เป็นภาษาโปรแกรมระดับระบบ (systems programming language) เราจึงสามารถเลือกระดับของแอบสแตรกชัน (abstraction) ที่ต้องการทำงานด้วยได้อย่างอิสระ และสามารถลงลึกไปในระดับต่ำ (low-level) กว่าที่ทำได้หรือเหมาะสมในภาษาอื่น ๆ

ประการที่สอง เราจะไม่นำ `async` และ `await` มาใช้ในโปรเจกต์นี้ เพราะการสร้างพูลเธรดด้วยตัวเองก็ถือเป็นความท้าทายที่สำคัญมากพออยู่แล้ว โดยไม่ต้องเพิ่มความซับซ้อนของการสร้างรันไทม์แบบ async เข้ามาอีก อย่างไรก็ตาม เราจะชี้ให้เห็นว่า `async` และ `await` สามารถนำมาประยุกต์ใช้แก้โจทย์ปัญหาแบบเดียวกับที่เราพบในบทนี้ได้อย่างไร และที่สำคัญ ตามที่เราได้เห็นกันในบทที่ 17 รันไทม์แบบ async ส่วนใหญ่ต่างก็ใช้พูลเธรดในการบริหารจัดการงานเบื้องหลังเช่นกัน

ดังนั้น เราจะลงมือเขียนเว็บเซิร์ฟเวอร์ HTTP ขั้นพื้นฐานและสร้างพูลเธรดขึ้นมาด้วยตัวเอง เพื่อให้คุณได้เข้าใจแนวคิดและเทคนิคสำคัญที่อยู่เบื้องหลังเครตต่าง ๆ ที่คุณจะได้ใช้งานจริงในอนาคต
