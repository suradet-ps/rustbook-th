# โปรเจกต์สุดท้าย: สร้างเว็บเซิร์ฟเวอร์แบบหลายเธรด

มันเป็นการเดินทางที่ยาวนาน แต่เราก็มาถึงจุดสิ้นสุดของหนังสือเล่มนี้แล้ว ในบทนี้ เราจะสร้างโปรเจกต์อีกหนึ่งโปรเจกต์ด้วยกันเพื่อสาธิตแนวคิดบางส่วนที่เราครอบคลุมในบทสุดท้ายๆ รวมทั้งทบทวนบทเรียนก่อนหน้านี้บางส่วน

สำหรับโปรเจกต์สุดท้ายของเรา เราจะสร้างเว็บเซิร์ฟเวอร์ (web server) ที่พูดว่า “Hello!” และมีหน้าตาเหมือนรูปที่ 21-1 ในเว็บเบราว์เซอร์

นี่คือแผนของเราในการสร้างเว็บเซิร์ฟเวอร์:

1. เรียนรู้เกี่ยวกับ TCP และ HTTP สักเล็กน้อย
2. รอฟังการเชื่อมต่อ TCP บนซ็อกเก็ต (socket)
3. แยกวิเคราะห์คำขอ (request) HTTP จำนวนเล็กน้อย
4. สร้างการตอบกลับ (response) HTTP ที่เหมาะสม
5. ปรับปรุงทรูพุต (throughput) ของเซิร์ฟเวอร์ของเราด้วยพูลเธรด (thread pool)

ก่อนที่เราจะเริ่ม เราควรกล่าวถึงรายละเอียดสองประการ ประการแรก วิธีที่เราจะใช้นี้ไม่ใช่วิธีที่ดีที่สุดในการสร้างเว็บเซิร์ฟเวอร์ด้วย Rust สมาชิกในชุมชนได้เผยแพร่เครต (crate) ที่พร้อมใช้ในโปรดักชันจำนวนหนึ่งไว้ที่ [crates.io](https://crates.io/) ซึ่งจัดเตรียมการอิมพลีเมนต์เว็บเซิร์ฟเวอร์และพูลเธรดที่สมบูรณ์กว่าที่เราจะสร้าง อย่างไรก็ตาม เจตนาของเราในบทนี้คือช่วยให้คุณเรียนรู้ ไม่ใช่เลือกเส้นทางที่ง่าย เพราะ Rust เป็นภาษาโปรแกรมระดับระบบ เราจึงสามารถเลือกระดับของแอบสแตรกชัน (abstraction) ที่เราต้องการทำงานด้วยได้ และสามารถลงไปในระดับที่ต่ำกว่าที่เป็นไปได้หรือสมเหตุสมผลในภาษาอื่นได้

ประการที่สอง เราจะไม่ใช้ async และ await ที่นี่ การสร้างพูลเธรดเป็นความท้าทายที่ใหญ่พออยู่แล้วด้วยตัวมันเอง โดยไม่ต้องเพิ่มการสร้างรันไทม์ async เข้าไปด้วย! อย่างไรก็ตาม เราจะกล่าวถึงว่า async และ await อาจนำมาปรับใช้กับปัญหาเดียวกันบางอย่างที่เราจะเห็นในบทนี้ได้อย่างไร ท้ายที่สุด ดังที่เราได้กล่าวไว้ในบทที่ 17 รันไทม์ async จำนวนมากใช้พูลเธรดในการจัดการงานของมัน

เราจึงจะเขียนเซิร์ฟเวอร์ HTTP พื้นฐานและพูลเธรดด้วยตัวเอง เพื่อให้คุณได้เรียนรู้แนวคิดและเทคนิคทั่วไปที่อยู่เบื้องหลังเครตที่คุณอาจใช้ในอนาคต
