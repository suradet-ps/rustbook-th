## การควบคุมโฟลว์แบบกระชับด้วย `if let` และ `let...else`

ไวยากรณ์ `if let` ช่วยให้เราสามารถรวม `if` และ `let` เข้าด้วยกันเพื่อจัดการกับค่าที่ตรงกับแพตเทิร์นเพียงรูปแบบเดียวได้อย่างกระชับ โดยไม่ต้องสนใจกรณีอื่นๆ ที่เหลือ ลองพิจารณาโปรแกรมในลิสติ้ง 6-6 ที่นำค่า `Option<u8>` ในตัวแปร `config_max` มาจับคู่กับแพตเทิร์น แต่ต้องการให้โค้ดทำงานเฉพาะในกรณีที่ค่านั้นเป็นวาเรียนต์ `Some` เท่านั้น


หากค่านั้นเป็น `Some` เราจะพิมพ์ค่าที่บรรจุอยู่ภายในวาเรียนต์ `Some` ออกมา โดยการผูกค่านั้นเข้ากับตัวแปร `max` ในแพตเทิร์น และเราไม่ได้ต้องการทำอะไรกับค่า `None` เลย แต่เพื่อให้ตรงตามข้อกำหนดของนิพจน์ `match` ที่ต้องครอบคลุมทุกกรณี เราจึงจำใจต้องเพิ่ม `_ => ()` ต่อท้ายหลังจากจัดการวาเรียนต์แรกไปแล้ว ซึ่งกลายเป็นโค้ดส่วนเกินที่ซ้ำซากและน่ารำคาญ (boilerplate code)

```rust
{{#rustdoc_include ../listings/ch06-enums-and-pattern-matching/no-listing-12-if-let/src/main.rs:here}}
```

ไวยากรณ์ `if let` จะรับแพตเทิร์นและนิพจน์โดยคั่นด้วยเครื่องหมายเท่ากับ (`=`) หลักการทำงานของมันเหมือนกับ `match` ทุกอย่าง โดยนิพจน์ทางขวาจะถูกส่งเข้าไปเปรียบเทียบ และแพตเทิร์นทางซ้ายจะทำหน้าที่เป็นอาร์มแรกของ `match` ในตัวอย่างนี้ แพตเทิร์นคือ `Some(max)` และตัวแปร `max` จะถูกผูกเข้ากับค่าที่อยู่ภายใน `Some` จากนั้นเราก็สามารถนำ `max` มาใช้งานภายในบล็อกของ `if let` ได้ในลักษณะเดียวกับที่เราใช้ `max` ในอาร์มของ `match` โดยโค้ดในบล็อก `if let` จะทำงานก็ต่อเมื่อค่านั้นตรงกับแพตเทิร์นที่กำหนดไว้เท่านั้น

การใช้ `if let` ช่วยให้พิมพ์โค้ดน้อยลง ย่อหน้าน้อยลง และลดโค้ด boilerplate ลงไปได้มาก อย่างไรก็ดี สิ่งที่ต้องแลกมาคือเราจะสูญเสียการตรวจสอบความครอบคลุมทุกกรณี (exhaustive checking) ที่ `match` บังคับใช้เพื่อป้องกันไม่ให้เราลืมจัดการกรณีใดกรณีหนึ่งไป การตัดสินใจเลือกระหว่าง `match` กับ `if let` จึงขึ้นอยู่กับสถานการณ์และลักษณะงานของคุณ ว่าความกระชับที่ได้มานั้นคุ้มค่ากับการยอมแลกการตรวจสอบความครบถ้วนของกรณีต่างๆ หรือไม่

พูดอีกอย่างหนึ่งก็คือ เราสามารถมองว่า `if let` เป็นน้ำตาลทางไวยากรณ์ (syntax sugar) ของคำสั่ง `match` ที่สั่งให้โค้ดทำงานเมื่อค่าตรงกับแพตเทิร์นหนึ่ง แล้วละเว้นค่าอื่นๆ ทั้งหมดที่เหลือ

นอกจากนี้ เรายังสามารถใส่ `else` คู่กับ `if let` ได้ด้วย โดยบล็อกโค้ดในส่วนของ `else` จะเทียบเท่ากับบล็อกโค้ดในกรณี `_` ของนิพจน์ `match` หากเขียนเทียบเคียงกัน ย้อนกลับไปดูนิยามของ enum `Coin` ในลิสติ้ง 6-4 ที่วาเรียนต์ `Quarter` มีการเก็บค่า `UsState` เอาไว้ข้างใน หากเราต้องการนับจำนวนเหรียญทั้งหมดที่ไม่ใช่เหรียญควอเตอร์ ควบคู่ไปกับการขานชื่อรัฐของเหรียญควอเตอร์ที่พบ เราสามารถเขียนด้วยนิพจน์ `match` ได้ดังนี้:

อย่างไรก็ตาม การเขียนแบบนี้ก็ยังชวนให้สับสนและติดตามการทำงานได้ยากอยู่ดี! เพราะกิ่งหนึ่งของ `if let` มีหน้าที่ส่งค่ากลับออกมา ส่วนอีกกิ่งหนึ่งกลับ return ออกจากฟังก์ชันไปเลย

เพื่อให้การเขียนรูปแบบยอดนิยมนี้มีความสวยงามและเป็นธรรมชาติยิ่งขึ้น Rust จึงมีไวยากรณ์ `let...else` โดย `let...else` จะรับแพตเทิร์นไว้ทางฝั่งซ้าย และรับนิพจน์ไว้ทางฝั่งขวา คล้ายกับ `if let` มาก แต่จะไม่มีกิ่ง `if` มีเพียงแค่กิ่ง `else` เท่านั้น หากแพตเทิร์นจับคู่สำเร็จ มันจะผูกค่าจากแพตเทิร์นเข้ามาไว้ในขอบเขตภายนอก (outer scope) ทันที แต่ถ้าแพตเทิร์น_ไม่_ตรงกัน โปรแกรมจะวิ่งเข้าไปทำงานในส่วนของ `else` ซึ่งบังคับว่าจะต้องมีคำสั่ง return ออกจากฟังก์ชัน (หรือคำสั่งอื่นที่ทำให้หลุดจากโฟลว์การทำงาน)

หากคุณพบเจอสถานการณ์ที่ตรรกะในโปรแกรมดูยืดเยื้อหรือซ้ำซ้อนเกินกว่าจะใช้ `match` อย่าลืมว่าคุณยังมีเครื่องมืออย่าง `if let` และ `let...else` อยู่ในกล่องเครื่องมือของ Rust ให้เลือกใช้งานได้อย่างเหมาะสม

## สรุป

จนถึงตอนนี้ เราได้เรียนรู้วิธีการใช้ enum เพื่อสร้างชนิดข้อมูลที่กำหนดขึ้นเอง ซึ่งสามารถเลือกเป็นค่าใดค่าหนึ่งจากกลุ่มของค่าที่แจกแจงไว้ได้อย่างชัดเจน นอกจากนี้ เรายังได้เห็นว่าชนิดข้อมูล `Option<T>` ในไลบรารีมาตรฐานช่วยให้เราใช้ประโยชน์จากระบบชนิดข้อมูลในการป้องกันข้อผิดพลาดได้อย่างไร และเมื่อค่าของ enum มีข้อมูลบรรจุอยู่ภายใน เราก็สามารถใช้ `match` หรือ `if let` ในการดึงข้อมูลเหล่านั้นออกมาใช้งานได้ ขึ้นอยู่กับว่าเราต้องการจัดการกับกรณีต่างๆ มากน้อยเพียงใด

ตอนนี้โปรแกรม Rust ของคุณสามารถถ่ายทอดแนวคิดต่างๆ ในโดเมนของงานได้อย่างสมบูรณ์ผ่าน struct และ enum การสร้างชนิดข้อมูลที่กำหนดขึ้นเองเพื่อใช้ใน API ยังช่วยรับประกันความปลอดภัยของชนิดข้อมูล (type safety) โดยคอมไพเลอร์จะคอยตรวจสอบอย่างเข้มงวดว่า ฟังก์ชันต่างๆ จะได้รับเฉพาะค่าที่มีชนิดข้อมูลตรงตามที่ฟังก์ชันนั้นๆ คาดหวังไว้เท่านั้น

และเพื่อที่เราจะสามารถออกแบบและส่งมอบ API ที่จัดโครงสร้างอย่างเป็นระเบียบ เรียบง่ายต่อการใช้งาน และเปิดเผยให้ผู้ใช้มองเห็นเฉพาะสิ่งที่จำเป็นต้องใช้จริงๆ ในบทถัดไปเราจะมาเรียนรู้เรื่องมอดูล (modules) ของภาษารัสต์กัน
