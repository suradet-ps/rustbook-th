## การควบคุมโฟลว์แบบกระชับด้วย `if let` และ `let...else`

วากยสัมพันธ์ `if let` ช่วยให้คุณรวม `if` และ `let` เข้าด้วยกันเป็นวิธีที่สั้นกระชับกว่าในการจัดการค่าที่จับคู่กับแพตเทิร์น (pattern) หนึ่งในขณะที่เพิกเฉยต่อค่าที่เหลือ พิจารณาโปรแกรมในลิสติ้ง 6-6 ที่จับคู่กับค่า `Option<u8>` ในตัวแปร `config_max` แต่ต้องการรันโค้ดเฉพาะเมื่อค่าเป็นวาเรียนต์ (variant) `Some`

หากค่าเป็น `Some` เราจะพิมพ์ค่าที่อยู่ในวาเรียนต์ `Some` ออกมาโดยผูกค่าเข้ากับตัวแปร `max` ในแพตเทิร์น เราไม่ต้องการทำอะไรกับค่า `None` เพื่อให้เอ็กซ์เพรสชัน `match` ผ่าน เราต้องเพิ่ม `_ => ()` หลังจากจัดการเพียงวาเรียนต์เดียว ซึ่งเป็นโค้ดโบลเลอร์เพลต (boilerplate) ที่น่ารำคาญ

วากยสัมพันธ์ `if let` รับแพตเทิร์นและเอ็กซ์เพรสชันที่คั่นด้วยเครื่องหมายเท่ากับ มันทำงานเหมือนกับ `match` โดยที่เอ็กซ์เพรสชันถูกส่งให้ `match` และแพตเทิร์นเป็นอาร์ม (arm) แรกของมัน ในกรณีนี้ แพตเทิร์นคือ `Some(max)` และ `max` ผูกกับค่าที่อยู่ภายใน `Some` จากนั้นเราสามารถใช้ `max` ในเนื้อในของบล็อก `if let` ได้ในลักษณะเดียวกับที่เราใช้ `max` ในอาร์ม `match` ที่สอดคล้องกัน โค้ดในบล็อก `if let` จะรันเฉพาะเมื่อค่าจับคู่กับแพตเทิร์นได้

การใช้ `if let` หมายถึงการพิมพ์น้อยลง การเยื้องน้อยลง และโค้ดโบลเลอร์เพลตน้อยลง อย่างไรก็ตาม คุณจะสูญเสียการตรวจสอบความครบถ้วนทุกกรณีที่ `match` บังคับใช้ ซึ่งรับประกันว่าคุณไม่ได้ลืมจัดการกรณีใดๆ การเลือกระหว่าง `match` กับ `if let` ขึ้นอยู่กับว่าคุณกำลังทำอะไรในสถานการณ์เฉพาะของคุณ และการได้ความกระชับมาเป็นการแลกเปลี่ยนที่เหมาะสมกับการสูญเสียการตรวจสอบความครบถ้วนทุกกรณีหรือไม่

กล่าวอีกนัยหนึ่ง คุณสามารถคิดว่า `if let` เป็นน้ำตาลทางวากยสัมพันธ์ (syntax sugar) สำหรับ `match` ที่รันโค้ดเมื่อค่าจับคู่กับแพตเทิร์นหนึ่งแล้วเพิกเฉยต่อค่าอื่นๆ ทั้งหมด

เราสามารถใส่ `else` ไว้กับ `if let` ได้ บล็อกโค้ดที่ใช้กับ `else` นั้นเหมือนกับบล็อกโค้ดที่จะใช้กับกรณี `_` ในเอ็กซ์เพรสชัน `match` ที่เทียบเท่ากับ `if let` และ `else` ย้อนนึกถึงนิยาม enum `Coin` ในลิสติ้ง 6-4 ซึ่งวาเรียนต์ `Quarter` เก็บค่า `UsState` ไว้ด้วย หากเราต้องการนับเหรียญที่ไม่ใช่ควอเตอร์ทั้งหมดที่เราเห็นพร้อมกับประกาศรัฐของควอเตอร์ไปด้วย เราทำเช่นนั้นได้ด้วยเอ็กซ์เพรสชัน `match` ดังนี้:

หากคุณมีสถานการณ์ที่โปรแกรมของคุณมีตรรกะที่ยืดยาวเกินกว่าจะแสดงออกด้วย `match` โปรดจำไว้ว่า `if let` และ `let...else` ก็อยู่ในกล่องเครื่องมือ Rust ของคุณเช่นกัน

## สรุป

ตอนนี้เราได้ครอบคลุมวิธีใช้ enum เพื่อสร้างชนิดข้อมูลกำหนดเองที่สามารถเป็นหนึ่งในชุดของค่าที่แจกแจงไว้ได้แล้ว เราได้แสดงให้เห็นว่าชนิด `Option<T>` ของไลบรารีมาตรฐานช่วยให้คุณใช้ระบบชนิดข้อมูลเพื่อป้องกันข้อผิดพลาดได้อย่างไร เมื่อค่า enum มีข้อมูลอยู่ข้างใน คุณสามารถใช้ `match` หรือ `if let` เพื่อดึงและใช้ค่าเหล่านั้นได้ โดยขึ้นอยู่กับว่าคุณต้องจัดการกี่กรณี

โปรแกรม Rust ของคุณตอนนี้สามารถแสดงแนวคิดในโดเมนของคุณได้โดยใช้ struct และ enum การสร้างชนิดข้อมูลกำหนดเองเพื่อใช้ใน API ของคุณช่วยรับประกันความปลอดภัยของชนิดข้อมูล (type safety): คอมไพเลอร์จะทำให้แน่ใจว่าฟังก์ชันของคุณได้รับเฉพาะค่าที่มีชนิดที่แต่ละฟังก์ชันคาดหวังไว้

เพื่อมอบ API ที่จัดระเบียบอย่างดีให้กับผู้ใช้ของคุณ ใช้งานได้ตรงไปตรงมา และเปิดเผยเฉพาะสิ่งที่ผู้ใช้ของคุณต้องการจริงๆ ตอนนี้มาหันไปดูมอดูล (module) ของ Rust กัน
