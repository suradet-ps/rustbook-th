# สมาร์ตพอยน์เตอร์

พอยน์เตอร์ (pointer) เป็นแนวคิดทั่วไปสำหรับตัวแปรที่บรรจุที่อยู่ในหน่วยความจำ ที่อยู่นี้หมายถึง หรือ “ชี้ไปที่” ข้อมูลอื่นๆ ชนิดของพอยน์เตอร์ที่พบได้บ่อยที่สุดใน Rust คือเรเฟอเรนซ์ (reference) ซึ่งคุณได้เรียนรู้ไปแล้วในบทที่ 4 เรเฟอเรนซ์ถูกระบุด้วยสัญลักษณ์ `&` และยืมค่าที่มันชี้ไป มันไม่มีความสามารถพิเศษใดๆ นอกจากการอ้างถึงข้อมูล และไม่มีโอเวอร์เฮดใดๆ

ในทางกลับกัน _สมาร์ตพอยน์เตอร์_ (smart pointer) คือโครงสร้างข้อมูลที่ทำตัวเหมือนพอยน์เตอร์แต่ยังมีข้อมูลเมตาและความสามารถเพิ่มเติม แนวคิดของสมาร์ตพอยน์เตอร์ไม่ใช่เอกลักษณ์เฉพาะของ Rust: สมาร์ตพอยน์เตอร์กำเนิดใน C++ และมีอยู่ในภาษาอื่นๆ ด้วย Rust มีสมาร์ตพอยน์เตอร์หลากหลายชนิดที่นิยามไว้ในไลบรารีมาตรฐาน ซึ่งให้ฟังก์ชันการทำงานเกินกว่าที่เรเฟอเรนซ์มอบให้ เพื่อสำรวจแนวคิดทั่วไป เราจะดูตัวอย่างของสมาร์ตพอยน์เตอร์ที่แตกต่างกันสองสามตัวอย่าง รวมถึงชนิดสมาร์ตพอยน์เตอร์แบบ_การนับจำนวนเรเฟอเรนซ์_ (reference counting) พอยน์เตอร์นี้ช่วยให้คุณอนุญาตให้ข้อมูลมีเจ้าของหลายรายได้ โดยการติดตามจำนวนเจ้าของ และเมื่อไม่มีเจ้าของเหลืออยู่ ก็ทำความสะอาดข้อมูลนั้น

ใน Rust ด้วยแนวคิดเรื่องความเป็นเจ้าของ (ownership) และการยืม (borrowing) จึงมีความแตกต่างเพิ่มเติมระหว่างเรเฟอเรนซ์และสมาร์ตพอยน์เตอร์: ในขณะที่เรเฟอเรนซ์เพียงยืมข้อมูล แต่ในหลายกรณี สมาร์ตพอยน์เตอร์_เป็นเจ้าของ_ข้อมูลที่มันชี้ไป

สมาร์ตพอยน์เตอร์มักถูกอิมพลีเมนต์โดยใช้ struct ต่างจาก struct ทั่วไป สมาร์ตพอยน์เตอร์อิมพลีเมนต์เทรต (trait) `Deref` และ `Drop` เทรต `Deref` อนุญาตให้อินสแตนซ์ (instance) ของ struct สมาร์ตพอยน์เตอร์ทำตัวเหมือนเรเฟอเรนซ์ เพื่อให้คุณเขียนโค้ดที่ทำงานกับทั้งเรเฟอเรนซ์หรือสมาร์ตพอยน์เตอร์ได้ เทรต `Drop` อนุญาตให้คุณปรับแต่งโค้ดที่จะถูกรันเมื่ออินสแตนซ์ของสมาร์ตพอยน์เตอร์ออกจากสโคป ในบทนี้ เราจะพูดคุยถึงเทรตทั้งสองนี้และสาธิตว่าทำไมมันจึงสำคัญต่อสมาร์ตพอยน์เตอร์

เนื่องจากแพตเทิร์น (pattern) ของสมาร์ตพอยน์เตอร์เป็นแพตเทิร์นการออกแบบทั่วไปที่ถูกใช้บ่อยใน Rust บทนี้จะไม่ครอบคลุมสมาร์ตพอยน์เตอร์ที่มีอยู่ทั้งหมด ไลบรารีหลายแห่งมีสมาร์ตพอยน์เตอร์เป็นของตัวเอง และคุณยังเขียนของตัวเองได้ด้วย เราจะครอบคลุมสมาร์ตพอยน์เตอร์ที่พบบ่อยที่สุดในไลบรารีมาตรฐาน:

- `Box<T>` สำหรับจัดสรรค่าบนฮีป (heap)
- `Rc<T>` ชนิดการนับจำนวนเรเฟอเรนซ์ที่เปิดให้มีความเป็นเจ้าของหลายราย
- `Ref<T>` และ `RefMut<T>` ซึ่งเข้าถึงผ่าน `RefCell<T>` ชนิดที่บังคับกฎการยืมตอนรันไทม์แทนที่จะเป็นตอนคอมไพล์

นอกจากนี้ เราจะครอบคลุมแพตเทิร์น_การเปลี่ยนแปลงค่าภายใน_ (interior mutability) ซึ่งเป็นแพตเทิร์นที่ชนิดข้อมูลแบบเปลี่ยนแปลงไม่ได้ (immutable) เปิดเผย API สำหรับเปลี่ยนแปลงค่าภายใน เราจะพูดคุยถึงวงจรเรเฟอเรนซ์ด้วย: ว่ามันสามารถรั่วไหลหน่วยความจำได้อย่างไรและจะป้องกันได้อย่างไร
