## ทุกจุดที่ใช้แพตเทิร์นได้

แพตเทิร์นปรากฏขึ้นในหลายตำแหน่งใน Rust และคุณได้ใช้มันอย่างมากโดยไม่รู้ตัว! หัวข้อนี้พูดถึงทุกตำแหน่งที่แพตเทิร์นใช้ได้

### อาร์มของ `match`

ดังที่ได้พูดคุยกันในบทที่ 6 เราใช้แพตเทิร์นในอาร์ม (arm) ของเอ็กซ์เพรสชัน (expression) `match` ในเชิงรูปแบบ เอ็กซ์เพรสชัน `match` ถูกนิยามว่าเป็นคำสงวน `match` ค่าที่จะจับคู่ และอาร์ม match หนึ่งอาร์มหรือมากกว่าซึ่งประกอบด้วยแพตเทิร์นและเอ็กซ์เพรสชันที่จะรันหากค่าจับคู่กับแพตเทิร์นของอาร์มนั้น ดังนี้:

<!--
  Manually formatted rather than using Markdown intentionally: Markdown does not
  support italicizing code in the body of a block like this!
-->

<pre><code>match <em>VALUE</em> {
    <em>PATTERN</em> => <em>EXPRESSION</em>,
    <em>PATTERN</em> => <em>EXPRESSION</em>,
    <em>PATTERN</em> => <em>EXPRESSION</em>,
}</code></pre>

ตัวอย่างเช่น นี่คือเอ็กซ์เพรสชัน `match` จากลิสติ้ง 6-5 ที่จับคู่กับค่า `Option<i32>` ในตัวแปร `x`:

```rust,ignore
match x {
    None => None,
    Some(i) => Some(i + 1),
}
```

แพตเทิร์นในเอ็กซ์เพรสชัน `match` นี้คือ `None` และ `Some(i)` ที่อยู่ทางด้านซ้ายของลูกศรแต่ละอัน

ข้อกำหนดหนึ่งของเอ็กซ์เพรสชัน `match` คือมันต้องครบถ้วนทุกกรณี (exhaustive) ในความหมายที่ว่าความเป็นไปได้ทั้งหมดของค่าในเอ็กซ์เพรสชัน `match` ต้องถูกนำมาพิจารณา วิธีหนึ่งในการรับประกันว่าคุณได้ครอบคลุมทุกความเป็นไปได้คือการมีแพตเทิร์นแบบครอบคลุมทั้งหมด (catch-all pattern) สำหรับอาร์มสุดท้าย ตัวอย่างเช่น ชื่อตัวแปรที่จับคู่กับค่าใดก็ได้จะไม่มีทางจับคู่ไม่สำเร็จ จึงครอบคลุมทุกกรณีที่เหลืออยู่

แพตเทิร์น `_` โดยเฉพาะจะจับคู่กับทุกสิ่ง แต่ไม่เคยผูกกับตัวแปร จึงมักถูกใช้ในอาร์ม match สุดท้าย ตัวอย่างเช่น แพตเทิร์น `_` มีประโยชน์เมื่อคุณต้องการเพิกเฉยต่อค่าใดๆ ที่ไม่ได้ระบุไว้ เราจะครอบคลุมแพตเทิร์น `_` อย่างละเอียดยิ่งขึ้นใน[“การเพิกเฉยต่อค่าในแพตเทิร์น”][ignoring-values-in-a-pattern]<!-- ignore --> ในช่วงหลังของบทนี้

### สเตตเมนต์ `let`

ก่อนบทนี้ เราได้พูดคุยอย่างชัดแจ้งถึงการใช้แพตเทิร์นกับ `match` และ `if let` เท่านั้น แต่ที่จริงแล้ว เราได้ใช้แพตเทิร์นในตำแหน่งอื่นๆ ด้วย รวมถึงในสเตตเมนต์ (statement) `let` ตัวอย่างเช่น พิจารณาการกำหนดค่าให้ตัวแปรแบบตรงไปตรงมาด้วย `let` นี้:

```rust
let x = 5;
```

ทุกครั้งที่คุณใช้สเตตเมนต์ `let` เช่นนี้ คุณกำลังใช้แพตเทิร์นอยู่ แม้ว่าคุณอาจไม่รู้ตัวก็ตาม! ในเชิงรูปแบบยิ่งกว่านั้น สเตตเมนต์ `let` มีหน้าตาดังนี้:

<!--
  Manually formatted rather than using Markdown intentionally: Markdown does not
  support italicizing code in the body of a block like this!
-->

<pre>
<code>let <em>PATTERN</em> = <em>EXPRESSION</em>;</code>
</pre>

ในสเตตเมนต์อย่าง `let x = 5;` ที่มีชื่อตัวแปรอยู่ในช่อง PATTERN ชื่อตัวแปรเป็นเพียงรูปแบบที่เรียบง่ายเป็นพิเศษของแพตเทิร์น Rust เปรียบเทียบเอ็กซ์เพรสชันกับแพตเทิร์นแล้วกำหนดชื่อทั้งหมดที่มันพบ ดังนั้น ในตัวอย่าง `let x = 5;` นั้น `x` คือแพตเทิร์นที่หมายความว่า “ผูกสิ่งที่จับคู่ตรงนี้เข้ากับตัวแปร `x`” เพราะชื่อ `x` เป็นแพตเทิร์นทั้งหมด แพตเทิร์นนี้จึงหมายความโดยนัยว่า “ผูกทุกอย่างเข้ากับตัวแปร `x` ไม่ว่าค่าจะเป็นอะไรก็ตาม”

เพื่อให้เห็นแง่มุมการจับคู่แพตเทิร์น (pattern matching) ของ `let` ชัดเจนยิ่งขึ้น พิจารณาลิสติ้ง 19-1 ซึ่งใช้แพตเทิร์นกับ `let` เพื่อแยกโครงสร้างข้อมูลทูเพิล

### เอ็กซ์เพรสชัน `if let` แบบมีเงื่อนไข

ในบทที่ 6 เราได้พูดคุยถึงวิธีใช้เอ็กซ์เพรสชัน `if let` โดยหลักเป็นวิธีที่สั้นกว่าในการเขียนสิ่งที่เทียบเท่ากับ `match` ที่จับคู่เพียงกรณีเดียว หากต้องการ `if let` สามารถมี `else` ที่สอดคล้องกันซึ่งบรรจุโค้ดที่จะรันหากแพตเทิร์นใน `if let` ไม่จับคู่

ลิสติ้ง 19-3 แสดงว่าเราสามารถผสมและจับคู่เอ็กซ์เพรสชัน `if let`, `else if` และ `else if let` ได้ด้วย การทำเช่นนี้ให้ความยืดหยุ่นมากกว่าเอ็กซ์เพรสชัน `match` ที่เราระบุได้เพียงค่าเดียวเพื่อเปรียบเทียบกับแพตเทิร์น นอกจากนี้ Rust ไม่ได้กำหนดว่าเงื่อนไขในชุดของอาร์ม `if let`, `else if` และ `else if let` ต้องเกี่ยวข้องกัน

โค้ดในลิสติ้ง 19-3 ตัดสินว่าจะให้พื้นหลังของคุณเป็นสีอะไรโดยอิงจากการตรวจสอบเงื่อนไขหลายอย่างเป็นชุด สำหรับตัวอย่างนี้ เราได้สร้างตัวแปรที่มีค่าฮาร์ดโค้ดไว้ ซึ่งโปรแกรมจริงอาจรับค่ามาจากอินพุตของผู้ใช้

โครงสร้างแบบมีเงื่อนไขนี้ช่วยให้เรารองรับความต้องการที่ซับซ้อนได้ ด้วยค่าฮาร์ดโค้ดที่เรามีในที่นี้ ตัวอย่างนี้จะพิมพ์ `Using purple as the background color`

คุณจะเห็นว่า `if let` สามารถแนะนำตัวแปรใหม่ที่บังเงาตัวแปรที่มีอยู่ได้ในลักษณะเดียวกับที่อาร์ม `match` ทำได้: บรรทัด `if let Ok(age) = age` แนะนำตัวแปร `age` ใหม่ที่บรรจุค่าที่อยู่ภายในวาเรียนต์ `Ok` ซึ่งบังเงาตัวแปร `age` ที่มีอยู่เดิม นี่หมายความว่าเราต้องวางเงื่อนไข `if age > 30` ไว้ภายในบล็อกนั้น: เราไม่สามารถรวมสองเงื่อนไขนี้เป็น `if let Ok(age) = age && age > 30` ได้ `age` ใหม่ที่เราต้องการเปรียบเทียบกับ 30 จะยังใช้ไม่ได้จนกว่าสโคปใหม่จะเริ่มต้นด้วยวงเล็บปีกกา

ข้อเสียของการใช้เอ็กซ์เพรสชัน `if let` คือคอมไพเลอร์ไม่ตรวจสอบความครบถ้วนทุกกรณี ในขณะที่เอ็กซ์เพรสชัน `match` นั้นคอมไพเลอร์ตรวจสอบให้ หากเราละเว้นบล็อก `else` สุดท้ายและพลาดการจัดการบางกรณีไป คอมไพเลอร์จะไม่เตือนเราเกี่ยวกับบั๊กทางตรรกะที่อาจเกิดขึ้น

โค้ดนี้พิมพ์ `Current location: (3, 5)` ค่า `&(3, 5)` จับคู่กับแพตเทิร์น `&(x, y)` ดังนั้น `x` คือค่า `3` และ `y` คือค่า `5`

เรายังสามารถใช้แพตเทิร์นในรายการพารามิเตอร์ของโคลเชอร์ (closure) ได้ในลักษณะเดียวกับในรายการพารามิเตอร์ของฟังก์ชัน เพราะโคลเชอร์คล้ายกับฟังก์ชัน ดังที่ได้พูดคุยกันในบทที่ 13

ณ จุดนี้ คุณได้เห็นวิธีใช้แพตเทิร์นหลายวิธีแล้ว แต่แพตเทิร์นไม่ได้ทำงานเหมือนกันในทุกตำแหน่งที่เราใช้มันได้ ในบางตำแหน่ง แพตเทิร์นต้องเป็นแพตเทิร์นที่จับคู่สำเร็จเสมอ (irrefutable) ในสถานการณ์อื่นๆ มันเป็นแพตเทิร์นที่อาจจับคู่ไม่สำเร็จ (refutable) ได้ เราจะพูดคุยถึงสองแนวคิดนี้ต่อไป
