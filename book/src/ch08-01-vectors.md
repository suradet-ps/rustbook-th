## เก็บรายการค่าด้วยเวกเตอร์

คอลเลกชันชนิดแรกที่เราจะมาศึกษากันคือ `Vec<T>` หรือที่รู้จักกันทั่วไปในชื่อ **เวกเตอร์ (vector)** เวกเตอร์ช่วยให้คุณสามารถจัดเก็บข้อมูลมากกว่าหนึ่งค่าไว้ในโครงสร้างข้อมูลเดี่ยวชิ้นเดียว โดยวางค่าทั้งหมดเรียงต่อกันเป็นแถวยาวในหน่วยความจำ และเวกเตอร์จะสามารถจัดเก็บได้เฉพาะค่าที่มีชนิดข้อมูลเดียวกันทั้งหมดเท่านั้น เวกเตอร์จึงมีประโยชน์อย่างยิ่งเมื่อคุณต้องการจัดเก็บรายการของข้อมูล เช่น แต่ละบรรทัดของข้อความในไฟล์ หรือราคาสินค้าแต่ละชิ้นในตะกร้าสินค้า

ในทางตรงกันข้าม เมื่อเราส่งค่าดัชนีที่อยู่นอกขอบเขตของเวกเตอร์เข้าไปยังเมธอด `get` มันจะส่งค่า `None` กลับมาอย่างนุ่มนวลโดยไม่ทำให้โปรแกรมแพนิก ซึ่งคุณควรเลือกใช้วิธีนี้เมื่อการเข้าถึงข้อมูลนอกช่วงมีโอกาสเกิดขึ้นได้เป็นปกติในสถานการณ์ทั่วไป จากนั้นโค้ดของคุณก็จะมีตรรกะคอยดักจับจัดการกับทั้งกรณี `Some(&element)` หรือกรณี `None` ดังที่เราได้เรียนรู้กันไปแล้วในบทที่ 6 ตัวอย่างเช่น หากค่าดัชนีนั้นได้รับมาจากการที่ผู้ใช้กรอกตัวเลขเข้ามา แล้วผู้ใช้เผลอพิมพ์ตัวเลขที่มากเกินไปจนได้ค่า `None` โปรแกรมของคุณก็สามารถแจ้งเตือนผู้ใช้ได้อย่างสุภาพว่าในเวกเตอร์มีข้อมูลอยู่กี่ตัว พร้อมทั้งเปิดโอกาสให้พวกเขากรอกค่าใหม่อีกครั้ง ซึ่งย่อมเป็นมิตรต่อผู้ใช้งานมากกว่าการปล่อยให้โปรแกรมแครชดับไปต่อหน้าต่อตาเพียงเพราะพิมพ์ผิด!

เมื่อโปรแกรมถือเรเฟอเรนซ์ที่ถูกต้องเอาไว้ ตัวตรวจการยืม (borrow checker) จะคอยบังคับใช้กฎความเป็นเจ้าของและการยืม (ownership and borrowing rules - จากบทที่ 4) อย่างเคร่งครัด เพื่อให้มั่นใจได้ว่าเรเฟอเรนซ์นี้ รวมถึงเรเฟอเรนซ์อื่นๆ ทั้งหมดที่ชี้ไปยังข้อมูลภายในเวกเตอร์จะยังคงถูกต้องและปลอดภัยตลอดเวลา ย้อนกลับไปดูกฎสำคัญที่ระบุว่า คุณไม่สามารถถือเรเฟอเรนซ์แบบเปลี่ยนแปลงได้ (mutable reference) และเรเฟอเรนซ์แบบเปลี่ยนแปลงไม่ได้ (immutable reference) ร่วมกันภายในสโคปเดียวกันได้ กฎข้อนี้จะแสดงให้เห็นชัดเจนในลิสติ้ง 8-6 เมื่อเราถือเรเฟอเรนซ์แบบเปลี่ยนแปลงไม่ได้ของข้อมูลตัวแรกในเวกเตอร์เอาไว้ แล้วพยายามจะเพิ่มข้อมูลตัวใหม่ต่อท้ายเวกเตอร์ ซึ่งโปรแกรมนี้จะคอมไพล์ไม่ผ่านอย่างแน่นอน หากเราพยายามนำเรเฟอเรนซ์ของตัวแรกนั้นมาเรียกใช้งานต่อในภายหลัง

ในการปรับเปลี่ยนค่าที่ตัวเรเฟอเรนซ์แบบเปลี่ยนแปลงได้ชี้ไป เราจำเป็นต้องใช้ตัวดำเนินการดีเรเฟอเรนซ์ (dereference operator) คือเครื่องหมายดอกจัน `*` เพื่อเข้าถึงตัวข้อมูลจริงที่อยู่ใน `i` เสียก่อน จึงจะสามารถใช้ตัวดำเนินการ `+=` ได้ ซึ่งเราจะได้พูดคุยเกี่ยวกับตัวดำเนินการดีเรเฟอเรนซ์อย่างละเอียดในหัวข้อ [“การตามเรเฟอเรนซ์ไปยังค่า”][deref]<!-- ignore --> ในบทที่ 15

การวนลูปผ่านเวกเตอร์ ไม่ว่าจะเป็นแบบอ่านอย่างเดียวหรือแบบแก้ไขข้อมูล ล้วนมีความปลอดภัยอย่างยิ่งด้วยกฎเกณฑ์ของ borrow checker หากเราพยายามแทรกหรือลบสมาชิกภายในตัวลูป `for` ในลิสติ้ง 8-7 หรือลิสติ้ง 8-8 คอมไพเลอร์จะปฏิเสธและแจ้งข้อผิดพลาดออกมาคล้ายกับในลิสติ้ง 8-6 ทันที เพราะเรเฟอเรนซ์ของเวกเตอร์ที่ลูป `for` ถือครองอยู่นั้น จะช่วยป้องกันไม่ให้เกิดการแก้ไขโครงสร้างของเวกเตอร์ทั้งหมดไปพร้อมๆ กัน

### การใช้ enum เพื่อจัดเก็บหลายชนิดข้อมูล

เวกเตอร์สามารถจัดเก็บได้เฉพาะข้อมูลที่เป็นชนิดเดียวกันเท่านั้น ซึ่งในบางกรณีอาจทำให้รู้สึกไม่สะดวกเท่าใดนัก เพราะแน่นอนว่าย่อมมีหลายสถานการณ์ที่เราจำเป็นต้องจัดเก็บรายการข้อมูลที่มีชนิดแตกต่างกันคละกันไป แต่โชคดีที่วาเรียนต์ต่างๆ ของ enum ล้วนถูกนิยามอยู่ภายใต้ชนิดข้อมูล enum เดียวกัน ดังนั้นเมื่อเราต้องการชนิดข้อมูลเดี่ยวชนิดเดียวที่สามารถเป็นตัวแทนของข้อมูลต่างชนิดกันได้ เราจึงสามารถนิยามและใช้งาน enum เข้ามาช่วยได้!

ตัวอย่างเช่น สมมติว่าเราต้องการอ่านค่าจากแถวหนึ่งในโปรแกรมสเปรดชีต ซึ่งข้อมูลในแต่ละคอลัมน์ของแถวนั้นมีทั้งตัวเลขจำนวนเต็ม, ตัวเลขทศนิยม และข้อความสตริง เราสามารถนิยาม enum ที่แต่ละวาเรียนต์ทำหน้าที่เก็บชนิดข้อมูลที่แตกต่างกันเหล่านั้น และวาเรียนต์ทั้งหมดก็จะถือว่าเป็นชนิดข้อมูลเดียวกัน นั่นคือชนิดของ enum ตัวนั้น จากนั้นเราก็สร้างเวกเตอร์ขึ้นมาเพื่อจัดเก็บ enum ดังกล่าว ซึ่งในทางปฏิบัติแล้ว ก็คือการทำให้เวกเตอร์สามารถจัดเก็บข้อมูลต่างชนิดกันได้นั่นเอง ดังที่แสดงไว้ในลิสติ้ง 8-9

Rust จำเป็นต้องรู้ชนิดข้อมูลที่จะบรรจุอยู่ในเวกเตอร์ให้ได้อย่างแน่ชัดตั้งแต่ตอนคอมไพล์ เพื่อที่คอมไพเลอร์จะได้คำนวณขนาดหน่วยความจำบนฮีปที่จะต้องใช้สำหรับจัดเก็บสมาชิกแต่ละตัวได้อย่างถูกต้องแม่นยำ นอกจากนี้ เรายังต้องระบุให้ชัดเจนด้วยว่าอนุญาตให้มีชนิดข้อมูลใดบ้างในเวกเตอร์นี้ หาก Rust ยอมให้เวกเตอร์เก็บชนิดข้อมูลใดๆ ก็ได้อย่างอิสระ ก็อาจมีความเสี่ยงที่ชนิดข้อมูลบางชนิดจะทำให้เกิดข้อผิดพลาดขึ้นเมื่อมีคำสั่งมาดำเนินการกับสมาชิกในเวกเตอร์ การนำ enum มาใช้ควบคู่กับคำสั่ง `match` จะช่วยให้ Rust มั่นใจได้ตั้งแต่ตอนคอมไพล์ว่า ทุกกรณีที่เป็นไปได้จะได้รับการจัดการอย่างครบถ้วนแน่นอน ดังที่เราได้พูดคุยกันในบทที่ 6

แต่ถ้าหากคุณไม่สามารถล่วงรู้ชนิดข้อมูลทั้งหมดที่โปรแกรมจะต้องรับเข้ามาในเวกเตอร์ในตอนรันไทม์ได้อย่างครบถ้วน เทคนิคการใช้ enum นี้ก็อาจจะไม่ตอบโจทย์ ในกรณีเช่นนั้น คุณสามารถเปลี่ยนไปใช้เทคนิคที่เรียกว่า **เทรตออบเจกต์ (trait object)** แทนได้ ซึ่งเราจะได้เรียนรู้กันในบทที่ 18

หลังจากที่เราได้เรียนรู้วิธีการใช้งานเวกเตอร์ที่พบบ่อยกันไปแล้ว อย่าลืมเข้าไปอ่าน [เอกสารประกอบ API ของ `Vec<T>`][vec-api]<!-- ignore --> เพื่อศึกษาเมธอดที่มีประโยชน์อื่นๆ อีกมากมายที่ไลบรารีมาตรฐานเตรียมไว้ให้ เช่น นอกเหนือจากเมธอด `push` แล้ว ยังมีเมธอด `pop` ที่ใช้สำหรับลบและส่งค่าสมาชิกตัวสุดท้ายกลับออกมา เป็นต้น
