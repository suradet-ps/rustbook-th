## ภาคผนวก E: ฉบับของ Rust

ในบทที่ 1 คุณได้เห็นแล้วว่าคำสั่ง `cargo new` ได้เพิ่มข้อมูลเมทาดาทาเกี่ยวกับฉบับ (edition) ลงในไฟล์ _Cargo.toml_ ของคุณ ภาคผนวกนี้จะอธิบายว่าสิ่งนั้นมีความหมายอย่างไร!

ภาษา Rust และคอมไพเลอร์มีรอบการเผยแพร่เวอร์ชันใหม่ทุก 6 สัปดาห์ ซึ่งหมายความว่าผู้ใช้งานจะได้รับฟีเจอร์ใหม่ ๆ เข้ามาอย่างต่อเนื่อง ภาษาโปรแกรมอื่น ๆ อาจเลือกปล่อยการเปลี่ยนแปลงครั้งใหญ่แบบนาน ๆ ครั้ง ทว่า Rust เลือกที่จะปล่อยการอัปเดตย่อย ๆ บ่อยกว่า เมื่อเวลาผ่านไป การเปลี่ยนแปลงเล็ก ๆ น้อย ๆ เหล่านี้จะสะสมรวมกันจนเกิดความก้าวหน้าอย่างมีนัยสำคัญ แต่หากมองเปรียบเทียบในแต่ละรอบการเผยแพร่ การจะมองย้อนกลับไปแล้วอุทานว่า “ว้าว ระหว่าง Rust 1.10 กับ Rust 1.31 ภาษา Rust เปลี่ยนไปเยอะมาก!” ก็อาจเป็นเรื่องที่สังเกตเห็นได้ยาก

ทุก ๆ ประมาณ 3 ปี ทีมพัฒนา Rust จะเปิดตัว _ฉบับ (edition)_ ใหม่ของ Rust โดยแต่ละฉบับจะรวบรวมฟีเจอร์ทั้งหมดที่ถูกเพิ่มเข้ามาแล้วให้อยู่ในรูปของแพ็กเกจที่เข้าใจได้ชัดเจน พร้อมด้วยเอกสารประกอบและชุดเครื่องมือที่ได้รับการอัปเดตอย่างสมบูรณ์ ซึ่งฉบับใหม่นี้จะถูกปล่อยออกมาเป็นส่วนหนึ่งของรอบการเผยแพร่ทุก 6 สัปดาห์ตามปกติ

แต่ละฉบับมีจุดประสงค์ที่ตอบโจทย์กลุ่มบุคคลที่แตกต่างกัน:

- สำหรับผู้ใช้งาน Rust ในปัจจุบัน ฉบับใหม่จะรวบรวมการเปลี่ยนแปลงย่อย ๆ มารวมเป็นแพ็กเกจที่เข้าใจและนำไปปรับใช้ได้ง่าย
- สำหรับผู้ที่ยังไม่ได้ใช้งาน ฉบับใหม่คือสัญญาณบ่งบอกว่ามีความก้าวหน้าครั้งสำคัญเกิดขึ้นในภาษา ซึ่งอาจเป็นแรงจูงใจให้หันมาทดลองใช้งาน Rust อีกครั้ง
- สำหรับทีมงานผู้พัฒนาภาษา Rust เอง ฉบับใหม่คือเป้าหมายร่วมและจุดรวมพลังขับเคลื่อนโปรเจกต์ในภาพรวม

ณ ขณะที่เขียนหนังสือเล่มนี้ มีฉบับของ Rust ให้เลือกใช้งานได้ 4 ฉบับ ได้แก่ Rust 2015, Rust 2018, Rust 2021 และ Rust 2024 โดยหนังสือเล่มนี้เขียนขึ้นโดยใช้สำนวนและแบบแผนของ Rust ฉบับ 2024

คีย์ `edition` ในไฟล์ _Cargo.toml_ จะระบุว่าคอมไพเลอร์ควรประมวลผลโค้ดของคุณตามข้อกำหนดของฉบับใด หากไม่มีการระบุคีย์นี้ Rust จะเลือกใช้ฉบับ `2015` โดยอัตโนมัติเพื่อรักษาความเข้ากันได้ย้อนหลัง (backward compatibility)

แต่ละโปรเจกต์สามารถเลือกเปลี่ยนไปใช้ฉบับอื่นนอกเหนือจากฉบับ 2015 ที่เป็นค่าเริ่มต้นได้ โดยในแต่ละฉบับอาจมีการเปลี่ยนแปลงที่ไม่เข้ากันกับโค้ดเดิม เช่น การเพิ่มคำสงวน (keyword) ใหม่ซึ่งอาจชนกับชื่อตัวระบุ (identifier) ที่เคยตั้งไว้ในโค้ดเดิม ทว่าหากคุณไม่ได้เลือกเปลี่ยนไปใช้ฉบับใหม่ดังกล่าว โค้ดของคุณจะยังคงคอมไพล์ผ่านได้ตามปกติอย่างต่อเนื่อง แม้คุณจะอัปเกรดเวอร์ชันของคอมไพเลอร์ Rust ไปเป็นเวอร์ชันล่าสุดแล้วก็ตาม

คอมไพเลอร์ของ Rust ทุกเวอร์ชันจะรองรับฉบับใดก็ตามที่เปิดตัวมาก่อนการเผยแพร่ของคอมไพเลอร์เวอร์ชันนั้น และสามารถลิงก์เครต (crates) ที่เขียนด้วยฉบับต่าง ๆ เข้าด้วยกันได้อย่างราบรื่น การเปลี่ยนแปลงของฉบับจะมีผลเฉพาะขั้นตอนที่คอมไพเลอร์แยกวิเคราะห์ไวยากรณ์ (parse) โค้ดในเบื้องต้นเท่านั้น ดังนั้น หากโปรเจกต์ของคุณใช้ Rust 2015 แต่ดีเพนเดนซี (dependency) ตัวหนึ่งใช้ Rust 2018 โปรเจกต์ของคุณก็ยังคงคอมไพล์ผ่านและสามารถเรียกใช้งานดีเพนเดนซีนั้นได้โดยไม่มีปัญหา ในทำนองเดียวกัน หากโปรเจกต์ของคุณใช้ Rust 2018 แต่ดีเพนเดนซีใช้ Rust 2015 ก็ทำงานร่วมกันได้อย่างสมบูรณ์แบบเช่นกัน

เพื่อความเข้าใจที่ชัดเจน: ฟีเจอร์ส่วนใหญ่จะเปิดให้ใช้งานได้ในทุกฉบับ นักพัฒนาที่ใช้ Rust ฉบับใดก็ตามจะยังคงได้รับประโยชน์จากการปรับปรุงประสิทธิภาพต่าง ๆ เมื่อมีการปล่อยเวอร์ชันเสถียรใหม่ออกมา อย่างไรก็ตาม ในบางกรณี โดยเฉพาะเมื่อมีการเพิ่มคำสงวนใหม่เข้ามา ฟีเจอร์ใหม่บางอย่างอาจเปิดให้ใช้งานได้เฉพาะในฉบับใหม่เท่านั้น คุณจึงต้องสลับไปใช้ฉบับที่ใหม่กว่าหากต้องการใช้ประโยชน์จากฟีเจอร์เหล่านั้น

สามารถศึกษาข้อมูลและรายละเอียดเพิ่มเติมได้ในคู่มือ [_The Rust Edition Guide_][edition-guide] ซึ่งเป็นหนังสือฉบับสมบูรณ์ที่แจกแจงข้อแตกต่างระหว่างฉบับต่าง ๆ และอธิบายวิธีการอัปเกรดโค้ดของคุณไปสู่ฉบับใหม่โดยอัตโนมัติผ่านคำสั่ง `cargo fix`
