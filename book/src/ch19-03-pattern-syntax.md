### การจับคู่ตัวแปรที่มีชื่อ

ตัวแปรที่มีชื่อเป็นแพตเทิร์นที่จับคู่สำเร็จเสมอซึ่งจับคู่กับค่าใดก็ได้ และเราได้ใช้มันหลายครั้งในหนังสือเล่มนี้ อย่างไรก็ตาม มีความยุ่งยากเกิดขึ้นเมื่อคุณใช้ตัวแปรที่มีชื่อในเอ็กซ์เพรสชัน `match`, `if let` หรือ `while let` เพราะเอ็กซ์เพรสชันแต่ละชนิดเหล่านี้เริ่มสโคปใหม่ ตัวแปรที่ถูกประกาศเป็นส่วนหนึ่งของแพตเทิร์นภายในเอ็กซ์เพรสชันเหล่านี้จะบังเงาตัวแปรที่มีชื่อเดียวกันนอกโครงสร้างนั้น เช่นเดียวกับกรณีของตัวแปรทั้งหมด ในลิสติ้ง 19-11 เราประกาศตัวแปรชื่อ `x` ที่มีค่า `Some(5)` และตัวแปร `y` ที่มีค่า `10` จากนั้นเราสร้างเอ็กซ์เพรสชัน `match` บนค่า `x` ลองดูแพตเทิร์นในอาร์ม match และ `println!` ตอนท้าย แล้วลองหาคำตอบว่าโค้ดจะพิมพ์อะไรก่อนที่คุณจะรันโค้ดนี้หรืออ่านต่อ

มาดูกันทีละขั้นว่าเกิดอะไรขึ้นเมื่อเอ็กซ์เพรสชัน `match` ทำงาน แพตเทิร์นในอาร์ม match แรกไม่จับคู่กับค่าที่กำหนดไว้ของ `x` โค้ดจึงดำเนินต่อไป

แพตเทิร์นในอาร์ม match ที่สองแนะนำตัวแปรใหม่ชื่อ `y` ที่จะจับคู่กับค่าใดก็ได้ที่อยู่ภายในค่า `Some` เพราะเราอยู่ในสโคปใหม่ภายในเอ็กซ์เพรสชัน `match` นี่จึงเป็นตัวแปร `y` ตัวใหม่ ไม่ใช่ `y` ที่เราประกาศไว้ตอนต้นด้วยค่า `10` การผูกค่า (binding) `y` ใหม่นี้จะจับคู่กับค่าใดก็ได้ที่อยู่ภายใน `Some` ซึ่งก็คือสิ่งที่เรามีใน `x` ดังนั้น `y` ใหม่นี้จึงผูกกับค่าภายในของ `Some` ใน `x` ค่านั้นคือ `5` เอ็กซ์เพรสชันของอาร์มนั้นจึงทำงานและพิมพ์ `Matched, y = 5`

หาก `x` เป็นค่า `None` แทนที่จะเป็น `Some(5)` แพตเทิร์นในสองอาร์มแรกจะไม่จับคู่ ค่านั้นจึงจะจับคู่กับขีดล่าง เราไม่ได้แนะนำตัวแปร `x` ในแพตเทิร์นของอาร์มขีดล่าง `x` ในเอ็กซ์เพรสชันจึงยังเป็น `x` ตัวนอกที่ยังไม่ถูกบังเงา ในกรณีสมมติเช่นนี้ `match` จะพิมพ์ `Default case, x = None`

เมื่อเอ็กซ์เพรสชัน `match` เสร็จสิ้น สโคปของมันก็จบลง และสโคปของ `y` ตัวในก็เช่นกัน `println!` ตัวสุดท้ายสร้างผลลัพธ์ `at the end: x = Some(5), y = 10`

ในการสร้างเอ็กซ์เพรสชัน `match` ที่เปรียบเทียบค่าของ `x` และ `y` ตัวนอก แทนที่จะแนะนำตัวแปรใหม่ที่บังเงาตัวแปร `y` ที่มีอยู่ เราจะต้องใช้เงื่อนไขการ์ด match (match guard) แทน เราจะพูดถึงการ์ด match ในภายหลังในหัวข้อ[“การเพิ่มเงื่อนไขด้วยการ์ด match”](#การเพิมเงือนไขดวยการด-match)<!-- ignore -->

สำหรับวาเรียนต์ของ enum ที่คล้าย struct เช่น `Message::Move` เราใช้แพตเทิร์นที่คล้ายกับแพตเทิร์นที่เราระบุเพื่อจับคู่กับ struct ได้ หลังชื่อวาเรียนต์ เราวางวงเล็บปีกกาแล้วระบุฟิลด์พร้อมตัวแปร เพื่อให้เราแยกชิ้นส่วนเพื่อใช้ในโค้ดของอาร์มนี้ได้ ในที่นี้เราใช้รูปแบบย่อเหมือนที่เราทำในลิสติ้ง 19-13

สำหรับวาเรียนต์ของ enum ที่คล้ายทูเพิล เช่น `Message::Write` ที่บรรจุทูเพิลที่มีสมาชิกหนึ่งตัว และ `Message::ChangeColor` ที่บรรจุทูเพิลที่มีสมาชิกสามตัว แพตเทิร์นจะคล้ายกับแพตเทิร์นที่เราระบุเพื่อจับคู่กับทูเพิล จำนวนตัวแปรในแพตเทิร์นต้องตรงกับจำนวนสมาชิกในวาเรียนต์ที่เรากำลังจับคู่

### การเพิ่มเงื่อนไขด้วยการ์ด match

_การ์ด match_ (match guard) เป็นเงื่อนไข `if` เพิ่มเติมที่ระบุหลังแพตเทิร์นในอาร์ม `match` ซึ่งต้องเป็นจริงด้วยเพื่อให้อาร์มนั้นถูกเลือก การ์ด match มีประโยชน์ในการแสดงแนวคิดที่ซับซ้อนกว่าที่แพตเทิร์นเพียงอย่างเดียวทำได้ อย่างไรก็ตาม โปรดสังเกตว่ามันใช้ได้เฉพาะในเอ็กซ์เพรสชัน `match` เท่านั้น ไม่ใช่ในเอ็กซ์เพรสชัน `if let` หรือ `while let`

เงื่อนไขสามารถใช้ตัวแปรที่สร้างในแพตเทิร์นได้ ลิสติ้ง 19-26 แสดง `match` ที่อาร์มแรกมีแพตเทิร์น `Some(x)` และมีการ์ด match `if x % 2 == 0` (ซึ่งจะเป็น `true` หากตัวเลขเป็นจำนวนคู่)

<Listing number="19-26" caption="การเพิ่มการ์ด match ให้กับแพตเทิร์น">

```rust
{{#rustdoc_include ../listings/ch19-patterns-and-matching/listing-19-26/src/main.rs:here}}
```

</Listing>

ตัวอย่างนี้จะพิมพ์ `The number 4 is even` เมื่อ `num` ถูกเปรียบเทียบกับแพตเทิร์นในอาร์มแรก มันจับคู่ได้เพราะ `Some(4)` จับคู่กับ `Some(x)` จากนั้นการ์ด match จะตรวจสอบว่าเศษที่ได้จากการหาร `x` ด้วย 2 เท่ากับ 0 หรือไม่ และเนื่องจากเท่ากัน อาร์มแรกจึงถูกเลือก

หาก `num` เป็น `Some(5)` แทน การ์ด match ในอาร์มแรกจะเป็น `false` เพราะเศษที่ได้จากการหาร 5 ด้วย 2 คือ 1 ซึ่งไม่เท่ากับ 0 Rust จะไปยังอาร์มที่สอง ซึ่งจะจับคู่ได้เพราะอาร์มที่สองไม่มีการ์ด match จึงจับคู่กับวาเรียนต์ `Some` ใดก็ได้

ไม่มีวิธีแสดงเงื่อนไข `if x % 2 == 0` ภายในแพตเทิร์น การ์ด match จึงให้ความสามารถในการแสดงตรรกะนี้แก่เรา ข้อเสียของความสามารถในการแสดงออกที่เพิ่มขึ้นนี้คือคอมไพเลอร์จะไม่พยายามตรวจสอบความครบถ้วนทุกกรณีเมื่อมีการใช้เอ็กซ์เพรสชันการ์ด match

เมื่อพูดคุยถึงลิสติ้ง 19-11 เราได้กล่าวว่าเราสามารถใช้การ์ด match เพื่อแก้ปัญหาเรื่องการบังเงาของแพตเทิร์นได้ ย้อนนึกว่าเราสร้างตัวแปรใหม่ภายในแพตเทิร์นในเอ็กซ์เพรสชัน `match` แทนที่จะใช้ตัวแปรนอก `match` ตัวแปรใหม่นั้นทำให้เราไม่สามารถทดสอบกับค่าของตัวแปรตัวนอกได้ ลิสติ้ง 19-27 แสดงวิธีที่เราสามารถใช้การ์ด match เพื่อแก้ปัญหานี้

<Listing number="19-27" file-name="src/main.rs" caption="การใช้การ์ด match เพื่อทดสอบความเท่ากันกับตัวแปรตัวนอก">

```rust
{{#rustdoc_include ../listings/ch19-patterns-and-matching/listing-19-27/src/main.rs}}
```

</Listing>

โค้ดนี้จะพิมพ์ `Default case, x = Some(5)` แพตเทิร์นในอาร์ม match ที่สองไม่ได้แนะนำตัวแปร `y` ใหม่ที่จะบังเงา `y` ตัวนอก ซึ่งหมายความว่าเราใช้ `y` ตัวนอกในการ์ด match ได้ แทนที่จะระบุแพตเทิร์นเป็น `Some(y)` ซึ่งจะบังเงา `y` ตัวนอก เราระบุ `Some(n)` การทำเช่นนี้สร้างตัวแปรใหม่ `n` ที่ไม่ได้บังเงาอะไร เพราะไม่มีตัวแปร `n` อยู่นอก `match`

การ์ด match `if n == y` ไม่ใช่แพตเทิร์น จึงไม่ได้แนะนำตัวแปรใหม่ `y` นี้_คือ_ `y` ตัวนอก ไม่ใช่ `y` ตัวใหม่ที่บังเงามัน และเราสามารถมองหาค่าที่มีค่าเดียวกับ `y` ตัวนอกได้โดยการเปรียบเทียบ `n` กับ `y`

คุณยังสามารถใช้ตัวดำเนินการ _หรือ_ `|` ในการ์ด match เพื่อระบุหลายแพตเทิร์นได้ เงื่อนไขการ์ด match จะมีผลกับทุกแพตเทิร์น ลิสติ้ง 19-28 แสดงลำดับความสำคัญเมื่อรวมแพตเทิร์นที่ใช้ `|` กับการ์ด match ส่วนสำคัญของตัวอย่างนี้คือการ์ด match `if y` มีผลกับ `4`, `5` _และ_ `6` แม้ว่ามันอาจดูเหมือนว่า `if y` มีผลกับ `6` เท่านั้น

<Listing number="19-28" caption="การรวมหลายแพตเทิร์นกับการ์ด match">

```rust
{{#rustdoc_include ../listings/ch19-patterns-and-matching/listing-19-28/src/main.rs:here}}
```

</Listing>

เงื่อนไขของ match ระบุว่าอาร์มจะจับคู่ได้ก็ต่อเมื่อค่าของ `x` เท่ากับ `4`, `5` หรือ `6` _และ_ `y` เป็น `true` เมื่อโค้ดนี้รัน แพตเทิร์นของอาร์มแรกจับคู่ได้เพราะ `x` เป็น `4` แต่การ์ด match `if y` เป็น `false` อาร์มแรกจึงไม่ถูกเลือก โค้ดจะไปยังอาร์มที่สอง ซึ่งจับคู่ได้ และโปรแกรมนี้พิมพ์ `no` เหตุผลก็คือเงื่อนไข `if` มีผลกับแพตเทิร์นทั้งหมด `4 | 5 | 6` ไม่ใช่แค่ค่าสุดท้าย `6` กล่าวอีกนัยหนึ่ง ลำดับความสำคัญของการ์ด match เมื่อเทียบกับแพตเทิร์นมีพฤติกรรมเช่นนี้:

```text
(4 | 5 | 6) if y => ...
```

ไม่ใช่เช่นนี้:

```text
4 | 5 | (6 if y) => ...
```

หลังจากรันโค้ด พฤติกรรมของลำดับความสำคัญก็ชัดเจน: หากการ์ด match ถูกใช้เฉพาะกับค่าสุดท้ายในรายการค่าที่ระบุด้วยตัวดำเนินการ `|` อาร์มจะจับคู่ได้ และโปรแกรมจะพิมพ์ `yes`

### การใช้การผูกค่าด้วย `@`

ตัวดำเนินการ _at_ `@` ช่วยให้เราสร้างตัวแปรที่เก็บค่าในขณะเดียวกับที่เรากำลังทดสอบค่านั้นกับแพตเทิร์น ในลิสติ้ง 19-29 เราต้องการทดสอบว่าฟิลด์ `id` ของ `Message::Hello` อยู่ในช่วง `3..=7` เรายังต้องการผูกค่ากับตัวแปร `id` เพื่อให้เราใช้มันในโค้ดที่เชื่อมโยงกับอาร์มได้ด้วย

<Listing number="19-29" caption="การใช้ `@` เพื่อผูกกับค่าในแพตเทิร์นพร้อมทั้งทดสอบค่านั้นด้วย">

```rust
{{#rustdoc_include ../listings/ch19-patterns-and-matching/listing-19-29/src/main.rs:here}}
```

</Listing>

ตัวอย่างนี้จะพิมพ์ `Found an id in range: 5` โดยการระบุ `id @` ก่อนช่วง `3..=7` เราเก็บค่าใดก็ตามที่จับคู่กับช่วงนั้นไว้ในตัวแปรชื่อ `id` พร้อมทั้งทดสอบว่าค่านั้นจับคู่กับแพตเทิร์นช่วงหรือไม่

ในอาร์มที่สอง ซึ่งเรามีเพียงช่วงที่ระบุในแพตเทิร์น โค้ดที่เชื่อมโยงกับอาร์มไม่มีตัวแปรที่บรรจุค่าจริงของฟิลด์ `id` ค่าของฟิลด์ `id` อาจเป็น 10, 11 หรือ 12 แต่โค้ดที่ใช้กับแพตเทิร์นนั้นไม่รู้ว่าค่าใดกันแน่ โค้ดของแพตเทิร์นไม่สามารถใช้ค่าจากฟิลด์ `id` ได้เพราะเราไม่ได้บันทึกค่า `id` ไว้ในตัวแปร

ในอาร์มสุดท้าย ซึ่งเราได้ระบุตัวแปรโดยไม่มีช่วง เรามีค่าที่พร้อมใช้ในโค้ดของอาร์มในตัวแปรชื่อ `id` จริง เหตุผลคือเราได้ใช้วากยสัมพันธ์รูปแบบย่อของฟิลด์ struct แต่เราไม่ได้ใช้การทดสอบใดๆ กับค่าในฟิลด์ `id` ในอาร์มนี้เหมือนที่เราทำกับสองอาร์มแรก: ค่าใดก็จับคู่กับแพตเทิร์นนี้ได้

การใช้ `@` ช่วยให้เราทดสอบค่าและบันทึกมันไว้ในตัวแปรภายในแพตเทิร์นเดียว

## สรุป

แพตเทิร์นของ Rust มีประโยชน์อย่างยิ่งในการแยกแยะระหว่างข้อมูลชนิดต่างๆ เมื่อใช้ในเอ็กซ์เพรสชัน `match` Rust รับประกันว่าแพตเทิร์นของคุณครอบคลุมทุกค่าที่เป็นไปได้ ไม่เช่นนั้นโปรแกรมของคุณจะไม่คอมไพล์ แพตเทิร์นในสเตตเมนต์ `let` และพารามิเตอร์ของฟังก์ชันทำให้โครงสร้างเหล่านั้นมีประโยชน์มากขึ้น โดยเปิดให้แยกโครงสร้างข้อมูลค่าออกเป็นส่วนย่อยๆ และกำหนดส่วนเหล่านั้นให้ตัวแปร เราสร้างแพตเทิร์นแบบง่ายหรือแบบซับซ้อนให้เหมาะกับความต้องการของเราได้

ต่อไป สำหรับบทรองสุดท้ายของหนังสือ เราจะดูแง่มุมขั้นสูงบางประการของฟีเจอร์ต่างๆ ของ Rust
