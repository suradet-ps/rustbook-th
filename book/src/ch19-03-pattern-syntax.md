ในหัวข้อนี้ เรารวบรวมไวยากรณ์และรูปแบบทั้งหมดที่ใช้ได้กับแพตเทิร์น (pattern) รวมถึงพูดคุยว่าเหตุใดและเมื่อใดที่คุณควรเลือกใช้งานแต่ละรูปแบบ

### การจับคู่ตัวแปรที่มีชื่อ

ตัวแปรที่มีชื่อจัดเป็นแพตเทิร์นที่จับคู่สำเร็จเสมอ (irrefutable pattern) ซึ่งสามารถจับคู่ได้กับทุกค่า และเราได้ใช้งานรูปแบบนี้กันมาหลายครั้งตลอดทั้งเล่ม อย่างไรก็ตาม ความซับซ้อนจะเกิดขึ้นเมื่อคุณนำตัวแปรที่มีชื่อไปใช้ในนิพจน์ `match`, `if let` หรือ `while let` เนื่องจากนิพจน์เหล่านี้จะสร้างสโคปใหม่ขึ้นมาเสมอ ตัวแปรที่ประกาศขึ้นเป็นส่วนหนึ่งของแพตเทิร์นภายในนิพจน์เหล่านี้จึงจะไปบดบัง (shadow) ตัวแปรที่มีชื่อเดียวกันซึ่งอยู่นอกโครงสร้างคำสั่งนั้น เช่นเดียวกับพฤติกรรมปกติของตัวแปรทั่วไป ในลิสติ้ง 19-11 เราประกาศตัวแปรชื่อ `x` ที่เก็บค่า `Some(5)` และตัวแปร `y` ที่เก็บค่า `10` จากนั้นสร้างนิพจน์ `match` สำหรับค่า `x` ลองพิจารณาแพตเทิร์นในแต่ละอาร์มของ `match` และคำสั่ง `println!` ตอนท้าย แล้วลองคาดเดาดูว่าโค้ดจะพิมพ์อะไรออกมาก่อนที่คุณจะรันโค้ดหรืออ่านคำอธิบายถัดไป

มาดูการทำงานทีละขั้นเมื่อนิพจน์ `match` ทำงานกัน แพตเทิร์นในอาร์มแรกของ `match` จะจับคู่ไม่ตรงกับค่า `x` ที่กำหนดไว้ โค้ดจึงทำงานต่อไปยังอาร์มถัดไป

แพตเทิร์นในอาร์มที่สองของ `match` ประกาศตัวแปรใหม่ชื่อ `y` ซึ่งจะจับคู่กับค่าใดก็ตามที่อยู่ภายในค่า `Some` และเนื่องจากเราอยู่ในสโคปใหม่ภายในนิพจน์ `match` นี่จึงเป็นตัวแปร `y` ตัวใหม่ ไม่ใช่ตัวแปร `y` ที่เราประกาศไว้ตอนต้นด้วยค่า `10` การผูกค่า (binding) `y` ใหม่นี้จะจับคู่กับค่าใดก็ได้ที่อยู่ภายใน `Some` ซึ่งก็คือค่าที่มีอยู่ใน `x` ดังนั้น `y` ใหม่นี้จึงผูกเข้ากับค่าภายในของ `Some` ใน `x` ซึ่งมีค่าเป็น `5` นิพจน์ของอาร์มนั้นจึงทำงานและพิมพ์ `Matched, y = 5` ออกมา

หาก `x` มีค่าเป็น `None` แทนที่จะเป็น `Some(5)` แพตเทิร์นในสองอาร์มแรกจะไม่ตรงเงื่อนไข ค่านั้นจึงจะถูกจับคู่ด้วยเครื่องหมายขีดล่าง (underscore) และเนื่องจากเราไม่ได้ประกาศตัวแปร `x` ขึ้นมาใหม่ในแพตเทิร์นของอาร์มขีดล่าง ตัวแปร `x` ในบล็อกนั้นจึงยังคงเป็น `x` ตัวนอกที่ไม่ถูกบดบัง ในกรณีสมมตินี้ `match` จะพิมพ์ `Default case, x = None`

เมื่อนิพจน์ `match` ทำงานเสร็จสิ้น สโคปของมันก็จะสิ้นสุดลง และสโคปของ `y` ตัวในก็สิ้นสุดลงด้วยเช่นกัน คำสั่ง `println!` ตัวสุดท้ายจึงให้ผลลัพธ์เป็น `at the end: x = Some(5), y = 10`

หากเราต้องการสร้างนิพจน์ `match` ที่เปรียบเทียบค่าของ `x` กับ `y` ตัวนอก แทนที่จะเป็นการประกาศตัวแปรใหม่ที่บดบังตัวแปร `y` เดิม เราจะต้องใช้เงื่อนไขการ์ด match (match guard) เข้ามาช่วย ซึ่งเราจะอธิบายเรื่องการ์ด match ต่อไปในหัวข้อ[“การเพิ่มเงื่อนไขด้วยการ์ด match”](#การเพิมเงือนไขดวยการด-match)<!-- ignore -->

สำหรับวาเรียนต์ (variant) ของ enum ที่ไม่มีข้อมูลแนบมาด้วย เช่น `Message::Quit` เราจะไม่สามารถแยกโครงสร้างข้อมูลได้อีก ทำได้เพียงจับคู่กับค่าลิเทอรัล `Message::Quit` ตรง ๆ และไม่มีตัวแปรใดอยู่ในแพตเทิร์นนั้น

สำหรับวาเรียนต์ของ enum ที่มีลักษณะคล้าย struct เช่น `Message::Move` เราสามารถใช้แพตเทิร์นในลักษณะเดียวกับตอนที่จับคู่ struct ได้ โดยใส่วงเล็บปีกกา `{}` ต่อท้ายชื่อวาเรียนต์แล้วระบุชื่อฟิลด์พร้อมตัวแปร เพื่อแยกค่าออกมาใช้ในโค้ดของอาร์มนั้น ซึ่งในที่นี้เราใช้ไวยากรณ์แบบย่อเหมือนกับในลิสติ้ง 19-13

สำหรับวาเรียนต์ของ enum ที่มีลักษณะคล้ายทูเพิล เช่น `Message::Write` ที่เก็บทูเพิลที่มีสมาชิกหนึ่งตัว และ `Message::ChangeColor` ที่เก็บทูเพิลที่มีสมาชิกสามตัว แพตเทิร์นจะมีลักษณะเดียวกับการจับคู่ทูเพิล โดยจำนวนตัวแปรในแพตเทิร์นจะต้องตรงกับจำนวนสมาชิกภายในวาเรียนต์นั้น ๆ พอดี

### การเพิ่มเงื่อนไขด้วยการ์ด match

_การ์ด match_ (match guard) คือเงื่อนไข `if` เพิ่มเติมที่ระบุไว้หลังแพตเทิร์นในอาร์มของ `match` ซึ่งเงื่อนไขนี้จะต้องเป็นจริงด้วย อาร์มนั้นจึงจะถูกเลือกทำงาน การ์ด match มีประโยชน์อย่างมากในการแสดงตรรกะที่ซับซ้อนเกินกว่าที่ตัวแพตเทิร์นเพียงอย่างเดียวจะทำได้ อย่างไรก็ตาม โปรดทราบว่าการ์ด match ใช้งานได้เฉพาะในนิพจน์ `match` เท่านั้น ไม่สามารถใช้ในนิพจน์ `if let` หรือ `while let` ได้

เงื่อนไขดังกล่าวยังสามารถเข้าถึงตัวแปรที่ถูกสร้างขึ้นในแพตเทิร์นได้ด้วย ลิสติ้ง 19-26 แสดงนิพจน์ `match` ที่อาร์มแรกมีแพตเทิร์น `Some(x)` พร้อมการ์ด match `if x % 2 == 0` (ซึ่งจะเป็น `true` เมื่อตัวเลขเป็นจำนวนคู่)

<Listing number="19-26" caption="การเพิ่มการ์ด match ให้กับแพตเทิร์น">

```rust
{{#rustdoc_include ../listings/ch19-patterns-and-matching/listing-19-26/src/main.rs:here}}
```

</Listing>

ตัวอย่างนี้จะพิมพ์ `The number 4 is even` ออกมา เมื่อนำ `num` ไปเปรียบเทียบกับแพตเทิร์นในอาร์มแรก จะพบว่าจับคู่ได้สำเร็จเพราะ `Some(4)` ตรงกับ `Some(x)` จากนั้นการ์ด match จะตรวจสอบต่อว่าเศษจากการหาร `x` ด้วย 2 เท่ากับ 0 หรือไม่ และเนื่องจากเท่ากับ 0 อาร์มแรกจึงถูกเลือกทำงาน

หาก `num` มีค่าเป็น `Some(5)` แทน การ์ด match ในอาร์มแรกก็จะได้ผลลัพธ์เป็น `false` เพราะเศษจากการหาร 5 ด้วย 2 คือ 1 ซึ่งไม่เท่ากับ 0 Rust ก็จะข้ามไปยังอาร์มที่สอง ซึ่งจะจับคู่สำเร็จเนื่องจากอาร์มที่สองไม่มีการ์ด match จึงยอมรับวาเรียนต์ `Some` ใดก็ได้

เนื่องจากเราไม่สามารถเขียนเงื่อนไข `if x % 2 == 0` ลงในแพตเทิร์นตรง ๆ ได้ การ์ด match จึงเข้ามาช่วยให้เราแสดงตรรกะนี้ได้อย่างสะดวก ทว่าข้อแลกเปลี่ยนของความยืดหยุ่นที่เพิ่มขึ้นนี้คือ คอมไพเลอร์จะไม่สามารถตรวจสอบความครอบคลุมทุกกรณี (exhaustiveness) ของแพตเทิร์นได้อย่างสมบูรณ์เมื่อมีการใช้การ์ด match ร่วมด้วย

ในการพูดคุยถึงลิสติ้ง 19-11 เราเคยกล่าวไว้ว่าเราสามารถใช้การ์ด match เพื่อแก้ปัญหาการบดบังตัวแปร (shadowing) ในแพตเทิร์นได้ ย้อนกลับไปในตัวอย่างนั้น เราสร้างตัวแปรใหม่ขึ้นมาภายในแพตเทิร์นของนิพจน์ `match` แทนที่จะเป็นตัวแปรภายนอก ส่งผลให้เราไม่สามารถตรวจสอบเปรียบเทียบกับค่าของตัวแปรภายนอกได้ ลิสติ้ง 19-27 แสดงวิธีใช้การ์ด match เพื่อแก้ไขปัญหานี้

<Listing number="19-27" file-name="src/main.rs" caption="การใช้การ์ด match เพื่อทดสอบความเท่ากันกับตัวแปรตัวนอก">

โค้ดนี้จะพิมพ์ `Default case, x = Some(5)` แพตเทิร์นในอาร์มที่สองไม่ได้ประกาศตัวแปร `y` ขึ้นมาใหม่ที่จะไปบดบัง `y` ตัวนอก ซึ่งหมายความว่าเราสามารถนำ `y` ตัวนอกมาใช้ในการ์ด match ได้ โดยแทนที่เราจะกำหนดแพตเทิร์นเป็น `Some(y)` (ซึ่งจะบดบัง `y` ตัวนอก) เราเปลี่ยนมากำหนดเป็น `Some(n)` แทน ซึ่งจะสร้างตัวแปรใหม่ `n` ที่ไม่ได้ไปบดบังตัวแปรใด ๆ เลย เพราะไม่มีตัวแปรชื่อ `n` อยู่ภายนอก `match`

การ์ด match `if n == y` ไม่ใช่แพตเทิร์น จึงไม่มีการประกาศตัวแปรใหม่ ดังนั้น `y` ในที่นี้ _คือ_ `y` ตัวนอกจริง ๆ ไม่ใช่ `y` ตัวใหม่ที่ไปบดบังมัน เราจึงสามารถตรวจสอบหาค่าที่ตรงกับ `y` ตัวนอกได้โดยการเปรียบเทียบ `n` กับ `y`

นอกจากนี้ คุณยังสามารถใช้ตัวดำเนินการ _หรือ_ `|` ร่วมกับการ์ด match เพื่อกำหนดหลายแพตเทิร์นได้ โดยเงื่อนไขของการ์ด match จะมีผลกับทุก ๆ แพตเทิร์นที่ระบุ ลิสติ้ง 19-28 แสดงลำดับความสำคัญเมื่อรวมแพตเทิร์นที่ใช้ `|` เข้ากับการ์ด match สิ่งสำคัญของตัวอย่างนี้คือ การ์ด match `if y` จะมีผลครอบคลุมทั้ง `4`, `5` _และ_ `6` แม้ว่าเมื่อมองดูอาจเหมือนกับว่า `if y` มีผลเฉพาะกับ `6` เท่านั้นก็ตาม

<Listing number="19-28" caption="การรวมหลายแพตเทิร์นกับการ์ด match">

```rust
{{#rustdoc_include ../listings/ch19-patterns-and-matching/listing-19-28/src/main.rs:here}}
```

</Listing>

เงื่อนไขของ `match` ระบุว่าอาร์มจะจับคู่สำเร็จก็ต่อเมื่อค่าของ `x` เท่ากับ `4`, `5` หรือ `6` _และ_ `y` มีค่าเป็น `true` เมื่อโค้ดนี้ทำงาน แพตเทิร์นของอาร์มแรกจับคู่สำเร็จเพราะ `x` มีค่าเป็น `4` แต่เนื่องจากการ์ด match `if y` เป็น `false` อาร์มแรกจึงไม่ถูกเลือก โค้ดจึงดำเนินต่อไปยังอาร์มที่สองซึ่งจับคู่สำเร็จ และโปรแกรมนี้จะพิมพ์ `no` ออกมา เหตุผลก็คือเงื่อนไข `if` จะมีผลกับแพตเทิร์นทั้งหมดคือ `4 | 5 | 6` ไม่ใช่แค่ค่าสุดท้ายคือ `6` กล่าวคือ ลำดับความสำคัญของการ์ด match เมื่อเทียบกับแพตเทิร์นจะมีพฤติกรรมดังนี้:

```text
(4 | 5 | 6) if y => ...
```

ไม่ใช่แบบนี้:

```text
4 | 5 | (6 if y) => ...
```

เมื่อรันโค้ดแล้ว พฤติกรรมของลำดับความสำคัญนี้จะเห็นได้อย่างชัดเจน: เพราะหากการ์ด match มีผลเฉพาะกับค่าสุดท้ายในรายการที่เชื่อมด้วยตัวดำเนินการ `|` แล้วล่ะก็ อาร์มแรกก็ย่อมจะจับคู่สำเร็จ และโปรแกรมก็จะพิมพ์ `yes` ออกมาแทน

### การใช้การผูกค่าด้วย `@`

ตัวดำเนินการ _at_ `@` ช่วยให้เราสร้างตัวแปรเพื่อเก็บค่าไปพร้อม ๆ กับการทดสอบค่านั้นกับแพตเทิร์น ในลิสติ้ง 19-29 เราต้องการทดสอบว่าฟิลด์ `id` ของ `Message::Hello` อยู่ในช่วง `3..=7` หรือไม่ พร้อมทั้งต้องการผูกค่านั้นเข้ากับตัวแปร `id` เพื่อให้เราสามารถนำค่านั้นไปใช้งานในโค้ดของอาร์มดังกล่าวได้ด้วย

<Listing number="19-29" caption="การใช้ `@` เพื่อผูกกับค่าในแพตเทิร์นพร้อมทั้งทดสอบค่านั้นด้วย">

```rust
{{#rustdoc_include ../listings/ch19-patterns-and-matching/listing-19-29/src/main.rs:here}}
```

</Listing>

ตัวอย่างนี้จะพิมพ์ `Found an id in range: 5` ออกมา โดยการระบุ `id @` ไว้ข้างหน้าช่วง `3..=7` เราจะดักจับค่าใดก็ตามที่จับคู่ตรงกับช่วงนั้นมาเก็บไว้ในตัวแปรชื่อ `id` ไปพร้อมกับทดสอบว่าค่านั้นตรงตามเงื่อนไขของช่วงหรือไม่

ในอาร์มที่สอง ซึ่งเราระบุเพียงช่วงในแพตเทิร์น โค้ดในอาร์มนั้นจะไม่มีตัวแปรที่เก็บค่าจริงของฟิลด์ `id` เลย ค่าของฟิลด์ `id` อาจเป็น 10, 11 หรือ 12 แต่โค้ดของอาร์มนั้นไม่รู้แน่ชัดว่าเป็นค่าใดกันแน่ จึงไม่สามารถนำค่าจากฟิลด์ `id` มาใช้งานได้เพราะเราไม่ได้บันทึกค่า `id` ไว้ในตัวแปรใด

ในอาร์มสุดท้าย ซึ่งเราระบุตัวแปรไว้โดยไม่มีช่วง เราจะมีค่าพร้อมใช้งานในโค้ดของอาร์มผ่านตัวแปรชื่อ `id` เนื่องจากเราใช้ไวยากรณ์แบบย่อของฟิลด์ struct ทว่าเราไม่ได้ใส่การทดสอบเงื่อนไขใด ๆ กับค่าในฟิลด์ `id` ในอาร์มนี้เหมือนกับสองอาร์มแรก: ค่าใดก็ตามจึงสามารถจับคู่กับแพตเทิร์นนี้ได้ทั้งหมด

การใช้ `@` ช่วยให้เราทดสอบค่าและบันทึกค่านั้นไว้ในตัวแปรได้จบครบภายในแพตเทิร์นเดียว

## สรุป

แพตเทิร์นของ Rust มีประโยชน์อย่างยิ่งในการจำแนกความแตกต่างระหว่างข้อมูลชนิดต่าง ๆ เมื่อนำไปใช้ในนิพจน์ `match` แล้ว Rust จะช่วยรับประกันว่าแพตเทิร์นของคุณครอบคลุมทุกค่าที่เป็นไปได้เสมอ มิฉะนั้นโปรแกรมก็จะไม่ผ่านการคอมไพล์ นอกจากนี้ แพตเทิร์นในสเตตเมนต์ `let` และพารามิเตอร์ของฟังก์ชันยังช่วยเพิ่มประโยชน์ให้แก่โครงสร้างคำสั่งเหล่านั้น โดยเปิดทางให้เราแยกโครงสร้างข้อมูลออกเป็นชิ้นส่วนย่อย ๆ และกำหนดค่านั้นให้แก่ตัวแปรได้อย่างสะดวก เราจึงสามารถสร้างแพตเทิร์นทั้งแบบเรียบง่ายหรือแบบซับซ้อนให้ตรงกับความต้องการของงานได้อย่างยืดหยุ่น

ในบทถัดไป ซึ่งเป็นบทรองสุดท้ายของหนังสือเล่มนี้ เราจะไปสำรวจแง่มุมและคุณลักษณะขั้นสูงต่าง ๆ ของฟีเจอร์ในภาษา Rust กัน
