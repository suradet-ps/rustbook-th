## รับอาร์กิวเมนต์จากบรรทัดคำสั่ง

มาเริ่มต้นสร้างโปรเจกต์ใหม่กันเช่นเคยด้วยคำสั่ง `cargo new` โดยเราจะตั้งชื่อโปรเจกต์ว่า `minigrep` เพื่อแยกความแตกต่างจากเครื่องมือ `grep` ที่อาจมีติดตั้งอยู่ในระบบของคุณอยู่แล้ว:

```console
$ cargo new minigrep
     Created binary (application) `minigrep` project
$ cd minigrep
```

ภารกิจแรกของเราคือการทำให้ `minigrep` สามารถรับอาร์กิวเมนต์ (arguments) จากคอมมานด์ไลน์ได้ 2 ตัว ได้แก่: พาธของไฟล์ และข้อความสตริงที่ต้องการค้นหา กล่าวคือ เราต้องการสั่งรันโปรแกรมของเราด้วยคำสั่ง `cargo run` ตามด้วยเครื่องหมายยัติภังค์ 2 ตัว (`--`) เพื่อระบุว่าอาร์กิวเมนต์ที่ตามมาหลังจากนี้เป็นของโปรแกรมเรา ไม่ใช่ของ `cargo` จากนั้นจึงตามด้วยสตริงที่ต้องการค้นหา และพาธของไฟล์เป้าหมาย ดังนี้:

```console
$ cargo run -- searchstring example-filename.txt
```

ในตอนนี้ โปรแกรมเริ่มต้นที่สร้างขึ้นโดย `cargo new` ยังไม่สามารถประมวลผลอาร์กิวเมนต์ที่เราส่งเข้าไปได้ แม้ว่าจะมีไลบรารีสำเร็จรูปบน [crates.io](https://crates.io/) ที่ช่วยอำนวยความสะดวกในการเขียนโปรแกรมรับอาร์กิวเมนต์คอมมานด์ไลน์อยู่มากมาย แต่เนื่องจากคุณกำลังศึกษาเรียนรู้แนวคิดนี้ เรามาลองอิมพลีเมนต์ความสามารถนี้ด้วยตัวเราเองกันก่อน

### การอ่านค่าอาร์กิวเมนต์

เพื่อให้ `minigrep` สามารถอ่านค่าอาร์กิวเมนต์จากคอมมานด์ไลน์ที่เราส่งเข้าไปได้ เราจะต้องใช้ฟังก์ชัน `std::env::args` ที่มีอยู่ในไลบรารีมาตรฐานของ Rust ฟังก์ชันนี้จะส่งคืนค่าเป็นอิเทอเรเตอร์ (iterator) ของอาร์กิวเมนต์คอมมานด์ไลน์ที่ส่งให้กับ `minigrep` ซึ่งเราจะได้เรียนรู้เรื่องอิเทอเรเตอร์อย่างละเอียดใน[บทที่ 13][ch13]<!-- ignore --> สำหรับตอนนี้ คุณจำเป็นต้องรู้คุณลักษณะของอิเทอเรเตอร์เพียง 2 ประการก่อน: อิเทอเรเตอร์จะทยอยส่งมอบลำดับของค่าออกมาทีละตัว และเราสามารถเรียกใช้เมธอด `collect` บนอิเทอเรเตอร์เพื่อแปลงมันให้กลายเป็นคอลเลกชัน (collection) เช่น เวกเตอร์ (vector) ที่บรรจุสมาชิกทั้งหมดที่อิเทอเรเตอร์ส่งมอบออกมา

อันดับแรก เราจะนำมอดูล `std::env` เข้ามาสู่สโคปด้วยคำสั่ง `use` เพื่อให้สามารถเรียกใช้ฟังก์ชัน `args` ได้ โปรดสังเกตว่าฟังก์ชัน `std::env::args` มีการซ้อนอยู่ภายในมอดูล 2 ระดับ ตามที่เราเคยอธิบายไว้ใน[บทที่ 7][ch7-idiomatic-use]<!-- ignore --> ว่าในกรณีที่ฟังก์ชันเป้าหมายซ้อนอยู่ในมอดูลมากกว่าหนึ่งระดับ เรามักเลือกนำมอดูลแม่เข้ามาสู่สโคปแทนที่จะนำตัวฟังก์ชันเข้ามาโดยตรง การทำเช่นนี้ทำให้เราสามารถเรียกใช้ฟังก์ชันอื่นๆ จาก `std::env` ได้อย่างสะดวก และยังลดความคลุมเครือลงเมื่อเทียบกับการประกาศ `use std::env::args` แล้วเรียกใช้ด้วยชื่อ `args` สั้นๆ เพราะ `args` อาจถูกเข้าใจผิดว่าเป็นฟังก์ชันที่นิยามขึ้นภายในมอดูลปัจจุบันได้ง่าย

> ### ฟังก์ชัน `args` และ Unicode ที่ไม่ถูกต้อง
>
> โปรดทราบว่า `std::env::args` จะเกิดการแพนิก (panic) หากมีอาร์กิวเมนต์ใดก็ตามที่มีรหัส Unicode ไม่ถูกต้อง หากโปรแกรมของคุณจำเป็นต้องรองรับอาร์กิวเมนต์ที่อาจมีรหัส Unicode ไม่ถูกต้อง ให้เปลี่ยนไปใช้ฟังก์ชัน `std::env::args_os` แทน โดยฟังก์ชันดังกล่าวจะส่งคืนอิเทอเรเตอร์ที่ให้ผลลัพธ์เป็นค่าชนิด `OsString` แทนที่จะเป็น `String` แต่ในที่นี้เราเลือกใช้ `std::env::args` เพื่อความเรียบง่าย เนื่องจากค่า `OsString` จะมีความแตกต่างกันไปในแต่ละระบบปฏิบัติการและจัดการได้ซับซ้อนกว่าค่า `String`

ในบรรทัดแรกของฟังก์ชัน `main` เราได้เรียกใช้ `env::args()` และตามด้วยเมธอด `collect()` ทันทีเพื่อแปลงอิเทอเรเตอร์ให้กลายเป็นเวกเตอร์ที่บรรจุค่าทั้งหมดที่ได้จากอิเทอเรเตอร์ เนื่องจากเมธอด `collect` สามารถนำไปสร้างคอลเลกชันได้หลากหลายชนิด เราจึงต้องระบุชนิดข้อมูลกำกับไว้ให้กับตัวแปร `args` อย่างชัดเจน เพื่อบอกว่าเราต้องการเวกเตอร์ของสตริง แม้ว่าตามปกติคุณแทบไม่ต้องระบุชนิดข้อมูลด้วยตนเองใน Rust แต่ `collect` เป็นหนึ่งในฟังก์ชันที่คุณจำเป็นต้องระบุชนิดข้อมูลอยู่เสมอ เพราะคอมไพเลอร์ Rust ไม่สามารถคาดเดาได้ว่าคุณต้องการคอลเลกชันชนิดใด
