## เพิ่มฟังก์ชันการทำงานด้วยการพัฒนาแบบขับเคลื่อนด้วยเทสต์

ในเมื่อเรามีโลจิกการค้นหาอยู่ใน _src/lib.rs_ แยกจากฟังก์ชัน `main` แล้ว การเขียนเทสต์ (test) สำหรับฟังก์ชันการทำงานแกนหลักของโค้ดเราจึงง่ายขึ้นมาก เราเรียกฟังก์ชันโดยตรงด้วยอาร์กิวเมนต์ (argument) ต่างๆ และตรวจสอบค่าที่คืนกลับได้ โดยไม่ต้องเรียกไบนารีของเราจากบรรทัดคำสั่ง (command line)

ในหัวข้อนี้ เราจะเพิ่มโลจิกการค้นหาให้โปรแกรม `minigrep` โดยใช้กระบวนการพัฒนาแบบขับเคลื่อนด้วยเทสต์ (test-driven development: TDD) ซึ่งมีขั้นตอนดังนี้:

1. เขียนเทสต์ที่ล้มเหลวแล้วรันมันเพื่อให้แน่ใจว่ามันล้มเหลวด้วยเหตุผลที่คุณคาดไว้
2. เขียนหรือแก้ไขโค้ดเพียงพอที่จะทำให้เทสต์ใหม่ผ่าน
3. รีแฟกเตอร์ (refactor) โค้ดที่คุณเพิ่งเพิ่มหรือแก้ไข และให้แน่ใจว่าเทสต์ยังคงผ่าน
4. วนซ้ำจากขั้นตอนที่ 1!

แม้ว่ามันจะเป็นเพียงหนึ่งในหลายวิธีในการเขียนซอฟต์แวร์ แต่ TDD ช่วยขับเคลื่อนการออกแบบโค้ดได้ การเขียนเทสต์ก่อนที่คุณจะเขียนโค้ดที่ทำให้เทสต์ผ่าน ช่วยรักษาความครอบคลุมของเทสต์ (test coverage) ให้สูงตลอดกระบวนการ

เราจะพัฒนาแบบขับเคลื่อนด้วยเทสต์การอิมพลีเมนต์ฟังก์ชันการทำงานที่จะค้นหาสตริง query ในเนื้อหาของไฟล์จริงๆ และสร้างรายการบรรทัดที่ตรงกับ query เราจะเพิ่มฟังก์ชันการทำงานนี้ในฟังก์ชันชื่อ `search`

ตอนนี้มาพูดคุยกันว่าทำไมเราต้องนิยามไลฟ์ไทม์ (lifetime) `'a` อย่างชัดแจ้งในซิกเนเจอร์ของ `search` และใช้ไลฟ์ไทม์นั้นกับอาร์กิวเมนต์ `contents` และค่าที่คืนกลับ ย้อนนึกใน[บทที่ 10][ch10-lifetimes]<!-- ignore --> ว่าพารามิเตอร์ไลฟ์ไทม์ระบุว่าไลฟ์ไทม์ของอาร์กิวเมนต์ใดเชื่อมโยงกับไลฟ์ไทม์ของค่าที่คืนกลับ ในกรณีนี้ เราบ่งชี้ว่าเวกเตอร์ที่คืนกลับควรบรรจุสตริงสไลซ์ที่อ้างถึงสไลซ์ของอาร์กิวเมนต์ `contents` (ไม่ใช่ของอาร์กิวเมนต์ `query`)

กล่าวอีกนัยหนึ่ง เราบอก Rust ว่าข้อมูลที่ฟังก์ชัน `search` คืนกลับจะมีชีวิตอยู่ได้ตราบเท่าข้อมูลที่ถูกส่งเข้าฟังก์ชัน `search` ทางอาร์กิวเมนต์ `contents` สิ่งนี้สำคัญมาก! ข้อมูลที่ถูกสไลซ์_อ้างถึง_ต้องใช้ได้เพื่อให้เรเฟอเรนซ์นั้นใช้ได้ หากคอมไพล์เลอร์สันนิษฐานว่าเรากำลังสร้างสตริงสไลซ์ของ `query` ไม่ใช่ของ `contents` มันจะตรวจสอบความปลอดภัยผิดพลาด

หากเราลืมการระบุไลฟ์ไทม์และลองคอมไพล์ฟังก์ชันนี้ เราจะได้ข้อผิดพลาดนี้:

```console
{{#include ../listings/ch12-an-io-project/output-only-02-missing-lifetimes/output.txt}}
```

Rust ไม่สามารถรู้ได้ว่าเราต้องการพารามิเตอร์ตัวใดจากสองตัวสำหรับเอาต์พุต เราจึงต้องบอกมันอย่างชัดแจ้ง โปรดสังเกตว่าข้อความช่วยเหลือแนะนำให้ระบุพารามิเตอร์ไลฟ์ไทม์เดียวกันสำหรับพารามิเตอร์ทั้งหมดและชนิดเอาต์พุต ซึ่งไม่ถูกต้อง! เนื่องจาก `contents` เป็นพารามิเตอร์ที่บรรจุข้อความทั้งหมดของเรา และเราต้องการคืนส่วนต่างๆ ของข้อความนั้นที่ตรงกัน เราจึงรู้ว่า `contents` เป็นพารามิเตอร์เดียวที่ควรเชื่อมโยงกับค่าที่คืนกลับโดยใช้ไวยากรณ์ไลฟ์ไทม์

ภาษาการเขียนโปรแกรมอื่นๆ ไม่กำหนดให้คุณเชื่อมโยงอาร์กิวเมนต์กับค่าที่คืนกลับในซิกเนเจอร์ แต่แนวปฏิบัตินี้จะง่ายขึ้นเมื่อเวลาผ่านไป คุณอาจต้องการเปรียบเทียบตัวอย่างนี้กับตัวอย่างในหัวข้อ[“การตรวจสอบความถูกต้องของเรเฟอเรนซ์ด้วยไลฟ์ไทม์”][validating-references-with-lifetimes]<!-- ignore --> ในบทที่ 10

### การเขียนโค้ดให้เทสต์ผ่าน

ตอนนี้เทสต์ของเราล้มเหลวเพราะเราคืนเวกเตอร์ว่างเสมอ เพื่อแก้ไขและอิมพลีเมนต์ `search` โปรแกรมของเราต้องทำตามขั้นตอนเหล่านี้:

1. วนซ้ำผ่านแต่ละบรรทัดของเนื้อหา
2. ตรวจสอบว่าบรรทัดนั้นบรรจุสตริง query ของเราหรือไม่
3. หากบรรจุ ให้เพิ่มมันเข้าไปในรายการค่าที่เรากำลังคืนกลับ
4. หากไม่บรรจุ ก็ไม่ต้องทำอะไร
5. คืนรายการผลลัพธ์ที่ตรงกัน

มาดำเนินการทีละขั้น เริ่มจากการวนซ้ำผ่านบรรทัดต่างๆ
