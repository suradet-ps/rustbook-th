## ควบคุมวิธีการรันเทสต์

เช่นเดียวกับที่ `cargo run` คอมไพล์โค้ดของคุณแล้วรันไบนารีที่ได้ `cargo test` จะคอมไพล์โค้ดของคุณในโหมดเทสต์และรันไบนารีเทสต์ที่ได้ พฤติกรรมเริ่มต้นของไบนารีที่ `cargo test` สร้างขึ้นคือรันเทสต์ (test) ทั้งหมดแบบขนาน และดักจับเอาต์พุตที่เกิดขึ้นระหว่างการรันเทสต์ ป้องกันไม่ให้เอาต์พุตถูกแสดงผล และทำให้อ่านเอาต์พุตที่เกี่ยวข้องกับผลลัพธ์เทสต์ได้ง่ายขึ้น อย่างไรก็ตาม คุณสามารถระบุตัวเลือกบรรทัดคำสั่งเพื่อเปลี่ยนพฤติกรรมเริ่มต้นนี้ได้

ตัวเลือกบรรทัดคำสั่งบางอย่างส่งไปที่ `cargo test` และบางอย่างส่งไปที่ไบนารีเทสต์ที่ได้ ในการแยกอาร์กิวเมนต์สองประเภทนี้ออกจากกัน คุณจะระบุอาร์กิวเมนต์ที่ส่งไปที่ `cargo test` ก่อน ตามด้วยตัวคั่น `--` แล้วจึงตามด้วยตัวเลือกที่ส่งไปที่ไบนารีเทสต์ การรัน `cargo test --help` จะแสดงตัวเลือกที่คุณใช้กับ `cargo test` ได้ และการรัน `cargo test -- --help` จะแสดงตัวเลือกที่คุณใช้ได้หลังตัวคั่น ตัวเลือกเหล่านี้ยังมีเอกสารประกอบอยู่ใน[หัวข้อ “Tests” ของหนังสือ _The `rustc` Book_][tests]

[tests]: https://doc.rust-lang.org/rustc/tests/index.html

### การรันเทสต์แบบขนานหรือแบบทีละตัว

เมื่อคุณรันเทสต์หลายตัว โดยค่าเริ่มต้นพวกมันจะรันแบบขนานโดยใช้เธรด (thread) หมายความว่ามันรันเสร็จเร็วขึ้นและคุณได้รับผลตอบกลับเร็วขึ้น เนื่องจากเทสต์กำลังทำงานในเวลาเดียวกัน คุณต้องทำให้แน่ใจว่าเทสต์ของคุณไม่พึ่งพากันและกันหรือพึ่งพาสถานะที่ใช้ร่วมกัน (shared state) ใดๆ รวมถึงสภาพแวดล้อมที่ใช้ร่วมกัน เช่น ไดเรกทอรีทำงานปัจจุบันหรือตัวแปรสภาพแวดล้อม

ตัวอย่างเช่น สมมติว่าเทสต์แต่ละตัวของคุณรันโค้ดที่สร้างไฟล์บนดิสก์ชื่อ _test-output.txt_ และเขียนข้อมูลบางอย่างลงในไฟล์นั้น จากนั้นเทสต์แต่ละตัวจะอ่านข้อมูลในไฟล์นั้นและยืนยันว่าไฟล์บรรจุค่าที่เฉพาะเจาะจง ซึ่งแตกต่างกันในแต่ละเทสต์ เนื่องจากเทสต์รันในเวลาเดียวกัน เทสต์ตัวหนึ่งอาจเขียนทับไฟล์ในช่วงเวลาระหว่างที่เทสต์อีกตัวกำลังเขียนและอ่านไฟล์นั้น เทสต์ตัวที่สองก็จะล้มเหลว ไม่ใช่เพราะโค้ดไม่ถูกต้อง แต่เพราะเทสต์รบกวนกันเองขณะรันแบบขนาน วิธีแก้อย่างหนึ่งคือทำให้แน่ใจว่าเทสต์แต่ละตัวเขียนไปยังไฟล์ที่ต่างกัน วิธีแก้อีกอย่างคือรันเทสต์ทีละตัว

หากคุณไม่ต้องการรันเทสต์แบบขนาน หรือต้องการควบคุมจำนวนเธรดที่ใช้อย่างละเอียดยิ่งขึ้น คุณสามารถส่งแฟล็ก `--test-threads` และจำนวนเธรดที่คุณต้องการใช้ไปยังไบนารีเทสต์ได้ มาดูตัวอย่างต่อไปนี้:

```console
$ cargo test -- --test-threads=1
```

เราตั้งจำนวนเธรดทดสอบเป็น `1` เพื่อบอกโปรแกรมว่าไม่ให้ใช้การทำงานขนาน (parallelism) ใดๆ การรันเทสต์โดยใช้เธรดเดียวจะใช้เวลานานกว่าการรันแบบขนาน แต่เทสต์จะไม่รบกวนกันและกันหากพวกมันใช้สถานะร่วมกัน

### การแสดงเอาต์พุตของฟังก์ชัน

โดยค่าเริ่มต้น หากเทสต์ผ่าน ไลบรารีทดสอบของ Rust จะดักจับทุกอย่างที่ถูกพิมพ์ไปยังเอาต์พุตมาตรฐาน ตัวอย่างเช่น หากเราเรียก `println!` ในเทสต์และเทสต์ผ่าน เราจะไม่เห็นเอาต์พุตของ `println!` ในเทอร์มินัล (terminal) เราจะเห็นเพียงบรรทัดที่บ่งชี้ว่าเทสต์ผ่าน หากเทสต์ล้มเหลว เราจะเห็นทุกอย่างที่ถูกพิมพ์ไปยังเอาต์พุตมาตรฐานพร้อมกับส่วนที่เหลือของข้อความความล้มเหลว

### การข้ามเทสต์เว้นแต่จะถูกร้องขออย่างเจาะจง
