## ควบคุมวิธีการรันเทสต์

เช่นเดียวกับที่คำสั่ง `cargo run` จะคอมไพล์โค้ดของคุณแล้วสั่งรันไฟล์ไบนารีผลลัพธ์ คำสั่ง `cargo test` ก็จะคอมไพล์โค้ดของคุณในโหมดทดสอบ (test mode) แล้วสั่งรันไฟล์ไบนารีสำหรับการทดสอบผลลัพธ์เช่นกัน โดยพฤติกรรมเริ่มต้นของไบนารีที่ `cargo test` สร้างขึ้นคือจะรันเทสต์ทั้งหมดแบบคู่ขนาน (parallel) และจะดักจับ (capture) เอาต์พุตทั้งหมดที่เกิดขึ้นในระหว่างการรันเทสต์เอาไว้ ไม่ให้แสดงออกมาในเทอร์มินัล เพื่อให้อ่านผลลัพธ์สรุปของเทสต์ได้ง่ายและเป็นระเบียบ อย่างไรก็ดี คุณสามารถระบุตัวเลือกผ่านคอมมานด์ไลน์เพื่อปรับเปลี่ยนพฤติกรรมเริ่มต้นนี้ได้ตามต้องการ

ตัวเลือกคอมมานด์ไลน์บางตัวจะถูกส่งไปยังคำสั่ง `cargo test` โดยตรง ในขณะที่บางตัวจะถูกส่งต่อไปยังไบนารีทดสอบ ในการแยกอาร์กิวเมนต์ทั้งสองประเภทนี้ออกจากกัน คุณจะต้องระบุอาร์กิวเมนต์ที่ส่งให้ `cargo test` ก่อน ตามด้วยตัวคั่น `--` แล้วจึงตามด้วยตัวเลือกที่จะส่งต่อไปยังไบนารีทดสอบ การสั่งรัน `cargo test --help` จะแสดงตัวเลือกที่คุณสามารถใช้กับ `cargo test` ได้ และการรัน `cargo test -- --help` จะแสดงตัวเลือกที่คุณสามารถระบุต่อท้ายตัวคั่นได้ ตัวเลือกเหล่านี้ยังมีเอกสารอธิบายไว้อย่างละเอียดใน [หัวข้อ “Tests” ของหนังสือ _The `rustc` Book_][tests]

[tests]: https://doc.rust-lang.org/rustc/tests/index.html

### การรันเทสต์แบบขนานหรือแบบทีละตัว

เมื่อคุณสั่งรันเทสต์หลายๆ ตัว โดยค่าเริ่มต้นพวกมันจะถูกรันแบบคู่ขนาน (parallel) ผ่านเธรด (threads) ซึ่งช่วยให้การรันทดสอบเสร็จสิ้นอย่างรวดเร็วและคุณได้รับผลตอบรับทันท่วงที ทว่าเนื่องจากเทสต์ต่างๆ ทำงานพร้อมกัน คุณจึงต้องมั่นใจว่าชุดทดสอบของคุณไม่มีการพึ่งพาซึ่งกันและกัน หรือพึ่งพาสถานะที่ใช้ร่วมกัน (shared state) ใดๆ รวมถึงสภาพแวดล้อมส่วนกลาง เช่น ไดเรกทอรีทำงานปัจจุบันหรือตัวแปรสภาพแวดล้อม (environment variables)

ตัวอย่างเช่น สมมติว่าเทสต์แต่ละตัวของคุณรันโค้ดที่สร้างไฟล์บนดิสก์ชื่อ _test-output.txt_ แล้วเขียนข้อมูลบางอย่างลงไป จากนั้นเทสต์แต่ละตัวจะอ่านข้อมูลจากไฟล์นั้นขึ้นมาตรวจสอบยืนยันค่า ซึ่งแต่ละเทสต์ก็คาดหวังค่าที่แตกต่างกันออกไป เมื่อเทสต์เหล่านี้รันพร้อมกัน เทสต์ตัวหนึ่งอาจเข้าไปเขียนทับไฟล์ในช่วงจังหวะเวลาระหว่างที่อีกเทสต์หนึ่งกำลังเขียนและเตรียมอ่านไฟล์ ส่งผลให้เทสต์ตัวที่สองเกิดล้มเหลวขึ้นมา ซึ่งไม่ได้เป็นเพราะโค้ดมีข้อผิดพลาด แต่เป็นเพราะเทสต์รบกวนการทำงานซึ่งกันและกันขณะรันแบบขนาน วิธีแก้ปัญหาประการหนึ่งคือการทำให้มั่นใจว่าแต่ละเทสต์จะเขียนข้อมูลลงในไฟล์ที่ต่างกัน หรืออีกวิธีหนึ่งคือการสั่งให้เทสต์ทำงานทีละตัวตามลำดับ

หากคุณไม่ต้องการให้เทสต์ทำงานแบบขนาน หรือต้องการควบคุมจำนวนเธรดที่ใช้งานอย่างเจาะจง คุณสามารถส่งแฟล็ก `--test-threads` พร้อมระบุจำนวนเธรดที่ต้องการไปยังไบนารีทดสอบได้ ดังตัวอย่างต่อไปนี้:

```console
$ cargo test -- --test-threads=1
```

เรากำหนดจำนวนเธรดทดสอบเป็น `1` เพื่อบอกให้โปรแกรมไม่ต้องใช้การทำงานแบบขนาน แม้ว่าการรันเทสต์ด้วยเธรดเดียวจะใช้เวลานานกว่าการรันแบบขนาน แต่ก็ช่วยให้มั่นใจได้ว่าเทสต์จะไม่รบกวนกันเองหากจำเป็นต้องใช้สถานะร่วมกัน

### การแสดงเอาต์พุตของฟังก์ชัน

โดยค่าเริ่มต้น หากเทสต์นั้นผ่าน ไลบรารีการทดสอบของ Rust จะดักจับ (capture) ทุกข้อความที่พิมพ์ออกสู่เอาต์พุตมาตรฐาน (standard output) เอาไว้ ตัวอย่างเช่น หากเราเรียกใช้คำสั่ง `println!` ภายในเทสต์แล้วเทสต์นั้นผ่าน เราจะไม่เห็นข้อความของ `println!` ในเทอร์มินัลเลย โดยจะเห็นเพียงบรรทัดที่รายงานว่าเทสต์ผ่านเท่านั้น แต่หากเทสต์ล้มเหลว ข้อความทั้งหมดที่พิมพ์ออกทางเอาต์พุตมาตรฐานจะแสดงออกมาให้เห็นร่วมกับข้อความแจ้งความล้มเหลว
