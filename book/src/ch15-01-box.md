## ใช้ `Box<T>` ชี้ไปยังข้อมูลบนฮีป

สมาร์ตพอยน์เตอร์ (smart pointer) ที่ตรงไปตรงมาที่สุดคือบ็อกซ์ (box) ซึ่งชนิดของมันเขียนว่า `Box<T>` _บ็อกซ์_อนุญาตให้คุณเก็บข้อมูลบนฮีป (heap) แทนที่จะเป็นบนสแตก (stack) สิ่งที่เหลืออยู่บนสแตกคือพอยน์เตอร์ไปยังข้อมูลบนฮีป อ้างอิงบทที่ 4 เพื่อทบทวนความแตกต่างระหว่างสแตกและฮีป

บ็อกซ์ไม่มีโอเวอร์เฮดด้านประสิทธิภาพ นอกเหนือไปจากการเก็บข้อมูลของมันไว้บนฮีปแทนที่จะเป็นบนสแตก แต่พวกมันก็ไม่มีความสามารถพิเศษเพิ่มเติมมากนักเช่นกัน คุณจะใช้มันบ่อยที่สุดในสถานการณ์เหล่านี้:

- เมื่อคุณมีชนิดข้อมูลที่ขนาดไม่สามารถรู้ได้ตอนคอมไพล์ และคุณต้องการใช้ค่าของชนิดนั้นในบริบทที่ต้องการขนาดที่แน่นอน
- เมื่อคุณมีข้อมูลจำนวนมาก และคุณต้องการโอนความเป็นเจ้าของแต่รับประกันว่าข้อมูลจะไม่ถูกคัดลอกเมื่อคุณทำเช่นนั้น
- เมื่อคุณต้องการเป็นเจ้าของค่า และคุณสนใจเพียงว่ามันเป็นชนิดข้อมูลที่อิมพลีเมนต์เทรตใดเทรตหนึ่งโดยเฉพาะ มากกว่าที่จะเป็นชนิดข้อมูลที่เจาะจง

เราจะสาธิตสถานการณ์แรกใน[“การเปิดใช้ชนิดข้อมูลแบบเรียกซ้ำด้วยบ็อกซ์”](#enabling-recursive-types-with-boxes)<!-- ignore --> ในกรณีที่สอง การโอนความเป็นเจ้าของข้อมูลจำนวนมากอาจใช้เวลานานเพราะข้อมูลถูกคัดลอกไปมาบนสแตก เพื่อปรับปรุงประสิทธิภาพในสถานการณ์นี้ เราสามารถเก็บข้อมูลจำนวนมากไว้บนฮีปในบ็อกซ์ได้ จากนั้น จะมีเพียงข้อมูลพอยน์เตอร์จำนวนเล็กน้อยเท่านั้นที่ถูกคัดลอกไปมาบนสแตก ในขณะที่ข้อมูลที่มันอ้างถึงยังคงอยู่ในที่เดียวบนฮีป กรณีที่สามเป็นที่รู้จักในชื่อ_เทรตออบเจกต์_ (trait object) และ[“การใช้เทรตออบเจกต์เพื่อนามธรรมพฤติกรรมร่วม”][trait-objects]<!-- ignore --> ในบทที่ 18 อุทิศให้กับหัวข้อนั้น ดังนั้น สิ่งที่คุณเรียนรู้ที่นี่จะถูกนำไปใช้ซ้ำอีกครั้งในหัวข้อนั้น!

### การเปิดใช้ชนิดข้อมูลแบบเรียกซ้ำด้วยบ็อกซ์

ค่าของ_ชนิดข้อมูลแบบเรียกซ้ำ_ (recursive type) สามารถมีค่าอื่นที่เป็นชนิดเดียวกันเป็นส่วนหนึ่งของตัวมันเองได้ ชนิดข้อมูลแบบเรียกซ้ำก่อปัญหาเพราะ Rust จำเป็นต้องรู้ตอนคอมไพล์ว่าชนิดข้อมูลหนึ่งกินพื้นที่เท่าใด อย่างไรก็ตาม การซ้อนกันของค่าของชนิดข้อมูลแบบเรียกซ้ำอาจดำเนินต่อไปได้ไม่สิ้นสุดในทางทฤษฎี Rust จึงไม่สามารถรู้ได้ว่าค่านั้นต้องใช้พื้นที่เท่าใด เนื่องจากบ็อกซ์มีขนาดที่รู้ได้ เราจึงสามารถเปิดใช้ชนิดข้อมูลแบบเรียกซ้ำได้โดยการแทรกบ็อกซ์ลงไปในนิยามของชนิดข้อมูลแบบเรียกซ้ำ

ในฐานะตัวอย่างของชนิดข้อมูลแบบเรียกซ้ำ มาสำรวจ cons list กัน นี่คือชนิดข้อมูลที่พบได้ทั่วไปในภาษาโปรแกรมเชิงฟังก์ชัน ชนิด cons list ที่เราจะนิยามนั้นตรงไปตรงมา ยกเว้นส่วนของการเรียกซ้ำ ดังนั้น แนวคิดในตัวอย่างที่เราจะทำงานด้วยจะเกิดประโยชน์ทุกครั้งที่คุณเจอสถานการณ์ที่ซับซ้อนมากขึ้นซึ่งเกี่ยวข้องกับชนิดข้อมูลแบบเรียกซ้ำ

#### การทำความเข้าใจ Cons List

_cons list_ เป็นโครงสร้างข้อมูลที่มาจากภาษาโปรแกรม Lisp และภาษาถิ่นของมัน ประกอบขึ้นจากคู่ที่ซ้อนกัน และเป็นเวอร์ชันของลิสต์แบบเชื่อมโยง (linked list) ใน Lisp ชื่อของมันมาจากฟังก์ชัน `cons` (ย่อมาจาก _construct function_) ใน Lisp ที่สร้างคู่ใหม่จากอาร์กิวเมนต์สองตัวของมัน โดยการเรียก `cons` บนคู่ที่ประกอบด้วยค่าและคู่อื่น เราสามารถสร้าง cons list ที่ประกอบขึ้นจากคู่แบบเรียกซ้ำได้

ยกตัวอย่างเช่น นี่คือตัวแทนแบบซูโดโค้ดของ cons list ที่บรรจุลิสต์ `1, 2, 3` โดยแต่ละคู่อยู่ในวงเล็บ:

```text
(1, (2, (3, Nil)))
```

แต่ละรายการใน cons list บรรจุสององค์ประกอบ: ค่าของรายการปัจจุบันและของรายการถัดไป รายการสุดท้ายในลิสต์บรรจุเพียงค่าเดียวที่เรียกว่า `Nil` โดยไม่มีรายการถัดไป cons list ถูกสร้างขึ้นโดยการเรียกฟังก์ชัน `cons` ซ้ำๆ ชื่อมาตรฐานที่ใช้แสดงกรณีฐานของความเวียนเกิดคือ `Nil` โปรดสังเกตว่าสิ่งนี้ไม่เหมือนกับแนวคิด “null” หรือ “nil” ที่พูดคุยกันในบทที่ 6 ซึ่งเป็นค่าที่ไม่ถูกต้องหรือไม่มีค่า

cons list ไม่ใช่โครงสร้างข้อมูลที่ใช้กันทั่วไปใน Rust ส่วนใหญ่แล้วเมื่อคุณมีรายการของสิ่งต่างๆ ใน Rust `Vec<T>` เป็นตัวเลือกที่ดีกว่าที่จะใช้ ชนิดข้อมูลแบบเรียกซ้ำอื่นๆ ที่ซับซ้อนกว่า_มี_ประโยชน์ในสถานการณ์ต่างๆ แต่การเริ่มด้วย cons list ในบทนี้ทำให้เราสำรวจได้ว่าบ็อกซ์ช่วยให้เรานิยามชนิดข้อมูลแบบเรียกซ้ำได้อย่างไรโดยไม่ไขว้เขวมากนัก

#### การได้มาซึ่งชนิดข้อมูลแบบเรียกซ้ำที่มีขนาดที่รู้ได้

เนื่องจาก Rust ไม่สามารถคำนวณได้ว่าต้องจัดสรรพื้นที่เท่าใดสำหรับชนิดข้อมูลที่นิยามแบบเรียกซ้ำ คอมไพเลอร์จึงให้ข้อผิดพลาดพร้อมคำแนะนำที่เป็นประโยชน์นี้:

ในคำแนะนำนี้ _การอ้อม_ (indirection) หมายความว่าแทนที่จะเก็บค่าโดยตรง เราควรเปลี่ยนโครงสร้างข้อมูลให้เก็บค่าโดยอ้อมด้วยการเก็บพอยน์เตอร์ไปยังค่าแทน

เนื่องจาก `Box<T>` เป็นพอยน์เตอร์ Rust จึงรู้เสมอว่า `Box<T>` ต้องใช้พื้นที่เท่าใด: ขนาดของพอยน์เตอร์ไม่เปลี่ยนแปลงตามปริมาณข้อมูลที่มันชี้ไป ซึ่งหมายความว่าเราสามารถใส่ `Box<T>` ไว้ในวาเรียนต์ `Cons` แทนที่จะเป็นค่า `List` อีกค่าหนึ่งโดยตรงได้ `Box<T>` จะชี้ไปยังค่า `List` ถัดไปที่จะอยู่บนฮีปแทนที่จะอยู่ภายในวาเรียนต์ `Cons` ในเชิงแนวคิด เรายังคงมีลิสต์ที่สร้างขึ้นจากลิสต์ที่บรรจุลิสต์อื่นๆ แต่การอิมพลีเมนต์นี้กลับเหมือนกับการวางรายการต่างๆ ไว้ข้างๆ กันมากกว่าที่จะซ้อนไว้ภายในกัน
