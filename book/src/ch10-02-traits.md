## นิยามพฤติกรรมร่วมด้วยเทรต

_เทรต_ (trait) นิยามฟังก์ชันการทำงานที่ชนิดข้อมูลหนึ่งๆ มีและสามารถแบ่งปันให้กับชนิดอื่นๆ ได้ เราใช้เทรตเพื่อนิยามพฤติกรรมร่วมกันในแบบนามธรรมได้ เราสามารถใช้_บาวด์ของเทรต_ (trait bound) เพื่อระบุว่าชนิดเจเนอริก (generic) สามารถเป็นชนิดใดก็ได้ที่มีพฤติกรรมบางอย่าง

> หมายเหตุ: เทรตคล้ายกับฟีเจอร์ที่มักถูกเรียกว่า _อินเทอร์เฟซ_ (interface) ในภาษาอื่น แม้ว่าจะมีความแตกต่างบางประการ

### การนิยามเทรต

พฤติกรรมของชนิดข้อมูลประกอบด้วยเมธอดที่เราเรียกใช้บนชนิดนั้นได้ ชนิดข้อมูลที่ต่างกันมีพฤติกรรมร่วมกันหากเราสามารถเรียกเมธอดเดียวกันบนทุกชนิดนั้นได้ นิยามของเทรตเป็นวิธีจัดกลุ่มซิกเนเจอร์ของเมธอดเข้าด้วยกันเพื่อนิยามชุดของพฤติกรรมที่จำเป็นต่อการบรรลุวัตถุประสงค์บางอย่าง

ตัวอย่างเช่น สมมติว่าเรามี struct หลายตัวที่บรรจุข้อความชนิดและปริมาณต่างๆ กัน: struct `NewsArticle` ที่บรรจุข่าวที่ถูกส่งจากสถานที่หนึ่งๆ และ `SocialPost` ที่มีได้ไม่เกิน 280 อักขระ พร้อมข้อมูลเมตาที่ระบุว่ามันเป็นโพสต์ใหม่ การรีโพสต์ หรือการตอบกลับโพสต์อื่น

เราต้องการสร้างเครตไลบรารี (library crate) สำหรับรวมสื่อชื่อ `aggregator` ที่สามารถแสดงบทสรุปของข้อมูลที่อาจถูกจัดเก็บในอินสแตนซ์ (instance) `NewsArticle` หรือ `SocialPost` ได้ ในการทำเช่นนี้ เราต้องการบทสรุปจากแต่ละชนิด และเราจะขอบทสรุปนั้นโดยเรียกเมธอด `summarize` บนอินสแตนซ์ ลิสติ้ง 10-12 แสดงนิยามของเทรต `Summary` แบบสาธารณะ (public) ที่แสดงพฤติกรรมนี้

ในที่นี้ เราประกาศเทรตด้วยคำสงวน `trait` ตามด้วยชื่อของเทรต ซึ่งในกรณีนี้คือ `Summary` เรายังประกาศเทรตนี้เป็น `pub` เพื่อให้เครตที่พึ่งพาเครตนี้สามารถใช้เทรตนี้ได้ด้วย ดังที่เราจะเห็นในตัวอย่างไม่กี่ตัวอย่างข้างหน้า ภายในวงเล็บปีกกา เราประกาศซิกเนเจอร์ของเมธอดที่อธิบายพฤติกรรมของชนิดข้อมูลที่อิมพลีเมนต์เทรตนี้ ซึ่งในกรณีนี้คือ `fn summarize(&self) -> String`

หลังซิกเนเจอร์ของเมธอด แทนที่จะให้การอิมพลีเมนต์ภายในวงเล็บปีกกา เราใช้อัฒภาคแทน ชนิดข้อมูลแต่ละชนิดที่อิมพลีเมนต์เทรตนี้ต้องจัดเตรียมพฤติกรรมกำหนดเองของตัวเองสำหรับบอดี้ของเมธอด คอมไพเลอร์จะบังคับว่าชนิดใดก็ตามที่มีเทรต `Summary` จะต้องมีเมธอด `summarize` ที่นิยามด้วยซิกเนเจอร์นี้อย่างแม่นยำ

เทรตสามารถมีหลายเมธอดในบอดี้ของมันได้: ซิกเนเจอร์ของเมธอดจะถูกระบุบรรทัดละหนึ่งอัน และแต่ละบรรทัดลงท้ายด้วยอัฒภาค

เครตอื่นๆ ที่พึ่งพาเครต `aggregator` ก็สามารถนำเทรต `Summary` เข้าสู่สโคปเพื่ออิมพลีเมนต์ `Summary` บนชนิดข้อมูลของตัวเองได้เช่นกัน ข้อจำกัดหนึ่งที่ควรทราบคือ เราสามารถอิมพลีเมนต์เทรตบนชนิดข้อมูลได้ก็ต่อเมื่อเทรตหรือชนิดข้อมูลอย่างใดอย่างหนึ่ง หรือทั้งสองอย่าง เป็นของเครตของเรา ตัวอย่างเช่น เราสามารถอิมพลีเมนต์เทรตของไลบรารีมาตรฐานอย่าง `Display` บนชนิดข้อมูลกำหนดเองอย่าง `SocialPost` ได้ในฐานะส่วนหนึ่งของฟังก์ชันการทำงานของเครต `aggregator` ของเรา เพราะชนิด `SocialPost` เป็นของเครต `aggregator` ของเรา เรายังสามารถอิมพลีเมนต์ `Summary` บน `Vec<T>` ในเครต `aggregator` ของเราได้ เพราะเทรต `Summary` เป็นของเครต `aggregator` ของเรา

แต่เราอิมพลีเมนต์เทรตภายนอกบนชนิดข้อมูลภายนอกไม่ได้ ตัวอย่างเช่น เราอิมพลีเมนต์เทรต `Display` บน `Vec<T>` ภายในเครต `aggregator` ของเราไม่ได้ เพราะ `Display` และ `Vec<T>` ต่างก็ถูกนิยามในไลบรารีมาตรฐานและไม่ได้เป็นของเครต `aggregator` ของเรา ข้อจำกัดนี้เป็นส่วนหนึ่งของคุณสมบัติที่เรียกว่า _ความสอดคล้อง_ (coherence) และเจาะจงยิ่งกว่านั้นคือ _กฎออร์แฟน_ (orphan rule) ที่ได้ชื่อเช่นนี้เพราะชนิดข้อมูลแม่ไม่ได้อยู่ด้วย กฎนี้ทำให้มั่นใจว่าโค้ดของคนอื่นไม่อาจทำให้โค้ดของคุณพัง และในทางกลับกันก็เช่นกัน หากไม่มีกฎนี้ สองเครตอาจอิมพลีเมนต์เทรตเดียวกันให้กับชนิดเดียวกันได้ และ Rust ก็จะไม่รู้ว่าจะใช้การอิมพลีเมนต์ใด

แทนที่จะเป็นชนิดที่เป็นรูปธรรมสำหรับพารามิเตอร์ `item` เราได้ระบุคำสงวน `impl` และชื่อเทรต พารามิเตอร์นี้ยอมรับชนิดใดก็ได้ที่อิมพลีเมนต์เทรตที่ระบุ ในบอดี้ของ `notify` เราสามารถเรียกเมธอดใดๆ บน `item` ที่มาจากเทรต `Summary` เช่น `summarize` เราเรียก `notify` และส่งอินสแตนซ์ใดก็ได้ของ `NewsArticle` หรือ `SocialPost` เข้าไปได้ โค้ดที่เรียกฟังก์ชันนี้ด้วยชนิดอื่น เช่น `String` หรือ `i32` จะไม่คอมไพล์ผ่าน เพราะชนิดเหล่านั้นไม่ได้อิมพลีเมนต์ `Summary`

#### ไวยากรณ์บาวด์ของเทรต

ไวยากรณ์ `impl Trait` ใช้ได้ดีกับกรณีตรงไปตรงมา แต่ที่จริงแล้วมันคือนามแฝงทางไวยากรณ์ (syntax sugar) ของรูปแบบที่ยาวกว่าซึ่งรู้จักกันในชื่อ _บาวด์ของเทรต_ ซึ่งมีหน้าตาดังนี้:

```rust,ignore
pub fn notify<T: Summary>(item: &T) {
    println!("Breaking news! {}", item.summarize());
}
```

รูปแบบที่ยาวกว่านี้เทียบเท่ากับตัวอย่างในหัวข้อก่อนหน้าแต่ยาวเยิ่นเย้อกว่า เราเขียนบาวด์ของเทรตไว้พร้อมกับการประกาศพารามิเตอร์ชนิดข้อมูลแบบเจเนอริก หลังเครื่องหมายทวิภาคและภายในวงเล็บมุม

ไวยากรณ์ `impl Trait` นั้นสะดวกและทำให้โค้ดกระชับขึ้นในกรณีง่ายๆ ส่วนไวยากรณ์บาวด์ของเทรตแบบเต็มรูปสามารถแสดงความซับซ้อนได้มากกว่าในกรณีอื่นๆ ตัวอย่างเช่น เราสามารถมีสองพารามิเตอร์ที่อิมพลีเมนต์ `Summary` การทำเช่นนั้นด้วยไวยากรณ์ `impl Trait` มีหน้าตาดังนี้:

```rust,ignore
pub fn notify(item1: &impl Summary, item2: &impl Summary) {
```

การใช้ `impl Trait` เหมาะสมหากเราต้องการให้ฟังก์ชันนี้ยอมให้ `item1` และ `item2` มีชนิดต่างกันได้ (ตราบใดที่ทั้งสองชนิดอิมพลีเมนต์ `Summary`) อย่างไรก็ตาม หากเราต้องการบังคับให้พารามิเตอร์ทั้งสองมีชนิดเดียวกัน เราต้องใช้บาวด์ของเทรต ดังนี้:

```rust,ignore
pub fn notify<T: Summary>(item1: &T, item2: &T) {
```

ชนิดเจเนอริก `T` ที่ระบุเป็นชนิดของพารามิเตอร์ `item1` และ `item2` จำกัดฟังก์ชันให้ชนิดที่เป็นรูปธรรมของค่าที่ส่งเป็นอาร์กิวเมนต์สำหรับ `item1` และ `item2` ต้องเป็นชนิดเดียวกัน

#### บาวด์ของเทรตหลายตัวด้วยไวยากรณ์ `+`

เรายังสามารถระบุบาวด์ของเทรตมากกว่าหนึ่งตัวได้ สมมติว่าเราต้องการให้ `notify` ใช้การจัดรูปแบบเพื่อแสดงผลรวมทั้ง `summarize` กับ `item` ด้วย: เราระบุในนิยามของ `notify` ว่า `item` ต้องอิมพลีเมนต์ทั้ง `Display` และ `Summary` เราทำเช่นนั้นได้โดยใช้ไวยากรณ์ `+`:

```rust,ignore
pub fn notify(item: &(impl Summary + Display)) {
```

ไวยากรณ์ `+` ยังใช้ได้กับบาวด์ของเทรตบนชนิดเจเนอริกด้วย:

```rust,ignore
pub fn notify<T: Summary + Display>(item: &T) {
```

เมื่อระบุบาวด์ของเทรตทั้งสองตัวแล้ว บอดี้ของ `notify` สามารถเรียก `summarize` และใช้ `{}` เพื่อจัดรูปแบบ `item` ได้

#### บาวด์ของเทรตที่ชัดเจนขึ้นด้วยอนุประโยค `where`

การใช้บาวด์ของเทรตมากเกินไปมีข้อเสีย แต่ละเจเนอริกมีบาวด์ของเทรตของตัวเอง ดังนั้นฟังก์ชันที่มีพารามิเตอร์ชนิดข้อมูลแบบเจเนอริกหลายตัวอาจมีข้อมูลบาวด์ของเทรตจำนวนมากระหว่างชื่อฟังก์ชันกับรายการพารามิเตอร์ ทำให้ซิกเนเจอร์ของฟังก์ชันอ่านยาก ด้วยเหตุนี้ Rust จึงมีไวยากรณ์ทางเลือกสำหรับระบุบาวด์ของเทรตภายในอนุประโยค `where` หลังซิกเนเจอร์ของฟังก์ชัน ดังนั้น แทนที่จะเขียนแบบนี้:

```rust,ignore
fn some_function<T: Display + Clone, U: Clone + Debug>(t: &T, u: &U) -> i32 {
```

เรายังสามารถใช้ไวยากรณ์ `impl Trait` ในตำแหน่งของค่าที่คืนกลับเพื่อคืนค่าที่มีชนิดข้อมูลบางชนิดซึ่งอิมพลีเมนต์เทรตได้ ดังที่แสดงที่นี่:


การใช้ `impl Summary` เป็นชนิดที่คืนกลับ เราได้ระบุว่าฟังก์ชัน `returns_summarizable` คืนค่าที่มีชนิดข้อมูลบางชนิดซึ่งอิมพลีเมนต์เทรต `Summary` โดยไม่ต้องระบุชื่อชนิดที่เป็นรูปธรรม ในกรณีนี้ `returns_summarizable` คืนค่า `SocialPost` แต่โค้ดที่เรียกฟังก์ชันนี้ไม่จำเป็นต้องรู้เรื่องนั้น

ความสามารถในการระบุชนิดที่คืนกลับด้วยเทรตที่มันอิมพลีเมนต์เท่านั้นมีประโยชน์เป็นพิเศษในบริบทของโคลเชอร์ (closure) และอิเทอเรเตอร์ (iterator) ซึ่งเราจะครอบคลุมในบทที่ 13 โคลเชอร์และอิเทอเรเตอร์สร้างชนิดข้อมูลที่คอมไพเลอร์เท่านั้นที่รู้จัก หรือชนิดข้อมูลที่ยาวมากเมื่อต้องระบุ ไวยากรณ์ `impl Trait` ช่วยให้คุณระบุอย่างกระชับได้ว่าฟังก์ชันคืนค่าที่มีชนิดข้อมูลบางชนิดซึ่งอิมพลีเมนต์เทรต `Iterator` โดยไม่ต้องเขียนชนิดข้อมูลที่ยาวมากออกมา

### การใช้บาวด์ของเทรตเพื่ออิมพลีเมนต์เมธอดแบบมีเงื่อนไข

การใช้บาวด์ของเทรตร่วมกับบล็อก `impl` ที่ใช้พารามิเตอร์ชนิดข้อมูลแบบเจเนอริก ทำให้เราสามารถอิมพลีเมนต์เมธอดแบบมีเงื่อนไขสำหรับชนิดข้อมูลที่อิมพลีเมนต์เทรตที่ระบุได้ ตัวอย่างเช่น ชนิด `Pair<T>` ในลิสติ้ง 10-15 อิมพลีเมนต์ฟังก์ชัน `new` เพื่อคืนอินสแตนซ์ใหม่ของ `Pair<T>` เสมอ (ย้อนนึกถึงหัวข้อ[“วากยสัมพันธ์ของเมธอด”][methods]<!-- ignore --> ในบทที่ 5 ว่า `Self` เป็นนามแฝงของชนิดข้อมูลของบล็อก `impl` ซึ่งในกรณีนี้คือ `Pair<T>`) แต่ในบล็อก `impl` ถัดมา `Pair<T>` อิมพลีเมนต์เมธอด `cmp_display` เฉพาะเมื่อชนิดข้อมูลภายใน `T` ของมันอิมพลีเมนต์เทรต `PartialOrd` ที่เปิดใช้การเปรียบเทียบ_และ_เทรต `Display` ที่เปิดใช้การพิมพ์

เรายังสามารถอิมพลีเมนต์เทรตแบบมีเงื่อนไขสำหรับชนิดใดก็ได้ที่อิมพลีเมนต์เทรตอื่นได้ การอิมพลีเมนต์เทรตบนชนิดใดก็ตามที่ตรงตามบาวด์ของเทรตเรียกว่า _การอิมพลีเมนต์แบบคลุมทั้งหมด_ (blanket implementation) และถูกใช้อย่างแพร่หลายในไลบรารีมาตรฐานของ Rust ตัวอย่างเช่น ไลบรารีมาตรฐานอิมพลีเมนต์เทรต `ToString` บนชนิดใดก็ได้ที่อิมพลีเมนต์เทรต `Display` บล็อก `impl` ในไลบรารีมาตรฐานมีหน้าตาคล้ายกับโค้ดนี้:

```rust,ignore
impl<T: Display> ToString for T {
    // --snip--
}
```

เพราะไลบรารีมาตรฐานมีการอิมพลีเมนต์แบบคลุมทั้งหมดนี้ เราจึงสามารถเรียกเมธอด `to_string` ที่นิยามโดยเทรต `ToString` บนชนิดใดก็ได้ที่อิมพลีเมนต์เทรต `Display` ตัวอย่างเช่น เราสามารถแปลงจำนวนเต็มเป็นค่า `String` ที่สอดคล้องกันได้ดังนี้ เพราะจำนวนเต็มอิมพลีเมนต์ `Display`:

```rust
let s = 3.to_string();
```

การอิมพลีเมนต์แบบคลุมทั้งหมดจะปรากฏในเอกสารประกอบของเทรตในหัวข้อ “Implementors”

เทรตและบาวด์ของเทรตช่วยให้เราเขียนโค้ดที่ใช้พารามิเตอร์ชนิดข้อมูลแบบเจเนอริกเพื่อลดความซ้ำซ้อน แต่ในขณะเดียวกันก็ระบุแก่คอมไพเลอร์ว่าเราต้องการให้ชนิดเจเนอริกมีพฤติกรรมหนึ่งๆ คอมไพเลอร์จึงสามารถใช้ข้อมูลบาวด์ของเทรตเพื่อตรวจสอบว่าชนิดที่เป็นรูปธรรมทั้งหมดที่ใช้กับโค้ดของเราจัดเตรียมพฤติกรรมที่ถูกต้อง ในภาษาแบบไดนามิก เราจะได้ข้อผิดพลาดตอนรันไทม์หากเราเรียกเมธอดบนชนิดข้อมูลที่ไม่ได้นิยามเมธอดนั้น แต่ Rust ย้ายข้อผิดพลาดเหล่านี้ไปยังตอนคอมไพล์ เพื่อบังคับให้เราแก้ไขปัญหาเหล่านั้นก่อนที่โค้ดของเราจะรันได้ด้วยซ้ำ นอกจากนี้ เรายังไม่ต้องเขียนโค้ดที่ตรวจสอบพฤติกรรมตอนรันไทม์ เพราะเราได้ตรวจสอบตอนคอมไพล์แล้ว การทำเช่นนี้ช่วยเพิ่มประสิทธิภาพโดยไม่ต้องแลกกับความยืดหยุ่นของเจเนอริก
